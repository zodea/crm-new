## Problem Statement

施工进度页仍从本地适配读取和保存 WBS。当前中央项目、工程量区域、模板和阶段完成已由 #442 承接，但现有浏览器排程不能沿同一身份读取这些事实，也没有中央版本冲突保护。用户可能在项目、楼栋分组、工序与工程量详情之间看到割裂来源。

## Solution

接通「选择当前项目 → 选择合同清单或内部暂估 → 套用工序库建组 → 调整日期和依赖 → 刷新回读 → 下钻同一阶段完成 → 返回同一工序」的完整中央路径。沿用 #412、ADR 0010/0017/0018/0020 和现行排程蓝本的规则，不重新定义施工及工资业务。

## User Stories

1. 作为排程经办人，我要读取当前授权项目和已有分组，空项目明确显示未建计划，不能自动取同名演示对象。
2. 作为排程经办人，我要从同一项目选择唯一施工合同，以清单显式楼栋范围建立分组，避免同名户型被误当楼栋覆盖证据。
3. 作为排程经办人，我要在签约前从真实区域和暂估分项建立计划，持续看到待绑定合同提示，不能用合同量或现场量补齐缺失暂估量。两户暂估为 8 / null 时保留缺失信息，真实 0 仍可辨认；平方米和米分别汇总，不跨单位相加。
4. 作为排程经办人，我要从缺区域提示进入整页区域配置，返回后保留有效草稿并重新核实范围。
5. 作为排程经办人，我要在范围、工序、确认三步中调整计划，失败时留在确认步骤保留草稿，重试不产生重复分组。
6. 作为工序库维护人，我要保存不可变版本，基于旧版调整产生下一版本，既有项目保留原库和工序快照。
7. 作为排程经办人，我要区分自动阶段进度与手工进度，自动进度只来自适用户的当前阶段完成，责任分配不能冒充施工完成。验证适用户分母、不同阶段隔离、实际开始取最早完成日，未全部完成不填实际完成日；手工进度限定 0–100，项目和分组按已定工期权重汇总。
8. 作为排程经办人，我要调整工序和个别楼层日期，人工微调层保留自己的计划，其他自动层按已定规则调整。
9. 作为排程经办人，我要维护同组 FS 与滞后关系，循环、自依赖及非法来源须有明确反馈。
10. 作为排程经办人，我要在调期破坏依赖前确认，取消不写入，确认保留置灰关系和审计，并可在条件满足后显式恢复。
11. 作为排程经办人，我要设定基线、增加或按既定规则移除工序，刷新后回读同一身份和已保存计划。
12. 作为排程经办人，我要先查看暂估绑定施工合同的范围、分项和数量差异；不满足覆盖时不能绑定，成功不改写原暂估快照或完成事实。
13. 作为排程经办人，我要在其他操作已修改来源时得到可恢复的冲突，保留输入，明确重新读取后再决定如何保存。
14. 作为排程查看人，我要在排程、首页和工程量矩阵之间按项目、分组、任务、阶段及稳定分项身份往返，恢复原楼栋、月份、视图、工种与责任户；合同清单可进入对应楼层计划，户详情可沿同一来源返回。失效身份显示原因。
15. 作为迁移经办人，我要对旧分组、任务、依赖、楼层计划和工序库版本受控预检、确认、对账和恢复；缺失关系不能靠名称或假数据兜底。
16. 作为使用人，我要在手机、平板和桌面看清按钮与状态，只有表格和甘特自身滚动，确认与键盘操作保持可达。

## Implementation Decisions

- 正式浏览器排程读写统一通过 Repository、HTTP 与领域命令；桌面本地适配与演示边界继续遵守 ADR 0020，不保留两个并行正式来源。
- 复用既有计划、依赖、版本工序库及合同绑定领域规则，将事务写入从页面状态中抽出；不把 SQL 或任意表写入暴露为 HTTP 能力。
- 当前项目、合同清单、工程量范围及阶段完成作为带来源版本的输入，后台验证身份和归属。排程保有自己的计划、基线和绑定快照，不复制第二套施工完成录入。
- 命令具备当前会话能力检查、作用域隔离、重复提交识别及来源版本校验；成功保存后读取同一中央事实，确定冲突与传输结果不确定分别恢复。
- 迁移沿用现有备份、候选准备、对账和恢复入口；每项旧关系按稳定映射接入并报告缺口，不回放历史写入通知。
- 权威文档更新现有词义、数据、读写和排程页面入口；仅在真实新增架构取舍时增加 ADR。

## Testing Decisions

- 以领域服务和实际浏览器路径检验保存、刷新及来源往返，不依赖静态源码包含某字段。
- 复用既有排程计划、工序库、合同绑定、中央工程量及受控迁移测试接缝；先建立陈旧版本、范围错配和迟到请求的失败复现，再修正。
- 核对真实三步建组、手工与自动进度、日期/依赖取消确认、禁用与恢复、工序库版本隔离、绑定前后快照、保存后冷刷新、无权/断网/重复及迁移恢复。
- 390/768/1024/1280–1440px 实际界面、局部横滚、键盘焦点和浮层验收；更新使用指南并重新生成、逐页核查 PDF。
- 固定提交基准完成 Standards 与 Spec 双轴复核，以及类型、定向测试和最终全量本地检查。云端 CI 仍遵守现有单独确认规则。

## Out of Scope

工资生成与发放、目标成本中央保存、材料/机械按分项深化、完整审批/RBAC、多租户、生产数据库和部署均保留各自承接。本切片不宣告 #412 全域完成。

## Further Notes

承接 #412 的 PRG-01/02/03 以及 PRG-08/09/10 中排程适用部分；旧 #300/#347 的关闭是替代，不取消义务。依赖 #442 当前区域、阶段与完成来源，已提交的 #434 首页来源入口和 #435 返回恢复协议继续复用。剩余目标成本和 A/C1/C2 工资仍有独立实施范围。
