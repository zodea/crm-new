## 仍须补齐的完整用户路径

1. 受控读取旧工资全图 → 预检身份及退役 B → 确认接管 → 普通台账/详情冷读 → 重复确认保日常更正 → 危险恢复整批拒绝。
2. A：中央完成事实与现场量 → 工资域价格核对 → 整页草稿 → 重新核对 → 实际发放及分配 → 冷读冻结 → 工程量来源往返。月度、结算、尾款沿现行合法档位分别验证。
3. C1：当前项目工人名册 → 真实日期考勤保存 → 当月工资草稿与各人工资费率 → 核对 → 发放 → 当月来源封锁与真实输出。
4. C2：主体费率及确认规则 → 逐日签工与人工确认 → 唯一来源工资 → 发放 → 签工锁定 → 冻结的签工记录表及工资表。
5. 已发工资 → 独立调整/冲销与原单追溯 → 成本/已付同源回读。未发生的预期扣回不能伪装实际资金变化；跨月少发与原单调整不能重复扣减同一金额，具体入账场景须在实施规格中逐一演示。

## 2026-09-13 P0完整图复核

本次只读核对现行 SQLite DDL、迁移及工资读取/发放代码，未创建数据库或运行工资测试。以下补充用于约束 P0 的受控来源读取，不新增业务规则或宣称旧数据已具备新来源资格。

- **项目分桶与独立来源**：`payroll_subject_configs`、`wage_statements`、`attendance_records`、`signed_daywork_records` 的 `project_id` 均为 `NOT NULL`（[schema.ts:404](../../../app/lib/db/schema.ts#L404)、[419](../../../app/lib/db/schema.ts#L419)、[482](../../../app/lib/db/schema.ts#L482)、[498](../../../app/lib/db/schema.ts#L498)）。完整来源可按真实项目组织，纳入该项目尚未建工资的主体配置、考勤及未被领用的待确认/已确认签工；不能仅从工资头向下 JOIN 导出。项目映射缺失应显式阻断或隔离，不能仿照预算无项目草稿补造空项目分桶。
- **工资子图及历史**：头之外还包括 `wage_statement_lines`、`wage_statement_members`、`wage_statement_allocations`、`wage_statement_daywork_records`。与上述四表共同组成现有八表范围，来源读取保留各自稳定 ID、软删除历史及已有可识别审计。核对会软删旧行、旧成员和旧签工关联再写新行（[statements.ts:349](../../../app/lib/payroll/statements.ts#L349)、[372](../../../app/lib/payroll/statements.ts#L372)、[419](../../../app/lib/payroll/statements.ts#L419)），只迁当前可见子行会丢失真实更换历史。共享来源按原 ID 去重，不能随多张工资各造一份。
- **发放快照必须完整保留**：现行发放写入的 `snapshot_json` 除金额、成员、分配、行和签工正文，还含 C2 `subjectConfig` 的费率/规则及来源版本、月份、格式、档位和比例（[statements.ts:808](../../../app/lib/payroll/statements.ts#L808)）。当前 `parseReleaseSnapshot` 返回形状会裁掉后面这些字段（[statements.ts:966](../../../app/lib/payroll/statements.ts#L966)）；P0 应保存原始行与原快照全文，不能将 `loadWageStatement` 或输出 DTO 重新序列化当作完整图。合法空值、缺失/损坏快照及表与快照不一致分别保留诊断，不能用当前姓名、配置或量价补成旧发放事实。
- **来源锁由现有关系推导**：当前没有独立锁表。C1 已发月锁与 C2 月度互斥覆盖工资头负责人及全部成员（[attendance.ts:34](../../../app/lib/payroll/attendance.ts#L34)、[142](../../../app/lib/payroll/attendance.ts#L142)）；C2 另由签工关联判定唯一占用和已发不可改（[daywork.ts:295](../../../app/lib/payroll/daywork.ts#L295)、[322](../../../app/lib/payroll/daywork.ts#L322)）。零分配、没有工资行或没有当月工时的成员仍须保留。迁入及恢复必须一起复验头状态、月份、成员、关联及各自删除状态，防止其他负责人或日常独立工资已占用的来源被再次释放或恢复。
- **旧 A/C1 不能补造来源 ID**：A 旧行仅保存工人/分项汇总及量价，生成时虽连接完成与责任，返回时未保存 `completion/assignment` 明细 ID（[statements.ts:1504](../../../app/lib/payroll/statements.ts#L1504)、[1555](../../../app/lib/payroll/statements.ts#L1555)）；C1 保存汇总行和来源指纹，没有考勤行关联表（[statements.ts:1400](../../../app/lib/payroll/statements.ts#L1400)、[1459](../../../app/lib/payroll/statements.ts#L1459)）。`source_version` 不是可反解的外键集合。P0 保全原值与可证明的关系，缺证据时保留明确缺口，不按当前同名人、同分项、同项目或相同数量重建历史计薪资格。

原件与审计沿真实来源核对：通用载体为 `file_refs`、`file_payloads`、`operation_logs`（[schema.ts:388](../../../app/lib/db/schema.ts#L388)、[migrations.ts:120](../../../app/lib/db/migrations.ts#L120)、[228](../../../app/lib/db/migrations.ts#L228)）。本次未在工资领域找到现成工资附件写入口或明确的工资专属 `owner_type`；现有导出即时从工资数据生成，也不等于持久化原件。实施时只接可证明归属的旧文件与正文，未知归属保留诊断；班组/工人的已有原件继续归其身份域，不能复制成另一套工资原件。
