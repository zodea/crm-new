# 分供方证照中央链实施规格

> 已按用户授权发布至 [#407 定稿评论](https://github.com/zodea/crm-new/issues/407#issuecomment-5644844393)。本文为发布时本地审阅快照，当前规格与决定以 Issue 为准。调查基线为 `e761e9ee2d94554ed64464b19f3eba57d1655d9e`，2026-09-12 读取 #407 正文及全部评论；字段、词义和长期规则仍以现有权威源为准。

## Problem Statement

分供方已经能在浏览器中央主档中创建、编辑和查看，但“证照附件”进入后仍显示中央专用存储尚未接入。完整文件、资料要求、有效期、OCR 人工核对和资料核验目前只在旧桌面适配中可写。列表营业执照列因缺当前文件来源显示不可用，不能让经办人完成“建档 → 补资料 → 人工核验 → 详情/列表回读”。

另一个确定性语义错误在旧 OCR 链：统一社会信用代码候选指向内部唯一识别码。#407 已明确两者不同，不能沿用错误映射，也不能按旧值长度静默搬运历史数据。

## Solution

沿既有独立证照页接通中央证照专用领域。经办人上传真实原件，维护类别、有效期和要求，核对自动齐全度后执行已有人工核验。主档、列表和证照页读取同一当前结果。OCR 作为后续完整切片，保留原始候选、人工确认和失败恢复；确认主档字段仍走受权限及版本校验的领域命令。

## User Stories

1. 作为经办人，我能从分供方详情进入其证照页，始终确认当前稳定身份和来源，避免同名资料串档。
2. 作为经办人，我能查看真实空态、加载失败和无权原因，并在失败后重试，避免把未接入当作未上传。
3. 作为经办人，我能上传 PDF、PNG、JPG/JPEG 原件，保存后刷新并预览、下载同一字节，避免只留下文件名。
4. 作为经办人，我能看到每份文件的类别和有效期，单独更正这些事实，避免重新上传才能改日期。
5. 作为经办人，我能维护逐类别“需提供/可选/不适用”及既定原因，避免为了让状态变绿而伪造不存在的资料。
6. 作为经办人，我能删除错误证照，并沿现有撤回审计恢复同一份证照，避免恢复成另一份原件。
7. 作为核验人，我能依据有效原件、类别要求和上海业务日期看到缺失/过期或齐全待核验，避免系统自动宣布合格。
8. 作为核验人，我能对齐全待核验资料执行通过或附原因退回，并记录当前凭证，避免普通表单伪造人工结论。
9. 作为核验人，我能在影响结论的必需资料、要求或关键主档事实变化后重新核验；无关可选资料变化不会无故撤销原结论。
10. 作为列表使用者，我能在列表、详情和证照页看到一致状态及真实营业执照入口；未知、无文件和有文件分别显示。
11. 作为经办人，我能在并发更改、响应丢失或网络失败后保留输入并恢复原提交，避免重复文件和核验记录。
12. 作为经办人，我在快速切换 A/B、来源或页签时，不会让旧上传、旧读取、OCR 或确认结果写入当前另一主体。
13. 作为旧数据维护人，我能显式迁入证照、要求、正文、核验凭证及专用审计，看到无法解释身份和缺正文问题，不按名称猜关系。
14. 作为旧数据维护人，我能保留无正文旧路径的线索并重新选原件上传，不让旧路径授予文件读取权或计作齐全。
15. 作为旧数据维护人，我能对账并在合法窗口恢复本批迁移；其他独立中央记录保留，存在下游依赖时明确阻断。
16. 作为经办人，我能按已有 OCR 设置识别当前证照，服务失败仍可人工维护，不把识别失败当成上传失败。
17. 作为经办人，我能保存识别候选后“稍后核对”，刷新后从待核对状态继续，原始结果和已确认结果分别可追溯。
18. 作为经办人，我能逐项选择保留当前、采用识别或人工修正，类别冲突默认保留当前，未确认时不覆盖主档。
19. 作为经办人，我确认统一社会信用代码时只写税号字段，内部唯一识别码保留原含义；历史混写提示核对而不自动迁值。
20. 作为经办人，我能确认税务查询结果并回读凭证；官网验证码仍由本人完成，未查到不会自动判小规模。
21. 作为只读用户，我只能使用当前授权的来源和文件；演示原件、猜测 ID 或过期授权不能进入正式命令。
22. 作为复核人，我能通过本票流程图、实际交互截图及更新后的指南核对正常、失败和返回路径，明确本地通过与正式部署边界。

## Implementation Decisions

- 使用中央分供方稳定身份及既有专用文件/要求/审计边界；证照不变成普通主档附件，不建立第二份正式分供方。列表、详情、日常写入及迁移确认后的原件都消费同一源。
- 首片提供原件、要求、有效期、状态、人工核验和受控迁移的完整可演示路径；第二片提供 OCR 候选到人工确认、主档回填和纳税人核验的完整路径。第二片依赖第一片，第一片不等待识别服务可用。
- 文件元数据、正文、所属证照及适用状态在同一原子边界保存。预览/下载按当前所有者身份、来源、权限重新核验；扩展名、MIME、文件签名及 20 MB 上限沿既有校验。缺正文保留事实但不计入齐全度。
- 资料状态沿既定四态。人工通过和退回只从齐全待核验进入；退回原因必填。关键工商/银行字段变更、必需文件/类别/有效期/要求变更以及时间推移导致的过期，按现行规则使旧凭证失效；无关可选文件和劳务范围不触发误失效。中央主档编辑与证照命令共同执行此规则，不能只在前端刷新标签。
- 自动状态从当前有效事实派生；主档和证照共享版本校验或等价原子协调，避免文件已变而人工结论仍被旧命令确认。现有会话身份用于命令审计，不扩展完整人员/RBAC 系统；历史没有操作者时保留未知。
- 受控迁移接管完整可解释图及核验凭证。缺供应商级凭证的旧人工态按现行规则重算；不能用单证照核验日期替代。已应用历史迁移保持不变。OCR 原文属于专用业务记录，通用日志和专用动作审计不复制正文、税号、银行账号或备注内容。
- 保存使用命令身份、当前来源版本及服务端权限复验。同键同内容重试返回原结果，不同内容复用同键拒绝；陈旧确认保稿。页面/请求所有权隔离同源 A/B 以及来源切换的迟到结果。
- OCR 统一社会信用代码和纳税人识别号都指向税号语义；若一份材料提供矛盾候选，明确人工核对，不静默择一。历史错误字段保留原始值，确认时展示实际目标与冲突。税号重复规则沿主档现有校验。
- 只用既有 OCR 设置与人工税务核验能力；未设置或失败有明确提示和手工路径。税务官网地址沿既有配置，不新增抓取、自动查询或验证码绕过。
- 不新增生产依赖；当前中央可重置实例只验证功能，正式保存和部署仍归 #416。

## Testing Decisions

优先沿“实际证照页 → Repository/HTTP → 中央领域 → 主档与文件回读”建立测试。先在当前中央分供方复现证照不可用，以及 OCR 信用代码候选错误目标，再让相同断言通过。借用现有证照状态/OCR 纯领域测试、主档命令测试和送货/合作原件字节验收方式，不用源码字符串或 Toast 替代存储事实。

至少验证：上传后冷刷新与字节哈希；缺失/真实零文件/无权区别；上海日期过期边界；人工核验原子性；必需与可选变更不同结果；主档关键字段变化与非关键变化；撤回同一身份；同名不同 ID；响应丢失只生成一次；来源/页签切换迟到；完整旧图确认与故障无部分接管；OCR 稍后核对再进入、冲突默认保留、税号目标及主档重复冲突。390/768/1024/1280/1440px、局部滚动、焦点和浮层需实际验收。

## Out of Scope

新增审批、付款准入政策、自动税务查询、完整账号/RBAC、多租户、演示写入、Tauri 正式交付、生产存储选型，以及其他主档全部工具和导出不由本规格代验。
