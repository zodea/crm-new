# 识别界面 UX 基准：发票 / 送货单识别校对界面设计参考

> **非权威历史调研。** 本文记录 2026-07-05 的候选布局、引擎判断与优先级，不是当前页面或任务规格。独立“识别中心”导航已经退役，发票、送货单和 OCR 设置沿各自现行入口工作；页面合同见 [发票蓝本](../rewrite/pages/finance-invoice.md)、[送货单蓝本](../rewrite/pages/material-delivery.md)，引擎与联网边界见 [ADR 0006](../adr/0006-ocr-paddleocr-vl-single-model.md)。下文坐标能力判断、PP-OCRv6 建议及“三栏只做加法”不能覆盖上述已采纳决定。

> 调研日期：2026-07-05
> 目的：对标业界优秀的发票/票据/送货单识别产品与开源方案，学其排版布局与功能，改进 新app 识别界面（用户自评"自己想的、简陋、有不连贯的地方"）。
> 对齐对象：识别中心蓝本（反馈轮7）。所有建议均为在现有蓝本上"做加法"，不推翻三栏骨架。
> ⚠️ **布局比例为历史调研快照**：18/40/42 等精确比例只表示宽屏参考。现行设计与 Nuxt 必须遵循 [ADR 0013 响应式与自适应契约](../adr/0013-align-all-ui-to-online-design.md)，三栏在窄容器需分段/堆叠，不能固定压缩。

---

## 0. 一句话结论

蓝本的骨架（发票左18%+中40%+右42% 三栏、送货单六阶段左图右表）**已经是业界公认布局的加强版，方向对**。当前最大的两个缺口是：**① 点字段↔高亮原图边界框的双向联动**（几乎所有校对界面的通用基石，蓝本原图栏目前偏静态预览）；**② 统一的置信度色卡贯穿全界面**。补上这两条，"简陋/不连贯"感立降一半。

> ⚠**技术前置**：双向高亮需要 OCR 返回**坐标**。源项目两个引擎都不返回坐标（`@paddlejs-models/ocr` 出纯文本行、PaddleOCR-VL 出 markdown）；而 **PP-OCRv6 Studio 的 `POST /ocr` 返回 `lines:[{text, box:[x0,y0,x1,y1]}]`**——这是"换 PP-OCRv6"的一个有力论据。详见 `ocr-recognition-strategy.md` / ADR-0006。

## 1. 跨产品提炼的通用 UX 范式

1. **左右分栏是绝对主流**：一侧提取字段列表、一侧原始影像；字段按 header 基础字段 与 line items 明细表 两组呈现（Rossum / Docsumo / Tipalti）。
2. **点字段↔点原图双向高亮定位边界框**——最核心的校对交互（Rossum 最完整；Mindee/Veryfi 提供归一化/像素坐标供自建）。
3. **置信度色阶可视化**：黄=AI 初提取未复核、绿=人工已确认、红=非法/阻断；ABBYY 用红色标不确定字符；普遍支持可配阈值只审低置信项。
4. **AI vs 人工双状态区分**：灰勾=AI 校验、绿勾=人工确认，明确"谁确认过"。
5. **键盘流校对**：Tab 跳字段、Enter 确认，减少鼠标依赖（Rossum / docTR-Labeler）。
6. **明细行=表格网格（magic grid）逐格编辑**，每行每格独立置信度；可**手动画表格网格**补漏（Docsumo draw table grid / Rossum Magic Grid）。
7. **只审异常/低置信项而非全量核对**：规则引擎/阈值触发 flag（Nanonets / Klippa / 金蝶）。
8. **字段来源可解释**：hover 显示值来自 OCR / 历史学习 / 规则，建立信任（Ramp "Coded by Ramp"）。
9. **人工修正回流为训练信号**：同供应商/同版式下次自动改对（Tipalti / 百度 iOCR 模板）。
10. **批量流两条路径**：横向=Inbox/队列逐单据过（Rossum/Bill.com）；纵向=group verification 成组批量校对同一字段（ABBYY）。
11. **中国场景专属**：单页多票切分预览（TextIn 多票识别2.0）、群拍群读群验真（每刻）、异常检测（连号/重复/抬头/未盖章）。

## 2. 发票识别界面：推荐布局（对齐蓝本 + 注入业界范式）

**整体骨架保持**：左18%+中40%+右42%，子模式"字段校对/打印排版"顶部切换。无需改动。

- **左栏18%·队列化**：升级为 Rossum/Bill.com 式"收件箱队列"——单行=缩略图+发票号后8位+供应商+状态点。筛选值改成**状态优先级排序**（识别失败→待复核→待归档→建议通过），从上往下扫最需处理的。每项挂极小状态圆点色阶（红/黄/绿/灰），与右栏边框色系一致，形成"列表色=字段色"。
- **中栏40%·原图=证据面板**（最该补强）：除放大/旋转外，叠加**边界框高亮层**——右栏点某字段→中栏原图对应位置画高亮框并自动滚动定位；反向点原图框→右栏字段获焦。高亮框颜色随置信度色阶。**坐标缺失则降级为不高亮但不报错。**
- **右栏42%·9字段两列紧凑网格**（保持蓝本）：置信度=边框色+角标%、绿字段免确认仅黄/红出✓、货物明细默认折叠。增补：①字段行 hover 显示**来源 tooltip**（OCR/历史/规则，学 Ramp）；②"✓确认"旁给**一键"全部确认剩余黄字段"**；③预警文案统一为一套措辞（避免"必填/不能为空/请填写"混用）。
- **底部操作条保持**：[废弃]…[重新识别][归档入账]，打印按钮撤出校对模式。

## 3. 送货单识别界面：推荐布局（六阶段 + 补强校对连贯感）

- **六阶段顶部化为进度条**：上传→整理树→分区→识别→校对→输出 做成**常驻步骤指示器**，当前步高亮、已完成打勾、可点回退。**这是消除"不连贯"最直接的一招**。
- **阶段五 FileCard·左图右表双向联动**：保持"文件卡片左图右表明细行"，但把明细行做成真正表格网格并与左侧原图缩略**双向高亮**（点某明细行→左图对应行区域高亮框）。送货单校对的核心价值点。
- **明细行=类 Excel 逐格编辑 + Magic Grid 兜底**：点选即改、Tab/Enter 跳格、复制粘贴、行首增删行。当引擎切错行列/漏识别整行时，提供**"在原图上画表格网格"**兜底——在放大原图上拖行列分隔线，列头下拉绑定到 名称/单位/数量/单价/金额，一键重转录该表。**送货单版式杂、最易翻车处的关键救济。**
- **逐行置信色阶 + 只看未完善**：保留"只看未完善"筛选，叠加逐行/逐格色阶，校对精力集中在可疑处。
- **整理树保持 + 归属可视**：文件夹推断 工地→公司 逻辑保留，冲突处（文件夹名 vs OCR 公司名）醒目标记+三选一，与阶段五公司冲突统一为一套 ProblemDialog。

## 4. 两界面都该有的高价值功能（按优先级）

1. **点字段↔高亮原图边界框双向定位**（两界面共用一套 `BoundingBoxOverlay` 组件）——当前最大缺口，优先级最高。
2. **逐字段/逐行置信度色阶**（黄/绿/红/灰），粒度细到字段/单元格而非整段整表。
3. **"确认"与"修改"分成两种低成本动作 + 一键批量确认剩余低置信字段**（Google DocAI Confirm 思路）。
4. **字段/明细行来源 tooltip**（OCR/历史/规则），建立信任。
5. **业务勾稽自动校验**：发票 明细合计=价税合计、送货单 数量×单价=金额行校验，不平即标红定位。
6. **重复/异常检测前置进校对界面**：发票号查重（蓝本已有）+ 送货单同工地同公司同单号查重 + 连号/未盖章类异常。
7. **键盘流校对**：Tab 确认并跳下一个未验证字段、Enter 推进、方向键在原图候选框间移动、Ctrl+S 保存、明细区 Ctrl+加行。
8. **预标注即预填**：即使低置信也填入 AI 猜测值只标红（改预填比从零打快），杜绝低置信留空。
9. **按供应商/版式记忆修正**：同供应商同版式下次自动改对（送货单供应商多尤其受益）——依赖后端学习能力，最后做。

## 5. 针对"简陋/不连贯"的连贯性改法（最见效）

1. **加常驻流程进度指示器**（发票5步/送货单6阶段，当前步高亮+已完成打勾+可点回退）——visibility of system status，最见效。
2. **建立单一"置信度色卡"贯穿全界面**：列表状态点、原图高亮框、右栏输入框边框、明细行底色都用同一套黄/绿/红/灰，做到"列表色=原图框色=字段边框色"。
3. **消除字段与原图的割裂**：只要实现点字段↔高亮原图这一条双向联动，简陋感立降一半。
4. **校验文案与状态词统一为一套词表**（待验证/已确认/警告/错误；必填只用一种措辞）。
5. **错误/预警内联紧贴问题字段并预留固定空间**，避免提示弹入弹出导致按钮乱跳的布局跳动。
6. **"确认"和"修改"视觉与动作明确二分**，已复核/未复核字段有清晰视觉区分。
7. **发票与送货单两界面复用同一套校对组件**（BoundingBoxOverlay / 置信度输入框 / 明细网格 / ProblemDialog / 底部操作条），用户学一次通用。
8. **底部统一操作条范式**（危险靠左隔开+主操作靠右），两界面一致。

## 7. 与蓝本的一致点与增补

**一致点（蓝本已领先，保持）**：①三栏 split-view；②置信度=边框色+角标%、绿字段免确认、货物明细折叠；③"全绿降级为建议通过、判决权在人"符合 HITL 最佳实践；④底部操作条范式；⑤送货单六阶段+左图右表+输出两路径；⑥"识别是动作、台账是资产"等价于业界 queue/inbox + 导出归档闭环。

**建议增补（蓝本未明确、业界必备，均为加法不冲突）**：①点字段↔高亮原图双向联动；②明细行 Magic Grid 在原图拖线校正结构；③业务勾稽自动校验；④字段来源 tooltip + 键盘流；⑤逐行/逐格置信色阶；⑥按供应商记忆修正。

## 8. 按 ROI 排序的落地改进清单

1. **【最高 ROI·先做】** 点字段↔高亮原图边界框双向联动（`BoundingBoxOverlay` 组件，发票中栏+送货单 FileCard 共用）。**依赖 OCR 返回归一化坐标**（PP-OCRv6 有 box；VL/paddlejs 无——见 §0 前置）；缺坐标则降级不高亮不报错。
2. **【高 ROI】** 统一置信度色卡贯穿列表点/原图框/输入框边框/明细行底色。纯前端、成本低、立竿见影。
3. **【高 ROI】** 加常驻流程进度指示器（发票5步/送货单6阶段可点回退）。
4. **【高 ROI】** 明细行改类 Excel 逐格键盘编辑 + 逐行置信色阶。
5. **【中高 ROI】** 业务勾稽自动校验（明细合计=价税合计、数量×单价=金额）不平标红定位。
6. **【中高 ROI】** "批量确认剩余黄字段"一键 Confirm + Tab 只停未验证字段。
7. **【中 ROI】** 字段来源 tooltip + 校验文案统一词表。
8. **【中 ROI·送货单专项】** Magic Grid 在原图拖线校正明细表结构 + 列绑字段一键重转录（第二迭代）。
9. **【中 ROI】** 重复/异常检测前置进校对界面。
10. **【长期 ROI】** 按供应商/版式记忆人工修正（依赖后端学习，最后做）。
