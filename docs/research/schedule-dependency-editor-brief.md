## 1. 为什么需要补图

立项时，施工进度页已在甘特图中展示「前后置依赖（FS）」连线，也会在调期后检查依赖冲突；当时设计稿的「工序详情」弹窗没有提供依赖的查看、设置或移除入口。下文记录该次补图要求，不表示当前仍缺少这些入口。

生产端已经保存 `task_dependencies`，当前首期能力为：给一道后续工序选择一道同楼栋分组内的前置工序，关系固定为 FS，并设置 lag 天数。该能力不能继续以未经设计的字段直接塞进工序详情弹窗，因此需要补齐正式设计。

本次只补**依赖设置交互**，不重画施工进度主工作台，不改变现有 WBS、甘特、工序详情和新建楼栋分组的整体视觉语言。

## 2. 概念与用户价值

### FS

`FS` = Finish-to-Start（完成后开始）：前置工序达到计划完成节点后，后续工序才能到达计划开始节点。

示例：

```text
给排水安装（前置） ──完成──▶ 卫生间回填及防水（后续）
```

### lag

`lag` 是前置完成节点与后续开始节点之间的日历天偏移：

| 值 | 自然语言 | 使用场景 |
|---|---|---|
| `0` | 前置完成后立即开始 | 普通顺序衔接 |
| `+2` | 前置完成后等待 2 天再开始 | 养护、验收、材料进场等待 |
| `-3` | 前置完成前 3 天即可开始 | 流水搭接、交叉施工 |

它解决四个问题：

1. 让甘特依赖线有明确、可维护的数据来源。
2. 识别「后道开工早于依赖允许日期」的排程冲突。
3. 前道调期后，说明哪些后续工序受影响。
4. 为后续自动顺延提供计算依据；本次不设计自动顺延操作。

## 3. 设计范围

设计端需补齐以下 4 个画面/状态：

1. **工序详情 · 无依赖摘要**：展示「尚未设置前置依赖」与「设置依赖」入口。
2. **工序详情 · 已有依赖摘要**：展示自然语言摘要与「修改」入口。
3. **依赖设置弹窗 · 正常状态**：新建或编辑前置工序与 lag。
4. **依赖设置弹窗 · 冲突状态**：明确显示最早允许开始日、当前计划开始日和冲突天数。
5. **已禁用关系**：甘特调期确认后以灰色虚线保留关系，并在依赖弹窗提供受日期与环检测保护的恢复入口。

移除依赖的二次确认复用既有 `confirm(simple)` 视觉，不另创新弹窗风格；设计稿只需表现从依赖设置弹窗触发它的入口。

## 4. 推荐交互链

```text
点击 WBS 工序行
  → 打开现有「工序详情」
  → 点击依赖摘要行的「设置依赖 / 修改」
  → 关闭工序详情并打开「依赖设置」
  → 保存或取消
  → 返回该工序的「工序详情」
```

不要叠两层 Dialog。视觉上可以是弹窗内容替换，但交互结果必须表现为同一时间只存在一个模态层，避免双遮罩、焦点陷阱嵌套和 Esc 关闭歧义。

## 5. 工序详情内的入口

入口放在现有「当前区间 N 天……」说明与「实际进度」区之间，使用一行紧凑摘要，不把完整依赖表单直接展开在工序详情里。

### 无依赖

```text
┌──────────────────────────────────────────┐
│  ⤴  前后置依赖   尚未设置前置工序       设置依赖 › │
└──────────────────────────────────────────┘
```

- 中性底色，不能比实际进度区更抢眼。
- 「设置依赖」使用小号 secondary/ghost 按钮，不作为弹窗主 CTA。
- 首道工序或没有可选前置工序时，文案改为「当前没有可作为前置的工序」，入口 disabled，并提供原因 tooltip。

### 已有依赖

```text
┌─────────────────────────────────────────────────┐
│  ⤴  给排水安装完成后 2 天开始   FS · +2天    修改 › │
└─────────────────────────────────────────────────┘
```

- 主文案优先使用自然语言，不要求普通用户先理解缩写。
- `FS · +2天` 是次级技术标识；`0` 显示 `FS · 0天`，负数显示 `FS · -3天`。
- 摘要过长时，前置工序名称可截断，但 hover/focus 必须能看到完整值。

## 6. 独立「依赖设置」弹窗

### 6.1 结构草图

```text
┌──────────────────────────────────────────────┐
│  依赖设置 · 卫生间回填及防水             ×  │
│  户内10栋-22栋 · 当前仅支持完成后开始（FS） │
├──────────────────────────────────────────────┤
│                                              │
│  前置工序                                    │
│  [ 给排水安装                            ▼ ] │
│                                              │
│  关系类型                    间隔天数        │
│  [ 完成 → 开始（FS） ]       [  2 ] 天       │
│                                              │
│  给排水安装完成后等待 2 天，                 │
│  卫生间回填及防水才可开始。                  │
│                                              │
│  最早允许开始  2026/06/09                    │
│  当前计划开始  2026/06/06                    │
│  ⚠ 当前计划早于允许日期 3 天                 │
│                                              │
├──────────────────────────────────────────────┤
│  [移除依赖]                    [取消] [保存] │
└──────────────────────────────────────────────┘
```

### 6.2 尺度与视觉

- 桌面宽度参考现有工序详情弹窗：`420–440px`，不得沿用当前 Nuxt 的 `680px` 大表单宽度。
- 使用设计稿既有 `--panel`、`--line`、`--surface-2`、`--brand`、`--warn-soft`、`--danger`、`--shadow-pop`。
- 弹窗圆角、标题栏、关闭按钮、字段高度和 footer 必须与补齐后的工序详情弹窗同源。
- 字段标签 12px/600，输入正文 13px，日期与 lag 数字使用 `--font-mono`。
- 「保存」为 primary；「取消」为 secondary；「移除依赖」为左侧 danger outline，仅编辑已有依赖时出现。
- 前置工序或 Lag 改动后，通过关闭、Esc 或取消离开必须先确认放弃；保存或主动移除成功后回到工序详情。
- 主动移除不进入「已禁用的冲突关系」；该区域只展示甘特调期确认产生的冲突禁用，并显示原因、禁用时间和操作日志审计信息。
- 不新增蓝色水波或完成动效。

### 6.3 字段

| 字段 | 控件 | 规则 |
|---|---|---|
| 当前工序 | 标题/副标题只读 | 显示工序名与楼栋分组，不重复做输入框 |
| 前置工序 | Select | 只列同一楼栋分组、计划开始早于当前工序且未删除的工序；必填 |
| 关系类型 | 只读字段 | 首期固定「完成 → 开始（FS）」；不要做可选 SS/FF/SF 的假入口 |
| 间隔天数 | Number input | 整数，范围 `-365…365`，默认 `0`；旁边固定单位「天」 |

当前生产 UI 一道后续工序只编辑一条前置依赖。本次不要扩成多依赖列表，也不要设计「添加另一条依赖」；数据库的多关系扩展能力留待后续独立需求。

## 7. 预览与冲突反馈

选择前置工序或修改 lag 后，弹窗内即时更新自然语言解释和日期预览，不等待保存。

### 无冲突

- 使用中性或轻品牌底色。
- 展示「最早允许开始」与「当前计划开始」。
- 文案示例：`当前计划满足依赖关系。`

### 有冲突

- 使用 `--warn-soft` 背景与 `--warn` 图标/边框，不使用整块危险红色。
- 必须同时展示：前置工序计划完成日、lag、最早允许开始日、当前后续工序计划开始日、相差天数。
- 文案示例：`当前计划早于允许日期 3 天；保存依赖不会自动修改工序日期。`
- 保存按钮保持可用。保存后由现有 warning toast 提醒用户继续调整日期；本次不设计自动顺延。

### 非法状态

以下情况阻止保存，并在对应字段下显示行内错误：

- 未选择前置工序。
- 前置工序与当前工序相同。
- 前置工序不属于同一楼栋分组。
- 形成循环依赖。
- lag 不是整数或超出 `-365…365`。

## 8. 状态矩阵

| 状态 | 设计要求 |
|---|---|
| 新建 | 前置工序为空或默认推荐上一道工序；lag 默认 `0` |
| 编辑 | 回填当前前置工序与 lag；显示「移除依赖」 |
| 保存中 | 保存按钮原文 + spinner、disabled，锁定字段防重复提交 |
| 保存失败 | 弹窗不关闭，保留输入；字段错误就地显示，系统错误走 system toast |
| 无候选工序 | Select disabled，解释「当前没有可作为前置的工序」 |
| 冲突 | warning 预览可见，允许保存，不自动改日期 |
| 移除 | 调用全局 simple confirm；确认后关闭并刷新甘特连线 |

## 9. 响应式补图

至少输出两个参考状态：

1. **桌面 1280/1440px**：居中 `420–440px` 紧凑弹窗。
2. **手机 390px**：宽度 `calc(100dvw - 24px)`；两列「关系类型 / 间隔天数」改为单列；footer 可换行，但保存与取消必须可见。

768/1024px 沿用桌面弹窗结构，只受最大宽度约束。不得出现页面级横向滚动；Select 的下拉内容和完整工序名必须可达。

## 10. 可达性与键盘

- 基于既有 reka-ui Dialog 语义：打开后焦点进入第一个可编辑字段，焦点陷阱、Esc、遮罩关闭与焦点返回保持有效。
- 未保存内容发生变化后，Esc/遮罩关闭应走既有「放弃修改」确认。
- Select、number input、取消、保存、移除依赖全部可用键盘操作并有清晰 focus ring。
- 冲突说明使用可读文本，不只靠黄色区分。

## 11. 明确不做

- 不重画施工进度主工具栏、WBS 树表或甘特视觉。
- 不增加 SS、FF、SF 类型选择；数据模型预留不等于本期 UI 开放。
- 不设计多个前置依赖的列表编辑。
- 不设计拖拽连线建依赖。
- 不在保存依赖时自动顺延后续工序。
- 不把依赖编辑并入通用 `formModal` 字段配置；它有日期预览和冲突状态，属于施工进度领域弹窗。

## 13. 设计验收口径

[#244](https://github.com/zodea/crm-new/issues/244) 补图完成后，应能从 `app.dc.html` 实际完成以下旅程：

1. 打开施工进度 → 点击一道工序 → 看见依赖摘要。
2. 点击「设置依赖/修改」→ 打开依赖设置弹窗。
3. 切换前置工序或调整 lag → 自然语言与最早允许日期即时变化。
4. 制造冲突 → 看见明确 warning，但保存仍可达。
5. 编辑已有依赖 → 可触发移除确认。
6. 390px 下所有字段和 footer 操作可达、无页面横向溢出。
