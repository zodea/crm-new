# 模块复核与红圈对齐协作规程

逐模块复核界面、交互、数据处理，或把复核结论转成规格与实施票时，按本规程工作。
任务总图：[瑞航 CRM 全模块复核与红圈对齐路线：前台交互和数据处理优先](https://github.com/zodea/crm-new/issues/402)。
模块目录、当前任务和依赖只查总图及其原生子 Issue；本文件只规定协作过程与完成门槛。

## 1. 范围与工作顺序

本轮优先交付前台界面、交互和数据处理；“同步”指对照红圈并落实对应能力。
保留瑞航品牌、独有业务能力及现行已采纳决定，按模块推进调查、定稿、实现和验收。
生产持久化、备份恢复与部署单列后置上线关口，不作为前台模块复核的开工前置。

- 现有排除范围在场景表中标为“不适用”，写明总图或现行规格依据。
- 完整审批引擎、完整账号/RBAC/人员体系、多租户、红圈数据互通、通用离线 outbox、Tauri 正式交付不在本轮扩展范围。
- 已定退役或排除项沿用现行决定；B 类工资等历史待办不得仅因旧文档仍有描述而重新提问或开发。
- 现有 capability、来源隔离、权限反馈、单据状态及审计仍须复核；范围排除不豁免已有功能的正确性。
- 某模块可独立调查时立即推进；依赖只阻止需要该事实的定稿或实施，不阻止独立采证。

完成本步：选定当前模块 Issue、代码版本、范围和实际前置，已定排除与本轮适用场景分清。

## 2. 先调查事实

1. 按根目录 [AGENTS.md](../../AGENTS.md) 和 [Issue 规则](./issue-tracker.md) 检查工作树，查询当前 Issue 正文、评论及承接关系。
2. 记录代码 SHA、运行形态、工作区和数据来源；区分已合入、正在开发与仅在本地的成果。
3. 从 [文档入口](../README.md) 读取相关术语、ADR、页面蓝本、数据、读写与导航契约。
4. 枚举业务对象、动态类型、页面入口、状态、动作、字段分区、附件和上下游关系。
5. 按 [运行态参考协议](../design/runtime-reference-audit.md) 只读观察红圈，再用本地运行、代码和测试核对对应行为。
6. 对照正常、边界、失败、重复、更正、回退和跨模块场景，记录差异及尚缺的证据。

红圈只记录实际观察到的结构和安全行为；邻近页、空数据、权限受限和历史记录分别标明。
红圈缺直接证据时采用现行本地权威，并记录证据缺口；不可由按钮外观推断保存、审批或支付行为。
参考图按既有协议脱敏；本地写入复现使用明确的测试数据，记录其来源及清理归属。
路由数、截图数和历史关闭票只作调查线索；动态 `kind` 及同页不同状态逐场景展开。

完成本步：每个适用对象及场景都有现状、依据、差异或明确的证据缺口，能指出影响范围。

## 3. 自治判断与必要提问

模块深化使用 `grill-with-docs`，实际加载 `grilling` 与 `domain-modeling`。
用户所称“grill-me-docs”对应当前安装的 `grill-with-docs`；按实际技能名加载，不另造同义流程。
本轮用户已授权代理依据 Issue、代码、运行证据和现行规则直接判断；技能的通用确认步骤按此授权执行。

| 情形 | 代理动作 | 记录位置 |
| --- | --- | --- |
| 用户已定或已有适用的现行规则 | 直接采用，核对实现是否满足 | 当前 Issue 链接决定及权威源 |
| 事实调查可解答，或是现有范围内可逆实施选择 | 自行判断并推进，补充必要验证 | 当前 Issue 记录依据、影响、验证 |
| 证据缺失但存在明确现行安全行为 | 保留现行行为，登记补采或实施缺口 | 当前 Issue 记录边界与后续承接 |
| 证据不能决定的业务取舍 | 给出具体情境、可选结果及建议，再向用户提问 | 当前 Issue 记录问题与最终决定 |

只有会改变业务含义、使用范围、合法状态或用户责任，且现有证据不能裁定的问题才交给用户。
查得到的事实、例行实现方式、已经回答的问题和已定排除不作为访谈问题。
提问按前置依赖分轮，只问当前可决定的业务问题；等待期间继续不依赖答案的工作。
用户已经授权的范围不重复索要批准；真实业务问题未得到答案时，不以等待时间推定同意。

每个代理判断记录“结论 → 依据 → 影响 → 验证”；出现代码与权威源冲突时先在 Issue 留证，再同单元消除冲突。
词义确定后更新 [CONTEXT.md](../../CONTEXT.md)；只有难逆、需要解释且存在真实取舍的架构决定才新增或修订 ADR。

完成本步：每项差异归入“用户已定 / 代理判断 / 待用户取舍 / 不适用”，后续动作和责任明确。

## 4. 场景与差异记录

在模块 Issue 使用下列模板；一条记录对应一个可判断行为，相关场景可引用同一差异。
字段定义、状态表与计算规则链接现有权威源；这里只记录当前场景的输入、差异和目标结果。

```text
场景/差异 ID：
业务对象、动态类型、页面入口与来源：
初始状态、操作者及现有 capability、数据来源：
触发步骤与具体输入：

红圈证据：目标视图、日期/视口、证据等级、可观察行为及缺口
本地现状：代码版本、运行环境、实际结果、复现/测试证据
现行依据：Issue 决定、术语、ADR、页面/数据/读写契约链接
差异类型：界面/交互/字段/关系/计算/状态/失败恢复/跨域

裁定类别：用户已定/代理判断/待用户取舍/不适用
目标行为与理由：
适用动作、允许状态、禁止状态及明确反馈：
写入权威、原子边界、关联身份、审计与回读路径：
影响的其他页面、汇总、附件及下游单据：

正常验收：操作、可见结果、保存与回读结果
边界验收：空值/零值/缺关系/额度/日期等适用条件
失败验收：中断/重复/冲突/无权/重试及应保留状态
更正验收：取消/撤回/作废/更正的合法路径及下游结果
跨域验收：来源→目标→写入→汇总/回读→返回

实施承接、真实阻塞项、权威文档更新点：
验收证据、未决项及本记录关闭条件：
```

同一模块至少核对下表各维度；不适用项注明现行依据，适用但未实现项必须进入承接票。

| 维度 | 必须回答的内容 |
| --- | --- |
| 界面与导航 | 列表、详情、表单、页签、深链和来源返回；密度、滚动、焦点与浮层是否符合当前权威 |
| 查询与汇总 | 搜索、筛选、排序、分页、列设置及导出是否使用同一完整筛选集，汇总范围是否明确 |
| 字段与关系 | 可编辑值怎样持久化；lookup、明细、附件的真实身份；缺失、重复、错配如何处理 |
| 计算与状态 | 金额、数量、税价、日期、累计及空值口径；派生与快照边界；合法状态和既定动作 |
| 写入与回读 | 从表单到领域写入再到列表、详情和下游；事务、幂等、版本和审计是否真实生效 |
| 取消与更正 | 脏数据离开、草稿、撤回、软删除、恢复、作废或冲销按本域已定规则执行后的结果 |
| 失败与重复 | 无权、缺关系、网络/解析失败、重复提交、并发冲突和重试；已有值及部分结果如何保留 |
| 文件与工具 | 原件/元数据归属、OCR 人工核对、导入映射/去重/续导、导出/打印及实际文件结果 |
| 跨模块 | 上游身份和事实如何进入下游，修改后汇总与余额如何变化，返回是否恢复原上下文 |

完整复核指本域约定的生命周期完整；不要求每个实体机械开放全部 CRUD、审批或离线动作。
场景中的可见反馈、存储事实、下游结果分别验证；Toast、HTTP 接通或页面可打开不能替代后两者。

完成本步：全部适用维度都有可复现验收例，差异有裁定或明确问题，遗漏能力有唯一承接者。

### 列表、详情子表与工作台的逐页对应

按 [2026-09-08 用户确认](https://github.com/zodea/crm-new/issues/404#issuecomment-5582280040)，每个具体界面都要对应列内容、名称入口、状态标签、表头操作、搜索及其右侧工具；公共壳接入或代表页通过只证明各自范围。

从现有路由、导航、页面蓝本和运行账本展开“路由 + 实际 kind + 视图/页签 + 运行环境 + 子表”。同一路由的动态单据类型、浏览器/桌面分支和详情中的各张表分别登记；非侧栏入口、原生表格、导入预览和矩阵也逐项判断适用性。矩阵、甘特与明细编辑保留其领域结构，按可用查询和操作逐项核对。

每页在所属模块 Issue 填写以下对应表；公共目标只链接 [CRM 列表模式](../rewrite/CRM-PATTERNS.md#1-列表页) 和[组件规格](../design/kit-ui-component-specs.md)，字段和动作结论写回该页蓝本。

| 对应项 | 必须登记的事实与验收 |
| --- | --- |
| 页面身份与证据 | 实际入口、类型、视图、环境、参考路径/日期/视口、直接或邻近证据；代码 SHA 和本地数据来源 |
| 每一列 | 参考标题/顺序 → 瑞航业务含义 → 真实字段或派生来源 → 默认位置；同名不同义、未映射和明确排除分别说明 |
| 名称与状态 | 名称目标及完整值；真实状态、标签文字和语义色；列表/详情/编辑回读一致，未识别状态有明确反馈 |
| 常驻文字与帮助 | 每段解释文字归为必要常驻、就近帮助或删除；字段释义/口径提示支持鼠标、键盘和触摸；校验、权限、失败、未保存及必要来源反馈保持可见 |
| 每个表头 | 支持的筛选/排序/调整列宽、可见入口、激活状态、完整数据范围；清除后模型、图标和结果共同恢复 |
| 搜索 | 实际搜索字段、触发方式、完整授权数据集、组合条件、分页/总数/汇总、无结果/清空、详情返回恢复 |
| 右侧每个工具 | 图标或文字 → 明确名称 → 菜单/目标 → 作用范围 → capability → 成功/失败与恢复；未知图标先登记补采 |
| 运行验收 | 参考视口和规定宽度、表内横滚、长内容、键盘/焦点/浮层；加载、空态、无权、失败与重试 |
| 承接与结论 | 已验证、待实现、待采证、待业务裁定或有依据的不适用；每个未通过项链接唯一实施承接，不以文件或按钮存在判完成 |

完成本项：全部展开界面、默认列和可见工具都有去向；逐页真实查询及状态验收已分别记录。采用通用模板不能替代领域字段投影检查，历史 E2E 若仍指向已退役入口须随实施更新。

## 5. 转成规格与实施票

当前模块决定充分后使用 `to-spec → to-tickets`，独立模块无需等待全站调查结束。
总图的调查/决策子票承载事实和取舍；可执行实施票承载定稿行为，二者分别判断完成。
输出 `to-spec` 前确认：

- 对象、动态类型、初始状态、合法动作、目标界面和来源返回明确。
- 字段/关系/计算引用权威源，写入、回读、更正及下游影响均有明确规则。
- 正常、边界、失败、重复与跨域验收例足以判断成功和失败。
- 真正阻止实施的业务问题已解决，其余缺口有明确排除或独立承接。
- 测试切入点和所需运行证据由既有接缝推导；例行技术选择沿用户授权直接判断并记录。

输出 `to-tickets` 时按完整用户路径作纵向切片，每票能单独演示或验证。
每票写清交付行为、受影响页面、写入边界、异常结果、文档更新、测试策略、真实阻塞及关闭条件。
依赖覆盖实际需要的公共交互、文件、数据和上游事实；采证可并行不表示实现没有依赖。
拆分粒度、实现顺序和测试方式可从现状确定时由代理决定；只有改变已授权业务范围时再提问。
发布与标签按 [Issue 规则](./issue-tracker.md) 及总图授权执行，先核对已有承接，避免重复实施票。

完成本步：实施票无需下一位代理补猜业务规则，且每个未完成验收项都有唯一承接与依赖。

## 6. 实现、验证与关闭

实施使用匹配的技能，按 [AGENTS.md](../../AGENTS.md) 完成最小充分测试与提交纪律，并用 `code-review-matt` 核对标准与规格。
前台修改必须做实际浏览器验收；参考视口与规定宽度、局部横滚、键盘焦点及浮层层级同时成立。
数据修改验证写入后的列表/详情/下游回读、刷新及适用的失败重试，保留可复现证据。
GitHub Actions 的套件、估算和确认继续遵守 [CI 规则](./ci-usage.md)，本规程不扩大运行授权。

| 关闭门 | 必须已完成 | 结论边界 |
| --- | --- | --- |
| 调查与决定 | 场景覆盖、事实/证据分级、自治判断与业务裁定齐备；未完工作有承接 | 可进入规格和实现，不等于功能已实现 |
| 前台功能 | 适用界面、交互、数据写入/回读及异常场景验证通过，文档一致 | 模块明确范围功能通过，不等于全域通过 |
| 跨模块链 | 同一身份和来源贯穿上游、下游、汇总、更正及返回，依赖链集成验证通过 | 所验收业务链闭合，不扩大到未测链路 |
| 生产可用 | 后置持久化、重启、备份恢复、迁移切换和部署关口完成 | 才可称正式可用；不倒置为前台调查前置 |

中央可重置实例仅证明记录范围内的行为；线上关口保留独立承接，不提前选部署产品或新增依赖。
关闭对应职责的 Issue 前写回提交、测试、运行证据与剩余边界；旧票替代按总图记录为“被替代”，不冒称实现完成。

## 7. 记录归属与交接

- 过程证据、代理判断、用户回答、依赖和验收：对应 GitHub Issue；总图保留结论链接。
- 词义：[CONTEXT.md](../../CONTEXT.md)；架构取舍：[ADR](../adr/README.md)。
- 字段与数据：[DATABASE.md](../rewrite/DATABASE.md)；读写与导航：从 [文档入口](../README.md) 进入各自契约。
- 页面与交互：[页面蓝本](../rewrite/pages/) 和 [设计入口](../design/README.md)；状态与证据更新各自既有账本。
- 用户流程变化：同单元更新 [使用指南](../guides/README.md)，在既有输出位置生成并逐页渲染检查 PDF。

交接只给当前 Issue、已验证结论、未决问题、可执行下一步和真实阻塞；字段表、模块目录及在线状态保持单一来源。
