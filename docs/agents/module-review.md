# 模块复核与红圈对齐协作规程

用于已确认范围内的模块复核与实施规格。通用决策、技能、事实与法律核查、Issue 及交付授权遵守 [AGENTS.md](../../AGENTS.md)，本文件只补充采证和验收方法。

## 1. 范围与工作顺序

- 明确模块、代码版本、适用场景、排除项及真实依赖；排除项注明用户决定或现行规格依据，历史待办不自动恢复为需求。
- 范围排除不豁免现有权限、来源隔离、状态和审计的正确性；保留瑞航品牌与独有能力。
- 可独立采证的部分先调查；定稿和实施前接齐所需上游事实。前台、跨模块链与生产可用分别验收。

## 2. 先调查事实

1. 记录代码 SHA、运行环境、工作区与数据来源，区分已合入、开发中和本地成果。
2. 直接读取相关现行规格，枚举对象、动态类型、入口、状态、动作、字段、附件与上下游关系。
3. 按 [运行态参考协议](../design/runtime-reference-audit.md#2-严格只读观察协议) 采证，用本地运行、代码和测试核对对应行为。
4. 展开正常、边界、失败、重复、更正、回退和跨模块场景，说明现状、依据、差异、证据缺口与影响。

邻近页、空数据、权限受限和历史记录分别标明；缺直接证据时沿用现行本地规格，不由按钮外观推断保存、审批或支付行为。参考图脱敏，本地写入复现使用来源与清理归属明确的测试数据。

## 3. 自治判断与必要提问

业务取舍访谈用 `grilling`，术语或架构决定用 `domain-modeling`。每项差异归为“用户已定 / 既定方案内判断 / 待用户确认 / 不适用”，说明依据、影响与验证。

证据不足时保留明确的现行行为并注明缺口；需要变更方案时向用户说明具体情境、选择与建议。事实查证不等于方案变更授权，等待期间可继续独立采证。

## 4. 场景与差异记录

一项差异对应一个可判断行为，相关场景共用记录；字段、状态表与计算规则直接链接权威源。

| 记录项 | 必要内容 |
| --- | --- |
| 对象与条件 | 场景标识、动态类型、入口/来源、初始状态、操作者与 capability |
| 证据与现状 | 参考路径/日期/视口/等级；本地版本/环境/数据来源、复现结果及缺口 |
| 触发与裁定 | 步骤、输入、差异类型、规则依据、裁定类别、目标行为及允许/禁止动作 |
| 数据影响 | 写入权威、事务边界、关联身份、审计、回读及下游页面/汇总/附件 |
| 验收 | 正常、空/零/缺关系等边界、失败/重复/重试、更正及跨域返回的预期结果 |
| 承接 | 真正阻塞、未决项、文档更新、完成条件与验证证据 |

同一模块至少核对下表各维度；不适用项注明现行依据，适用但未实现项明确后续承接。

| 维度 | 必须回答的内容 |
| --- | --- |
| 界面与导航 | 列表、详情、表单、页签、深链和来源返回；密度、滚动、焦点与浮层是否符合当前权威 |
| 查询与汇总 | 搜索、筛选、排序、分页、列设置及导出是否使用同一完整筛选集，汇总范围是否明确 |
| 字段与关系 | 可编辑值怎样持久化；lookup、明细、附件的真实身份；缺失、重复、错配如何处理 |
| 计算与状态 | 金额、数量、税价、日期、累计及空值口径；派生与快照边界；合法状态和既定动作 |
| 写入与回读 | 从表单到领域写入再到列表、详情和下游；事务、幂等、版本和审计是否真实生效 |
| 取消与更正 | 脏数据离开、草稿、撤回、软删除、恢复、作废或冲销按本域已定规则执行后的结果 |
| 失败与重复 | 无权、缺关系、网络/解析失败、重复提交、并发冲突和重试；已有值及部分结果如何保留 |
| 文件与工具 | 原件/元数据归属、OCR 人工核对、导入映射/去重/续导、导出/打印及实际文件结果 |
| 跨模块 | 上游身份和事实如何进入下游，修改后汇总与余额如何变化，返回是否恢复原上下文 |

以本域已确认的生命周期为边界，不机械补齐全部 CRUD、审批或离线动作。适用维度须有可复现验收例；可见反馈、存储事实与下游结果分别验证，Toast、HTTP 接通或页面可打开不能替代后两者。

### 列表、详情子表与工作台的逐页对应

按“路由 + 实际 kind + 视图/页签 + 运行环境 + 子表”展开，同一路由的动态类型、浏览器/桌面分支及每张子表分别核对。非侧栏入口、原生表格和导入预览也判断适用性；矩阵、甘特与明细编辑保留领域结构。

公共目标见 [DESIGN-SYSTEM 列表结构](../rewrite/DESIGN-SYSTEM.md#a01-list-pattern)和[组件规格](../design/kit-ui-component-specs.md)，查询与写入直达 READ-MODELS / COMMANDS，字段与动作差异写回对应页面蓝本。

| 对应项 | 必须登记的事实与验收 |
| --- | --- |
| 页面身份与证据 | 实际入口、类型、视图、环境、参考路径/日期/视口、直接或邻近证据；代码 SHA 和本地数据来源 |
| 每一列 | 参考标题/顺序 → 瑞航业务含义 → 真实字段或派生来源 → 默认位置；同名不同义、未映射和明确排除分别说明 |
| 名称与状态 | 名称目标及完整值；真实状态、标签文字和语义色；列表/详情/编辑回读一致，未识别状态有明确反馈 |
| 常驻文字与帮助 | 每段解释文字归为必要常驻、就近帮助或删除；字段释义/口径提示支持鼠标、键盘和触摸；校验、权限、失败、未保存及必要来源反馈保持可见 |
| 每个表头 | 支持的筛选/排序/调整列宽、可见入口、激活状态、完整数据范围；清除后模型、图标和结果共同恢复 |
| 搜索 | 实际搜索字段、触发方式、完整授权数据集、组合条件、分页/总数/汇总、无结果/清空、详情返回恢复 |
| 右侧每个工具 | 图标或文字 → 明确名称 → 菜单/目标 → 作用范围 → capability → 成功/失败与恢复；未知图标先登记补采 |
| 运行验收 | 参考视口和规定宽度、表内横滚、长内容、键盘/焦点/浮层；加载、空态、无权、失败与重试 |
| 承接与结论 | 已验证、待实现、待采证、待业务裁定或有依据的不适用；每个未通过项链接唯一实施承接，不以文件或按钮存在判完成 |

每个展开界面、默认列和可见工具均有结论；公共壳或代表页通过不能替代逐页字段、查询和状态验收，指向退役入口的 E2E 随实施更新。

## 5. 定稿与实施拆分

定稿前须明确对象、状态、合法动作、界面与来源返回；写入、回读、更正和下游规则齐备，验收例能区分成功与失败。业务阻塞已由用户裁定，其余缺口有排除依据或唯一承接。

按完整用户路径拆分可独立验证的单元，写清交付行为、页面、数据边界、异常、文档、测试及完成条件。依赖覆盖实际需要的公共交互、文件、数据与上游事实；独立模块无需等待全站调查完成。

## 6. 实现、验证与关闭

按根规则验证与交付，使用 `code-review` 核对标准与规格。数据修改须覆盖写入后的列表、详情和下游回读、刷新及适用的失败重试。

| 关闭门 | 必须已完成 | 结论边界 |
| --- | --- | --- |
| 调查与决定 | 场景覆盖、事实/证据分级、自治判断与业务裁定齐备；未完工作有承接 | 可进入规格和实现，不等于功能已实现 |
| 前台功能 | 适用界面、交互、数据写入/回读及异常场景验证通过，文档一致 | 模块明确范围功能通过，不等于全域通过 |
| 跨模块链 | 同一身份和来源贯穿上游、下游、汇总、更正及返回，依赖链集成验证通过 | 所验收业务链闭合，不扩大到未测链路 |
| 生产可用 | 后置持久化、重启、备份恢复、迁移切换和部署关口完成 | 才可称正式可用；不倒置为前台调查前置 |

中央可重置实例仅证明所测行为；关闭任务需说明验证证据与剩余边界，旧票替代不冒称实现完成。

## 7. 记录归属与交接

任务要求、待办、进度与反馈留在当前任务或获授权的 Issue，不另建本地副本。长期规则按[领域文档归属](./domain.md)更新现有权威源；用户流程变化更新既有 [Markdown 使用指南](../guides/README.md)，按需内嵌 `show-me` 图示。

交接只给已验证结论、未决问题、下一步与真实阻塞，链接现有证据。
