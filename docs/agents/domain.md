# 域文档使用规则

本仓库采用单一上下文布局：

```text
/
├─ CONTEXT.md
└─ docs/
   ├─ adr/
   └─ rewrite/DATABASE.md
```

## 消费顺序

1. 从根目录 `CONTEXT.md` 获取业务术语、关系和易混区别。
2. 读取与当前模块相关的 ADR，理解已经采纳的约束和被替代条款。
3. 涉及实体、字段、关系、索引或迁移时读取 `docs/rewrite/DATABASE.md`。
4. 涉及单页内容时读取 `docs/rewrite/pages/` 对应蓝本。

业务实体、类型和测试命名使用 `CONTEXT.md` 中对应概念；普通叙述可使用含义准确的自然表达。

## 维护边界

- 新的稳定词义写入 `CONTEXT.md`，不要把实现状态写成词义。
- 会约束未来实现的决策写 ADR；ADR 冲突必须显式提出，不能被新代码静默推翻。
- 字段和关系只写 `DATABASE.md`；其他文档引用章节，不维护副本。
- 还没有定稿的候选词或外部系统观察放 `docs/research/`，并注明非权威源。

文档与代码冲突时，查代码和现行文档核实事实；业务含义或需求不清时直接问用户，确定后在同一工作单元同步实现与权威源。
