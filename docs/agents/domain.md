# 域文档

工程技能(improve-codebase-architecture / diagnose / tdd 等)探索代码库时如何消费本仓库的域文档。

## 探索前先读

- 根目录 **`CONTEXT.md`** —— 项目域语言(设计稿工作流、交互行为、业务术语,每条带 _Avoid_ 禁用同义词)。
- **`docs/adr/`** —— 读与当前工作区域相关的 ADR。

本仓库是单一上下文布局(无 `CONTEXT-MAP.md`):

```
/
├── CONTEXT.md
├── docs/adr/
│   ├── 0001-invoice-single-table.md
│   └── 0002-change-order-generates-ledger.md
└── ...
```

若这些文件不存在,**静默继续**,不要提示缺失、不要主动建议创建。生产者技能(`/grill-with-docs`)会在术语或决策真正定稿时惰性创建。

## 使用词汇表的词汇

输出中涉及域概念时(issue 标题、重构提案、假设、测试名),使用 `CONTEXT.md` 定义的术语,不要漂移到词条 _Avoid_ 明确禁用的同义词(如「分供方」不写成「供应商」,「软删除」不写成「逻辑删除」)。

需要的概念不在词汇表里时,这是个信号——要么你在发明项目不用的语言(重新考虑),要么存在真实缺口(记下来交给 `/grill-with-docs`)。

## ADR 冲突要显式提出

输出与现有 ADR 矛盾时,显式指出而不是静默推翻:

> _与 ADR-0001(发票单表)矛盾——但值得重开,因为……_
