# Git 钩子与合并收尾

Husky 由 `pnpm install` 的 `prepare` 启用；入口在 [`.husky/`](../../.husky/)，仓库策略在 [scripts/git-hooks.mjs](../../scripts/git-hooks.mjs)。钩子在提交/推送时检查，不主动发起提交或推送；授权与提交范围按根 `AGENTS.md` 执行。

## 提交检查

| 时机 | 顺序与作用 |
| --- | --- |
| `pre-commit` | `git diff --cached --check` 检查新增冲突标记与空白；`git-hooks.mjs staged` 拦截暂存的临时目录、嵌套工作树和缓存；`pnpm exec lint-staged --concurrent=1` 逐批检查暂存代码 |
| `commit-msg` | `pnpm exec commitlint --edit "$1"`，按 [commitlint.config.mjs](../../commitlint.config.mjs) 校验提交说明 |

任一步失败即停止。暂存路径检查涵盖新增、修改、复制、重命名和类型变化，允许删除历史误入产物。[lint-staged 配置](../../.lintstagedrc) 无 `--fix`；失败后修具体文件再暂存。Windows 命令长度分块后的各批次按同一配置串行执行，避免多个 ESLint 同时分配内存或生成 Nuxt 类型；检查文件和规则保持一致。lint-staged 仍可能临时备份、还原部分暂存文件。提交钩子不运行类型检查或测试。

commitlint 继承官方 `config-conventional`，仅关闭 `subject-case` 以容纳中文混用专有名词；scope 可省略，类型须小写，说明非空。标准 merge/revert/fixup/squash 辅助消息遵循其默认忽略规则。具体校验看当前配置及[官方规则](https://commitlint.js.org/reference/rules.html)，中文含义由作者审阅。

## 推送检查

Git 提供远端名称和待推送的本地/远端引用，脚本按以下顺序判断：

1. **确定范围。** 输入损坏或读取失败时停止。已有远端引用与旧 SHA 比较；新引用与该远端 `main` 的共同祖先比较。找不到基准时纳入验证；删除引用跳过验证。
2. **识别纯文档。** 仅根目录 `.md`，以及 `docs/` 内的 `md/txt/log/png/jpg/jpeg/webp/gif/svg/pdf` 允许跳过。代码、JSON、CSS、配置、脚本、钩子和未知扩展名纳入验证；重命名同时检查旧、新路径。
3. **锁定版本。** 需验证的所有引用必须指向当前 `HEAD`；多个引用指向同一版本只验一次，不同版本须到各自工作目录分别验证。
4. **核对目录。** 需验证时，已跟踪源码/配置须与 `HEAD` 一致，且不能有未忽略的新源码/配置。无关文档与已忽略文件不阻止验证；脚本不自动暂存、stash 或回退。
5. **执行检查。** 当前实际命令为 `pnpm typecheck && pnpm test`：应用类型检查通过后运行单元与 jsdom 组件测试，任一失败即阻止推送。
6. **复核一致性。** 检查期间 `HEAD` 或源码/配置变化时停止，重新验证。

钩子与手动执行统一使用 pnpm。脚本显示“完整测试已通过”也只代表第 5 步，浏览器组件、E2E、视觉、Rust 及普通测试整体类型检查未包含在内，按[测试入口](../testing/README.md)补足本次需要的验证。

无标准输入元数据而直接运行推送脚本，会对当前 `HEAD` 执行同样检查。钩子可被 Git 跳过选项关闭；被忽略的依赖、环境文件也不在提交一致性检查中，因此钩子通过不代表环境或其他套件已经验证。

## 临时文件与缓存

路径以 [`.gitignore`](../../.gitignore) 和暂存路径检查为准。共享规则、技能与正式证据保持可追踪，不整目录忽略 `.codex/`、`.agents/`。忽略规则不取消已有跟踪，也不删除文件；清理前先保全正式产物与其他会话内容。

## 合并后的分支清理

获授权的合并完成后只清理对应工作分支；历史分支批量清理另行处理。直接在 `main` 开发无需另建或删分支。

1. **确认合并。** 核实 PR 的 `MERGED` 状态、目标与实际合并提交，并刷新远端引用；关闭 PR/Issue 或分支消失不能代替合并证据。
2. **列出对象。** 记录本地/远端候选分支、当前 SHA 和关联工作树。保留 `main`、默认及长期共享分支、仍有后续工作或其他会话使用的分支。
3. **核实归并。** 普通合并用 `git merge-base --is-ancestor <候选SHA> <目标分支>` 核验每个端点；squash/rebase 则核对 PR 原 head、合并结果及补丁等价性。新增未合入提交或证明不足时保留，不能只依赖 `branch -d` 的上游判断。
4. **保全工作树。** 用 `git worktree list` 定位，检查已跟踪、未跟踪和忽略文件，以及活动会话/进程。数据库、密钥、浏览器配置、用户文档及归属不明资料先保全；核实绝对路径并采用可恢复清理，条件不足时保留并说明，禁止 `worktree remove --force`。
5. **精确删除。** 切离候选后用 `git branch -d`，失败时查因而非升级为 `-D`。远端再次核实 SHA 后按下式删除；SHA 变化则重新核验，引用已不存在则无需操作。
6. **核对结果。** 刷新失效的远端跟踪引用，检查分支、工作树与 Git 状态，报告删除/保留对象及恢复依据。

```text
git push --force-with-lease=refs/heads/<分支>:<已核验SHA> origin :refs/heads/<分支>
```

占位符须来自刚核验的同一远端；仅删除精确引用，不重写历史或执行激进 GC。不设置自动批量删分支的 `post-merge` 钩子，因为同步上游也会触发它。
