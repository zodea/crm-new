# 01 · 批 A — 底座 + 新菜单 + 合同主线

> 顺序：**1（最先，且必须扎实）**。公共上下文（决议/流程/坑/原语/验收线）见根目录 [HANDOFF.md](../../HANDOFF.md)，本文件只写本批范围。
> 用户点名优先项之一：**合同**。

## 目标

把「底座 + 红圈式菜单 + 合同主线」立起来，后面 B–E 全靠这层底座。做完＝能从新菜单点开三类合同列表、点合同名进通用详情、全站合同名蓝链能跳、返回=关页签。

## 1. 底座四件（先造，验收线以此为准）

1. **`EntityLink(type, id, label?)`** → 加进 `kit/KitAtoms.jsx`。蓝色可点，内部一张 `type→route+params` 映射表（**只此一处**），点击 `window.DC.navigate(...)`。全站表格列 render 一律用它，不再各处手写 button。
2. **`EntityListScreen(meta)`** → 新 `kit/EntityListScreen.jsx`。一份 meta 生成整页红圈式列表：
   - `columns`（含蓝链列、money 四级对账列）、`toolbar`（视图切换 + 搜索 + 筛选 + ⚙列 + **导入 + 导出** + 新建）、底部 `summary` 业务汇总行、`defaultView`（业务态，非"全部"）、可选 `leftNav`（左侧分类，如 分包合同 劳务/专业）。
   - CRUD 闭环**照抄 P1** `kit/ProjectDetailScreen.jsx` 的 `SubTable`（新增/编辑 formModal 由列自动生成、删除软删 undoToast、搜索过滤、sum 随 state 重算）。
   - 导入→`importModal`（ADR 0005 字段映射）；导出→数据表走 Excel（列/范围选择），文件/原件才走 `exportModal`（ADR 0004 文件夹规范）。
3. **`DetailShell`**（详情外壳，可放 `kit/KitAtoms.jsx` 或独立）：摘要条（四级对账 MetricGrid）+ SegTab 壳 + 右侧文书预览 chip + 文件栏。**不挂审批流**。
4. **`ContractDetailScreen(kind)`** → 新 `kit/ContractDetailScreen.jsx`。用 DetailShell，`kind ∈ {施工, 分包, 材采}` 显隐字段与关联 Tab（变洽签/结算/收票/付款）。合同文书预览复用 P1 里 `previewDoc`。

## 2. 轻实体仓（`kit/data.js`）

- `contracts[]`（kind/projectId/supplierId/costId/amount/changedAmount/累计结算收票支付 mock/status）
- 施工合同挂 projectId（甲方侧）；分包/材采挂 projectId+supplierId。
- 与项目详情 Tab③/④ 的合同**同源**（Tab 变成过滤视图；数据从 data.js 读，别再组件内 mock）。
