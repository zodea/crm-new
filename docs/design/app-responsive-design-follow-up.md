## 为什么暂不修改设计稿

2026-07-18 实施 #112 R1 时，另一个 agent 正在同步修改 Claude Design。为避免覆盖线上 `app` 或 `DC重构设计源码/**` 的并行成果，本阶段只落 Nuxt 共享响应式原语，不改设计稿及其仓库镜像。

现场核对当前 Claude Design `app`：列表页、指标卡、表格和带左分区导航的整页表单仍以宽屏参考样态呈现。该宽屏构图继续作为视觉基准；窄屏如何降列、换行和收敛，仍以 ADR 0013 为准。

## 并行决策冲突

本阶段开始时基线为 `e155bb01`；实施期间并行 agent 提交 `b5a138ee`，新增 ADR 0014，并把业务实体的新增/编辑主形态从 `FormDialog` 改为独立路由的整页表单。该决策晚于 #112 R1 的 `FormDialog` 描述，属于现场发生的规格冲突。

本轮不据此扩做整页表单壳，也不修改在线设计或 `DC重构设计源码/**`：

- 本轮 `FormDialog` 响应式收口只适用于 ADR 0014 仍保留的行级小对象和兜底弹窗，不能作为业务实体继续使用弹窗的依据。
- 整页实体表单的左锚点、分区卡片、最多两列字段和五动作底栏，以 ADR 0014 为准，等待独立 Vue 实装 issue 后重新核对设计并实现。
- `#112` 的后续执行应先把 R1 评论中的 `FormDialog` 表述同步为上述边界，避免下一位 agent 按旧口径扩做大弹窗。

## 本轮 Nuxt 已先行的行为

- `MetricGrid`：`cols` 作为宽屏最大列数，按最小可读宽度自动降列。
- `form-grid/form-cell`：详情/共享展示网格由容器驱动 1/2/N 列，不再依赖固定第三列消边；ADR 0014 的整页实体表单仍以最多两列为上限。
- `FormDialog`：仅对保留的行级小对象/兜底弹窗，窄容器用顶部分区选择，字段单列，操作栏允许换行。
- `TablePager`：紧凑容器只保留当前页码，同时保留前后翻页和页大小选择。
- 工作区 gutter：从手机到宽屏按现有间距令牌渐进收敛。
