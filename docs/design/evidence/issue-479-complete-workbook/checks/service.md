# 输出目录服务与协议验收

2026-09-22，#479 的原生目录服务、HTTP 和冻结实际账定向验证。以下均由真实 SQLite 事务及公开工资/名册命令生成事实，没有用完整健康工资快照代替发放过程。

| 场景 | 实测结果 |
| --- | --- |
| C2 实发 525、成员 350/175/0、正式号 128 | 预览和保存保原金额、零成员及编号；保存、重复提交和读取不推进正式序列。未选名册只记交付缺口，不把工资金额改成未知。 |
| 三名工人、六张实际 PNG、有登记日的独立名册 | 固定同项目、完全相同原工资集合及名册版本；零额离场成员保留。资料齐全的独立名册可以完整归档，证据性质声明不被误算为资料缺口。 |
| 私密权限 | 公开目录 JSON 不含完整身份证或银行账号；只有工资读取权限可读旧目录及固定引用，但不能预览选定私密名册或读取名册正文。 |
| 名册和照片原件 | 后改当前姓名、转项目不重写已保存目录。照片正文与摘要损坏时拒绝新目录，未留下半份保存。 |
| 幂等、并发与迟到请求 | 同键同文只生成一份目录；同键异文、跨项目拒绝。确认未应用生成取消墓碑，迟到提交不能写入。 |
| 写入失败与撤权 | 回执写入触发故障、事务中撤销写权限均回滚目录及回执；恢复后原键可以安全重试。 |
| 正文、版本或回执损坏 | 与规范原预览及唯一回执交叉核验失败，不作为完整归档读取。 |
| 真实 HTTP | 预览、保存、列表、冷读取及 resolve 经 HTTP/Repository 往返；服务器已提交后模拟响应丢失，原键返回同一目录。工资金额继续以十进制文本传输，越项目和未知提交字段拒绝。 |
| 保存之后真实退款 | 原工资实发 1000，之后核算更正并实际退 40：旧目录净实际仍 1000，新版本为 960，原工资冻结实发仍 1000。旧预览再提交被拒绝，正式号和序列不变。 |
| 非法响应 | 错月份分组、重复组、跨单实际账、假名册、浮点金额、私密字段及不同预览版本均在读取边界拒绝。 |
