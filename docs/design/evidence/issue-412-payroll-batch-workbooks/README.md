# P7 批量资金与完整工资工作簿限定验收

P7 在本地中央验证实例完成了现有决定能够支持的范围。产品分为五个独立提交：批次协调与逐单回执 `f71196db`、台账交互与 A 取整配置 `f14fdd26`、完整工作簿与按月归档 `3181761d`、结果与归档保护 `c6d0a1ba`、待执行语义与中文状态 `a2f117f5`。本记录不把三项待业务裁定的范围或 #416 生产关口登记为完成。

## 已接通的行为

- 固定项目、月份和正式来源后，可选择同范围 A/C1/C2 可发工资；已发、删除、隔离历史和 B 类不能进入批次。
- 批次冷读绑定工作区与经办人；每项由服务端明确报告成功、确定未执行或待核实，并分别保留计划金额与确定实际金额，界面不按列表位置猜测结果。
- 输入资金后按每单合法可发余额建议金额。A 使用明确保存的“不取整”或“向下取整到整百元”，C1/C2 不套用 A 规则。未分配、超额、零余额和未知资格均明确显示。
- 经办人可逐单修改实际金额和完整成员分配。确认后先保存不可变计划，再按原 A/C1/C2 命令逐单执行；每项保留成功、明确未执行或待核实状态。刷新或冷重开只恢复已保存的原执行编号和正文，已成功项不再提交。
- “负责人全周期一册”按负责人、格式与 A 请款簿稳定身份组合全部已发工资；“项目按月归档”生成真实 ZIP 月份目录。每册含目录、周期对账、实际收付、缺口清单和冻结原表。
- A 周期应付取最新合法累计，C1/C2 汇总独立期间应付；净实际只读取所含原工资的实际收付。A 累计 1000/1600、实际 800/700 的反例得到 1600/1500/100。
- C1 保留工资和考勤原表，C2 保留工资和签工原表且不生成考勤。缺少冻结正文只进入缺口清单，不生成金额为零的替代页。
- 危险恢复在删源前检查批次计划、逐项尝试和协调回执；存在引用时整批拒绝。冻结原文有缺口时文件明确改称“部分工资工作簿”，公式合计和对账结论保持不可判定，实际账仍查询所选全部已发工资身份。

操作说明已写入 [工资与考勤指南](../../../guides/payroll-attendance.md#九批量资金与完整工作簿)，页面与数据边界见 [工资页面蓝本](../../../rewrite/pages/subcontract-payroll.md)。本阶段按用户要求只保留 Markdown 验收说明，没有生成指南 PDF。
