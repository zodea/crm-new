## 反例与依据

按月 ZIP 曾复用负责人全周期算法。全月都是 A 时取最后一张的累计应付，混入 C1/C2 时又变为各张本次核算相加。同一月份多名负责人、普通/管理簿因此会丢金额。

既有 [P7 规格](https://github.com/zodea/crm-new/blob/c16869fcbf954dddd46143839afe5790f3828f1a/docs/research/issue-review-2026-09-11/payroll-tickets/07-central-batch-payments-and-workbooks.md#公式与现金不能混算)规定月度与周期分别说明口径：A 周期采用最新累计，单月核算/支付差额独立展示，不代表周期新增债务。问题和修复边界已先登记在 [#412 评论](https://github.com/zodea/crm-new/issues/412#issuecomment-5769634230)。

| 范围与输入 | 修复前 | 修复后 |
| --- | --- | --- |
| 同月两名同名异 ID 负责人及一份管理簿，本次核算 800 + 300 + 200、累计 1600 / 900 / 550、实发净额 1130 | 公式 550、差额 −580 | 月度公式 1300、差额 170，3 张原单各自保留 |
| A 首月累计 1000/实800；次月累计1600/本次800/实700 | 次月被累计口径误导 | 次月800/700/100；全周期1600/1500/100 |
| 次月 A 本次800，C1 0.10，C2 0.20，实际700.30 | 格式变化导致算法分支改变 | 明确按月本次800.30/700.30/100.00 |
| C1 独立期间0.10+0.20，实际0.20 | 浮点尾差可能进入输出 | 公式0.30/实际0.20/差额0.10 |
| 实际金额未知，或历史公式为 NaN/Infinity | 不得输出假0 | 金额与差额空白、结论不可判定 |
| 公式与净实际各自分值安全，但两者相减超过安全整数 | 差额空白却仍标可计算 | 差额空白、结论不可判定 |
