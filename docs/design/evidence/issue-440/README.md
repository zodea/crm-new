## 范围与来源

当前户详情与工程量台账仍使用 ADR 0020 保留的本地领域 adapter；本票不宣称工程量中央事实链已经接入。浏览器使用隔离的新测试上下文及合成 SQLite 数据，不读写用户数据库。fixture 注入本地 production 命名快照只用于测试既有可写 adapter，不代表生产认证或持久化验收。

三量分别带完整值、已知部分、参与项数、缺项数和缺单位标记；各单位独立计算。全户按房间与分项的稳定身份去重，阶段各自计算；月度只读已完成且显式承担报量的阶段。没有修改模板量、完成事实、已生成月报量或工资快照。

## 失败复现与回归

- 月度现场量为 null 的数据库用例先失败：旧聚合返回 0；修复后完整值和已知部分均为 null，缺项与参与项各为 1。
- 户详情部分缺量用例先失败：旧阶段/全户总量把已知 5 当作完整合计；修复后显示缺 1 项。重读明确零后显示 0，撤下缺项提示。共用分项不会随多个阶段重复累计，不同单位各有独立合计。
- 未标明单位的月度用例先失败：原结果将 20 视为完整；修复后完整值、已知部分均未知，界面/导出提示“单位待核对”。
- 实际 XLSX 回读验证缺失数值保持空格、零是数字 0，同时保留单位、完整度和已知部分。原有 completed/draft、显式报量阶段、软删除来源和执行责任测试继续通过。

定向 `npm test -- tests/stores/quantity-derived.test.ts tests/components/QuantityUnitTotals.test.ts tests/quantity/export.test.ts`：3 文件 15 项通过。测试切入数据库派生读取、实际户详情组件及 XLSX 文件格式，未以源码字符串断言代替行为。

定向 ESLint 通过，类型检查通过。独立 Standards / Spec 分别完成源码预审与最终文档、浏览器测试及证据复核，均无未解决发现；提交检查结果由固定 SHA 的 Issue 评论补充。

## 真实浏览器与文件

`e2e/quantity-totals.spec.ts` 两个场景分别通过：五档视口和键盘用例 39.5 秒；真实页面下载与文件回读用例 39.8 秒（后者最后一次单独运行总计 49.3 秒）。

| 场景 | 实际验证 |
| --- | --- |
| 阶段与全户 | 同一平方米分项跨两个阶段、两个房间，合同量 0、暂估量 30、现场量部分已知 12；另一个米分项为 8。全户按单位展示，平方米没有被重复计入。 |
| 五档视口 | 390/768/1024/1280/1440 × 960；根文档没有横向溢出，390 的明细表保留局部横滚。 |
| 说明与焦点 | 从全户现场量帮助按钮用 Enter 打开，说明包含参与项、缺项和已知部分不可作完整合计；浮层边界在视口内，Escape 关闭后焦点回到触发按钮。 |
| 来源返回与下载 | 从实际户详情返回工程量矩阵，点击“导出台账”，接收真实浏览器下载后保存并回读。目录选择能力在测试中禁用，采用既有标准浏览器下载，不声称人工操作过系统目录。 |
| Excel 内容 | 三个工作表齐全；月度只有泥水完成的平方米/米两行，未承担报量的共用阶段没有重复带量。平方米合同量为数字 0，现场量为空、缺 1 项、已知部分 12，米现场量为数字 8。 |
