# #428 付款与动态成本的结算确认口径

- 日期：2026-09-10；实施票：[统一付款结算引用与动态成本的确认状态口径](https://github.com/zodea/crm-new/issues/428)，承接 #409/#410/#412/#413。
- 状态依据：`DATABASE.md` 的已确认结算与动态成本定义、`COMMANDS.md` 的其他结算状态机；没有将审批字符串映射为确认的现行迁移规则。

## 修复与失败证据

付款候选原先仅排草稿，付款保存未检查源结算状态，付款详情往期结算仅排草稿，动态成本还接受 `approved/已审批`。本轮在内存数据库的公开读写接缝建立 11 项失败断言，证明待确认记录能成为候选、被保存为付款关联，并抬高往期结算/成本。

四处现统一使用 `confirmed/已确认` 语义。付款保存重验状态，失败事务不留下付款头和分摊。已确认记录仍可选择、保存并进入汇总，既有身份/软删除过滤保留。旧测试夹具中的审批字符串更正为真实确认状态，不放宽付款对象边界。

## 验证

- 6 个相关测试文件、31 项通过，包含目标成本详情和付款对象边界。
- 付款管理 7 条与目标成本详情 4 条浏览器场景通过，涵盖四档视口、搜索/状态筛选、登记支付回填、详情往返与缺失态。
- 旧付款管理场景依赖默认演示数据，已改为在测试会话显式开启；冷启动只延长首次挂载等待，业务断言未删除。
- 付款指南同步已确认关联规则及尚无确认入口时的边界；3 页 PDF 已逐页渲染检查。

## 边界

本修复不把旧材料结算的“待确认”自动升级，不制造确认入口、审批事实或历史迁移结论。普通财务中央写源和已存零批复/未知金额的区分另由 #413 承接。
