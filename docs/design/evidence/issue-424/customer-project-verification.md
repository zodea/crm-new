## 事实与失败复现

- 开工工作树只有原有未跟踪 `.worktrees/`，未纳入本任务。检查了两个父票最新正文、全部评论、原生子票与依赖、关联 PR 和既有承接；发布子票前没有相同独立承接。
- 源码线索：客户 context 的项目集合仅为 demoProjects。此时只记录推断，没有把它当作实际丢失证据。
- 真实 Chromium 红阶段：使用独立 `x-ruihang-test-session` 合成客户与项目，经现有中央命令保存；项目表单回读的 customerId 与合成客户一致。打开该客户正式详情后，projectCount 实际为 0，预期为 1，且没有项目关联。冷启动请求超时没有计为业务复现。
- 事实接通后继续运行：项目详情刷新后返回客户，原链接焦点断言失败；横滚捕获 110px，但表格异步渲染重置为 0。两项均经过实际红阶段，再以同一旅程验证修复。
- 最终由 vxe 的数据渲染完成事件恢复表格横滚，再恢复关系区焦点；未使用固定延时掩盖异步问题。1440px 的实际可滚动范围小于 110px，测试使用其实际可达位置。

## 范围与权威规则

关系由现有中央项目 facts 投影；按同来源 customerId / secondaryCustomerId 匹配，主次同 ID 时一条项目且主客户优先。客户改名不会改 ID，项目更换客户后重新回读新的归属。客户列表不读取项目；客户详情直接取未富化项目事实，避免项目客户名称富化反调客户列表形成读取递归。

受限项目行从集合中排除，项目数量与列表同源；整个项目源无权或失败时列表为空、数量未知，展示独立问题态并按 retryable 提供重试。未创建关系表、本地镜像或新的正式数据源。

规则权威仍为[客户页](../../../rewrite/pages/base-customer.md)、[项目页](../../../rewrite/pages/project-info.md)、[中央读模型](../../../rewrite/READ-MODELS.md)和[导航契约](../../../rewrite/NAVIGATION.md)。本记录不复制字段表或替代 ADR 0020。

## 双轴复核

`code-review-matt` 以 `3edab0c47d1125a025c52bfad3d3aa9722ab8d64` 为固定点，由两个独立审查分别检查规范与规格。

- Standards：1 项 P2 公共原语缺少组件级验证，1 项判断性 P3 领域链接访问 vxe 内部结构。新增实际挂载 KitTable 的 7 项测试，验证渲染/布局/滚动完成后才发通知、无效输入和失效取消；位置读取收进类型化 `KIT_TABLE_VIEW_KEY`，并在组件权威规格登记。复核确认两项关闭。
- Spec：1 项 P2，同项目在合同/收款页签出现多行时可能错误聚焦第一行。先建立来源行存在/消失两项实际失败测试，再通过项目 ID 加稳定来源行锚点修复，原行消失聚焦关系区。复核确认关闭，未发现新增明确规格问题。

审查没有将只读源码判断写成浏览器事实；修复后另行复跑类型、4 个组件文件的 18 条测试、全量 2375 条测试及客户项目和既有关系浏览器旅程。复跑中首条曾在开发服务冷启动的合成请求阶段超时，测试改为等待客户界面真实挂载后再创建合成数据，独立复跑通过；该超时未计为业务丢失证据。最终有效提交 SHA 与测试结果回写 #424。
