# 工资退役入口、考勤来源与筛选往返验收

日期：2026-09-10。实施票：[#433](https://github.com/zodea/crm-new/issues/433)，承接 [#412](https://github.com/zodea/crm-new/issues/412)。本记录随修复提交；最终固定提交的类型、全量回归与独立复核以 Issue 回执为准。

## 权威与本次范围

按[工资与考勤蓝本](../../../rewrite/pages/subcontract-payroll.md)、[当前继承决定](https://github.com/zodea/crm-new/issues/412#issuecomment-5579069812)与 #350/#352 已定语义实施。工资/签工没有本轮可直接对照的外部同名页面，沿用本地 DC 工资与签工构图；历史只读参考的适用边界仍见[运行参考账本](../../runtime-reference-audit.md)，本地验证不提升外部证据等级。

- 新建仅提供 A/C1/C2。历史 B 的草稿、已核对、已发放均可读，改价、核对、发放和新工资输出拒绝执行，保留原金额、状态和快照。
- C1 台账、侧栏、独立详情和核对提示采用真实考勤语义；数量标题为考勤数量，A/C2 继续显示各自来源。没有改变计薪算法。
- 列表、独立详情、考勤、签工传递项目、月份、班组与工资状态；签工自身确认状态独立保存。同路径缓存页签收到新来源后重读；原范围切回保留未保存签工输入，换范围不携带旧编辑。

## 失败复现与验证

修复前，历史 B 改价、核对、发放三个公开命令均可改变记录；针对内存数据库的失败用例证明问题，修复后拒绝且公开读回与原记录一致。新建 B 选项、C1 来源及详情返回也先建立组件失败用例。

补充真实 `RouterView + KeepAlive` 复现：项目 B 离页后以项目 A 再进入签工仍显示 B。真实浏览器继续复现：签工改月返回已缓存工资页仍显示旧月；再进入已缓存考勤仍显示旧项目。三入口恢复逻辑修复后，原范围未保存证明人保留，跨项目/月/工资状态采用新范围。

独立复核追加两个 P2：省略班组或空/非法工资状态恢复旧缓存，以及工资/考勤保留未知项目。六个公开解析与真实 store 用例先失败，现三个入口统一按来源和实际选项恢复；完全无来源的普通入口保留缓存及工资返回状态。另补真实 store 异步窗口复现：新月份已输入但下一次读取尚未开始时，旧响应不得回写旧月份。共享页面壳热更新期间的浏览器失败不计为最终业务结论；最终五项在协作源码冻结后完整通过。
