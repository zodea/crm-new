## 失败复现与修正

| 场景 | 修正与验证方式 |
| --- | --- |
| Nuxt 初始导航覆盖恢复导航 | 恢复 hook 排在初始 force 导航后、首次挂载前；真实 Vue Router 顺序回归及浏览器启动验证 |
| 已有 15 个只读页签，在写态刷新 | 原先提前腾位会丢一个旧项；存储反例先失败，改为按最终保留入口处理容量 |
| 合法编码身份被规范化 | 原路径与规范路径原先并存；反例先失败，改为原子迁移页签、描述符和缓存键 |
| 同一页面不同页内锚点 | 原先额外占用页签，首页也可能失去固定身份；反例先失败，路径键排除 query/hash，完整地址仍保留 |
| 已排除写态，刷新后又出现旧编辑页签 | 浏览器反例证明 Nuxt 页面 route 在挂载前仍是旧值；外壳改跟随已确认的 router.currentRoute，复跑通过 |
| 视口变化时页签菜单关闭或丢焦点 | 浏览器反例定位自动滚入活动页签触发滚动关闭；菜单跟随页签栏滚动定位，归还焦点时不再滚动页面 |
| 活动页签有焦点但被挤出可见区域 | 1024px 截图发现后补充栏内边界断言，先失败再修复；尺寸变化后重新滚入活动项，五档复跑通过 |

首次冷启动曾因页面未挂载便在 5 秒内检查地址而超时；该次空白截图不能单独证明恢复逻辑错误。验收已等待应用外壳可见后再核对地址，启动次序另有实际路由与生命周期回归证明。
