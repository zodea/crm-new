# 旧恢复问题与业务重新打开

本记录承接 [#435 补修范围](https://github.com/zodea/crm-new/issues/435#issuecomment-5623827325)，基于 `ed463324`，与上一轮浏览器恢复实现的固定证据分开记录。此次只修复旧恢复失败拦截当前业务入口的问题，不增加领域详情读取能力。

## 失败复现与改动

此前从付款申请列表整页重载，再点击真实表格名称时，会因同 key 的旧详情仍待恢复而再次返回列表。固定截图已随 #439 归档于[付款验收证据](../../issue-439/tab-restore-reopen-blocked.png)。公开路由测试分别复现了“业务列表重新打开”和“同 key 普通直接深链”都被错误退回列表。

旧页签激活、重试和关闭后的回退现在显式执行恢复校验。普通导航取消先前恢复请求，导航实际成功后才撤掉相应旧问题，数据版本重新保持未知；取消导航保留原问题。旧无权页签再次点击仍会核验，普通页面仍按其当前来源与权限读取。

## 验证范围

- 页签定向测试：12 文件、319 项通过，包含新增 8 项真实路由/会话动作回归；覆盖重复撤权、取消导航、关闭回退、迟到响应与普通深链。
- 类型检查与本次明确 TS/Vue/E2E 文件的 ESLint 通过。
- 已有浏览器恢复回归 3/3 通过：刷新/关闭集合（3.9 秒）、撤权后的重试/关闭（2.6 秒）、迟到读取下新导航优先（1.6 秒）。
- 新五档业务列表回归先通过（22.8 秒），与 #442 的实际 API 用例同窗执行，共 2 项、35.2 秒；本票只计本身 1 项。覆盖每档恢复失败后从真实表格按 Enter 重新打开、零批复读回、问题清除、唯一页签与普通直接链接。逐图发现部分页签下划线处于原有 CSS 过渡帧后，仅将截图设置为关闭动画，最终窄复拍通过（21.6 秒）；本次与收款共 6 项、53.5 秒，本票仍只计自身 1 项。最终 6 张截图已逐张检查，活动页签、问题提示和响应式边界均清楚可见。
- 此前两轮先误用了手机隐藏的侧栏链接，又误把详情返回链接按按钮定位；已依据真实可访问树统一为详情的“返回付款申请”链接，两轮均不计作产品通过或产品缺陷。
- 两本指南已同步：页签指南 V1.1 共 3 页，付款指南 V1.4 共 4 页；已逐页渲染检查。付款指南只更新旧页签的重新打开操作，不改变付款规则。
- 独立 Standards 与 Spec 复核均无可操作 P1/P2；最终图片随本补修单独归档，不将同窗其他模块用例计入本票，也不升级上一轮固定提交的证据。

## 能力边界

付款等未接入领域仍不能自动恢复详情；从业务入口重新打开只沿当前既有流程。没有扩展 Tauri、生产持久化、通知或后台订阅，也没有改动收款专属 Target Registry/恢复读取分支。路由进入与实体读取授权继续分开判断。本次无需新增业务 grill。
