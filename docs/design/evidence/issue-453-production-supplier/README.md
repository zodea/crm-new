## 后端实际验证

- 固定 Node 24.12.0 内置 SQLite；公开 HTTP 路径由三个先后独立的服务进程处理，停止后重启需重新登录。公开测试 `tests/production/supplier-restart.test.ts` 覆盖主档首次提交失响应、原键恢复、原件读取、OCR 候选、人工确认失响应、冷恢复原确认、识别服务失效、提交前审计故障和撤权。
- 测试用 OCR 协议服务只返回可辨识的合成候选，经既有生产 provider 和公开 API 调用；不调用真实外部服务，不冒称重新评估识别质量。重启后原候选和人工改值分别保留，失败识别不删除原件。
- `supplier-storage.test.ts` 直接核对磁盘：同键异文、陈旧版本、动作类别冲突、普通及导入双指纹、原件事务回滚、外部识别等待期间的并发更正、权限撤销和原键封存、上海跨日撤销结论与冷开不重复递增。
- 新增可失败复现验证了读取时的派生变化不能绕过正式写入门禁；核验元数据缺失 `review`、损坏结论或布尔值时明确拒绝，原主档不变，不默认补空。
- 跨票备份复核发现“已有原件正文丢失”不能等同原始缺件。真实删除合成 BLOB 先复现失败，再把原摘要独立存入文件元数据；缺正文、摘要或元数据损坏均拒绝。完整旧迁入图及合法缺件的正式接管仍由 #468 验证，不能仅凭旧 ID 猜测。
- 未接管数量/金额的旧筛选深链先复现为假空结果，现明确返回不可用；前端同步禁用对应范围及排序，并提供清除数值条件的显式操作。实际主档没有被悄悄排除或混入开发数据。
- 定向业务和生产回归：10 文件、61 用例通过，22.89 秒；最后核验元数据修复后的磁盘与公开重启验证：2 文件、10 用例通过，15.05 秒。未运行 GitHub Actions，未新增生产依赖。
- 最后原件摘要与未知筛选修复后：磁盘、独立服务重启、原读模型合同 3 文件 23 项通过，22.60 秒。后端独立 Standards、Spec 两轴审查均通过；前端的领域未知状态及恢复边界也由两个非作者分别复核。
