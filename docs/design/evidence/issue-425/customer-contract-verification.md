- 开工分支 `codex/ui-reference-layout`，原工作树只有未跟踪 `.worktrees/`，本次未读取、修改或提交该目录。核对父票及已有承接正文、全部评论、原生子票/依赖与相关 PR；#379、#385、#395、#393 已合并且在基线，未发现重复开放承接。
- `demoContracts` 只作为调查线索。首先在隔离会话中使用合成正式客户/项目，经真实施工合同整页表单 POST 保存“合成客户合同回读407”；合同专属详情与 form GET 确认客户稳定 ID 正确，但客户 GET 的 `contractCount` 为 0、预期为 1，浏览器旅程失败。接通现有施工合同中央 facts 后同一旅程通过。
- 随后真正新建合成客户与关联项目，发现施工表单候选缺少刚保存的项目，浏览器实际失败。已在 #425 留证并明确必要实施范围：候选及命令验证消费当前中央身份集合，每次打开表单重取。修复后新客户、新项目、新合同、同名次客户隔离、项目换客户、合同显式改归属与客户改名的链条通过。
- 规格复核发现：合同详情保持打开超过返回有效期时，计算缓存仍保留旧入口。用 Chromium 可控时钟推进 31 分钟，修前找不到规范列表返回入口；复用 VueUse 定时器按实际有效期重新验证后，同一测试通过。
- 列表返回测试曾误要求地址显式包含默认 `pageSize=10`。实际搜索、状态、排序和第 2 页已恢复，规范地址省略默认值；断言改为验证等价默认值及实际分页控件，没有为测试改写业务规则。

## 本轮实施

客户投影复用施工合同读源的事实、权限与版本；合同自身 `customerId + dataOrigin` 决定归属，不从当前项目客户或名称推断，不建本地合同镜像。客户侧有效补充金额与施工详情共享计算，客户有效合同额与含已审定变洽签的合同详情金额仍按各自口径展示。合同源整体失败时，合同数量、有效合同额、待收差额及项目行合同摘要均未知，显示独立问题态；项目源失败不阻断可读合同集合。

新增正式身份从现有中央客户和项目 facts 读取，保存时再次校验稳定 ID、可读范围及项目当前主客户。历史合同不随项目换客户自动改写；显式更正合同归属仍通过同一命令。刷新表单候选避免使用过期身份集合。

导航复用唯一 Target Registry 和 #424 返回能力，将来源目标明确为 `project | contract` 加稳定 ID，防止同 ID 不同实体串接；只在 sessionStorage 保存视图状态。客户合同页签、工作区滚动、表内横滚、原合同链接焦点及嵌套客户列表筛选/分页均保留。原行消失时聚焦关系区，目标读取失败仍可沿有效来源返回；深链、来源错配、伪造和过期来源退回规范施工合同列表。

权威规则只见[客户页](../../../rewrite/pages/base-customer.md)、[合同表单](../../../rewrite/pages/contract-forms.md)、[核心合同](../../../rewrite/pages/core-contracts.md)、[中央读模型](../../../rewrite/READ-MODELS.md)、[命令](../../../rewrite/COMMANDS.md)及[导航契约](../../../rewrite/NAVIGATION.md)，本记录不替代这些源。
