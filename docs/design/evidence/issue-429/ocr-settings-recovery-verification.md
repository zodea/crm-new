# OCR 设置失败恢复验收

日期：2026-09-10。Issue：[#429](https://github.com/zodea/crm-new/issues/429)，承接 #414。实施基线 `84c4e5ec`，本记录随修复提交。

## 复现与结果

- 修改前，设置读取抛错后仍显示“已保存”；未加载的 store 也允许直接写入默认设置。定向测试已先复现这两项失败。
- 现在初读及后续重读失败均清除已读取资格，禁用参数、恢复默认和保存；读取成功后才恢复编辑。失败消息提供独立“重新读取设置”，运行状态“重新检测”保持原有只读职责。
- 保存失败保留草稿及未保存状态，允许再次保存；仅成功写入后显示成功提示。状态标签复用 KitStatusTag。
- 独立规格复核发现并发读取会提前释放保存门禁；现同一 store 的在途读取共用一份结果。页面与识别任务同时读取时，必须等该轮成功才允许保存；共同失败时均保持未读取状态，成功/失败两种并发回归已通过。
- 浏览器先写入隔离测试配置（图表开启、请求超时 45 秒），在页面实际加载的数据库门面注入一次读取失败，然后刷新页签。重读后恢复原配置；本场景所有设置写入均被测试门面拒绝，因此重读没有覆盖默认值。

## 验证

- OCR 页面、表单、store 三个测试文件共 13 项通过；覆盖读取失败、重读、并发读取、未读写入门禁、保存失败与成功回读。发票识别的 5 项回归也通过。
- 原有 OCR 浏览器 6 项通过；新增失败恢复浏览器场景通过。390 / 768 / 1024 / 1280 / 1440px 均无页面横向溢出；重读按钮可经 Tab/Shift+Tab 聚焦及 Enter 激活，禁用控件不能编辑。
- 类型检查通过；提交钩子执行完整测试，最终结果在本 Issue 提交回执记录。
- [使用指南](../../../guides/ocr-settings.md) 与 `output/pdf/瑞航CRM_OCR设置使用说明.pdf` 同步，PDF 三页均已渲染检查。
