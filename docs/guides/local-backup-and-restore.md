# 本机备份与隔离恢复

对应 [#451](https://github.com/zodea/crm-new/issues/451)。本切片为本机客户及原件提供一致备份、离线复制、隔离恢复验证和持续状态提示；当前使用独立合成目录验收。实际 NAS、移动硬盘、另一台电脑、空间与权限在 [#469 部署](https://github.com/zodea/crm-new/issues/469)及 [#470 恢复演练](https://github.com/zodea/crm-new/issues/470)核实。正式业务写入仍等待最终上线关口，看到“主备份在 24 小时内”不代表全站已经上线。

## 查看保护情况

本机登录后，顶部持续显示主备份状态和资料时点。点击“备份与恢复”查看最近成功的主备份、离线副本和隔离恢复验证。

- 尚未配置或尚无成功备份：请维护人完成下面的配置和基线步骤。
- 超过 24 小时、时间需要核对或最近备份失败：先核对电脑时间、介质连接、剩余空间和写入权限，再执行“立即备份”。已有成功副本保留。
- 状态暂不可用：先恢复连接并刷新状态，不能将上一次状态当作当前保护证明。

自动清理已暂停，主备份、暂存及离线副本会持续占用空间。请维护人定期检查各备份位置的可用空间并妥善处理容量问题。此前清理中断的副本可能不完整，需由维护人核验；历史操作提示不能证明副本完整。

资料时点来自一致副本开始生成的时间；离线复制晚完成不会把旧资料变新。后台状态核对不延长登录空闲期限。主备份默认每 12 小时尝试，服务启动和电脑唤醒后会补跑；失败后至少间隔 15 分钟再自动重试。补跑前超过 24 小时的保护空档会留在操作记录中，不因补跑成功抹去。

## 建立与核对副本

1. 使用“立即备份”。系统先在本机生成独立一致副本，核对参与领域、数据库关系、各表摘要和原件正文，再发布到主备份位置。
2. 主备份成功后连接移动硬盘，使用“复制到离线介质”。核对离线资料时点与本次主备份一致后再按 Windows 流程安全弹出。建议每个工作日结束后复制一次，以及升级发布或重要资料集中录入后再复制；移动盘不长期联机。
3. 使用“验证隔离恢复”。当前入口从最近成功主备份建立一个新隔离目录，逐项核对同一清单、摘要和版本，记录恢复证明；不覆盖或切换日常数据库。旧版本证明明确提示重新验证。
4. “最近操作”显示结果；出现失败或待核对时不要清理原副本。发送后失去响应，使用“核对原操作”，服务会按原编号回读。刷新或服务重启后重新登录，仍可核对该浏览器会话保留的编号。

这里只保留操作编号、动作和来源备份编号，不把客户字段、访问码或原件放入浏览器存储。关闭整个浏览器会话后，先从最近操作确认实际结果。备份目录中的不完整包不作为成功副本；应由维护人核实后处理，不手工混入其他文件。

## 首次正式写入与灾难恢复

基线需包含可验证的独立介质副本并通过隔离恢复。本切片记录该证明，同时保留最终上线关口，不能通过改成验证用途绕过正式门禁。

实际灾难恢复、发布回退、业务迁移回滚是不同操作。当前按钮只验证隔离副本；活动库切换、离线盘接管和全域业务对账由维护人按后续部署/恢复演练执行。不要直接覆盖活动库，不要删库排错，不要把历史工资或迁移引用保护当作可以用备份绕开的限制。

## 维护人配置

先按[本机客户保存指南](./local-customer-storage.md)配置固定运行时、工作区、用途和访问保护。以下位置只存在本机受控配置，不在仓库记录真实地址或凭据。

| 配置 | 用途 |
| --- | --- |
| `CRM_BACKUP_STAGING_DIRECTORY` | 已存在的本机临时副本目录 |
| `CRM_BACKUP_DIRECTORY` | 已存在且可写的 NAS 主备份目录，可为受控网络共享 |
| `CRM_BACKUP_OFFLINE_DIRECTORY` | 移动硬盘中已准备的离线副本目录；未连接时复制明确失败 |
| `CRM_BACKUP_RESTORE_DIRECTORY` | 已存在的本机隔离恢复根目录 |
| `CRM_BACKUP_INTERVAL_HOURS` | 主备份间隔，默认 12，允许 1–24 小时 |
| `CRM_BACKUP_DAILY_COPIES` | 兼容既有日保留配置，默认 30；自动清理暂停期间不触发删除 |
| `CRM_BACKUP_MONTHLY_COPIES` | 兼容既有月保留配置，默认 12；自动清理暂停期间不触发删除 |

四个目录和活动数据目录必须彼此独立、不能相互包含，也不能使用符号链接或重定向目录。配置变更后按维护流程重启。程序检查目录和内容，不能据此证明它们在不同物理设备上；真实介质独立性另行验收。

中文或深层目录仍按原目录填写配置，无需手工改成特殊路径格式。已验证的长路径范围及恢复限制直接见 [ADR 0021](../adr/0021-single-operator-windows-production-storage.md#正式存储与运行边界)；实际介质和权限仍须按本节核实。

备份及离线复制成功后不会自动到期清理副本；暂停期间，既有日/月份数配置仍参与原操作身份核验，但不会触发删除。计划备份仍按既定间隔执行，不能代替额外离线副本。

每个完整包只有 `data.sqlite` 和 `manifest.json`。原件与数据库同库，清单只含版本、身份、数量与摘要，不复制业务正文。原生原件缺正文、坏摘要、未知领域/实表或不兼容版本都会拒绝。历史缺件只按 [DATABASE 备份清单](../rewrite/DATABASE.md#pg-02-备份记录与隔离恢复证明451)及[旧清偿精确缺件证明](../rewrite/DATABASE.md#historical-expense-clearance)保留原状态；迁入身份或替代材料不表示原文件已找回，隔离恢复也不补造正文。

运行决策见 [ADR 0021](../adr/0021-single-operator-windows-production-storage.md)，模型及完整参与者清单见 [DATABASE](../rewrite/DATABASE.md#pg-02-备份记录与隔离恢复证明451)，运行证据见 [PG-02 验收](../design/evidence/issue-451-production-backup/README.md)。固定 Node `24.12.0` 的 `node:sqlite` 仍属实验 API，升级须先在副本验证。
