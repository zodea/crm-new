# 工人私密资料与工资实名名册

本文说明 #449 的中央浏览器流程。功能在本地测试实例验收，不代表生产持久化、正式账号或工资完整工作簿集成已经完成。工人资料、照片和名册版本使用同一中央边界；桌面旧本机入口不自动接入。

## 权限与入口

完整身份证、银行资料和照片需要单独的工人私密资料读取权限。只有工资读取、工资写入或一般工人权限，不能查看这些资料。默认会话不会自动得到私密权限。权限由服务端明确配置；本票没有新增账号管理页面。

工人详情中的“私密资料与照片”进入独立整页。维护劳动合同与照片还需要工人编辑权限。一般列表和详情继续显示脱敏信息；已有工人的完整编辑表单同样需要私密权限，因为表单包含身份证和银行账号。没有该权限时页面说明原因，不返回完整资料。新增草稿仍按原工人新增权限处理。

工资台账中的“实名名册归档”进入独立工作区。读取名册需同时有工资读取和工人私密权限，新增归档还需工资写入权限。

## 维护工人资料

1. 打开工人的“私密资料与照片”。核对姓名、性别、籍贯、身份证、开户行、账号与进退场日期；这些字段来自工人主档，需修改时进入“编辑工人主档”。
2. 填写劳动合同签订情况。未记录、明确未签订、已签订分别保存；已签订但没有日期时，名册保留缺日期提示。
3. 分别选用或上传证件照、银行卡照。两种用途由经办人明确选择，不根据文件名猜测。照片支持 PNG/JPEG，每张不超过 20 MB。
4. 点击“保存资料与照片”。保存形成新版本；再次上传会产生新的原件身份，已归档名册仍引用旧照片。

旧附件只有元数据而没有正文时显示“缺正文”，不能当作有效照片选用。未知旧分类保留原记录，不自动视为两类照片齐全。

## 从已发工资建立名册

1. 选择项目，再勾选已发的 A/C1/C2 工资。冻结成员缺损、删除或不可见工资不能用于归档。
2. 填写资料登记日期，点击“核对所选工资的名册”。系统从原工资冻结成员确定人员，包含负责人和零分配人员。同名但身份不同的人员分开保留，后来离职或转组不会让原成员消失。
3. 核对完整资料和缺口。资料登记日期与实际归档时间分别保存。若当前归属、进退场日期不足以证明所选日期的在场情况，状态显示未知，不擅自算在场或离场。
4. 点击“按当前预览归档新版本”。成员、字段、劳动合同事实、照片身份和摘要随该版本固定。资料缺口也保留，归档不代表材料齐全。

名册是独立日期的资料补充，不证明原工资发放时已经保存这些资料。后来补充资料后须重新预览并建立新版本；旧工资、旧名册和旧照片不被覆盖。

## 读取与下载

“已有归档版本”按项目列出登记日期、版本、成员数和缺口数。打开后查看固定内容，点击“下载名册与照片 ZIP”。包内包含实际 Excel 名册、按工人身份区分的两类照片原件及 Markdown 归档说明。身份证和银行卡号按文本写入，零成员不会被省略。

每次下载重新校验权限、归档范围和原件摘要。没有私密权限、照片不属于该归档或原件损坏时，下载停止；不能通过传入文件路径读取其他内容。

## 冲突与未确认提交

资料在预览后变化时，保存拒绝旧来源；原填写仍保留，先“核对原提交”确认没有应用，再按保留输入重新核对。提交响应丢失时不要另建重复版本，点击“核对原提交”。刷新后仍可找回同一提交编号：已保存的结果重新回读，未保存的编号会被安全关闭，迟到请求不能再次应用。

浏览器只保存待核对编号、目标身份和操作类型，不把实名名册和照片正文写入页面恢复缓存。未保存的照片与字段不作为浏览器冷恢复交付；离开前须先保存或确认放弃。

## 边界

当前独立名册与照片包可用范围以 [本票验收记录](../design/evidence/issue-449/README.md) 为准。正式工资编号、名册版本与工资完整工作簿的最终组合、生产备份和权限运维由相应工作单元继续接入。数据和权限契约见 [工人页面](../rewrite/pages/base-worker.md)、[中央命令](../rewrite/COMMANDS.md#工人私密资料与工资名册命令449)、[中央读取](../rewrite/READ-MODELS.md#工人私密资料与名册读取449)。
