## 一、选择正确的合同类型

| 类型 | 适用情况 | 必需的业务关系 |
| --- | --- | --- |
| 其他支出合同 | 项目机械租赁、检测服务及其他支出 | 工程名称明确对应一份真实施工主合同、真实项目与乙方分供方 |
| 公司支出合同 | 房租、软件及公司层面的其他支出 | 对方单位名称；不挂项目 |

公司支出合同没有项目筛选和项目字段，无需建立“公司”虚拟项目。项目其他收入合同不属于本功能。

## 二、查找与查看

1. 从“项目其他合同”进入其他支出合同或公司支出合同。
2. 按类别、状态或名称、编号、对方单位搜索。其他支出合同还可以按项目筛选。
3. 点击合同名称打开只读详情。进入页面不会保存或提交合同。
4. 在“详细资料”查看基本信息、合同条款、备注、附件记录和创建、修改信息。不存在的历史字段显示“未记录”。
5. 使用“收票登记”“付款信息”页签核对所属合同的记录；其他支出合同另有“支出结算”“增补合同”。没有记录时显示对应空态。

列表底部的数量和金额合计按当前筛选范围统计，不仅统计当前页。真实零金额显示为零；未记录金额不按零计算。

## 三、编辑与保存

1. 在详情点击“编辑合同”，进入独立整页表单。
2. 核对合同类型、项目或对方单位，再填写金额、日期、付款周期、条款和备注。
3. 新建其他支出合同含草稿，先动态搜索“工程名称”，按工程、施工主合同名称及编号明确选择；不默认第一份。同一次保存写入合同头及施工归属。乙方分供方和甲方（我方签约主体）同样从真实主档选择，名称相同不代表同一个对象。已有未记录施工归属的历史资料保原项目关系，可在详情单独核实施工归属。
4. 点击“保存”写入当前合同；默认保存后返回详情，刷新后仍从同一中央记录读取。已有合同的业务状态不会因普通保存被改回草稿。
5. “保存草稿”可暂存其他未完整字段，工程选择仍必填；“保存并提交”校验必填项并进入审批中。公司合同头继续独立，实际项目归属由业务费用明细维护。本功能不提供审批通过、结清等结果动作。

保存响应丢失或结果未知时保留输入、附件和原提交编号，先点“核对原提交结果”。确认已保存后只读取原目标，读取失败时继续核对，不重新发送正文；确认未应用后封存原号，才能以新意图保存。浏览器恢复只保最小编号与范围，不把文书正文或原件存入恢复定位。核对成功也保留后来输入和新增附件。合同版本冲突时可保留输入，也可明确载入最新版。

离开有未保存内容的表单时会显示确认框。取消或按 Escape 保留输入，并将焦点返回原操作按钮。

## 四、附件与票款口径

附件按所属合同及原增补协议的稳定目录展示名称、分类、上传人和时间。编辑时可以上传真实正文、移除或恢复本合同已有记录；删除与恢复在保存时生效，历史原件与原版本不物理删除。详情的“合同文件”支持原件预览和下载；缺正文的历史目录明确报缺件，未知上传时间不补造。

正式列表与详情不把旧累计列或冻结票款截图当当前现金。当前收票和支付来源未完整接通，金额保持未知并提示缺口；其他支出累计结算仅从实际 Other owner 的同合同、同项目、同分供方已确认结算读取，变更后合同金额含真实有效增补。公司合同不提供项目结算口径。缺税率时无税金额和税额仍显示“未记录”。

## 五、完整 Native 迁入与受保护恢复

在任一类合同列表展开“完整 Native 辅助合同迁入与受保护恢复”，明确选择真实完整 SQLite 导出文件。一次采用同时保全两类合同头、全部原增补、原件目录及审计，不把同名或同旧 ID 的公司与项目合同合并。

核验后逐项选择实际项目、分供方和已核实主体的稳定 ID 与版本。历史已归档主档只可明确用于保全旧关系，不复活，也不进入日常新建候选。目录仅有路径的原件须按原文件 ID 补传；原旧字段、未知扩展、冻结、回执及原身份映射完整保留。完整原库继续留在导出位置，正式库仅保存本领域原图与共享原件，边界见 [Native 一致快照](../rewrite/DATABASE.md#native-domain-snapshot)。

采用或恢复结果未知时先核对同一原编号。受保护整批恢复只退役本批采用；后来修改、原意图、真实下游或曾经存在的施工关联任一项不安全，整批拒绝，解绑也不解除原历史消费。原图、原件和不可变历史继续保留，不物理撤除唯一正文。旧原命令尚未明确映射当前操作者时保持结果不可核验，不凭新编号认定未应用。

## 六、从项目或分供方进入

其他支出合同详情中的项目、乙方分供方名称可进入对应只读详情。从项目或分供方页面的“其他支出合同”区域进入列表时，系统会限定该来源对象。

使用“返回来源”逐级返回。合同列表的搜索、筛选、页码，以及来源页签、位置和操作焦点会保留。无有效来源时返回该类合同列表。

## 七、异常与当前边界

| 状态 | 处理方式 |
| --- | --- |
| 暂无合同 | 有编辑权限时可点击新建 |
| 没有符合条件的合同 | 调整或清除筛选，不必重复建档 |
| 服务暂时不可用 | 读取点重新加载；有原提交编号时先核对，不另发正文 |
| 无权限 | 页面不展示写入口；联系权限管理人员核实 |
| 合同不存在或来源不匹配 | 返回来源重新进入，不通过改 URL 更换合同类型 |

正式工作区从已登记的同库 Auxiliary owner 读取两类列表、详情、整页表单、原件及完整迁入证据，进程重启后保留实际事实与原回执。开发验证实例继续仅供原界面回归，不能用来补正式缺源。

其他支出结算、原费用采用及实际财务流水继续由[专属结算指南](./other-expense-settlement.md)和其原 owner 管理。登记 Auxiliary 不代表收票、现金或所有辅助域已接通；材料采购结算与外部审批按各自模块说明，不能靠改名称或金额合并身份。
