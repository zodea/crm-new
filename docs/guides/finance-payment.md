## 二、查看付款申请详情

1. 进入“资金管理 → 付款申请”或“资金管理 → 付款管理”。
2. 点击付款申请名称，进入只读详情页。列表中的编辑动作仍进入付款申请整页表单，不会把查看和编辑混在同一页面。
3. 在详情页先核对顶部摘要，再查看基础信息、合同状态、结算关联、发票关联和支付记录。
4. 只有稳定 ID、数据来源和目标权限均有效的蓝色源单链接才能进入合同、发票或支付记录；缺关系或目标尚未接入时显示不可用原因，不根据名称或金额猜测关联，也不跳入另一数据来源。

批复金额显示“—”时，应同时查看旁边的说明。“未填写”表示没有录入批复金额；“历史批复待核验”表示旧记录不足以证明当时的批复含义，需要核对原始凭据。后者的待支付余额和完整合计也会保留未知，不能理解成没有欠款。已确认的银行支付仍显示真实金额。

## 三、阅读智能业务洞察

右侧“智能业务洞察”根据当前数据库中的付款申请、合同、结算、发票和支付记录实时派生，不是静态提示图。

- **审批状态**：展示已有申请状态及相应提示；状态提示不代表系统提供了审批流程，不能据此推断新的审批入口或自动审批规则。
- **结算勾稽**：有合同付款申请时，检查申请金额与已结算金额；无合同类型不强制要求结算单。
- **发票勾稽**：检查申请金额对应的发票关联金额。待开票或部分开票会提示风险，禁止发票类型却存在关联时提示异常。
- **付款上限**：检查已登记的确认支付是否超过申请/批复金额，并显示当前未付余额。未付余额本身是待办信息，不等于异常。
- **跨项目/分供方付款**：展示同一分供方在其他项目上的可追溯付款摘要，帮助复核集中付款，不替代项目级审批。

提示级别分为正常、信息、注意和异常。注意与异常会计入顶部待处理数量；每条提示都应回到源单核对后再处理。

## 四、登记支付

1. 在付款申请详情点击“登记支付”，或在“付款管理”对应行点击登记支付。
2. 系统进入“新建支付记录”整页表单，并自动带入付款申请、项目、分供方和当前未支付金额。
3. 核对支付日期、支付方式、收款账户和本次支付金额；金额以实际银行支付为准，不要直接接受回填值而跳过核对。
4. 保存后返回支付记录流程，再回到付款申请详情确认已付金额和未付金额已按真实支付记录更新。

如果已知可付金额已经全部支付，详情页不会继续提供可用的登记支付动作；如果只支付了一部分，下一次登记支付只回填剩余金额。明确批复为零元时，不会自动改按申请金额继续支付。

历史批复待核验的记录暂保留既有登记流程和兼容回填；回填值不是已核定的批复或余额，也不等于批准申请全额。此类历史记录是否暂停新增确认、如何按凭据核验，仍待业务裁定。已有确认支付不会因此被修改或撤回。

## 五、编辑付款申请

1. 在详情页点击“编辑申请”。
2. 编辑页仍使用付款申请整页表单；保存、提交等写入动作只在表单中进行。
3. 保存后返回详情重新核对合同、结算、发票和支付勾稽结果。若金额或关联源单发生变化，智能业务洞察会重新计算。

切回已经打开的付款详情时，页面会重新读取保存结果。整页重载后若出现未恢复提示，可直接从付款申请列表重新打开，无需先关闭旧页签；付款详情自动恢复尚未接入，记录不会因此删除。重新打开与重试恢复的区别见[页签与页面恢复指南](./tabs-and-recovery.md#四恢复失败如何处理)。

“本期批复金额”留空表示未填写；填写 `0` 表示明确批复零元。已填金额可以清空，保存并刷新后仍为空。历史待核验记录应先核对原始凭据，再明确填写金额或清空；仅修改审批备注、保存其他字段或点击“放弃修改”，都不会确认历史批复的含义。输入负数或无效金额会被拒绝，保存失败不会留下金额与来源的部分修改。

关联结算只可选择已确认的记录，草稿、待确认或仅审批通过的记录不会进入候选，也不计入合同往期结算和项目动态成本。保存时系统会再次检查：若源结算尚未确认，需先回到源单核对，不会留下半份付款申请或分摊记录。现有来源尚未提供确认入口时，应等待对应结算流程补齐，不能以待确认状态代替确认。

## 六、使用边界与后续能力

付款管理的“工资实际收付”是独立只读分区，按工资项目查看并进入原工资收付记录。它不改变付款申请待付、银行支付或往来指标；补退需从工资原更正进入专门整页，见[工资更正与实际收付](./payroll-adjustments.md)（P4 集成验证中）。

- 无合同零星材料仍按完整流程处理：先新增真实分供方，将送货单或收据作为附件归入个人开支或具体项目，再走费用报销；报销单不等于银行支付事实，实际付款仍单独登记并人工确认。
- 详情只展示本地数据派生的检查结果，不显示参考截图里的虚构审批人、审批时间、评论或盖章。
- “已付金额”只统计真实支付记录中已确认的支付分配；草稿或待复核支付不会被当作正式已付。
- 付款申请详情目前没有直接执行审批、批复或发票登记的入口；本指南不声称这些动作可在其他页面完成，只有现行模块规格和真实入口共同支持的操作才可使用。
- 完整审批引擎和跨项目审批工作台不在本轮范围。通知事件、已读与安全导航、服务端洞察可用性仍按公共能力任务复核，未通过前不得把本地检查卡片当作该链已完成。
- 本轮优先完善前台交互与数据处理；正式数据持久化、备份恢复和部署属于后置上线关口。已有页面能保存、刷新或显示结果，不等于已通过生产可用验收。
