# 完整工资工作簿与按月归档

本指南对应 [#479](https://github.com/zodea/crm-new/issues/479) 的浏览器中央验证版本。验收结果见[实际页面与文件记录](../design/evidence/issue-479-complete-workbook/README.md)；生产持久化另由 #467 承接。

## 选择工资与实名版本

1. 在工资台账选择正式资料和项目，点击“完整工作簿”，进入独立页面。它读取该项目的已发工资，不受台账当前月份或分页限制。
2. “负责人全周期一册”须明确选择负责人请款簿；同名不同人、普通施工簿、管理费簿和不同格式按稳定身份区分。“项目按月归档”包含项目内所选范围的各月已发工资。
3. 需要完整实名附件时，选择“名册归档版本”。列表只显示同项目且原工资集合完全相同的版本。没有合适版本时，点击“为当前工资范围准备实名名册版本”，核对成员、资料和登记日期，保存后返回原范围。
4. 点击“核对当前范围与固定版本”，检查原工资身份、正式编号、格式、月份、名册版本和缺口。未正式出具的工资可通过行内“核对正式出具”进入[正式编号页面](./payroll-official-numbering.md)，完成后返回并重新核对。

名册属于独立日期资料补充版本，不能证明这些照片在原工资发放时已经保存。负责人、零分配成员和后来离职或转组的成员仍按原工资固定身份保留。资料缺失要在名册维护页补充并另建版本，不能修改旧归档。

## 保存目录后再下载

预览核对无误后点击“保存当前目录版本”。保存的是本次选择的原工资、正式编号、实名版本引用，以及**保存时点**的实际收付。提示“工资目录已保存；文件尚未下载”后，再选择文件：

| 下载项 | 包含内容 |
| --- | --- |
| 工资 XLSX | 负责人全周期一册；目录、对账、收付、缺口和各张冻结原表，不含私密名册和照片 |
| 工资 ZIP（不含实名附件） | 保存目录与工资文件；按月模式实际按 `YYYY-MM/` 分目录 |
| 工资、名册与照片 ZIP | 工资原表、独立名册、两类照片原件、照片路径与摘要；需要单独工人私密资料权限 |

普通工资读写权限不会自动获得完整身份证、银行资料或照片权限。缺权限时仍可查看公开工资目录和下载工资文件；这些文件明确注明未包含实名附件。即使有私密权限，缺照片正文或其他资料仍会列出缺口，不能把“保存成功”当作附件齐全。

下载后打开 `00-保存目录.json` 与各册“目录”“保存目录”“交付缺口”，核对版本和原工资身份。完整包另有 `01-实名名册.xlsx`、名册说明及私密附件目录；照片采用安全的相对路径，工资册中的路径与 ZIP 文件一一对应。C1 保留工资和考勤，C2 保留工资和签工；A 保留冻结施工范围及适用费用、扣款页。

## 对账口径与版本变化

月度对账使用该月各原单的本次核算；周期对账中 A 使用最新合法累计应付，不重复累加每月累计。例如累计应付 1000→1600、实际 800/700，周期为 1600/1500/差额100；次月为本次核算800/实际700/差额100。缺资料与真实零分别保留，不能确定的金额不填零。缺照片不会抹掉已有工资公式。

旧目录保存之后新登记的退款、补发或资料版本，只会进入重新核对后保存的新目录。打开“已存版本”可以重新下载原时点资料；修改今天的姓名、银行资料、照片或施工量价不会改写原版本。重复下载不占新正式号，也不会自动重新归档名册。

## 中断与受控迁入

保存响应丢失时，页面保留“核对原保存结果”。刷新后继续核对原提交，不重复创建目录。服务已保存但读取失败，也不等于保存失败；先恢复结果再操作。

每次下载重新检查权限、固定名册关系和照片正文摘要。下载中撤权、原件摘要不符或文件生成失败会停止输出；修复读取条件后从已存版本重试，不需要重发工资。

受控迁入后的旧目录保留原始摘要，并将本代稳定身份明确映射。文件中的迁入说明会区分“原始归档摘要”和“本代映射 JSON”；不能拿原始摘要直接校验映射后的 JSON。迁入与危险恢复的权限、预检和整批保护沿[本地数据迁移指南](./local-data-migration.md)执行。
