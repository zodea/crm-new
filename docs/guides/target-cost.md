## 一、当前范围

目标成本预算已接同一个本机磁盘库，版本头、科目、基线、附件、原命令与审计同事务保存。当前在独立合成数据的隔离验证用途核对；整机发布和正式业务首次写入仍受既有备份、恢复与上线门禁约束。

目标成本分为版本头、科目明细和实际成本对比。版本头保存预算名称、项目、当前基线、金额基准及附件；科目明细在版本详情维护；实际成本来自已经发生且符合状态要求的源单。三部分分别读取和保存。

开发验证实例与本机磁盘来源分别核对。正式配置缺失、数据库损坏或版本不兼容时停止读写，不能借开发实例或旧浏览器库保存。预算版本不要求项目已经建立工程量；工程量、排程和完整工资仍按各自真实依赖接续。

## 二、查找预算版本

1. 打开“项目信息 → 目标成本”。
2. 输入版本关键词，或按项目、当前基线与状态筛选。页数和记录总数应对应同一筛选范围。
3. 点击版本名称进入详情；点击编辑进入该版本的整页表单。
4. 没有筛选结果时清除条件；确实没有版本时再新建。无法读取时使用重试，不把读取失败解释为记录已被删除。

同名版本须核对所属项目和版本身份。尚未关联项目的草稿会明确显示“未关联项目”，不会按名称自动归入另一个项目。

## 三、新建草稿与完善版本头

1. 新建目标成本，填写当前已有资料。
2. 项目或金额尚未确定时保存草稿，未填金额保持空值。确定为零时明确输入 `0`。
3. 完善版本时选择真实项目，填写版本名及必需金额。提交失败后，编辑控件恢复可用并定位到首个错误字段；按提示就地修正，已有输入应保留。
4. 分别填写合同收入、计划利润、已签合同额、含税合价、无税合价和税额。税价之间有差异时先核对来源；系统不自动覆盖人工确认值。
5. 按需要选择“当前对比基线”，再保存版本头。

版本头的“已签合同额”是本版本录入值。它不代表系统已经汇总了全部正式合同，不能直接当作成本来源完整性的证明。

保存版本头不会替代科目明细保存；在详情修改明细也不会自动把草稿版本提交。

## 四、维护科目明细

1. 打开目标版本详情，进入“科目明细”并开始编辑。
2. 选择专业分包、合同劳务、材料、机械、工人工资、费用报销或其他科目。
3. 填写分项名称和目标金额；单位可空，数量与单价可空，填写时须为非负数。
4. 在同一份草稿内新增、修改、调整顺序或移除行，然后保存整份明细。
5. 有错误时检查被标记的行与单元格，修正后再次保存。不要先离开页面再处理错误。
6. 保存成功后刷新详情，核对行序、金额、空值及仍应保留的历史行。

目标金额是独立确认值，不会被“数量 × 单价”强制改写。旧资料中只有科目、没有分项名称的合法历史会原样显示；主动编辑时再按当前规则补齐，不会为迁入自动编造名称。

离开未保存的明细或放弃编辑时会确认。选择取消应回到原稿；切换到另一个已打开的页签应保留本页输入。

## 五、切换基线、删除与恢复

同项目至多一个活跃版本为当前对比基线。保存新基线时，旧基线和新基线一起更新；如果期间另一人已经更改，先核对最新结果再决定，不重复覆盖。

草稿即使标记为当前基线，也不进入正式成本控制。查看历史版本时读取该版本自己的科目，不会换成当前基线的科目。

删除采用保留历史的方式。删除当前基线后允许项目暂时没有基线，不会自动挑选一条历史版本替代。恢复原基线若与后来设定的基线冲突，应先核对现有版本，不能同时恢复出两条基线。

## 六、预算与实际成本怎样核对

| 页面信息 | 应怎样理解 |
| --- | --- |
| 科目明细合计 | 当前版本已经保存的目标金额之和 |
| 含税预算基准 | 当前版本头的人工金额基准 |
| 动态成本 | 符合状态条件的真实成本来源汇总，不由预算倒推 |
| 累计支付 | 已发生的支付事实，与成本分别呈现 |
| 未记录或未接齐来源 | 数据不足，不能按零解释 |
| 明确零 | 已知且确认为零，与空值不同 |

成本来源未接齐、无权读取或缺少明确关系时，只能查看已知部分和缺口说明。剩余预算、偏差及汇总不能把缺失成本按零扣减；比率的分母为零或未知时不可计算。

存在可核验源单时从来源入口下钻，再返回原项目或版本。入口不可用时先阅读原因，不按同名记录手工猜接。完整工资、材料及财务成本链仍按 #412 与相关模块逐项接续验收。

工资成本和工资已付只采用已接管的原实际发放、补退及有效错记冲销净额；只确认核算差额时金额不变。未接齐的工资来源保持缺口，不以旧已发工资头补齐。可访问的原来源入口保留项目和预算版本。操作和分次处理例子见[工资更正与实际收付](./payroll-adjustments.md)。

## 七、保存与读取附件

在版本头的附件区选择真实文件，核对所属预算版本后保存。文件正文与附件关系应一并保存；保存失败时不会把半个附件关系算作成功。

旧资料只有文件名或本机路径、没有原件时，会明确显示原件缺失。可通过既有附件入口补传真实文件并移除旧缺失条目；系统不会扫描旧电脑路径或借用另一份同名文件。读取或下载时仍核对当前权限和所属版本。

## 八、并开页面、冲突与结果待确认

| 遇到的情况 | 处理方式 |
| --- | --- |
| 同时打开 A、B 两个版本 | 核对当前名称与项目，各自保存各自草稿 |
| 关闭、返回或刷新时提示未保存 | 继续编辑就取消；确需离开才确认放弃 |
| 提示记录已发生变化 | 保留输入，明确重新读取和核对，不直接覆盖 |
| 浏览器提示无法登记原编号、尚未发送 | 保留当前草稿与附件，恢复浏览器存储后重试；此时尚未向后台发送 |
| 提交后没有收到确定结果 | 核对原编号的可靠结果，不用修改后的输入重新发送 |
| 已保存但详情读取失败 | 只重试授权读取原版本；不重新保存或重复新增 |
| 旧页面的响应晚到 | 回到原版本核对；另一版本的输入不应被改变 |

普通列表刷新不会提升已经打开表单的保存依据；来源发生变化仍须由经办人显式核对。正文和附件只在页面内存保留，浏览器持久化只登记原编号、身份、动作与目标。刷新后核对已应用的原结果，或明确封存未应用编号，再按当前资料编辑；不承诺刷新还原未保存正文。两个新建预算按独立草稿身份隔离原编号。

## 九、接管旧预算

打开“设置 → 数据迁移”中的“目标成本预算接管”，选择完整 SQLite 原库。预检后逐个明确原项目对应的正式项目；原库保存了外部文件路径但缺正文时，逐件补传真实原件，不能用文件名或路径代替。没有项目的草稿无需造项目，仍完整接管。共同边界见[本地数据迁移指南](./local-data-migration.md)。

每个预算版本与所属科目、附件、顺序、空值、软删除历史及审计一起核对；稳定旧 ID、预算原 JSON 和未知扩展保留，BLOB 与超安全整数扩展保留原类型及精确值。完整 SQLite 仅用作只读核验输入，请在原位置保留原库文件；正式库只保存预算领域原图、来源摘要、版本、显式映射和共享原件 BLOB，其他私密领域不会随预算复制。已知零与未填写分开，合法历史空分项名或空附件大小不会被新建表单规则自动补造。

重复当前基线、项目关系歧义或缺少必要身份时先处理预检报告，不按名称或更新时间猜选。原件缺失作为资料缺口保留，不编造正文。

确认后从普通目标成本列表与详情冷刷新核对；再次确认同一原库不会覆盖后来日常更正。恢复本批预算先整批核验后来事实与审计，有日常命令、更正或依赖时拒绝整批恢复；符合条件时退役本批采用范围，唯一原件 BLOB、预算原图、历史与回执仍保留，完整原库文件继续由用户在原位置保留。恢复不撤其他正式项目、预算或财务事实。
