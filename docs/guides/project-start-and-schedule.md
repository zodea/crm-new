## 一、从新项目到日常维护

本指南明确区分当前已经完成且可操作的流程与已定稿待开发能力。项目列表现已读取中央后台权威数据，正式来源默认无测试样本；项目名称会通过统一目标注册表进入来源感知的只读详情，正式项目新增、编辑和 Excel 导入已接中央命令，删除仍不在当前中央写入范围。真实存量核心身份可通过迁移工作台确认切换，具体步骤见《本地核心身份数据迁移使用指南》。

## 二、新建、打开和切换项目

### 新建和维护项目（当前已可用）

1. 进入“项目信息 → 项目列表”，点击工具栏或空状态中的“新增项目”。
2. 填写项目名称和项目经理；客户身份迁移完成前，可先点“保存草稿”建立正式项目草稿。“保存”和“保存并提交”仍要求客户、项目名称和项目经理齐全。
3. 中央后台成功后会分配项目 ID 并进入项目详情；刷新详情或返回列表仍可看到该项目。
4. 要维护正式项目，在列表行或项目详情点“编辑”；测试数据没有正式编辑入口。
5. 若项目在表单打开后已被其他操作更新，保存会停止并显示冲突。选“保留我的内容”后检查差异并再次保存，或选“改用服务器最新版”放弃本地修改。
6. 若中央后台不可达，页面会明确提示“仅保留本地草稿，未正式保存”。重新打开同一表单可恢复输入；必须等服务恢复后再次显式保存，不要把这份本地草稿当作已建立的项目或关联到其他单据。

项目 Excel 导入已可按“选文件 → Sheet 与字段映射 → 人工预览 → 中央保存”操作，拒绝行保留原因，重试不会重复成功记录，详见[项目 Excel 导入指南](./project-excel-import.md)。删除仍未接中央命令；不要通过旧本地路由绕过。

### 打开或切换项目

- 首次进入项目列表时，“包含测试数据”默认关闭，只读取正式数据。正式工作区没有记录时会显示真实空态，不会自动用演示项目填充。
- 需要查看演示流程时，点击应用顶栏的“测试数据”，阅读“切换会重新加载应用”的提示，先保存其他页签内容再确认。后台会先核验测试数据查看权限，再重载到只读演示快照；按钮变为“已包含测试数据”，项目演示行持续显示来源标识，底部把正式与测试项目数、收入和预算分开汇总，其他尚未接中央后台的业务页、搜索候选、最近选择与通知样本也只在此模式显示。
- 再次点击“已包含测试数据”即可关闭。该偏好保存在当前浏览器工作区；清理环境或未来切换账号/工作区后回到关闭状态。
- 测试数据只读：项目列表的编辑/删除保持禁用，演示详情没有正式编辑入口；删除或伪造详情 URL 的来源参数不能绕过后台校验，直接进入演示表单或调用本地写接缝也会被拦截。修改演示数据需使用后续独立演示工作区能力。
- 在项目列表点击项目名称打开项目。系统按中央返回的项目 ID 和数据来源生成详情地址；打开后刷新浏览器仍会加载同一条记录，不依赖原列表继续停留在内存中。
- 如果手工修改地址导致项目 ID 与数据来源不一致，页面会显示“项目身份与来源不匹配”；该来源下没有此项目时显示“项目不存在或当前来源不可见”。系统不会按同名项目回退，也不会打开空白新建页。请使用“返回项目列表”重新选择。
- 项目列表可用左侧业务阶段筛选，再用搜索框按项目、客户或负责人缩小结果。
- 表头阶段、计划竣工、项目经理和客户筛选会作用于全部项目，分页、汇总与导出保持同一范围；导出不会只取当前页。
- 刷新失败时，列表会保留上一版数据并显示“重新加载”；点击重试不会清除当前搜索和筛选。
- 金额显示“—”表示来源未知，与真实的“¥0.00”不同；客户关系显示“无权限”时不会泄露客户名称。
- 在首页项目选择器输入项目名称或编码搜索，再选择项目。
- 首页只展示“全部项目”搜索结果，不再维护重复的“最近使用”分组。

### 从项目核对材料采购合同与分供方事实（当前已可用）

1. 从带有搜索、阶段、分页等条件的项目列表进入项目详情。
2. 点击“查看材料采购合同（数量）”。系统使用项目稳定 ID 与数据来源筛选材采合同，不按名称拼接关系。
3. 数量为 `0` 时入口仍可进入真实空列表；“未登记”“暂不可用”或“无权限”会显示各自状态，不会用 `0` 代替。
4. 在材采列表继续搜索或筛选，点击合同名称进入中央详情；可切换七个合同页签。
5. 从合同详情打开分供方的合同、结算、收票或付款事实，系统直接定位对应页签；刷新后仍保留当前事实页签。
6. 点击返回时依次恢复原合同页签、材采列表搜索/筛选/分页/滚动与行焦点、项目详情，最后恢复项目列表条件与项目焦点。

异常、外部或跨来源返回地址会被拒绝并回到规范列表；不要手工修改地址中的项目 ID、合同 ID 或 `origin`。

### 查看阶段资料与导出项目档案包（已定稿待开发）

当前项目详情已提供中央来源的基础只读信息与材料采购合同关系入口；阶段时间线、项目文件柜和“导出档案包”尚未接入这个权威详情。以下是已定稿待开发流程，当前版本不要按这些步骤操作。

需要交接、归档或离线留存时：

1. 在项目详情顶部点击“导出档案包”。
2. 在选择器中按目录勾选本次范围；默认只勾选有原件的核心资料，`99_待归类` 作为历史杂项目录保留。
3. 证照资料可以在目录中查看；当前 ZIP 不包含证照原件，原件导出下载权限后续另行配置。
4. 保存 ZIP 后，先查看 `01_项目信息与工程档案/00_档案说明与清单/文件清单.xlsx`，核对“本次选择”“导出状态”和“缺失原因”。

归档包按真实项目、阶段任务、甲供材、乙供材、班组和工人关系组织目录，不按文件名推断业务归属。甲供材当前没有独立真实供货单位实体，暂使用 `甲供材供货单位待配置` 目录名，不使用 `developer` 或客户关系代替供货单位；后续可接入真实供货单位或自定义名称。`99_待归类` 暂时保留，名称自定义能力后续再配置。没有保存原件正文的记录仍会写入清单，但不会伪造或导出空文件；同名文件会在包内稳定加序号，重复导出时目录顺序保持一致。

## 三、施工合同和工程量清单（可选）

1. 进入“主合同管理 → 施工合同”并新增合同。
2. 选择所属项目，填写合同资料并保存。
3. 上传合同工程量清单。
4. 在“清单拆表”完成识别、人工确认和归类。

空白拆表页在没有上传文件、没有识别结果时显示 **0%**；只有实际开始识别后才进入处理中状态。

清单行中的楼栋范围会用于后续建立楼栋分组。合同尚未建立时，可在“工程量管理 → 项目区域”直接维护楼栋、楼层和户，再维护户型暂估量，并在建组时选择“内部暂估”；不需要为了排程先补一份虚拟合同。

## 四、施工区域、户型模板与三量录入

1. 进入“分包及人工 → 工程量管理”。
2. 选择项目后点击“项目区域”，进入独立整页配置。
3. 依次新增楼栋、楼层和户；同级编码不能重复。
4. 若当前项目还没有户型模板，点击“新建户型模板”，保存后点击“返回区域配置”；若这次配置源于新建排程，系统会保留返回来源，之后仍可回到原排程草稿。
5. 给户选择本项目户型模板后保存；跨项目户型不能挂靠。
6. 返回工程量矩阵继续责任配置，或点击“新建楼栋分组”进入排程。
7. 需要维护三量时点击“户型模板”，维护房间、分项和三种数量后保存。

项目区域不依赖施工合同；工程量矩阵归档后区域结构会锁定，需要先解除归档再调整。

| 数量 | 用途 |
| --- | --- |
| 合同量 | 施工前默认展示，用于合同收支和数量误差对比 |
| 暂估量 | 内部排程与量差核对的独立依据，不能替代已完成施工事实 |
| 现场复核量 | 保存现场算式及结果；A 类工资按已完成施工事实取现场量，中央工资链另行接通 |

三种数量独立保存，不互相覆盖。现场复核量平时显示结果，点击单元格才显示算式；算式无效时不会保存。工资取数与排程分开：新 A 类工资的已定规则仅使用已完成施工事实及现场量，不能用合同量或暂估量代替。中央工资链仍由 #412 实施，旧兼容表单不作为这条定稿流程的完成证据。

在班组或工人主数据中可预先配置“可承接工种”和“可承接分项”。后续责任配置会按这些能力筛选并校验候选人，减少重复选择。

工程量矩阵中点击单元格“详情”，会进入独立户施工详情页；内容较多时不再挤在矩阵下方。

需要核对合同量与施工数量时，点击矩阵工具栏“量差总表”：

1. 选择合同量、暂估量或现场量作为对比口径，并按楼栋、分部、工种或分项缩小范围。
2. 查看合同量、所选量、量差、合同单价和量差金额；合同量会包含已审批的数量变更，已审批调价采用最新合同单价。没有明确楼栋归属的变更只在“待分摊签证”中计一次，不会按户重复放大。
3. 签证只调整合同量，因此“待分摊签证”行在暂估量或现场量口径下显示为缺数量，不计入合计；只有选合同量时它的量差为 0。看到这一行就说明该签证量还没有落到户型模板的暂估量或现场复核量里。
4. “缺数量”“缺单价”或“多价格”会直接显示；缺值行不会自动改用另一种数量，也不会计入可计算金额合计。
5. 量差金额使用甲方合同单价，不使用班组工资单价，也不直接产生工资。

## 五、楼栋分组和标准工序

### 建立楼栋分组

正式项目的建组、排程读取和后续调整使用同一中央记录。中央空项目显示未建计划；没有标准工序库时，先维护可用版本，系统不会自动加入演示排程。首页入口保持只读，以下操作从菜单中的独立“施工进度”工作区进入。

1. 进入“项目信息 → 施工进度”。
2. 搜索并选择项目。
3. 点击“新建楼栋分组”。
4. 选择范围依据：
   - 有合同清单时选“合同清单”，再选择施工合同和清单内楼栋。
   - 合同未签时选“内部暂估”，直接选择项目楼栋；逐栋核对户数、有效分项、已知暂估量和缺失项。平方米与米分别汇总，数据只读取该楼栋下户型模板的暂估事实。
   - 项目还没有楼栋区域时，点击“配置楼栋、楼层与户”进入楼栋、楼层、户配置；系统暂存当前项目、范围依据、名称、日期、楼栋和工序草稿。期间可以继续新建户型模板，补齐后按“返回区域配置 → 返回新建排程”回到原草稿；若加载暂时失败，草稿会保留供重试，已失效的楼栋会提示并从范围中移除。
5. 填写分组名称、计划开始日期和工序搭接方式。
6. 选择标准工序库。在甘特拖动整条调整锚点，拖右边缘调整工期；下方表格用于精确录入。
7. 点某道工序的前置设置，只从日期更早的工序中选择；核对 FS 前置关系和计划日期。
8. 进入确认步骤，核对项目、楼栋范围、范围依据、工序数、计划周期，以及内部暂估的户数、分项数和数量汇总。
9. 点击“生成排程”。如果生成失败，页面会保留确认步骤和输入并显示原因；处理后沿原页面重试。若传输中断、暂时无法确认保存结果，先核对原提交，不要另建一份相同计划。

建组界面按“确定范围 → 调整标准工序与日期 → 生成排程”三段完成。现有 22 道精装修工序是历史/演示参考，正式工序库空时不会自动填入；建组时会冻结工序库名称、版本和每道工序快照，以后标准库变化不会追溯改写既有项目计划。

每栋都须具有可用楼层、户、模板、有效分项和启用工序映射；一栋有数据不能掩盖另一栋缺源。数量缺失与范围无效分别提示：两户为 `8 / 未填写` 时保留已知的 8 和一户缺失，真实的 `0` 仍为 0，不把缺失补零。能否建组依据有效范围与映射判断，不按不同单位的数量相加判断。暂估量不会用合同量或现场复核量自动替代。

建组后持续标明“内部暂估/待绑定”。楼层计划保留创建时的分项、数量与来源；后来修改模板不改写这份暂估快照。后补合同时仍需单独核对数量差异。

### 维护标准工序库（当前已可用）

本节使用中央工序库的不可变版本。当前可用范围限定本地浏览器验证环境，工序库候选和楼栋分组使用同一来源。

1. 在施工进度点击“标准工序库”；也可从建组第二步进入。
2. 新体系点“新建空白工序库”；点击既有版本查看只读明细，再点“基于此版本新建”。任意可见旧版都可作为来源，库编码保持原值。
3. 维护显示名称、工种、默认工期、阶段/分项映射；工序编码是内部稳定标识，不在版本中改名。
4. 甘特用于调整顺序和工期，表格用于精确数字；两处修改实时使用同一份草稿。
5. 点“设置前置工序”后，只会看到计划日期更早的候选。
6. 调整造成前置错序时会列出受影响的“前置工序 → 后续工序”：取消不改变草稿；确认后关系置灰且仍保留。把顺序修复后可重新启用。
7. 点击“保存为新版本”，成功后进入新版本只读详情。刷新再打开旧版本，旧版仍保持原样；已经生成的项目快照也不被改写。

同编码版本按当前最高编号递增，已删除编号不重复使用。例如历史 v2 已删除，从可见 v1 新建时仍产生 v3。版本使用情况来自当前中央 WBS；建组、迁入或合法移除后重新读取，使用项目和数量随事实更新。来源不可读时显示未知，不当作没有项目使用。

保存失败会保留当前草稿。若提示同编码已有新版本，点击“重新核对当前版本系列”：取消仍保留原稿；确认只更新当前版本基准，核对后需要再次点击保存，不会自动提交。传输中断、无法确定是否已保存时，沿原表单重试，让系统核对原提交结果，不必再新建一份表单。

切换已打开页签会保留工序草稿，切回可继续；关闭或取消有修改的表单时先确认。保存成功或明确放弃后，旧表单关闭，不再恢复已经结束的草稿。从建组第二步进入时，沿“返回新建楼栋分组”回到原建组页，继续核对原步骤、组名和工期；返回后仍需显式确认生成排程。

### 内部暂估排程后补合同（当前已可用）

本流程使用同一中央 WBS 和施工合同来源；本轮实际完成范围见 [#445 验证记录](../design/evidence/issue-445/README.md)。从菜单进入独立施工进度工作区操作，首页来源页保持只读。

1. 在施工进度中找到“待绑定合同”的楼栋分组，点击“绑定”。
2. 按合同名称或编号搜索同项目施工合同；选中只生成预览，不会直接保存。
3. 核对逐栋覆盖、合同额外楼栋、稳定分项映射、冻结暂估量和当前合同量。平方米和米分别比较；合同额外楼栋不会自动并入分组。
4. 未覆盖楼栋或未映射分项会阻止绑定。缺楼栋证据时点击“补齐合同楼栋证据”，在独立页面选择清单行、同项目实际楼栋并填写更正理由；点击“保存楼栋证据”后返回原分组重新预览。只有已确认导入的基准行允许更正；签证新增或来源待核行会说明只读原因。
5. 不准备更正时点击“取消并返回绑定”，原合同选择保留，没有写入。不能靠隐式移除楼栋或新造拆分分组绕过覆盖阻断。
6. 无阻断时点击“确认绑定合同”，阅读最终确认后提交。取消确认仍保留合同选择，不改变排程。
7. 成功后回到同一施工进度，重新打开或刷新绑定依据，核对已绑定合同与绑定时保存的差异。已有绑定只读，不提供重复绑定、解绑或换绑。

两户冻结量为 `8 / 未填写` 时显示已知 8 和缺 1 项，差值为“不可确定”；真实 `0` 仍是确定值。只有同分项、同单位且双方来源完整时才计算差值。非零差异供人工核对，不要求差异为零，也不会用合同量覆盖暂估量。

预览后清单或分组发生变化，确认会停止；合同选择保留，点击“重新核对资料”后再次核对，系统不会自动提交。若传输中断、结果暂不能确定，沿页面恢复入口核对原提交，不另建一份相同绑定。切换项目或分组后，旧请求的迟到结果不会打开新页面的确认框或改变新目标。

在绑定依据的数量表点击“查看清单来源”，可查看该行原始与生效量价，再沿“绑定时的原楼层计划”进入相应楼层并返回来源页。路径按保存的身份关系定位；旧绑定缺少比较明细时只展示已有事实，不用当前模板补造旧楼层关系。

绑定不重建原分组，不改写工序、楼层人工微调、基线、完成事实或冻结暂估量，也不重新生成工资和报量。后续模板修改不改变原暂估快照，分项或清单软删除不隐藏排程自己保存的楼层计划。旧历史没有记录单位或逐户来源时会明确说明历史不足。

## 六、查看排程和维护实际进度

首页和独立施工进度工作区读取同一项目、分组、工序和当前阶段进度。读取失败、无权限、身份不匹配与真正没有计划分别提示，不改用其他项目或旧本地排程。工程量完成录入步骤见[工程量区域、模板与完成指南](./quantity-central-workflow.md)。

- 首页施工进度与施工进度工作台使用同一份排程数据和同一套时间轴规则。
- 首页用于快速查看计划、实际完成和偏差。
- 首页“打开施工进度”仍是当前项目的只读来源页；要维护计划，从菜单进入独立施工进度工作区。
- 拖动工序条可整体调整计划日期；拖动右边缘可调整工期。快速拖动时以鼠标松开位置为最终日期。
- 调期与前置工序冲突时，先列出受影响关系。取消不保存；确认继续后只把冲突依赖置灰并保留原因、时间及记录。修复日期后可恢复，仍须满足同组、无循环且后续工序没有其他活跃前置。主动移除的依赖保留记录，但不会混入冲突恢复列表。
- 修改某一楼层的计划时，仅该层成为人工微调；之后整体调期，其余自动楼层重新排布，人工楼层保持。设置基线、添加或移除工序后，刷新核对同一工序身份与保存结果。

- 有工程量来源的工序：点击“查看工程量”，进入矩阵定位阶段，在独立户施工详情页登记完成日期和验收信息；系统只统计本组楼栋及当前阶段适用范围内的已完成户与应做户。配置负责人不算完成，不同阶段即使关联同一分项也分别统计。
- 实际开始取当前阶段最早完成日；全部应做户完成后才显示实际完成日。更正完成记录后，重新读取即可看到当前结果；不会改写已发工资或已生成报量的历史快照。
- 没有工程量来源的工序：在工序详情中手工维护 0～100 的实际完成率；不会提供没有真实来源的完成下钻。
- 从矩阵进入户详情，再沿返回入口回到原工序时，保留有效的项目、来源、分组、任务、阶段、楼栋、月份、视图、工种和责任户条件。失效或错配的范围会提示，不能按名称替换成另一个对象。

保存时来源已经变化，会保留输入并要求重新核对。暂时不知道是否保存成功时，沿页面恢复入口核对原提交；切换项目后，旧请求不会把结果写到新项目。已有排程的受控迁入保留基线、手工进度、楼层微调、依赖禁用记录和已有合同绑定历史，迁移前须完成预检与备份，步骤见[本地数据迁移指南](./local-data-migration.md)。

### 目标成本版本与科目明细

当前浏览器验证实例已接通预算列表、整页版本头、七类科目明细、唯一基线、附件及删除恢复。进入“项目信息 → 目标成本”，先打开目标版本，再分别维护版本头和科目；二者是两个明确保存动作。未确定的金额保持空值，明确零按零保存；历史版本读取自己的明细。

并开页签、放弃确认、版本冲突与原提交恢复的步骤见[目标成本预算指南](./target-cost.md)。旧预算及原件按[本地迁移指南](./local-data-migration.md)受控接管。

成本对比已读取有明确关系的中央合同和结算来源，并保留来源入口及返回位置。完整工资、材料和财务成本来源仍由 [#412](https://github.com/zodea/crm-new/issues/412) 及相关模块接续；来源未接齐时明确显示缺口，不能将未知按零计算项目余额。当前验证不代表生产持久化或部署完成。

## 七、送货单逻辑归档与打印

当前流程的状态含义：

- 在“送货单归档库”点击“新增送货单”会进入独立整页表单；列表行和详情页的“编辑”进入同一套整页表单，编辑时保留原件和 OCR 留痕供对照。
- **已归档**：物理原件与人工核对后的逻辑送货记录已保存，可回读原件、材料行和修订历史。归档不等于有效到货、库存入库或可结算；这些物资流程由 #411/#409 后续接通。
- **待打印**：新归档单默认进入待打印队列；刷新页面后仍会保留。
- **已打印**：先点“打开打印”；打印机实际输出后，再回到队列单独点“登记已打印”。仅打开原件或调起系统打印框不会自动算作已打印。
- **不打印**：明确排除后不再出现在待打印范围，仍保留归档记录。

系统打印弹窗属于操作系统能力，网页无法可靠区分用户最终点击了“打印”还是“取消”，因此把“打开打印”和“登记已打印”拆成两个独立动作。未登记的单据不会消失；一个上传文件识别出多张送货单时，刷新后仍作为一个打印任务。
