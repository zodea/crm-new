## 一、从新项目到日常维护

本指南明确区分当前已经完成且可操作的流程与已定稿待开发能力。项目列表现已读取中央后台权威数据，正式来源默认无测试样本；项目名称会通过统一目标注册表进入来源感知的只读详情，正式项目新增和编辑已接中央命令，导入与删除仍不可用。真实存量核心身份可通过迁移工作台确认切换，具体步骤见《本地核心身份数据迁移使用指南》。

## 二、新建、打开和切换项目

### 新建和维护项目（当前已可用）

1. 进入“项目信息 → 项目列表”，点击工具栏或空状态中的“新增项目”。
2. 填写项目名称和项目经理；客户身份迁移完成前，可先点“保存草稿”建立正式项目草稿。“保存”和“保存并提交”仍要求客户、项目名称和项目经理齐全。
3. 中央后台成功后会分配项目 ID 并进入项目详情；刷新详情或返回列表仍可看到该项目。
4. 要维护正式项目，在列表行或项目详情点“编辑”；测试数据没有正式编辑入口。
5. 若项目在表单打开后已被其他操作更新，保存会停止并显示冲突。选“保留我的内容”后检查差异并再次保存，或选“改用服务器最新版”放弃本地修改。
6. 若中央后台不可达，页面会明确提示“仅保留本地草稿，未正式保存”。重新打开同一表单可恢复输入；必须等服务恢复后再次显式保存，不要把这份本地草稿当作已建立的项目或关联到其他单据。

“导入项目”和“删除项目”仍不在当前中央命令范围，入口保持禁用。不要通过旧的本地直达路由绕过中央写入。

### 打开或切换项目

- 首次进入项目列表时，“包含测试数据”默认关闭，只读取正式数据。正式工作区没有记录时会显示真实空态，不会自动用演示项目填充。
- 需要查看演示流程时，点击应用顶栏的“测试数据”，阅读“切换会重新加载应用”的提示，先保存其他页签内容再确认。后台会先核验测试数据查看权限，再重载到只读演示快照；按钮变为“已包含测试数据”，项目演示行持续显示来源标识，底部把正式与测试项目数、收入和预算分开汇总，其他尚未接中央后台的业务页、搜索候选、最近选择与通知样本也只在此模式显示。
- 再次点击“已包含测试数据”即可关闭。该偏好保存在当前浏览器工作区；清理环境或未来切换账号/工作区后回到关闭状态。
- 测试数据只读：项目列表的编辑/删除保持禁用，演示详情没有正式编辑入口；删除或伪造详情 URL 的来源参数不能绕过后台校验，直接进入演示表单或调用本地写接缝也会被拦截。修改演示数据需使用后续独立演示工作区能力。
- 在项目列表点击项目名称打开项目。系统按中央返回的项目 ID 和数据来源生成详情地址；打开后刷新浏览器仍会加载同一条记录，不依赖原列表继续停留在内存中。
- 如果手工修改地址导致项目 ID 与数据来源不一致，页面会显示“项目身份与来源不匹配”；该来源下没有此项目时显示“项目不存在或当前来源不可见”。系统不会按同名项目回退，也不会打开空白新建页。请使用“返回项目列表”重新选择。
- 项目列表可用左侧业务阶段筛选，再用搜索框按项目、客户或负责人缩小结果。
- 表头阶段、计划竣工、项目经理和客户筛选会作用于全部项目，分页、汇总与导出保持同一范围；导出不会只取当前页。
- 刷新失败时，列表会保留上一版数据并显示“重新加载”；点击重试不会清除当前搜索和筛选。
- 金额显示“—”表示来源未知，与真实的“¥0.00”不同；客户关系显示“无权限”时不会泄露客户名称。
- 在首页项目选择器输入项目名称或编码搜索，再选择项目。
- 首页只展示“全部项目”搜索结果，不再维护重复的“最近使用”分组。

### 从项目核对材料采购合同与分供方事实（当前已可用）

1. 从带有搜索、阶段、分页等条件的项目列表进入项目详情。
2. 点击“查看材料采购合同（数量）”。系统使用项目稳定 ID 与数据来源筛选材采合同，不按名称拼接关系。
3. 数量为 `0` 时入口仍可进入真实空列表；“未登记”“暂不可用”或“无权限”会显示各自状态，不会用 `0` 代替。
4. 在材采列表继续搜索或筛选，点击合同名称进入中央详情；可切换七个合同页签。
5. 从合同详情打开分供方的合同、结算、收票或付款事实，系统直接定位对应页签；刷新后仍保留当前事实页签。
6. 点击返回时依次恢复原合同页签、材采列表搜索/筛选/分页/滚动与行焦点、项目详情，最后恢复项目列表条件与项目焦点。

异常、外部或跨来源返回地址会被拒绝并回到规范列表；不要手工修改地址中的项目 ID、合同 ID 或 `origin`。

### 查看阶段资料与导出项目档案包（已定稿待开发）

当前项目详情已提供中央来源的基础只读信息与材料采购合同关系入口；阶段时间线、项目文件柜和“导出档案包”尚未接入这个权威详情。以下是已定稿待开发流程，当前版本不要按这些步骤操作。

需要交接、归档或离线留存时：

1. 在项目详情顶部点击“导出档案包”。
2. 在选择器中按目录勾选本次范围；默认只勾选有原件的核心资料，`99_待归类` 作为历史杂项目录保留。
3. 证照资料可以在目录中查看；当前 ZIP 不包含证照原件，原件导出下载权限后续另行配置。
4. 保存 ZIP 后，先查看 `01_项目信息与工程档案/00_档案说明与清单/文件清单.xlsx`，核对“本次选择”“导出状态”和“缺失原因”。

归档包按真实项目、阶段任务、甲供材、乙供材、班组和工人关系组织目录，不按文件名推断业务归属。甲供材当前没有独立真实供货单位实体，暂使用 `甲供材供货单位待配置` 目录名，不使用 `developer` 或客户关系代替供货单位；后续可接入真实供货单位或自定义名称。`99_待归类` 暂时保留，名称自定义能力后续再配置。没有保存原件正文的记录仍会写入清单，但不会伪造或导出空文件；同名文件会在包内稳定加序号，重复导出时目录顺序保持一致。

## 三、施工合同和工程量清单（可选）

1. 进入“主合同管理 → 施工合同”并新增合同。
2. 选择所属项目，填写合同资料并保存。
3. 上传合同工程量清单。
4. 在“清单拆表”完成识别、人工确认和归类。

空白拆表页在没有上传文件、没有识别结果时显示 **0%**；只有实际开始识别后才进入处理中状态。

清单行中的楼栋范围会用于后续建立楼栋分组。合同尚未建立时，可在“工程量管理 → 项目区域”直接维护楼栋、楼层和户，再维护户型暂估量，并在建组时选择“内部暂估”；不需要为了排程先补一份虚拟合同。

## 四、施工区域、户型模板与三量录入

1. 进入“分包及人工 → 工程量管理”。
2. 选择项目后点击“项目区域”，进入独立整页配置。
3. 依次新增楼栋、楼层和户；同级编码不能重复。
4. 若当前项目还没有户型模板，点击“新建户型模板”，保存后点击“返回区域配置”；若这次配置源于新建排程，系统会保留返回来源，之后仍可回到原排程草稿。
5. 给户选择本项目户型模板后保存；跨项目户型不能挂靠。
6. 返回工程量矩阵继续责任配置，或点击“新建楼栋分组”进入排程。
7. 需要维护三量时点击“户型模板”，维护房间、分项和三种数量后保存。

项目区域不依赖施工合同；工程量矩阵归档后区域结构会锁定，需要先解除归档再调整。

| 数量 | 用途 |
| --- | --- |
| 合同量 | 施工前默认展示，用于合同收支和数量误差对比 |
| 暂估量 | 工资预付可选取数，通常低于或不超过合同量 |
| 现场复核量 | 最终工资结算固定取数；保存现场算式及计算结果 |

三种数量独立保存，不互相覆盖。现场复核量平时显示结果，点击单元格才显示算式；算式无效时不会保存。工资预付只取暂估量或现场复核量，不取合同量。

在班组或工人主数据中可预先配置“可承接工种”和“可承接分项”。后续责任配置会按这些能力筛选并校验候选人，减少重复选择。

工程量矩阵中点击单元格“详情”，会进入独立户施工详情页；内容较多时不再挤在矩阵下方。

需要核对合同量与施工数量时，点击矩阵工具栏“量差总表”：

1. 选择合同量、暂估量或现场量作为对比口径，并按楼栋、分部、工种或分项缩小范围。
2. 查看合同量、所选量、量差、合同单价和量差金额；合同量会包含已审批的数量变更，已审批调价采用最新合同单价。没有明确楼栋归属的变更只在“待分摊签证”中计一次，不会按户重复放大。
3. 签证只调整合同量，因此“待分摊签证”行在暂估量或现场量口径下显示为缺数量，不计入合计；只有选合同量时它的量差为 0。看到这一行就说明该签证量还没有落到户型模板的暂估量或现场复核量里。
4. “缺数量”“缺单价”或“多价格”会直接显示；缺值行不会自动改用另一种数量，也不会计入可计算金额合计。
5. 量差金额使用甲方合同单价，不使用班组工资单价。工资建单仍只能选择暂估量或现场复核量。

## 五、楼栋分组和标准工序

1. 进入“项目信息 → 施工进度”。
2. 搜索并选择项目。
3. 点击“新建楼栋分组”。
4. 选择范围依据：
   - 有合同清单时选“合同清单”，再选择施工合同和清单内楼栋。
   - 合同未签时选“内部暂估”，直接选择项目楼栋；每栋会显示户数、暂估分项数和暂估量，数据只读取该楼栋下户型模板的暂估量。
   - 项目还没有楼栋区域时，点击“配置项目区域”直接进入楼栋、楼层、户配置；系统暂存当前项目、范围依据、名称、日期、楼栋和工序草稿。期间可以继续新建户型模板，补齐后按“返回区域配置 → 返回新建排程”回到原草稿；若加载暂时失败，草稿会保留供重试，已失效的楼栋会提示并从范围中移除。
5. 填写分组名称、计划开始日期和工序搭接方式。
6. 选择标准工序库。在甘特拖动整条调整锚点，拖右边缘调整工期；下方表格用于精确录入。
7. 点某道工序的前置设置，只从日期更早的工序中选择；核对 FS 前置关系和计划日期。
8. 进入确认步骤，核对项目、楼栋范围、范围依据、工序数、计划周期，以及内部暂估的户数、分项数和数量汇总。
9. 点击“生成排程”。如果生成失败，页面会保留当前三步草稿并显示原因；处理后点击“重试生成”，不要重复新建另一份计划。

建组界面按“确定范围 → 调整标准工序与日期 → 生成排程”三段完成。当前内置一版 22 道精装修标准工序；建组时会冻结工序库名称、版本和每道工序快照，以后标准库变化不会追溯改写既有项目计划。

内部暂估楼栋如果缺少户、户型模板或有效暂估分项，会显示具体阻断原因，不能带着空数量生成。暂估量不会用合同量或现场复核量自动替代；后补合同时仍需单独核对数量差异。

### 维护标准工序库

1. 在施工进度点击“标准工序库”；也可从建组第二步进入。
2. 新体系点“新建空白工序库”；调整现有体系点“基于此版本新建”。
3. 维护显示名称、工种、默认工期、阶段/分项映射；工序编码是内部稳定标识，不在版本中改名。
4. 甘特用于调整顺序和工期，表格用于精确数字；两处修改实时使用同一份草稿。
5. 点“设置前置工序”后，只会看到计划日期更早的候选。
6. 调整造成前置错序时会先确认：取消不改变；确认后关系显示为置灰且仍保留。把顺序修复后可重新启用。
7. 保存会产生新版本。来源版本及已经生成的项目排程不会被改写。

### 内部暂估排程后补合同

1. 在施工进度中找到“待绑定合同”的楼栋分组，点击“绑定”。
2. 按合同名称或编号搜索同项目施工合同；选中只生成预览，不会直接保存。
3. 核对楼栋覆盖、合同额外楼栋、分项映射、暂估量、合同量和量差。
4. 未覆盖楼栋或未映射分项会阻止绑定；可进入合同清单补齐证据，或返回排程处理分组。
5. 无阻断时点击“确认绑定合同”，再次确认后才切换范围依据。

绑定不会重建原分组，也不会改写工序、基线、完成事实或暂估量。数量差异始终使用建组时冻结的暂估量；后续修改户型模板不会让绑定预览漂移。首页和施工进度都会持续标示尚未绑定合同的分组。

## 六、查看排程和维护实际进度

- 首页施工进度与施工进度工作台使用同一份排程数据和同一套时间轴规则。
- 首页用于快速查看计划、实际完成和偏差。
- 点击“打开施工进度”进入完整工作台，维护日期、依赖、基线和实际进度。
- 拖动工序条可整体调整计划日期；拖动右边缘可调整工期。快速拖动时以鼠标松开位置为最终日期。
- 调期与前置工序冲突时会先确认；确认继续后只把冲突依赖置灰并保留记录，不直接删除。

- 有工程量来源的工序：点击“查看工程量”，进入矩阵定位阶段，在独立户施工详情页登记完成日期和验收信息；系统按已完成户数与应做户数汇总进度。
- 没有工程量来源的工序：在工序详情中手工维护实际完成率。

### 目标成本版本与科目明细

1. 进入“项目信息 → 目标成本”。
2. 可按关键词、项目、当前基线/历史版本和状态筛选；点击版本名称进入详情。
3. 在“科目明细”查看当前版本的成本科目、分项、数量、单价和目标金额。
4. 点击“编辑科目明细”，在明细网格新增、复制、修改或删除行；成本科目和分项名称必填，数量、单价和目标金额不能为负数。
5. 点击“保存科目明细”。校验或保存失败时，当前输入会保留在页面，错误显示在对应行和字段并定位首个错误，修正后可再次保存。
6. 切换到“成本对比”，查看正式合同、已确认结算、已发工资和已确认报销形成的实际成本；这些金额只读真实源单，不会反写预算科目。

编辑科目明细后，如果通过返回列表、查看项目、编辑版本或浏览器后退离开，系统会先询问是否放弃未保存内容。版本头的项目、当前基线和金额基准仍从“编辑版本”整页表单维护。科目明细与版本头是两个明确保存动作；编辑明细不会自动提交版本头。

## 七、送货单归档、入库与打印

当前流程的状态含义：

- 在“送货单归档库”点击“新增送货单”会进入独立整页表单；列表行和详情页的“编辑”进入同一套整页表单，编辑时保留原件和 OCR 留痕供对照。
- **已归档/已入库**：送货单原件、识别结果和材料价格事实已经进入归档库及材料台账。
- **待打印**：新归档单默认进入待打印队列；刷新页面后仍会保留。
- **已打印**：先点“打开打印”；打印机实际输出后，再回到队列单独点“登记已打印”。仅打开原件或调起系统打印框不会自动算作已打印。
- **不打印**：明确排除后不再出现在待打印范围，仍保留归档记录。

系统打印弹窗属于操作系统能力，网页无法可靠区分用户最终点击了“打印”还是“取消”，因此把“打开打印”和“登记已打印”拆成两个独立动作。未登记的单据不会消失；一个上传文件识别出多张送货单时，刷新后仍作为一个打印任务。

## 八、列表与工具栏

- 分包合同页顶部只保留项目筛选、搜索、刷新和新增操作。
- 合同数量由状态页签和表格底部统一展示；顶部不重复显示数量，筛选时不挤动布局。
- 密集表格只在表格区域内横向滚动，操作列保持紧凑；列宽从表头右边界拖动，方向一致。
- 客户、班组和工人列表可按名称等关键词搜索、按最近更新或名称排序，并使用各自的业务筛选缩小范围；筛选无结果时可直接清除条件。
- 客户、班组和工人名称可直接进入独立详情页；每行右侧提供详情、编辑和删除图标。无下游数据的删除先确认，完成后可在提示消息中撤回；有关联数据时必须输入档案名称并等待安全确认，且不提供事后撤回。仍被项目或在册工人引用的档案会直接阻止删除。
- 电话、身份证号和统一社会信用代码在列表与只读详情中脱敏显示；编辑整页表单仍用于维护原始档案。
- 客户详情展示名下项目、施工合同和收款，页签可用方向键切换，并可通过带 `tab` 参数的地址直接打开指定页签。
- 班组详情展示真实成员、责任项目、工资和扣罚；工人详情分别展示档案状态与在场状态，并展示能力、责任户、考勤、签工、个人工资和项目扣罚事实。
