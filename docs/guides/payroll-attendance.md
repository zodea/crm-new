## 一、当前可以做什么

浏览器先开放工资资料的受控迁入、台账和历史详情，以及同一项目的工资配置、考勤、签工和锁定情况查看。没有工资单的项目，也可以迁入和查看已有考勤、签工及主体配置。

新建工资、改价、核对、确认发放、修改考勤或签工，以及新打印和 Excel 生成仍在后续接续范围，当前入口会说明尚未开放。历史资料能打开不代表可以重新发放。B 类已经退役，历史只读，不会转换为 A/C1/C2。

本指南对应浏览器中央验证版本，不代表已上线或服务重启后可靠保存。桌面本地模式保留原有适配，不属于本轮浏览器交付；旧版指南的本地操作步骤不能作为当前浏览器已开放的依据。

## 二、先接管已有资料

1. 从本地资料迁移入口生成保护备份，并查看预检和导入计划。
2. 核对工资所属项目。项目没有工资头，但有配置、考勤或签工时，也应出现相应接管范围。
3. 阅读历史缺口：缺少人员或分项关系、退役 B 类、缺实际金额、缺成员分配、快照损坏，以及同人同月来源冲突分别提示。
4. 身份无法确定时先按提示核对原资料，不用姓名或金额猜接。可隔离的历史保留原值供查看，不变成新的计薪来源。
5. 完成确认与对账后，从普通工资台账或来源页重新读取；刷新后应仍是同一项目、单据和来源。

详细备份、试跑、确认和恢复步骤见[本地数据迁移指南](./local-data-migration.md)。重复确认不会覆盖接管后已有更正；恢复会破坏后来的工资或来源关系时，系统拒绝整批恢复，不只退回一半资料。

## 三、查看工资台账和详情

1. 打开“分包及人工 → 工资核算”，选择项目、月份、班组和工资状态。
2. 台账按当前条件显示已接管工资。空台账表示当前范围没有记录；读取失败或没有权限会另行提示，不用演示数据补位。
3. 点击目标工资进入历史详情。项目、月份、班组和工资状态用于返回；工资身份始终由这张单据决定。
4. 已发资料先看“发放时”的金额、人员、明细、成员分配和签工。之后改名、改价或修改当前档案，不会改变这部分记录。
5. 再查看保存的原工资头、关系和历史记录。原表与快照不一致时分别保留，不自动选择一个覆盖另一个。
6. 返回台账时保留原筛选；进入考勤或签工后再返回，仍保留当前项目、月份、班组和原工资状态。

“全部班组”和空状态也是有效范围，不恢复成上次选中的值。中央项目链接失效时会说明原因，需要从有效项目重新进入，系统不会悄悄切到另一项目。

## 四、怎样理解历史缺口

| 页面情况 | 应怎样理解 |
| --- | --- |
| 实际发放为 0 | 来源明确保存了零；不同于没有记录 |
| 实际发放显示未记录 | 冻结资料没有可信实发值，不默认填零，也不从当前应发反推 |
| 原工资头有金额，发放快照缺失或损坏 | 原表金额仍可追溯；它不会被自动当成完整冻结事实。先核对原资料 |
| 成员分配缺失 | 无法确认当时分别给了谁，不默认全部给负责人。分配总额相等但漏了零成员也属于缺口 |
| 部分快照 | 原文保留，但缺字段、人员关系、签工正文或金额勾稽不完整，不能据此生成新工资输出 |
| B 类或来源身份不明 | 历史隔离记录；只读不代表有新的核算、发放或成本资格 |

例如，原工资头保存 100 元但没有发放快照时，详情可以同时显示原记录金额 100 元和冻结实发未记录。这两处说明的是不同证据，不会为了消除差异把未知补成 100 元或 0 元。

## 五、查看考勤、签工和锁定

在工资台账点击“查看工资来源”，再切换“考勤记录”或“签工记录”，沿用同一项目、月份和班组。来源查看也包含尚未建立工资单的记录，以及已有主体配置；待确认与已确认签工分别呈现。签工确认状态只筛选签工，不替换返回工资时的草稿、已核对或已发放状态。

当前阶段只查看已有记录，录入和人工确认会在对应工资类型接通后开放。考勤数量为零仍是一条真实记录，不等同于没有考勤；未确认签工不会自动变成可计薪资料。

查看来源锁时，注意负责人和全部相关成员。成员实发为零、没有工资行或没有工时，并不表示已发月份可以再录一笔；C1/C2 的月份锁和 C2 的签工占用都需核对。历史关系被软删也不能使已经发生的锁无声消失。

同人同月并存互斥来源时，系统保留双方原记录并提示核对，不自动删掉其中一种。后续核算或更正必须处理这些缺口，不能利用迁入绕过重复计薪检查。

## 六、仍在接续的完整流程

以下是已确定、但尚未全部开放的后续业务流程：

1. A 类从实际完成与现场量进入工资配置、草稿、核对及发放；不从暂估量、合同清单或合同价形成直接工资。
2. C1 从真实考勤、各人工资标准进入当月核算；C2 从人工确认的逐日签工和主体费率进入当月核算。
3. 发放时核实来源仍一致，登记真实金额及全部成员分配，冻结后再提供对应打印和 Excel 输出。
4. 已发后补差、扣回或纠错保留原单，通过独立更正和实际收付记录追溯，不能直接改原快照。
5. 房补与管理费、户级空鼓与人工扣款、批量资金建议及完整工作簿继续按已定规则实现，不因历史只读完成而取消。

工资真实成本和付款展示会在相应实际发放/更正链验收后接入。当前预算中的工资来源缺口继续保持未知，不借空工资表产生完整成本或假余额。

规则与当前边界以[工资页面蓝本](../rewrite/pages/subcontract-payroll.md)为准，具体实施状态见[模块实现状态](../design/ui-implementation-status.md)；生产保存、备份恢复和部署由独立上线关口验收。
