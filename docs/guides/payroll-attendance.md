## 一、当前可以做什么

浏览器已开放工资资料的受控迁入、台账和历史详情，以及同一项目的工资配置、考勤、签工和锁定情况查看。没有工资单的项目，也可以迁入和查看已有考勤、签工及主体配置。

A 工资已开放新建、配置、核对、确认实际发放及冻结工资表，第六节说明完整操作。C1 已接通逐日考勤、个人标准、当月核对、实际发放及配对工资与考勤表，操作见第七节。C2 已接通逐日签工、人工确认、主体配置、工资核对与实际发放，以及配对签工表和工资表，操作见第八节。历史资料能打开不代表可以重新发放。B 类已经退役，历史只读，不会转换为 A/C1/C2。

本指南对应浏览器中央验证版本，不代表已上线或服务重启后可靠保存。桌面本地模式保留原有适配，不属于本轮浏览器交付；旧版指南的本地操作步骤不能作为当前浏览器已开放的依据。

## 二、先接管已有资料

1. 从本地资料迁移入口生成保护备份，并查看预检和导入计划。
2. 核对工资所属项目。项目没有工资头，但有配置、考勤或签工时，也应出现相应接管范围。
3. 阅读历史缺口：缺少人员或分项关系、退役 B 类、缺实际金额、缺成员分配、快照损坏，以及同人同月来源冲突分别提示。
4. 身份无法确定时先按提示核对原资料，不用姓名或金额猜接。可隔离的历史保留原值供查看，不变成新的计薪来源。
5. 完成确认与对账后，从普通工资台账或来源页重新读取；刷新后应仍是同一项目、单据和来源。

详细备份、试跑、确认和恢复步骤见[本地数据迁移指南](./local-data-migration.md)。重复确认不会覆盖接管后已有更正；恢复会破坏后来的工资或来源关系时，系统拒绝整批恢复，不只退回一半资料。

## 三、查看工资台账和详情

1. 打开“分包及人工 → 工资核算”，选择项目、月份、班组和工资状态。
2. 台账按当前条件显示已接管工资。空台账表示当前范围没有记录；读取失败或没有权限会另行提示，不用演示数据补位。
3. 点击目标工资进入历史详情。项目、月份、班组和工资状态用于返回；工资身份始终由这张单据决定。
4. 已发资料先看“发放时”的金额、人员、明细、成员分配及 C2 的签工。之后改名、改价或修改当前档案，不会改变这部分记录。
5. 再查看保存的原工资头、关系和历史记录。原表与快照不一致时分别保留，不自动选择一个覆盖另一个。
6. 返回台账时保留原筛选；进入考勤或签工后再返回，仍保留当前项目、月份、班组和原工资状态。

“全部班组”和空状态也是有效范围，不恢复成上次选中的值。中央项目链接失效时会说明原因，需要从有效项目重新进入，系统不会悄悄切到另一项目。

## 四、怎样理解历史缺口

| 页面情况 | 应怎样理解 |
| --- | --- |
| 实际发放为 0 | 来源明确保存了零；不同于没有记录 |
| 实际发放显示未记录 | 冻结资料没有可信实发值，不默认填零，也不从当前应发反推 |
| 原工资头有金额，发放快照缺失或损坏 | 原表金额仍可追溯；它不会被自动当成完整冻结事实。先核对原资料 |
| 成员分配缺失 | 无法确认当时分别给了谁，不默认全部给负责人。分配总额相等但漏了零成员也属于缺口 |
| 部分快照 | 原文保留，但缺字段、人员关系、该类型适用的签工正文或金额勾稽不完整，不能据此生成新工资输出 |
| B 类或来源身份不明 | 历史隔离记录；只读不代表有新的核算、发放或成本资格 |

例如，原工资头保存 100 元但没有发放快照时，详情可以同时显示原记录金额 100 元和冻结实发未记录。这两处说明的是不同证据，不会为了消除差异把未知补成 100 元或 0 元。

## 五、查看考勤、签工和锁定

在工资台账点击“查看工资来源”，再切换“考勤记录”或“签工记录”，沿用同一项目、月份和班组。来源查看也包含尚未建立工资单的记录，以及已有主体配置；待确认与已确认签工分别呈现。签工确认状态只筛选签工，不替换返回工资时的草稿、已核对或已发放状态。

考勤入口已可登记真实工时，见第七节；签工已支持新增和人工确认，见第八节。考勤数量为零仍是一条真实记录，不等同于没有考勤；未确认签工不会自动变成可计薪资料。

查看来源锁时，注意负责人和全部相关成员。成员实发为零、没有工资行或没有工时，并不表示已发月份可以再录一笔；C1/C2 的月份锁和 C2 的签工占用都需核对。历史关系被软删也不能使已经发生的锁无声消失。

同人同月并存互斥来源时，系统保留双方原记录并提示核对，不自动删掉其中一种。后续核算或更正必须处理这些缺口，不能利用迁入绕过重复计薪检查。

## 六、A 工资从完成量到实际发放

本节适用于当前浏览器验证版本的 A 工资；从真实完成量进入，同一单据保存、核对和确认实际发放。

### 1. 建立并核对草稿

1. 在工资台账选择项目和月份，点击“新建 A 工资草稿”。从工程量进入时带入项目与月份，负责人和成员仍由经办人明确选择；返回工程量保留原筛选，不按名称补接身份。
2. 填写请款负责人、班组和完整成员，包括本次没有金额的成员。选择月度、结算或尾款；合同价与暂估量不能作为 A 工资来源。
3. 月度比例默认沿用同一请款簿上月的月度工资单，已保存但未发的单据也可作为依据；上月结算比例不会覆盖月度比例。没有上月月度记录时使用明确的首月配置。结算默认 95% 并可调整，尾款固定 100%。普通工资和独立管理费各自继承。
4. 点击“核对完成量与单价”。只有对应月份及以前真正完成、原责任范围可确认的现场量进入工资。缺量、缺单位、缺责任或缺价会逐项说明；零数量是实际记录，不能把缺项当零。
5. 可沿来源进入原户、工人或班组查看，再返回同一草稿。页面切换保留输入，回来后重新核对发生变化的来源。
6. 保存工资草稿后进入同一单据详情，继续核对和发放。关闭或取消尚未保存的草稿时，按提示处理未保存内容。

### 2. 补齐工资配置

在草稿或未发详情点击“工资配置”，进入独立页面。先核对项目、月份、班组和负责人，再分别保存首月比例与工资单价。

工资基准价适用于当前负责人的指定分项与范围；个人例外保留单独工人的调整。明确生效月份和适用范围，填写真实单价；未配置和明确零价分别处理。修改现有价格使用“修订单价”，不要重复新增重叠范围。

首月比例与单价分别保存；一处保存不会默默覆盖另一处未保存输入。返回原工资后重新读取、核对来源。已经发放的月份和冻结工资不会随后来改价而重写。

### 3. 核对并登记真实收款

在工资详情点击“重新核对工资”，检查现场工资、按比例累计应付、此前实际已付和本次应发。此前少发只按真实发放计入，不按上次应发或成员分配重复扣减。

例如，当前累计应付 1280 元，此前实际发了 900 元，本次应发为 380 元；即使上次应发是 1000 元，也不能改扣 1000 元。

点击“确认实际发放”，填写实际总额和全体成员收款分配。默认可全部给负责人，其他成员明确保留 0；分配合计须等于实际总额，金额精确到分。实际总额不能超过当前本次应发，尚未发出的钱不能提前登记成实际支付。

确认时系统再次核对来源和此前实际已付。其他人已经发放、现场量或价格变化时，本单保存为“需重新核对”，保留填写内容；重新核对后再确认，不能重复使用旧的确认结果。

### 4. 处理异常并查看冻结工资表

| 遇到的情况 | 继续方式 |
| --- | --- |
| 缺现场量、单位、责任或单价 | 按提示进入原来源或工资配置补齐，返回原草稿重新核对 |
| 读取到新资料，但原草稿还有修改 | 原输入继续保留；明确核对当前来源后再保存 |
| 确认过程中断网或结果未能确认 | 保留页面与原提交，使用“核对原提交”确认结果；不要另建一张重发 |
| 暂时无权限 | 等权限恢复后核对原提交或重新读取；无权提示不等于之前没有保存 |
| 已发工资需要补差、退回或纠错 | 原单保持冻结，按[工资更正与实际收付](./payroll-adjustments.md)操作；P4 已通过本地验收 |

发放成功后刷新详情，核对发放时姓名、金额、来源和全体成员分配；再打印或下载冻结工资表。工资表、工资明细及组内分配使用同一次发放结果，零成员也保留。之后改名、转组或修改当前量价，不改变原单和输出。

证据完整并经冻结校验的 A 已发工资可生成本期输出，含受控迁入的完整原单；缺失或损坏的历史快照仍保留原文供查看，不能自动补成完整工资表。A 单份输出不等同于后续按月整册或负责人全周期工作簿。

## 七、C1 从逐日考勤到实际发放

本节适用于当前浏览器中央验证版本的 C1 路径。C1 适用于按真实考勤核算的时工，不要求项目已有工程量或施工完成记录。

### 1. 登记每人的真实考勤

1. 进入考勤，选择项目、月份和班组。未选项目或月份时保留空范围并提示选择，不默认读取其他项目或全年考勤。“全部班组”可以查看当前范围的所有人员，不改变工人的原档案归属。
2. 在工人所在行选择真实日期，录入正常工时、加班工时和施工内容。正常与加班合计不超过 24 小时，允许 0 和小数；7.51 小时应完整显示。
3. 保存后检查同一日期格。空格表示没有记录，保存过的 0 表示真实零工时；新格里尚未保存的默认工时不计入工资。
4. 同日合法重存修改原记录。转组前已有的同日考勤仍归原班组，在新组不能覆盖或另建第二条；原记录和不可修改原因仍可查看。

月底的日期在表格内部横向滚动，工人姓名列保持可见。保存失败保留当前格输入；切换范围前按未保存提示处理。提交结果未能确认时先核对原提交，不另录一遍。

同人同项目同月存在签工链或已发 C1/C2 时，页面会显示锁定原因。待确认签工也表示该月已经选择签工方式，不能另外录考勤；旧记录隐藏或删除不等于已经解除发放锁。

### 2. 核对个人工资标准

从 C1 草稿进入独立工资配置页，核对当前项目和月份。每人分别查看档案日薪、工资域兜底标准、独立加班时薪以及本次实际采用的来源。

合法档案日薪优先；档案未填时才采用明确保存的个人兜底。加班时薪独立保存，未填时按该人的有效日薪÷8计算；明确填 0 与未填分别处理。页面展示的建议值不会自动变成你已保存的配置。

保存结果未确认时保留原提交。浏览器整页刷新不会自动恢复配置这类写入页面；重新进入原项目、月份、班组的 C1 工资配置，核对保留的输入后使用“核对原提交”，不要新建重复提交。

例如，日薪 481 元、正常 8 小时、加班 2 小时，未另设加班价时采用 60.125 元/小时，工资为 601.25 元；明确设置加班价 55 元/小时后，工资为 591 元。系统保留费率精度，只把最终金额计算到分。

### 3. 保存草稿、重核并登记实发

1. 在新建工资中选择 C1、月份、负责人和完整成员。至少有一条当月真实考勤才能建单；没有记录时先返回登记。全零考勤可以保存零草稿并核对，但不能确认零应发的发放。
2. 逐人核对正常及加班工时、采用费率和工资。没有考勤的成员仍保留自己的零数量行与标准，不沿用负责人的价。
3. 保存草稿后进入原单，核对考勤来源。C1 固定当月 100%，没有 A 的结算、尾款或取整；上月已经发的钱不会再次从本月扣减。
4. 从原考勤或工人档案返回后，重新核对发生变化的来源。核对后仍未发的考勤可以按规则修正，工资需重新核对；“已核对”不代表已发放或已锁月。
5. 确认实际发放时填写真实总额和全体成员的到分分配，包括收款 0 元的成员。个人工资参考与实际收款分别保留，分配合计必须等于实发总额。

例如，本月核算 1041 元、实际发出 900 元，可以登记负责人 550 元、组员 350 元和另一成员 0 元。工资实发只有这笔 900 元，组内分配不再产生第二笔支付。

确认时来源变化或权限失效，系统拒绝不再有效的发放，保留原输入供重核；断网或成功后刷新失败时，先核对原提交结果。不能因为暂时没有成功提示就重新创建工资。

### 4. 查看同一发放的两份表

发放后刷新原单，检查原姓名、工时、个人标准、核算额、实发及零成员分配，再打印或下载配对的工资表与考勤表。两份表来自同一次冻结，后来的改名、转组或改价不会重写旧表；工资表保留签字、按手印及四方签字位置。

负责人和所有成员的当月考勤随发放锁定，即使成员没有工时或实际收款为 0。发现错误时保留原单，按[独立更正和实际补退](./payroll-adjustments.md)处理。旧 C1 缺少逐日原资料时只能查看保存证据，不能用今天的矩阵补成完整配对输出。

本节配对的是单张工资与对应考勤；按月整册和负责人全周期工作簿仍在后续范围。C2 配对签工表，不使用 C1 考勤表。

## 八、C2 从人工签工到实际发放

本节适用于当前浏览器中央验证版本的 C2 路径。签工按整工或半工登记，用工时段用于核对日内重叠，不自动折算工数，也不要求项目已有工程量。

### 1. 登记与人工确认

1. 打开签工台账，选择项目、月份和班组，明确区分“待确认”与“已确认”。未选范围时先选择，不把空页面当成全部月份没有签工。
2. 新增进入独立整页，选择实际用工人、日期、起止时间、整工 1 或半工 0.5，填写施工内容。开始须早于结束，同人同日时段不能重叠，合计不超过 1 工；相邻的两段半工可以分别登记。
3. 证明尚未齐备时保存为待确认。待确认不进入工资，但已占用同人同项目当月的签工方式，不能再另录 C1 考勤。
4. 有证明人和确认日期后明确确认；也可以在资料完整时一次保存并确认。确认日期不能早于签工日期；超过两天才完成的合法人工确认不会自动免付或扣款。
5. 保存失败保留原输入。若提示结果待核对，使用原提交继续核对，不再新增一条同样记录。另一窗口在成功后又合法修改了同一记录时，核对原提交与查看当前变化分别处理。

原签工尚未发放时，可以按提示进入整页修正内容、时段、证明信息或状态。该记录已被未发工资采用时，原工资需要重新核对；不能因此将同一记录再领给另一张工资。原记录已发放或月份锁定时只读保留，核算依据有误按[独立更正流程](./payroll-adjustments.md)处理；不通过补签重开原记录领取。

重读发现资料或权限变化时，页面保留原稿并立即按当前权限决定是否可编辑。确认未应用的旧提交后，点击“按当前资料重新核对本稿”再采用新依据；返回页签本身不会替你确认。人工确认弹窗也可重新核对当前记录，已填的证明人和日期仍保留。原提交曾要求重核、但后来另一窗口已经完成重核时，页面分别说明原结果和现在的状态，不把已经核对好的工资继续误报为未核对。

### 2. 配置主体单价并核对工资

1. 从 C2 工资进入当前项目、负责人的主体配置页，明确保存大工单价和确认规则文字。单价必须大于 0；缺值、0 或停用配置不能用于核算。规则可以明确留空，不会自动填回默认脚注。
2. 新建 C2 工资，选择月份、负责人和完整成员。成员可以包含本月无签工或实际收款 0 元的人，但至少需要一条合法可用的已确认签工。
3. 核对每条原签工、工数、主体价与人员汇总。待确认、他单已经领用或原资料有缺口的记录分别显示；同一签工不能在两张有效工资里重复计薪。
4. 保存并核对。C2 固定当月 100%，不扣上月已经发出的签工工资；如果配置或原签工发生变化，先按原来源重新核对，不沿用旧的“已核对”结果。

例如，主体价 350 元，负责人 1 工、组员 0.5 工，当月核算为 525 元。实际发出 500 元时，可登记负责人 350 元、组员 150 元及另一成员 0 元；实发是这一笔 500 元，成员分配不是第二笔工资支出。

### 3. 确认实发与两份冻结表

填写真实发放总额及全部成员到分分配，合计必须相等，不能漏掉零收款成员或超过本次核算金额。确认前来源或权限变化时保留输入并重核；断网、未知结果或成功后的读取失败，继续核对同一次原提交。

成功后从原工资读取当时姓名、主体单价、规则、每条签工与实际分配，再打印零星用工记录表及工资表，或下载同源 Excel。签工表保留日期、时段、工数、内容和证明信息；工资表保留签字、按手印及四方签字位。C2 不生成考勤表，单张配对输出也不代表完整月工作簿。

发放后负责人及全部成员当月来源锁定，即使某人没有签工或收款为 0。后来的改名、转组、改价或规则变化不重写原表；旧资料缺少完整来源或发放证据时只查看已有历史，不能用今天的配置补成新输出。

## 九、批量资金与完整工作簿

### 1. 批量核对或安排资金

1. 在工资台账选择正式资料、明确项目和月份。页面出现“选择本期可处理工资”和“批量核对 / 资金”；已发、删除、隔离历史及 B 类不会出现选择框。
2. 选择同项目同月的 A/C1/C2 工资，打开批量窗口。选择“批量核对”时不填资金；选择“批量发放”时输入本期真实资金总额。
3. 生成预览后逐行看当前可发、取整和阻断原因。A 的每个负责人、请款簿和月份须在“A 工资配置 → 发放取整”明确选择“不取整”或“向下取整到整百元”；C1/C2 不套 A 规则。
4. 系统先安排必须整单支付且资金足够的工资，同类按稳定请款簿身份排序；资金不足一单时先暂缓，再继续后面的可付整单。余额按其他工资的可发额比例分配到分，尾分优先给比例余数较大的工资，同余按稳定簿身份、原单身份确定。为用尽资金，最后允许突破整百：三份等权工资、1000 元资金得到 333.34/333.33/333.33；必须整单 600 元加普通工资 400 元、资金 700 元时得到 600/100。稳定簿身份不是工资正式序号，也不是当前行顺序。可逐行改实际金额及全体成员分配，零收款成员仍保留。
5. 固定计划不会立即发放。之后点击“执行下一项”，系统逐张保存原命令再执行；一张成功后才进入下一张。响应未知、关闭窗口或刷新后，重开相同选择并恢复当前项，系统只使用原编号和原正文。
6. 完成后回到台账刷新。暂缓项保持未发，已成功项不会重发；来源、成员、权限或外部操作变化会停止并要求重新核对。

资金总额为空、负数、超精度，实际金额超出资金或单张余额，成员遗漏、重复、外部人员以及分配差一分都会停留在原稿并说明原因。修改资金总额需重新生成预览。建议为0的单默认“暂缓”；它仍未发放，不算执行成功。资金超过所有工资可发上限，或余额不足任何剩余整单且其他工资已分满时，系统保留余额并显示原因，不会超发或生成预支。缺余额、缺取整配置继续显示缺口，不能当0参加分配。

### 2. 生成负责人全周期工作簿

1. 在工资台账选择正式资料和项目；月份可用于查看，但全周期输出会重新读取该项目全部已发工资，不只导出当前页。
2. 点击“完整工作簿”，选择“负责人全周期一册”，再选择负责人、格式和请款簿稳定身份。同一姓名的普通施工簿、独立管理费簿或其他格式不会混成一册。
3. 点击“生成全周期工作簿”。文件含目录、周期对账、实际收付、缺口清单和每张工资的冻结原表。A 的周期公式应付采用最新累计值；例如累计 1000/1600、实际 800/700，周期显示 1600、1500、差额 100，不显示 2600。
4. 打开文件核对稳定工资身份、月份、档位、原表页签和实际收付。缺冻结正文只进入缺口，不生成金额为 0 的替代页。

### 3. 生成项目按月归档

1. 在同一窗口选择“项目按月归档”。
2. 点击“生成按月 ZIP 归档”。下载的 ZIP 实际包含 `YYYY-MM/` 月份目录，每月一份完整工资工作簿，根目录含 `00-归档说明.md`。
3. C1 的原表页签为工资和考勤；C2 为工资和签工，绝不附带考勤；A 保留适用的普通/管理、费用和扣款冻结页。
4. 打开“月度对账”核对本月各张原单的本次核算合计，以及这些原单对应的已确认收付净额。A 不拿累计应付代替本次核算；例如上月累计 1000、实发 800，本月累计 1600、本次核算 800、实发 700，本月显示 800、700、差额 100，全周期仍显示 1600、1500、差额 100。同月多名负责人、普通/管理簿及 C1/C2 分别保留原单并按分合计；单月核算合计不代表周期新增债务。后续真实补退沿原工资范围进入净实际，原冻结实发另见目录与原表。
5. 打开 Markdown 说明和各月缺口清单。未知公式或实际金额不填零，不能计算时不显示已对平。编号、完整实名名册或原件尚未满足时会明确写出，不以空表冒充完整资料。

目前两类工作簿都是可回读的真实 XLSX/ZIP 输出，但正式编号仍标“编号待定”：系统不会在下载时发号，也不会从文件名猜旧号。实名名册、身份证、进退场日期、证件照和银行卡照的归档时点与最小授权尚待业务裁定，因此不会借工资读取权限导出整个工人目录；旧缺原件也不会补造。以上三项业务取舍确定后再补正式输出，不需要重做已完成的冻结工资和实际收付组合。

## 十、核对已发 A 工资的原施工范围

当前已可用：打开一张已发 A 工资，在“冻结工资输出”查看“原冻结施工范围”。普通工资和独立管理费分别沿自己的原责任列示楼栋、分项、单位、楼层、户和房间。窄屏中先聚焦明细区域，再使用左右方向键或横向滚动查看后面的列。

明确的连续层号会合并成区间，例如 `3–14、16–24、26–31楼`；缺少的15、25楼不会补进来。夹层、含糊层名和同名不同身份保留原标签。表中的“限定房间分项”只说明当时责任范围，不代表整层已收尾；缺位置或完成日期时会提示缺口，不能用当前资料补成旧原件。

下载冻结工资表后，原工资明细增加施工范围说明，另有“原施工范围”和“施工范围说明”页。打印把同一原范围接在原金额、收款签字和现场签字区之后；长表跨页会重复表头。文件名包含项目、楼栋/分项、月份/档位、负责人和稳定原件标记，超长名称会缩短显示。之后修改现场量、房间或楼层名称，不会改变这份冻结资料。此项只补输出，不改变计量、扣款或实发；正式编号和固定名册的完整归档按对应实施记录验收。

## 十一、仍在接续的完整流程

以下是已确定、但尚未全部开放的后续业务流程：

1. C2 实际开放以第八节的验收状态为准，历史签工能阅读不表示新写入和发放已通过。
2. 各类型发放均核实来源，登记真实金额及全部成员分配，冻结后提供对应打印和 Excel 输出。
3. 已发后补差、扣回或纠错保留原单，通过独立更正和实际收付记录追溯，不能直接改原快照。
4. 多条房补、独立管理簿和负价清单见[费用指南](./payroll-fees.md)；户级检查、整改及人工扣款见[空鼓指南](./payroll-hollow.md)，具体可用范围以各页验收状态为准。P7 的批量资金与非正式编号工作簿操作见第九节。

工资更正、实际收付、后月处理与跨页面核对见[专门指南](./payroll-adjustments.md)。P4 已通过本地验收；费用、扣款、正式编号、完整实名名册及生产部署分别登记，不能仅凭某个分区有金额认定全部工资流程完成。

规则与当前边界以[工资页面蓝本](../rewrite/pages/subcontract-payroll.md)为准，具体实施状态见[模块实现状态](../design/ui-implementation-status.md)；生产保存、备份恢复和部署由独立上线关口验收。
