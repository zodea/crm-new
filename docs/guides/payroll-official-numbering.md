# 正式工资编号与单份出具

本指南对应 #477 的中央浏览器流程。页面与单份输出以本票本地验收范围为准；生产磁盘保存、完整名册组合和全册归档由各自实施票验收。

## 从原工资进入预览

打开已发 A、C1 或 C2 的原工资详情，点击“预览 / 正式出具”。页面显示冻结时的负责人、月份、档位、核算金额、实际收款和零金额成员。预览不占号，不以当前工程量或姓名重算原工资。

原工资尚未发放、冻结证据不足、项目不匹配或当前无权时，按提示回原来源核对。历史 B 不生成新的正式编号。

## 首次登记项目旧纸号起点

每个项目首次出具前，需要人工核对旧纸质工资号，并填写“下一张正式编号”和“旧纸号核对依据”。例如确认旧号到127后，明确填写128；系统不会自动猜起点。

遇到重复旧号先核对；缺失旧号仍保持未知，不依据文件名、导入顺序补号，也不按年份自动清零。点击“登记项目起点”后再次核对确认。已登记序列不能从这个表单直接重置。

旧八张工资表没有正式编号字段时，只登记人工核对后的项目下一号，不凭口述把旧纸号贴到某张电子原单。系统不会自动扫描纸张中的重复号，也不会补齐历史缺号。

## 正式出具与重复输出

1. 核对本份冻结工资预览，点击“确认预览并正式出具”。
2. 在确认框中明确出具。成功回读后才显示本份正式编号和实际出具时间；页面中的“下一张可用编号”只是序列状态，不是本份已取得的编号。
3. 点击“下载正式工资 Excel”或“打印正式工资”。Excel保留各格式原表，并增加正式出具页；打印显示同一编号、原工资身份与出具信息。C1保留考勤表，C2保留签工表。

同一原工资只有一个正式编号。重复下载或打印沿用原号；编号不增加工资账或实际付款。文件名保留冻结原件摘要，项目和负责人长名称缩短后仍能区分不同原件。

## 中断、失败与返回

提交响应丢失时，点击“核对原编号提交”，不要另建重复出具。刷新后会恢复原提交编号，并从服务重新读取同一结果。原目标回读确认前暂停新的操作。

起点登记遇到来源变化时保留原输入，先核对原提交结果，再重新读取并确认。下载失败后正式编号仍已保存，重试下载沿用原号。

有未保存的起点输入时，返回会提示是否放弃；有待核对提交时，先核对再离开。“返回原工资”回到原详情，不改变原工资状态。
