## 一、当前已可用的分供方主链

浏览器中的分供方列表、分供方详情和正式分供方新增/编辑现已接入中央后台。正式分供方保存后，列表与详情重新读取中央结果；测试分供方只读。合同、结算、收票和付款均取真实稳定关系，不再从名称、旧累计字段或申请金额推算。

:::flow
当前已可用|打开中央列表|基础信息 → 分供方
当前已可用|搜索和筛选|按名称、简称、税号或联系人搜索，按类别和资料状态筛选
当前已可用|查看中央详情|点击分供方名称，进入来源感知的只读详情
当前已可用|查看四类事实|切换合同、结算、收票和付款事实；0 条仍进入真实空态
当前已可用|显式编辑正式分供方|从正式详情点击“编辑”，进入独立整页表单
当前已可用|保存并刷新|中央后台确认后返回同一详情，刷新仍可见
当前已可用|返回原列表|恢复搜索、筛选、排序、分页和原行焦点
已定稿待开发|中央删除与证照主链整合|当前主档命令不处理删除，也不替代证照专用文件与审核边界
:::

## 二、查找和查看分供方

1. 进入“基础信息 → 分供方”。
2. 在搜索框输入公司名、简称、统一社会信用代码或联系人。
3. 使用类别、资料状态和排序控件缩小中央结果；分页由中央端完成。
4. 点击分供方名称或行尾详情图标进入详情。列表没有直接编辑动作，必须先确认详情与来源。
5. 顶栏测试数据关闭时只显示正式分供方；显式开启且具有权限时才显示测试分供方。

统一社会信用代码、内部编码、银行账号和联系电话按 capability 遮罩。测试详情带“测试数据”标识且没有编辑入口；受限关系显示“无权限”，缺失关系显示“未记录”，两者都不会生成死链。

## 三、理解摘要和四类真实事实

详情顶部展示合作项目、累计合同金额、累计结算金额、累计收票金额、累计付款金额和应付金额。前五项可进入对应事实页签，即使金额为 0；应付金额只展示，不可点击。

| 事实 | 当前来源 | 进入目标 |
| --- | --- | --- |
| 合同 | supplier_id 指向当前分供方的有效合同，加有效补充协议 | 合同详情；项目关系可用时进入项目详情 |
| 结算 | 已登记且状态确认的支出结算 | 进入结算事实页签；没有 canonical 详情路由的行保持普通文本 |
| 收票 | supplier_id 指向当前分供方且已归档的发票 | 发票详情；未归档发票不计入金额 |
| 付款 | 已确认支付记录对当前分供方付款申请的实际分摊 | 付款申请只读详情；不把申请金额当成实付 |

应付金额等于有效合同金额减确认实付，仅用于摘要。它不是一张源单，因此不会伪装成蓝色入口。真实事实暂时为 0 时，页签显示“暂无……事实”，这表示当前没有记录，不表示服务失败。

## 四、新建和显式编辑正式分供方

### 新建

1. 在列表点击“新增分供方”，先选择分供方类别。
2. 填写公司全称、分供方类别和主要联系人；这三项在正式保存时必填。
3. 按需填写简称、税号、法定代表人、开票资料、银行资料和联系方式。
4. 点击“保存”。中央后台生成正式分供方 ID，页面进入新详情。

### 编辑

1. 从列表进入正式分供方详情。
2. 点击顶部“编辑”，在独立整页表单修改主档。
3. 保存成功后回到同一详情；刷新页面确认中央读回结果。
4. 若其他操作已先更新该分供方，系统阻止旧版本覆盖，可保留当前内容并基于最新版本重试，或改用服务器最新版。

统一社会信用代码或内部编码重复时，中央端返回字段错误。中央服务不可用时不会伪装保存成功。证照原件、OCR 和人工资料核验从详情顶部“证照附件”进入独立专用页面，不作为本次主档命令的普通附件。浏览器中的正式中央分供方会明确提示专用存储尚未接入，绝不读取或写入旧本地证照库；只有从顶栏显式开启并通过权限核验后，测试分供方才展示经中央身份核验的纯读证照快照。Tauri 桌面端的正式本地身份仍可使用原有证照维护流程。

## 五、返回原列表

从列表进入详情时，地址保存当前搜索、类别、资料状态、排序、页码、每页条数和原行锚点。继续进入编辑并保存后，点击“返回分供方列表”仍恢复这些状态，并把键盘焦点放回原分供方行。

外部地址、异常返回地址或不属于 `/base/supplier` 的目标会被拒绝，系统回到规范分供方列表。不要手工修改详情地址中的 `origin`；ID 与来源不一致时会显示来源错配。

## 六、当前边界

### 当前已可用

- 浏览器正式分供方中央新建、编辑、幂等命令、版本冲突和保存后读回。
- 正式与测试来源隔离，测试分供方只读，敏感字段按 capability 遮罩。
- 合作项目及合同、结算、归档发票、确认付款四类真实事实。
- 0 事实、缺失关系、无权限关系、来源错配、记录不存在和中央服务错误的独立状态。
- 证照专用地址完整保留来源与列表返回上下文；正式浏览器身份不可落入旧本地可写链，测试身份只读。

### 已定稿待开发

- 正式登录、完整 RBAC 和生产持久化后台；当前中央端是可重置的非生产证明实例。
- 分供方中央删除、软删除恢复及下游影响确认。
- 没有 canonical 只读详情路由的结算行目标；当前保持不可导航，不链接到编辑表单。
- 证照文件、OCR 与人工核验的中央化；当前完整可写专用流程只属于 Tauri 正式本地身份，浏览器正式中央身份保持明确不可用。
