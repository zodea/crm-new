## 二、从项目详情进入工作台

1. 打开“项目信息 → 项目列表”。
2. 点击项目名称进入项目详情。
3. 在右侧“项目分供方”区域选择一家分供方。
4. 系统打开当前项目和该分供方的合作工作台。

工作台顶部显示项目名、分供方名、合作状态，以及合同、请款、收票、已付和应付余额等真实摘要。点击返回按钮可回到项目详情；合作概览中的项目名和分供方名可以打开对应详情。

工作台通过中央 Repository 按项目 ID、分供方 ID 和数据来源读取。两个身份没有形成同来源关系时显示“关系不匹配”；读取中、真实零记录、无权限或服务异常分别显示对应状态。真实零记录仍保留六个页签和表头。

## 三、查看业务页签

### 合作概览

合作概览集中显示当前项目及项目状态、分供方类别与联系方式、合作状态，以及当前合作关系的金额摘要。

### 合同

合同页签显示当前项目与分供方之间的支出合同，包括原合同额、补充协议后的有效合同额、状态、签订日期和附件数。点击“查看源单”进入合同详情。

顶部合同汇总不计草稿、作废或无效合同；这些记录仍保留在明细中供追溯。汇总口径与分供方详情一致。

### 请款

请款页签显示付款申请单号、申请金额、批复金额、审批状态、申请日期和回票类型。演示请款目前不能从正式财务来源读取，来源显示“来源待核验”，不提供无法访问的源单链接；其他未核验的来源也不提供链接。

### 收票

收票页签显示发票号码、日期、发票类型、含税金额、税额和归档状态。只有已归档发票计入顶部收票汇总。当前发票目标仍为读写混用页，因此来源显示“目标待核验”，不会生成看似可点的编辑入口。

### 付款

付款页签只使用经过人工确认的支付事实。金额按支付记录分摊到当前项目和分供方付款申请的部分计算，不会把一张涉及多份申请的银行回单重复计入。支付记录只读目标尚未接入时显示“目标待核验”。

### 结算

结算页签只列出分包、材料或其他支出合同的过程/完工结算事实。合作终态结算属于另一种业务事实，当前规则尚未闭合，因此本页不提供填写或确认入口，也不会把两者混成同一笔结算。尚未通过只读目标校验的来源保持“目标待核验”。

结算汇总只计已确认记录；仅审批通过、尚未确认的记录不计入汇总，仍可在明细核对。

## 四、追溯和使用合作文件

工作台下方“合作文件”按真实来源分组，例如：

- 合作档案。
- 合同。
- 付款申请。
- 发票原件。
- 支付记录。
- 支出结算。

每份文件显示名称、类别、大小、上传人和时间。只有来源已登记为同来源只读目标时，分组才可点击“查看来源”并返回进入前的工作台页签；其余来源显示“目标待核验”。

“合作档案”中通过本向导导入的原件，可以按以下步骤使用：

1. 点击“预览”查看 PDF、常见图片或纯文本。PDF 保留全部原始页面；浏览器阻止弹窗时，允许本页弹出窗口后重试。
2. 点击“下载原件”保存原始文件。ZIP 等其他类型可以下载后查看；网页不会自动解包或执行文件内容。
3. 勾选需要的合作档案，点击“下载选中 ZIP”。包内保留各份原件，并附文件清单、摘要与导出说明；同名的不同文件追加序号，不互相覆盖。
4. 支持选择目录的浏览器会先请求保存位置，再读取原件；其他浏览器使用默认下载位置。取消目录选择不会读取或生成文件。读取期间可以点击“取消读取”。离开页面或切换来源后，尚未完成的读取结果不会继续保存。

历史文件没有正文时会明确提示，不能单独预览或下载；选入 ZIP 后在清单中登记缺失，并提示“本包不齐套”。无权限、当前项目或分供方已删除、关系变化、网络失败或原件校验失败时，本次保存失败，保留选择以便处理后重试。系统不会补用本机同名文件。

合同、付款申请、发票、支付或结算等其他业务来源的正文显示“尚未接入”，不因文件名相同就获得合作档案的下载权限。这些来源仍由各自模块继续接入。

查看、预览和下载都是只读操作，不会改变合作状态或源单数据。每次读取原件都按当前项目、分供方、合作关系和会话权限重新核验，上传人与读取人不必是同一人。

## 五、从文件导入分供方

### 第一步：选择文件

1. 在项目详情右侧点击“从文件导入分供方”。
2. 将多个文件拖入选择区，或点击“选择文件”。
3. 需要一次处理整个目录时，点击“选择文件夹”。
4. 核对文件名、相对路径、大小和类型。
5. 移除不需要处理的文件，然后点击“下一步：自动分类”。

文件在最终确认前不会写入数据库。

### 第二步：分类与调整

系统只在本机根据文件名执行初步分类：

- 优先匹配现有分供方公司全称，没有全称命中时才匹配别名；同层多个命中项取最长。
- 用“合同、请款、发票、回单、结算、资质”等关键词判断文件类别。
- 未匹配的文件生成一个待确认的候选分供方名称。

该步骤不读取文件正文、不上传云端，也不执行 OCR。请逐项核对：

1. 从下拉框选择正确的现有分供方，或保留“新分供方”。
2. 调整文件类别。
3. 新分供方可修改拟建名称。
4. 只有确认名称无误后，勾选“写入分供方主数据”。

未匹配文件没有明确确认时，系统不会进入下一步。

新建的最小分供方档案使用“其他”类别、“资料缺失”和草稿状态，后续可从分供方详情进入“编辑分供方”补充完整资料。导入文件只属于当前项目合作关系，不会成为分供方证照。

### 第三步：确认生成

确认页按分供方分组，清楚标记：

- “复用已有关系”。
- “新建项目关系”。
- “新建主数据”。
- 每个关系下将归档的文件和类别。

核对后点击“确认生成并返回项目”。系统会把当前项目身份、新分供方、项目关系和全部文件作为一批交给中央服务；任一项无效、无权限或版本已变更时，整批都不保存。成功后返回当前正式项目详情，右侧“项目分供方”立即显示新关系。

同一项目已经存在相同分供方关系时，系统只复用该关系并追加文件，不会再创建一条重复关系。

如果系统提示“项目分供方关系已更新”，说明确认期间有其他操作改变了关系版本。请重新进入导入页、核对最新关系后再次确认；不要为了绕过提示而在本地库手工补录。

## 六、合作终态结算边界

当前工作台不执行合作终态结算写入。用户可以在“结算”页签核对支出结算、请款、收票和付款事实，但不能在此填写最终金额、上传确认书或改变 ProjectSupplier 状态。

终态结算的多轮确认、唯一性、附件和状态迁移规则仍待后续票闭合。在该能力完成前，不应把支出结算单当作终态结算，也不应通过本地数据库或其他隐藏入口修改合作终态。

## 七、窄屏和键盘操作

- 手机上摘要和操作区会自动换行。
- 业务宽表只在表格内部横向滚动，不带动整个页面。
- 文件导入的三个步骤按页面宽度重排。
- 使用键盘 `Tab` 可以依次到达文件选择、移除、分供方、类别、确认框、上一步、下一步和最终确认。
- 下拉框可使用方向键选择，复选框可使用空格切换。
- 从已验证源单返回后，当前页签由受限返回地址恢复；未验证来源保持普通文本。
- 合作文件复选框用空格切换；预览、下载、ZIP 与取消按钮可用 `Tab` 到达并用 `Enter` 执行。

## 八、使用边界

- 工作台不负责新建或编辑合同、付款申请、发票、支付记录和支出结算单。
- 文件导入不自动生成业务单据。
- 文件选择和文件名分类在本机完成；只有用户最终确认后，文件和其归属才提交到中央正式数据链。
- 文件名分类只是初步建议，最终以人工调整结果为准。
- 只有已归档发票、已确认支付和已确认结算进入对应金额汇总。
- 合作终态结算不参与付款申请的结算分摊。
- 当前中央服务仍为浏览器测试实例；已验证的页面刷新和原件读取，不代表生产服务器重启持久化或生产权限体系已经完成。
