## 一、当前可以完成什么

本指南只说明已经完成、当前可以操作的流程。

施工主合同与分包主合同已接入正式持久存储，可在重启后核对同一合同、采用的签约主体版本及签约原件；施工主合同还可从项目菜单新建并核对管理费配置。分包后续单据与甲方商务单据仍按各自已开放范围使用；当前接管清单及环境限制直接见 [ARCHITECTURE](../rewrite/ARCHITECTURE.md#implementation-gaps)。


:::flow

合同维护|新增或编辑|进入独立整页表单 → 保存草稿或提交

## 二、查找和维护三类合同

### 列表筛选

1. 进入施工合同、分包合同或材料采购合同。
2. 先选项目；施工合同可继续选客户，分包和材料采购合同可继续选分供方。
3. 按草稿、审批中、履约中、已签订、已结算或已结清筛选。
4. 输入合同名称或完整合同编号搜索。
5. 点击合同名称查看详情。三类正式合同都只允许从详情显式进入整页编辑；当前中央列表不提供删除或快捷编辑，演示合同不显示写入口。

三类列表使用相同的筛选顺序，但金额方向不同：施工合同展示累计开票、收款和应收；分包及材料采购合同展示累计收票、支付和应付。系统只统计明确关联当前合同的单据，不会把同项目或同分供方的金额自动拼到合同中。列表里的项目、客户或分供方名称只有在系统能用稳定 ID 找到同源详情时才可点击；不能确认目标时保持普通文本，不会生成死链接。

金额显示“未知”时，先查看缺失金额或关联来源提示；合同本体仍可继续核对。关联源暂不可用、无权查看或金额未记录时，相关总额和余额也保持未知；只有完整读取后确实没有有效记录时才显示真实零。施工的累计结算读取非草稿甲方报量，最终结算单独核对；当前开票来源尚未接入时不会显示假零。金额完整度及汇总说明直接见 [READ-MODELS](../rewrite/READ-MODELS.md#read-status-and-completeness)。

从项目详情进入材料采购合同时，系统按项目稳定 ID 和数据来源锁定范围，并保留项目详情返回地址。列表中的 `0` 是可核验的真实零值，仍可进入专属空列表；“未登记”“暂不可用”和“无权限”分别显示，不会伪装成 `0` 或生成死链。在材采列表继续搜索、筛选并进入合同后，刷新合同详情仍保留列表来源；返回会等当前列表读取完成，再恢复原搜索、筛选、分页、滚动位置和合同焦点。原合同行已消失时，焦点返回列表标题。

### 新增和编辑

先在“系统设置 → 我方签约主体”维护真实签约名称及核实资料；新增和编辑使用独立整页表单。未核实的税号、地址或法定代表人留空，保存核实说明；停用保身份与历史。施工合同选择“乙方（我方）”，分包、材料等支出合同选择“甲方（我方）”；没有真实目录条目时先维护目录，不用项目客户或默认工作区替代。合同显示采用的核实版本，目录更名或停用后，原合同和已建协议继续显示当时采用的快照。设置职责及历史映射边界见 [ARCHITECTURE](../rewrite/ARCHITECTURE.md#our-signatories)。

设置整页保存也按统一原命令及同记录读回规则处理。发生版本冲突时，先核对页面显示的最新保存版本，再选择保留当前输入继续修改；原提交结果未知时先核对原编号。独立 Native 目前不能新增主体选择或维护一致目录，页面会明确提示；已有真实快照与旧主体原文继续保留，不能按同名自动映射。各运行环境的实际 owner 见 [DATABASE](../rewrite/DATABASE.md#our-signatory-storage)。

施工、分包、材料采购合同的“保存并新建”会保存当前合同并进入空白新建表单，不受“保存后关闭”勾选影响。若另一个新建页已有草稿，先确认是否放弃该草稿。多份合同可在不同页签交替编辑，保存各自的记录与版本。

提交后等待同一记录可靠读回，再按当前操作进入详情、关闭或新建。结果未知时保留原输入与附件，选择“核对原提交”；已有成功回执但读回失败时选择“重新读取已保存记录”。保存期间继续填写的内容会保留，不能因旧提交完成清空后来输入。仅明确未应用并封存原编号后才能以新编号提交，通用规则直引 [COMMANDS](../rewrite/COMMANDS.md#idempotency-and-recovery)。

施工、分包和材料合同的附件随本记录保存真实原字节。详情附件区可以预览支持的文件或下载原件；预览关闭后焦点返回原入口，下载仍核对当前来源与权限。历史附件只剩描述、缺少正文时显示“原件不可用”，需要重新上传真实文件；旧本机路径不具备读取能力。原件存储与 owner 定义直引 [DATABASE](../rewrite/DATABASE.md#共享正式存储版本与参与者463)。

- 施工合同：进入“主合同管理 → 施工合同”，点击“新增施工合同”。
- 从项目新建施工主合同：在项目列表打开本项目的操作菜单，选择“新建施工主合同”。独立表单带出当前真实项目与甲方，核对我方签约主体、合同编号和原件后保存；同一项目可以维护多份主合同。保存后从合同详情返回原项目，取消也返回原项目。
- 分包合同：进入“分包及人工 → 分包合同”，点击“新增分包合同”。
- 材料采购合同：进入“乙供材管理 → 材料采购合同”，点击“新增材料采购合同”。

正式新建分包合同先在“工程名称”动态搜索并明确选择施工主合同；同一工程有多份主合同时，根据候选中的合同名称和编号区分。项目由该选择带出，分供方与我方主体也通过动态查找已有正式身份。保存草稿同样需要工程选择；合同和所选工程归属同次保存，结果未知时只核对原提交，保存后读取失败时只重读已保存记录。历史迁入合同没有工程归属时保持原项目，不默认补选第一份主合同；对应决策只见 [ARCHITECTURE](../rewrite/ARCHITECTURE.md#opt-02-scope-decision)。

草稿可以先保存不完整内容；提交时会检查必填项、金额和项目—客户/分供方关系。施工、分包和材料采购合同的正式新建/编辑均由中央服务分配合同 ID，并执行重复提交保护与版本冲突校验；材料采购明细还会重新计算“数量 × 含税单价”。保存成功后回到同一中央详情读回，不用浏览器表单内容伪造成功结果。补充协议必须选择原合同，不会另存成一份没有来源的主合同。

### 批量导入材料采购合同

在材料采购合同列表选择“导入采购合同”，下载 Excel 模板。在“合同主档”中每行填写一份合同，在“采购明细”中每行填写一项材料；两表用相同的导入分组号对应。每份合同的分组号须唯一，明细须填写计量单位、计价单位、数量、含税单价，并在核对后将“数量及单位已核实”填为“是”。单个工作簿不超过 10 MiB 和 200 份合同。

上传后逐项核对项目、施工主合同、分供方及文件中填写的我方签约主体；重名候选按名称和稳定身份区分，须人工选择。已有合同会展示映射字段差异及明细、附件数量，可明确选择新建、替换或跳过。已有合同和文件都包含明细时暂不能批量替换：明细可能已被补充协议、财务或其他历史资料采用，目前无法完整核验所有引用。请查看原合同和相关资料后在合同页面处理；文件未提供的字段和已有原件会保留。草稿同号会提示核对，正式提交继续执行现行编号检查。文件填写的合同金额与明细合计不一致时须先核对，多个减项及补充协议在合同页面处理。

确认后，所选合同及各自的采购明细、工作簿来源原件和施工归属作为一批保存；任一项失败时整批不写入。工作簿是导入资料的来源证据，已签合同文书仍须按实际情况另行维护。结果不明确时选择“核对原批次并重新预览”，系统先核对全部原编号并读回已保存合同；刷新不会恢复文件和未保存选择。

施工合同的项目与甲方候选会在每次打开表单时重新读取正式记录；新建或明确改选归属时核对项目当前甲方。项目后来更换甲方，原主合同仍保留自己的项目与甲方组合，编辑备注、名称或管理费不会跟随项目移动甲方。已有真实业务、原意图或历史消费的主合同不能直接改成另一项目；项目、甲方或主合同已删除时，日常入口不能继续采用，原历史及原件保留。正式施工合同保存后，可在对应客户的“施工合同”页签核对同一合同。由该页签进入合同详情时，“返回客户详情”保留原客户页签、滚动与原合同焦点；刷新合同详情或显式编辑保存后仍可返回。具体步骤及失败反馈见[客户档案指南](./customer-records.md#保存施工合同后核对客户关系)。

### 接管历史施工主合同和补充协议

在“系统设置 → 数据迁移”的“施工主合同与补充协议接管”选择真实完整 SQLite 原库，逐项明确对应已有正式项目、甲方和原我方核实版本，并补齐原路径指向的签约原件。采用保留主合同与协议原 ID、原 JSON、未知扩展、管理费配置历史、文件目录和审计；原库仍由外部保管，正式库仅保存本领域的原图证据和共享原件，不存其他领域的整库内容。

结果未知时核对原施工接管提交；已应用但后读失败时只重试读取。恢复按原采用批次整批核对，后来主合同修改、BOQ、WBS、原命令或支出归属历史已引用任一主合同则整批拒绝。安全恢复只归档本批采用，保留原件、编号和历史。历史补充协议与原主合同完整关联并可查看原件；新增补充协议仍按其独立工作流的实际开放范围使用。

同页的“分包主合同与补充协议接管”读取完整 SQLite 原库，通过动态查找逐项明确原项目、分供方和原我方核实版本，并按原文件 ID 补齐路径原件。主合同、协议、未知扩展、原 JSON、编号和审计保留原身份；正式库仅保留本领域证据与共享原件。未知结果核对原分包接管提交，已应用后读失败只重读。已被后来编辑、费用、工程关联或其历史消费的任一合同会令整批恢复拒绝；安全恢复仅归档采用，保留原件与历史。完整分包变洽签、结算及其他后续单据未接来源时，详情显示待核，相关金额保持未知。

### 核对总合同管理费配置

在施工主合同整页表单的“总合同管理费配置”填写配置额与合同条款或原件依据，保存后在同一合同详情核对，再从“查看配置历史”检查原采用版本。项目详情的同名分区按每份总合同展示配置，点击“查看总合同”回到对应稳定记录；供应商合同没有这组配置。字段、空与零及实际成本关系只见 [DATABASE](../rewrite/DATABASE.md#construction-contract-management-fee-configuration)。

原提交结果未知或保存后读回失败时，沿本页独立恢复入口核对同一原编号；恢复后检查金额和依据。正式施工存储及历史接管均保全配置历史；配置不是实际管理费成本或付款，不据此补造成本与现金。

材料采购和分包主合同选定或改选分供方时，履约联系人和联系方式会以新主档值覆盖，包括已手填的内容；新主档缺值则清空。随后可在合同内编辑，保存后保留本合同采用的值，合同与分供方后续修改不互相覆盖。新合同税率默认“未填写”；合同录入的金额派生、未填与明确零的差异只见 [DATABASE 合同金额](../rewrite/DATABASE.md#canonical-合同与补充协议)，不据该录入例外推定材料比价税点或真实税额。

## 三、公司支出、其他支出与采购结算

### 公司支出合同

进入“项目其他合同 → 公司支出合同”。公司支出用于房租、软件和其他公司层面合同，不挂任何项目。列表可按类别、状态筛选，并搜索合同名称、编号或对方单位；页面不会出现项目列或项目筛选。

新增或编辑时填写合同名称、类别、对方单位、签订日期、服务期、合同金额、付款周期、主要条款、附件和备注。保存时不会创建“公司”虚拟项目，也不会把对方单位自动当成项目分供方。

### 其他支出合同

进入“项目其他合同 → 其他支出合同”。其他支出用于机械租赁、检测服务和其他项目杂项合同。新建时动态检索“工程名称”，明确施工主合同并带出真实项目，再检索实际分供方；列表可按项目、类别、状态筛选，并搜索合同名称、编号或对方单位。两类合同的具体操作见[其他支出及公司合同指南](auxiliary-contracts.md)。

草稿保存也须已选择工程归属，其他允许留空的资料可稍后补齐；提交时系统会检查合同名称、项目、有效分供方、签订日期和金额。项目与分供方应按实际合同关系选择。

### 按施工主合同核对材料与实际费用

正式施工主合同详情和项目详情的“施工合同开支来源”分别显示材料、分包及其他支出合同承诺、原费用已发生金额与实际已支付金额。三栏各读原记录，不相加成另一份成本。合同的有效补充协议沿原父合同归属；工资仍按原项目工资簿与真实支付项目独立核对，不把项目工资重复计入每份施工主合同。

新建材料合同或实际原费用时，先在“工程名称”动态搜索并选择真实工程及施工主合同；同工程多份主合同以合同名称和编号区分，不自动采用第一份。工程归属与原合同/费用由同一个原提交一起保存，草稿也必须选择。费用每条明细仅关联一份主合同，共用费用先拆成真实明细，同工程不同主合同可逐行选；不同工程分单记录。清偿行和 Other 对原费用的采用沿同一原费用引用，不新记费用。结果未知时核对原来源编号，已保存但后读失败时只重试同记录读取，不能再造第二次保存。

已成立历史或已冻结来源未归属时继续保留，在其现有整页表单或原费用行的“施工主合同归属”补充核对；后续改关联保留原归属历史。已有归属会单独显示真实主合同名称和编号，即使草稿暂不能另选合同；没有合同读取权限或资料暂不可读时，显示对应状态及原关联编号。历史补充关联沿独立原关联编号恢复，不改变原金额、已发生费用、实际银行记录或原件。

当前关联已接材采、分包、项目其他支出合同和具有真实项目的 F3 原费用行，新草稿只保归属，不伪计承诺、已发生费用或现金。各类承诺从原合同及有效协议读取；结算或实际付款归属尚不可证时分别保留来源缺口，不能用承诺或结算金额替代银行事实。公司合同仍独立，其实际项目业务费用按原费用行处理，历史无项目记录继续保留。合同资料缺源或无权读取时，总承诺保持未知并保留可证部分。施工关联可撤销，原归属历史与原经济事实、现金、原件仍保留，任何曾消费的原引用都阻止危险迁入批恢复。

### 其他支出结算操作

1. 进入“项目其他合同 → 其他支出结算”，点击新建。
2. 先选择项目，再从该项目已提交、非草稿的其他支出合同中选择真实源合同。
3. 系统从源合同带出项目、分供方、合同金额和累计支付；这些来源信息不需要重复录入。
4. 填写结算金额、税务信息、结算日期、结算期间、扣减说明，并上传结算单或对账资料。
5. 保存草稿后可继续编辑；提交后进入待确认状态。

如果当前项目没有可结算的其他支出合同，表单会提供“前往合同列表”入口。请先维护并提交合同；草稿合同和手写的无来源合同都不能用于结算。

### 材料采购结算

进入“乙供材管理 → 材料采购结算”。操作顺序与其他支出结算相同，但源合同只能选择同项目的材料采购合同。系统带出真实分供方和合同信息，用户录入结算金额、税务信息、期间、扣减说明和对账附件。

材料采购合同中的物资名称、规格、数量和单价仍在采购合同明细中维护。结算只记录本次金额和对账资料，不会复制一份采购明细，也不会显示没有业务实体支撑的结算明细表。

如果合同选择框没有匹配结果，请使用“前往合同列表”进入“乙供材管理 → 材料采购合同”，先维护并提交同项目合同；草稿采购合同不会成为结算候选。

### 查找、空态与状态

- 四类列表底部的条数和金额合计只统计当前筛选结果；换筛选或搜索后从第一页重新查看。
- “暂无记录”表示当前业务还没有数据，可直接新建；“没有匹配结果”表示筛选过窄，可清除筛选。
- 加载失败时使用“重新加载”，不要把错误状态当作零数据。
- 合同提交后进入审批中；结算提交后进入待确认。只有完成真实确认/审批的支出结算才计入项目动态成本。
- 宽表在自身区域横向滚动，页面本身不会随表格左右移动。

## 四、材料采购明细

材料采购合同的“材采明细”支持逐行编辑，施工合同和分包合同不会显示虚构明细。

1. 点击“新增明细”，填写物资名称、规格、材质、品牌、单位、数量、含税单价、计划到货日期和备注。单位手工填写，未填保持空白；材质没有证据时保持未记录。
2. 含税金额由数量乘以含税单价自动计算，不能手工覆盖。
3. 勾选一行后，可复制或删除选中行；复制行会生成新的明细。
4. 从 Excel 复制单列，聚焦明细对应列的起始格后粘贴；再粘其他列到同一批行。中间空单元格保留行位置，超出已有行时追加，已有行的其他字段保留；日期使用 `YYYY-MM-DD`。
5. 完整明细仍可通过“粘贴导入”按物资、规格、品牌、单位、数量、含税单价、到货日、备注的八列顺序追加。非法数字会整批拒绝并显示行号，修正后重试；此入口不读取 `.xlsx` 文件。
6. 使用“材料文件导入”选择 Excel/CSV 文件，确认 Sheet 和字段映射，再预览全部材料行；逐行核对数量、计量单位和计价单位，修正错误后重新确认。还有错误或未核实时整批不能追加，全部通过才一次追加当前草稿，并保留原有行与真实来源文件。材料名称不会覆盖已有材料行。
7. 有优惠或扣减时在“优惠与扣减”填写名称、正值扣减金额及依据，界面按负额纳入合计一次；不为对平修改原材料量价。正式保存检查已提供材料行及减项，提交另核对合同头与材料、减项合计，计算直引 [DATABASE](../rewrite/DATABASE.md#contract-amount-reconciliation)。

在材料主合同详情选择“新增补充协议”，核对已有原合同；项目与分供方由原合同带出。协议填写自己的材料行，引用原行时保留稳定身份、真实新单价、本次增额及文书依据，新增材料按真实量价填写。保存后回到原主合同“补充协议”页签并聚焦本协议，原签约依据保持冻结；历史缺少当时依据显示未知，不用后来主合同量价补写。当前用途与历史迁入边界见 [DATABASE](../rewrite/DATABASE.md#材采明细与公司支出合同)。

明细区在窄屏和长表格下只在自身区域横向滚动，不会带动整个页面。

## 五、查看合同详情

合同详情顶部展示完整合同名称、编号、类型、状态及金额摘要。合同阶段依次为“拟定、审批与签订、履约、结算、结清”，只反映合同当前状态，不补造审批人或审批记录。

- “基本信息”展示项目、客户或分供方、签约信息、联系人、条款和备注。
- “关联单据”只展示明确关联当前合同的补充协议、变更、报量、结算、票款或材料单据；成功读取后没有关联才显示空态，来源失败按提示重试。
- 施工合同提供“详细资料、补充合同、甲方变洽签、验收结算、票税管理、收款登记、竣工验收及保修”七个可刷新分区。实际竣工日期没有正式记录时明确显示“未记录”，不会用计划日期或合同状态补写；点击补充合同会在当前主合同的“补充合同”分区稳定聚焦；点击甲方变洽签、月度报量、最终结算、甲方罚扣、竣工验收或保修到期会进入各自中央只读详情，返回后恢复原合同分区、分组和行焦点。
- 正式施工合同详情可按项目与合同稳定 ID 打开专属 BOQ。当前 BOQ 目录没有完全匹配的目标时，页面明确显示“不可用”，不会切换到其他项目或合同。
- 材料采购合同提供“详细信息、采购明细、补充协议、材料管理、发票登记、付款信息、支出结算、项目扣罚”八个可刷新页签；补充协议按当前主合同稳定定位。成功读取后没有已核验关系时显示明确空态，不用同项目或同分供方记录填充。
- 材料采购合同详情提供当前分供方的合同、结算、收票和付款四类事实入口；目标页直接打开对应页签。即使事实为 `0` 也保留真实空态，返回时恢复原合同页签，再返回材采列表与项目详情。
- “合同文件”可下载当前合同真实归档的文件；PDF、常见安全图片和纯文本可直接预览，HTML、SVG 等活动内容只允许下载后查看。

只读详情中的联系电话会脱敏。项目、客户和分供方可从详情继续下钻；合同到已闭合事实使用同一中央来源与稳定 ID，其他尚未消费同一来源的发票、付款、结算、罚扣及材料来源事实保持普通文本，不进入本地写态或不可达记录。演示数据只有在工作区显式开启并获授权后出现，详情始终只读；三类正式合同都可从详情显式进入整页编辑。加载失败时页面会保留上一次成功读取的中央详情并提供重试。

### 分包中央七分区

分包合同提供“详细资料、分包变洽签、收票登记、付款、结算、项目罚扣、材料领用”七个可刷新分区。补充合同与分包变洽签在该分区按稳定 ID 分开聚焦；点击分包变洽签编号进入专属只读详情，返回后恢复原分区、行和焦点。链接失效或不属于当前主合同时，页面分别提示目标不存在或父子关系不匹配，不会打开无目标蓝字。付款申请/登记和过程/完工结算分区核对；结算、结清没有独立记录时显示“未记录”，不根据余额自动认定。

“材料领用”当前因缺少合同或分供方稳定外键显示明确空态。这不是无材料业务的认定，系统也不会按名称、项目或班组猜测归属。正式合同可从详情显式进入整页编辑，保存后回到同一分区并可刷新读回；演示合同始终只读。

## 六、甲方单据、分包单据与项目罚扣

### 进入和查找

主合同管理下可进入“甲方变洽签、甲方报量、竣工验收·保修、最终结算、甲方罚扣单”；分包及人工下可进入“分包变洽签、分包结算、项目罚扣”。

1. 先选择项目，再按页面提供的类型和状态继续缩小范围。
2. 输入编号、名称/事由、报量期次、合同或业务对象搜索。
3. 项目详情的“项目商务单据”区提供六类甲方单据和“分包变洽签”入口；每个入口只按当前项目稳定 ID 筛选。也可从施工/分包合同或分供方详情进入，列表会显示当前来源范围；需要查看全量时，点击清除来源条件。
4. 五类甲方单据与分包变洽签点击单据编号进入各自专属只读详情；只有可编辑正式状态才显示“编辑单据”或“处理流转”。这些单据不会进入通用占位页，也不会互相借用详情、权限或金额链。
5. 页面底部条数和金额只统计当前筛选结果；切换搜索、项目、类型、状态或来源范围后从第一页开始。

“暂无记录”表示当前类型还没有数据，可直接新建；“没有匹配结果”表示筛选过窄，可清除筛选；加载失败时使用“重新加载”。宽表只在表格区域左右滚动。

### 新建和编辑

- 甲方单据选择项目和施工合同；分包单据选择项目、分供方和相符的非施工支出合同。项目罚扣还可关联班组。
- 新建时按顺序选择项目、合同和分供方；来源关系冲突会提示修正，不会静默改成其他合同。
- 甲方变洽签和甲方报量有真实量价/报量明细。其余 6 类没有业务明细子表，不会显示一张无法保存的空明细表。
- 附件随当前单据归档。保存草稿允许稍后补齐；已上报、已申报或已审定后仍可用“保存附件”独立补传、删除或恢复附件，不会把业务状态退回草稿；只有版本冲突后选择“保留本页供复制”时附件也进入只读。提交或确认时会校验必填项，并把焦点带到首个错误字段。
- 编辑页加载失败时先重试或返回列表，不要在空白表单中重新填写并覆盖原记录。

### 甲方变洽签与月度报量专属详情

- 甲方变洽签详情展示合同原量/价、变更方式、变更量、新单价、申报金额、附件和审批摘要。BOQ 量价变更和纯金额签证在同一列表/详情中读取，已签证台账不重复计一份。
- 月度报量详情同时展示自动完成量、申报量、审定量、申报/审定金额与核减差额，并列出取数基准、快照版本、源数据更新时间、经办人和系统提交时间。尚未审定时保持“未审定”，不用申报值冒充。
- 详情中项目、甲方客户、施工合同和来源单据均以稳定 ID 解析。无权限、目标不存在或来源/类型错配会分别提示，不会按名称回退到其他记录。
- 附件有真实文件时列出文件名、类别、上传人和时间；没有附件时明确显示“暂无附件”。
- 从列表进入后返回会恢复搜索、项目/合同范围、类型、状态、页码、滚动与行焦点；从项目详情或施工合同进入后返回原项目六类卡片或合同分区，并恢复原锚点、滚动与焦点。详情内再打开项目、甲方客户或施工合同，也可显式返回原单据；来源 BOQ 会按稳定 ID 定位到变更或月度报量。
- 草稿显示“编辑单据”；已上报变洽签和已申报报量显示“处理流转”，进入同一整页表单完成签证/审定。取消或完成后回到原详情，不丢失来源。
- 新增 BOQ 项在变洽签完成签证后生成稳定清单行；后续月度报量可直接选用该行。调量、调价及报量金额都按已签证链的有效工程量和单价重算，不使用表单中可篡改的合计。
- 申报日期和签证日期必须是真实存在的日历日；新签证日期不能早于同合同已有签证，同日多张签证按系统实际执行先后续排，避免台账金额与有效 BOQ 顺序不一致。报量经办人和系统提交时间只在点击申报时冻结，草稿不会提前生成审计记录。
- “量价变更合计”与“审定含税金额”分开保存和展示。纯金额签证可只填审定含税或审定不含税金额；月度报量审定时每条明细都必须显式填写审定量，填写 `0` 表示确认审定为零，留空不会被当成零。

### 竣工验收与保修双视图

- 在“竣工验收·保修”列表顶部切换“竣工验收”和“保修到期”。两个视图中同一单据的编号和 ID 不变，不会复制一份保修记录。
- 验收视图显示验收单位、验收人、验收日期、验收结论和验收报告；保修视图显示保修负责人、起止日、到期确认单位、确认日期、确认说明和到期确认单。没有真实附件或日期时明确显示未记录，不按状态猜测。
- 单据依次执行“上报验收”、“确认验收”、“开始保修”和“确认保修到期”。每次成功动作都记录执行人、时间、前后状态和备注；越级、重复操作会被拒绝，保修到期后业务信息只读。
- 从全局列表进入时，返回会恢复原视图、搜索、筛选、页码、滚动和行焦点。从项目或施工合同的“竣工验收及保修”分区进入时，返回会回到原项目/合同、原分组与原行。

### 最终结算专属详情

- 详情顶部展示结算申报金额、审定金额、变更后合同金额、累计收款和结算收款差额。审定金额或日期没有真实记录时显示“未记录”，不用申报值或 `0` 补位。
- 变更后合同金额按“原合同金额 + 非草稿补充协议”计算；累计收款只统计当前合同的活跃收款。这些是详情查询时的真实聚合，不会把合计数反写到结算单头。
- “结算来源”表分开列出补充协议和收款记录。点击编号可按稳定 ID 打开施工合同中的补充协议或客户收款详情；返回时回到原最终结算。小屏上只在该来源表区域左右滚动，页面本身不横向滚动。
- 项目、甲方客户、施工合同和结算源单均可以下钻并返回原详情。附件区只展示真实结算文件。
- 从项目详情进入时，列表保留项目筛选和项目返回地址；看完详情回到列表后仍可返回项目的“最终结算”卡片，并恢复焦点。
- 当前可保存草稿并提交；已提交的业务字段为只读。审定动作尚未实现，页面不显示假审定按钮。

### 甲方罚扣专属详情

- 在“甲方罚扣单”列表点击罚扣编号，查看负向罚扣金额、罚扣日期、当前状态、联系单号、罚扣事由、申诉说明、备注和联系单附件。没有记录的说明或附件保持“未记录/暂无附件”，不从其他罚扣类型补值。
- 项目、甲方客户、施工合同和罚扣来源都按稳定 ID 下钻。也可从施工合同“验收结算”分区的甲方罚扣行进入同一详情；返回会恢复原列表或合同分区、行和焦点。
- 从项目详情进入时，列表和详情共同保留项目返回地址；返回项目后聚焦原“甲方罚扣”卡片，不会落到其他单据入口。
- 正式草稿可以从详情进入整页编辑；提交时必须选择真实项目和施工合同，并填写正数罚扣金额、日期与事由。提交后详情只读，联系单附件随同一中央命令保存并可刷新读回。
- 申诉说明只是罚扣事实，不表示系统已建立申诉审批流程。当前状态只有“草稿”和“已提交”；本页面不会把甲方罚扣混入项目罚扣，也不会自动形成分包结算抵扣。

### 分包变洽签专属详情

- 在“分包变洽签”列表点击变更编号，可查看审批金额、变更面积、实际审定价、日期、类型、变更事由、状态、备注和签证单附件。没有记录的金额或附件保持“未记录/暂无附件”，不从合同金额或结算金额补值；实际审定价汇总在只有部分记录已回填时标记“部分记录”，全部未回填时显示“尚未回填”，不会伪装成完整的零元合计。
- 项目、分供方、分包合同和源单都按稳定 ID 下钻。也可从项目详情“分包变洽签”卡片、分供方详情入口或分包合同同名分区的事实行进入；返回会恢复原项目卡片、分供方入口、列表筛选或合同分区、滚动、行和焦点。
- 正式草稿和已退回记录可从详情进入整页编辑；保存、提交或取消后回到原详情。已提交记录只读，演示来源始终没有编辑入口。
- 项目、分供方与分包合同必须属于同一正式关系；来源页还必须具备分包变洽签查看权限才显示可点击入口。目标不存在、无权限、类型或父合同错配会分别提示，不按名称或编号猜测其他记录。加载失败时可重试，并保留上一次成功读取的详情。
- 当前只提供草稿保存和提交。审批金额、变更面积与实际审定价是三项独立事实；未实现的审批动作、双日期和合同金额链不会以假按钮或推算值出现，也不会混入分包结算或项目罚扣。

| 甲方变洽签 | 草稿 → 已提交 → 已签证；签证后锁定收入变更台账 |
| 甲方报量 | 草稿 → 已申报 → 已审定；申报和审定量均留痕 |
| 竣工验收·保修 | 草稿 → 验收中 → 已验收 → 保修中 → 保修到期；每步均保留审计记录 |
| 最终结算 | 草稿 → 已提交；保存与提交走中央命令，审定事实未记录时保持空值 |
| 甲方罚扣单 | 草稿 → 已提交；申诉说明作为单据事实保存 |
| 分包变洽签 | 草稿 → 已提交；已退回记录可修改后重报 |
| 分包结算 | 草稿 → 已确认；确认后成为真实支出结算 |
| 项目罚扣 | 草稿 → 待抵扣 → 已抵扣；抵扣选择真实已确认分包结算 |

已签证变更不能通过普通编辑篡改量价链。项目罚扣部分抵扣时继续显示剩余金额，系统保存罚扣与结算的独立关系，不会手工覆盖结算总额。

## 七、工程量清单工作台

进入“分包及人工 → 工程量清单”，先选择项目，再选择该项目的施工合同。页面会保留完整合同编号。

### 合同清单

- 左侧按“分部 → 工种 → 分项”筛选，右侧查看清单行、数量、单价、合价和来源。
- 原合同合价、签证变更额和当前合同合价为只读金额。
- 窄屏时目录移到表格上方，表格仍在自身区域横向滚动。
- 正式本机的“清单完整原件”区可下载所采用的 XLSX 原文件；E 类原件独立标注为分项单价库。原历史只有描述时显示“原件不可用”，不以历史本机路径读取文件。
- 保存或更正结果未知时先“核对原提交”；已有成功回执但读取失败时“重新读取已保存记录”。必须读回原文件、原清单行或原签证实际目标才释放编号，同项目同合同的空列表不代表已完成读取。

### 变更单

- 可查看草稿、已上报、已打回和已签证状态。
- 只有已签证且已经关联真实甲方变更台账的编号，才能进入对应来源单据。
- 没有来源的记录不会显示一个无法打开的假链接。
- 已签证“新增”明细会成为合同清单的稳定行，与原清单一起进入后续变更和月度报量。
- 正式本机读取量价签证和纯金额签证，并保留各自来源。附件可独立上传、下载、删除和恢复；已签证的业务状态不因此退回草稿。原件共享保存，删除只隐藏当前单据的附件引用，其他真实引用仍可读取。

### 月度报量

当前浏览器中央流程从“主合同管理 → 甲方报量”进入；工程量准备步骤见[工程量中央流程指南](quantity-central-workflow.md)。工程量清单工作台的旧本地草稿生成、调整及导出仍按其实际适配范围使用，不作为中央报量已经提交的证明。

:::flow
准备|建立当月完成事实|配置模板三量及清单关联 → 明确唯一报量阶段 → 分配责任 → 登记完成和照片
新建|选择项目、施工合同与月份|进入甲方报量整页 → 填申报日期 → 默认按现场复核量读取
核对|逐项看自动量与申报量|明确零保留为零 → 缺量不预填申报量 → 单价或申报量缺失显示待核对
换基准|确认后重算整单|选择合同量、暂估量或现场复核量 → 保留原稿，或确认清除旧手工量并重新生成
申报|保存当时的取数依据|核对后保存并申报 → 冻结自动量、申报量、有效单价和基准 → 等待甲方审定
审定|记录甲方逐项结果|每项明确填写审定量（允许零）→ 确认审定 → 在详情核对核减差额
:::

- 只统计所选月份、已完成且映射为报量阶段的工程量。同一分项参与多个施工阶段时，不会重复计入月报。
- 已投入实际户的清单分项若未配置报量阶段，先按提示进入阶段配置，不能把此时的缺配置理解为当月零量。配置完成但当月没有完成记录时才是正常零量。
- 自动量为已知部分的小计；旁边出现“缺量”时不能理解为已经完整。申报量留空与填写 `0` 含义不同；明确核对后再填写，不使用另一套基准补齐。
- 更换基准会先询问。点“保留原稿”维持原基准和手工值；点“确认重算”清除所有旧明细中的手工申报量，使用新基准重新生成。
- 保存草稿、导出或调整工程量都不会自动推进为“已申报”或“已审定”。申报后的快照不因模板后续修改而变化；手填申报日期与系统实际提交时间分别保存。
- 切换页签再返回会重新核对当前取数来源，已填手工量仍保留。已生效签证调整单价时，未提交报量使用当前有效价重算金额；读取失败先重试，关系或本单状态变化按页面提示核对。已提交报量仍保留原快照。规则见 [A03 版本与依据核对](../rewrite/COMMANDS.md#version-and-dependency-checks)；这一有效价处理已有本地中央证明，正式持久接管仍须另行验收。

## 八、导入和拆分合同清单

1. 进入“主合同管理 → 清单拆表”，选择项目和施工合同。
2. 上传清单文件，确认系统识别的格式类别和工作表。
3. 在人工确认页逐个工作表核对字段映射、户型与套数、差额、镜像户型和零量行。
4. 缺少分项名称、工程量或合同单价时，页面会持续展示具体工作表、缺失字段和恢复方法；修正前不能继续。
5. 在结果预览确认清单行和“文件·工作表·行号”来源，再写入工程量清单。

导入不会静默猜测缺失关系。无法匹配户型或标准分项的行会保留在清单中，等待人工处理。

正式本机导入必须明确实际项目和施工主合同。上传后保存完整原件与已人工确认的清单行；E 类只进入独立分项价格轨。工程量页明确关联稳定清单行后采用合同量，不能按同名分项或历史引用索引冒充当前可用来源。留空表示未提供，明确 `0` 保持真实零。

接管历史数据时切换到“原 SQLite 施工清单迁入”，先确认同一完整原库的施工主合同，再上传完整 SQLite 和按原 ID 要求补传的原清单。页面核对原文件、量价变化、纯金额签证、独立 E 价和历史缺件；原库继续在外部保留。确认期间身份、权限或来源变化时重新核对，不沿旧预检提交。安全恢复隐藏原采用批次并保留原件及审计，已有后来工程量、WBS、工资或原命令引用时整批拒绝。正式甲方月报未接管的来源仍明确不可用，不能以本地预览替代正式申报。

## 九、窄屏和键盘操作

- 在手机、平板和桌面宽度下，页面本身不会左右滚动；密集表格在自己的区域滚动。
- 合同详情页签可用左右方向键切换。
- 明细行选择使用可聚焦的复选框；工具栏按钮和业务入口保留清晰焦点。
- 长合同名称允许换行，完整合同编号和金额不会因窄屏被省略。
- 单据列表的搜索、筛选、清除来源、新建和分页都可用键盘到达；提交校验失败后会聚焦首个需要修正的字段。
- 项目详情的六类甲方单据和分包变洽签卡片均可用键盘进入；跨列表和详情返回后会恢复原卡片焦点。

## 分包结算：查看、草稿与确认

当前已可用：从“分包及人工 → 分包结算”、项目的分包结算卡片，或分包合同的结算分区进入。列表选择“已确认”可查看确认结算；点击编号进入只读详情。返回可恢复原筛选与来源位置。

新建时依次选择项目、分供方、分包合同，填写名称、金额、日期并上传结算单。资料未齐可保存草稿；确认无误后选择“保存并确认”。确认后锁定业务字段；草稿详情的“编辑结算”才会打开编辑表单。

累计结算只包含同一合同关系下的已确认记录。未记录表示相关资料尚不完整，不等于金额为零。确认结算可作为项目罚扣抵扣来源；中央执行、部分抵扣余额与审计历史现已可用。不会把合作关系终态结算或材料冲销混入此流程。

## 项目罚扣：整改与结算抵扣

当前已可用：从“分包及人工 → 项目罚扣”、项目业务单据卡片、分包合同罚扣分区或责任班组的项目罚扣记录进入专属详情。点击项目、分供方、合同、班组或已抵扣结算名称可查看来源，使用返回入口回到原页面。

1. 新建罚扣，填写项目、日期、事由、正数金额；按已有资料选择分供方、分包合同及责任班组，补充整改期限、说明和附件。保存草稿可继续编辑；保存并提交后金额不再普通编辑。
2. 在详情核对罚扣金额、累计已抵扣和剩余可抵扣。需要补充整改时点击“记录整改”，填写说明后保存；历史保留每次经办和时间。
3. 点击“结算抵扣”，选择真实已确认分包结算，核对双方余额后填写本次金额并确认。可以部分抵扣，也可以对同一结算分次抵扣；全部扣完后显示已抵扣。
4. 如无候选，先核对罚扣来源合同或分供方与结算关系。仅有同项目或班组不足以选中结算；不得用相同名称或金额替代关系。
5. 网络失败时保留原输入并重试，不会重复记账。如提示资料已变化，点击“刷新余额后重新核对”，按最新余额再次确认。抵扣历史可下钻结算核对净额；手机上在历史表格内部横向滚动查看完整列。

旧记录未记载的经办与历史会标为“历史未记录”，不会补造。当前没有甲方罚扣转扣、审批或抵扣撤销流程；这些动作不会出现在本页。本指南的中央接口仍属于当前可重置验证环境，正式服务的持久化部署边界见项目说明。
## 正式身份前置条件

浏览器中新建施工合同须先在客户、项目档案中建立正式记录；新建分包合同须先建立正式项目和分供方。表单候选及提交校验使用同一正式来源，演示记录不能写入正式合同。空白工作区没有候选时，先到 /base/customer、/project 或 /base/supplier 建档。
