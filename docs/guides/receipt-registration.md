本指南说明普通收款的登记、查阅、附件和来源返回。字段规则以[收款页面契约](../rewrite/pages/finance-receipt.md)为准；本指南不定义新的审批或退款流程。

## 1. 从哪里开始

打开“资金管理 → 收款登记”。列表中的收款编号进入只读详情；“新增收款”和详情中的“编辑”分别进入独立表单。

列表可按项目、状态和关键词查找记录。金额未填写时显示“未填写”，明确填入的零显示为 0.00；读取失败或无权查看会显示原因，不会用零代替。

从客户、施工合同、项目或最终结算进入收款时，使用页面的返回入口回到来源。有效的来源记录会恢复原筛选、分页与位置；过期或不再适用的来源信息按页面提示回到相应列表。地址中的客户等上下文不会改变收款记录本身的归属。

## 2. 登记一笔收款

1. 填写收款日期，选择项目。付款方客户必须与项目的主客户一致。
2. 如需关联施工合同，从当前项目的合同中选择；普通收款允许不选合同。
3. 填写金额和收款方式，按实际资料填写付款方账号、承兑汇票号、到期日、收款期次和银行流水号。
4. 填写经办人、审核状态文本及备注，上传收款回单或其他附件。
5. 根据当前办理进度选择保存动作。

提交时，日期必须真实有效，项目与客户必须可读且关系正确，金额必须大于零。金额最多保留两位小数；信息不符时，页面会保留输入供修正。

银行流水号可留空；填写后不能与其他收款重复。草稿也参与这一检查，编辑当前收款保留自身流水号不会被误判为重复。

## 3. 保存动作的区别

| 动作 | 保存后的结果 |
| --- | --- |
| 保存草稿 | 可保留尚未填完的资料，状态为草稿；缺金额与零金额分别保存 |
| 保存 | 校验完整资料；新记录默认草稿，已有记录保留已存状态 |
| 保存并提交 | 校验完整资料，状态变为已提交 |
| 保存并新建 | 保存当前记录后打开空白表单，继续登记下一笔 |
| 取消 | 放弃未保存输入，返回来源；已有记录不受影响 |

审核状态字段用于记录现有资料，不代表系统新增了一套审批流程。当前不提供收款确认、撤回确认、退款、红冲或作废业务操作。

保存时会核对同一记录的读取结果，再执行关闭或新建。出现“原提交结果未知”时点击“核对原提交”，保留本页输入与附件；确认原提交未应用后，才继续保存。出现“已保存待刷新”时点击“重新读取已保存记录”，无需再次提交。原编号恢复与读取确认的公共规则见 [COMMANDS](../rewrite/COMMANDS.md#idempotency-and-recovery)。

资料错误可直接修正；版本冲突说明记录已有更新，可选择改用服务器最新版，或明确保留本页内容并采用已核对的新版本。保存期间产生的后续输入会保留，页面不会自动关闭或跳到下一笔；请核对后继续办理。

## 4. 查阅合同与客户关系

普通收款保存后即属于当前工作区的收款来源，无需先建立最终结算。客户、施工合同、项目和最终结算读取同一收款事实；同一收款即使被多个结算引用，也只累计一次。

草稿和已作废的历史记录不进入有效收款累计。没有合同的收款可在客户和项目关系中查阅，合同相关指标显示为不适用或未知，不强行归入另一份合同。

合同原金额、变更金额、含本次与不含本次的累计收款和占比由当前可读事实派生。尚未接通或不可读取的开票等事实显示原因；页面不会依据空白、旧缓存或演示记录补造金额。

历史资料没有独立的收款分类和收款类型时，显示“未记录”。保留金和现金实现额尚无完整可核对来源，详情会说明当前未知；收款方式、状态或累计金额不会被拿来代替这些资料。

## 5. 附件与删除恢复

选择文件后，文件名和待保存状态会显示在表单中。收款与文件正文一起保存；全部成功后，刷新页面仍可读取附件。

在详情中预览受支持的文件，或下载原文件。删除和恢复操作在编辑表单中随收款一起保存；取消编辑不会立即删除服务器上的附件。

旧附件若只有名称或原本机路径、没有保存正文，系统会说明当前无法读取。原路径不代表当前设备可以访问该文件，需要重新上传正文。

## 6. 旧数据与使用边界

历史本地收款只能通过受控迁移进入当前来源，首次打开收款页面不会自动导入。迁移包含原有字段、附件元数据和已保存正文；缺失资料不会被猜测补齐。

重复同步保留已经在中央修改的记录。回滚只撤销仍可安全撤销的迁移批次；有后续修改或独立引用时先提示核对，整批拒绝回滚并保留记录、原件和回执。独立新建的收款不随该批次删除。

浏览器验证环境的全链行为不代表生产持久化、备份和部署已完成验收；生产启用仍以相应后置工作结果为准。桌面原有数据适配边界见 [ADR 0020](../adr/0020-browser-authority-and-demo-workspace-boundary.md)。
