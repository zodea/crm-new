# 本机分供方保存与原提交核对

本指南对应 [#453](https://github.com/zodea/crm-new/issues/453) 的本机磁盘路径，使用方法沿用[分供方档案](./supplier-records.md)与[证照资料核验](./supplier-credential-review.md)。当前已用隔离合成数据验证独立进程重启；首次真实业务写入仍需通过 [ADR 0021 的备份门禁](../adr/0021-single-operator-windows-production-storage.md#备份与恢复)及 [#471 上线验收](https://github.com/zodea/crm-new/issues/471)。可重置验证实例仍有各自边界，不能用它们替代本机正式数据。

## 当前已可用

本机服务中，主档、证照原件、资料要求、有效期、审核结论、OCR 原始候选及人工确认、人工税务核验记录与原提交回执写入同一磁盘数据库。重新启动服务后需再次登录，再读取原有记录；空库不会自动生成示例分供方。

项目、合同、结算、发票和付款尚未由本票接管。列表和详情明确显示“尚未接入”，相关数量及金额显示为未知，不表示零条业务或金额为零。这些数值暂不能筛选或排序；旧地址若带有相关条件会明确报出原因，可清除数值条件后重试。

## 保存主档时连接中断

1. 在分供方整页表单保存，等待明确成功结果。未确认时保留页面中的输入。
2. 同页出现“原提交结果未知”时，使用“核对原提交”；已有成功回执但后续读取失败时，使用“重新读取已保存记录”。原编号确认前保存入口暂停，当前输入仍保留；核对成功后可继续更正。
3. 刷新或服务重启后重新登录，在分供方列表的“上次分供方提交需要核对”区域进入对应提交，也可返回原编辑地址。
4. 页面核对成功后读取磁盘中的同一分供方。未保存的原请求会被封存，随后可重新填写并发起新提交。

等待响应时又填写的内容不会被原送出稿覆盖；核对显示的已保存资料仍对应当次实际提交。如需新建另一家分供方，先完成当前原编号核对。

浏览器只保留原提交编号，不保存银行信息、税号、核验备注或文件正文。尚未保存的正文在刷新后需要重新填写；不要把原提交核对当成草稿备份。浏览器无法保留编号时，系统会在发送前阻止保存并说明原因。

## 证照原件与人工核验

1. 从分供方详情进入“证照附件”，上传并保存原件。原件成功保存后可以预览、下载、维护资料与人工核验。
2. 上传、删除、恢复或核验提交失去响应时，先使用“恢复原提交”核对结果，不另传一份相同文件。刷新后重新进入同一证照页，也会核对原提交并重新读取原件和资料。
3. 核对或重新读取失败时，原编号仍保留。权限或当前身份变化时按页面提示重新登录、重新读取，不能绕过权限继续下载。
4. 主档中的“记录人工核验”也使用同一恢复方式。重新打开原表单后，已保存的核验结论、备注与日期从磁盘读取；官网查询仍由用户完成。

OCR 候选只用于人工核对。识别结果不会自动覆盖主档，识别失败也不会删除已保存的原件；本票验证的是候选与人工确认在重启后继续存在，未重新评估外部识别质量。

## 当前有效性与消息中心

查看或跨日刷新只更新页面判断，历史人工核验、原件及原提交不会被读取动作改写。明确更正关键资料后，原核验保留为历史，当前资料需要重新核验。消息中心会显示中央服务检查得到的持续问题；已读和关闭提示分别保留，补齐资料后仍可核对历史提醒。操作见[证照到期与历史核验](./supplier-credential-review.md#到期提醒与历史核验)。

## 当前边界

本票沿用已有分供方业务规则，不扩展分供方主档删除、跨域事实接管或多账号权限。备份副本、完整旧库迁入和最终上线分别按对应后续票验收。数据契约以[数据权威](../rewrite/DATABASE.md#pg-04-本机分供方持久参与者453)为准，验证记录见[验收证据](../design/evidence/issue-453-production-supplier/README.md)。
