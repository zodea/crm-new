## 三、使用边界

- 识别结果只作预填，仍需人工核对、选择归属并确认归档。
- 超时越界或留空时不能保存，页面会显示原因。
- 设置读取失败时不会显示“已保存”，识别参数、恢复默认和保存均不可操作；“重新读取设置”会取回原配置，不写入默认值。“重新检测”只检查 OCR 服务状态。
- 保存失败会保留未保存修改；处理错误后再次点击“保存设置”。只有保存成功才显示成功提示。
- 人工校对阈值保持只读；清单拆表仍走文件解析与人工映射。

## 四、发票本地识别接入进度

正在接入的发票识别先提取电子 PDF 文字，再在浏览器本地识别图片和缺少文字的扫描页；未识别内容保持未知，候选需人工核对。云识别仅在本人明确选择发送所选文件后调用，且需要对应环境已配置并允许该服务。该路径尚需中央发票工作台和部署验收，当前登录页不代表已提供此功能。

部署准备使用 `@paddleocr/paddleocr-js` 0.4.2 及 PP-OCRv6 small 检测、识别模型。模型从该版本 SDK 内标明的 Paddle 官方地址获取，不能从用户票据推导；准备好后由部署者核对文件摘要。构建时设置 `CRM_LOCAL_OCR_BUNDLE_OUTPUT` 为项目 `.tmp` 下尚不存在的直接子目录，执行 `pnpm run build:local-ocr-sdk`，输出中包含运行文件与第三方许可声明。将模型和运行文件分别准备到资源目录的 `ocr-models`、`ocr-runtime` 子目录，再在应用构建时设置 `CRM_LOCAL_OCR_ASSETS_DIRECTORY` 指向资源目录。资源必须由同一站点提供；加载失败不自动转发云端。运行服务切换版本前须先保存用户正在操作的内容。

开发验证使用独立的本机开发服务和合成资料。设置 `CRM_OCR_TEST_BASE_URL` 为该服务的 `http://127.0.0.1:端口/`，`CRM_OCR_TEST_OUTPUT` 为项目 `.tmp` 下的输出目录前缀，再运行 `pnpm exec playwright test -c tests/ocr-local-browser/playwright.config.ts`。该测试依赖服务已提供上述模型和运行文件，不连接正式数据；每次自动追加唯一后缀，不复用旧输出目录。
