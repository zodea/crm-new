## 一、此功能迁移什么，当前不迁移什么

本指南说明浏览器中已有本地数据如何显式切换到中央后台。当前迁移包含核心身份、施工与分包合同、补充协议、甲方单据，以及其他支出与公司支出合同、其他支出结算。页面按身份和父子关系自动安排导入顺序；以预检、导入计划和对账中列出的实体为准。

迁移会保留旧 ID 到中央 ID 的映射，并保留项目与客户、施工/分包合同、补充协议、甲方单据、班组、工人、分供方之间的明确关系。施工合同还会携带完整 BOQ 目录和尚未生成月报量单的已完成期次事实，因此从未出现在历史变更/月报量里的 BOQ 行也不会丢失；历史单据里的冻结名称和量价只作当时证据，不会覆盖同一稳定 BOQ ID 的当前目录。补充协议必须用旧主合同 ID 唯一对应施工或分包合同；甲方变洽签/月度报量必须唯一对应已导入项目和施工合同。找不到父关系或同一旧 ID 存在歧义时会阻断，不会猜测。确认切换后，已迁入合同、补充协议和两类甲方单据会进入各自中央只读详情；未知事实仍显示“未记录”。

当前中央服务是沿正式 HTTP/Repository 接缝运行的可重置验证实例，用来证明迁移、对账与回滚流程；它不是已经上线的生产持久化业务库。客户、分供方、班组、工人和项目分供方的普通业务页面已由 #281 接入各自中央 Repository、命令与稳定身份导航；确认迁移后，这些页面会消费中央身份及关系，不再把旧 production SQLite 当作普通业务数据源。本迁移功能仍只负责显式切换、对账与回滚，不替代这些页面。

辅助合同还会接管已有附件记录和明确关联的票款投影。公司合同不需要项目；两个合同表即使旧 ID 相同也分别映射。确认前不会提前接管，回滚后撤销该批辅助合同接管。当前辅助合同操作及测试实例限制见[其他支出与公司支出合同指南](./auxiliary-contracts.md)。

其他支出结算随真实源合同之后迁入，保留附件、罚扣抵扣、付款申请与支付分摊关系。相关付款源单独立迁入中央身份，罚扣沿用同一项目罚扣源；完整迁移同时核对这些源单，不能省略罚扣后仅验证结算快照。试跑发现合同类型、项目或分供方不符会阻断。金额未知不补零，多结算支付无精确分摊时保持未知；操作见[结算指南](./other-expense-settlement.md)。

本指南不提供资金审批或支付、补齐历史字段、用名称或金额猜测关系、启动时自动迁移等能力。各业务页面是否已闭环，以[功能路由索引](./routes.md)和对应使用指南为准；导入后不能继续把旧本地库当作正式数据源。

### 工资、考勤与签工迁移范围

工资按项目接管完整资料：工资头、明细、成员、实际分配、主体配置、考勤、签工、签工关联及可识别操作历史。项目尚未建立工资单时，已有配置、考勤和未领用签工也必须列入计划；缺真实项目身份时阻断，不创建空项目代替。

发放快照保留原文，后来的姓名、费率和规则不补写旧资料。退役 B 类、未知实发、缺分配、坏快照、关系缺损和同人同月来源冲突分别提示；隔离记录保原值供查证，不因此获得新的发放资格。零分配成员及没有工资行的成员仍可能受已发月份锁定，软删关系也保留历史。

确认后从工资台账、历史详情及考勤/签工来源页冷读同一中央资料。当前工资只读接管与后续新建、核对、发放及输出分开，见[工资与考勤指南](./payroll-attendance.md)。重复确认保留后来更正；独立工资、配置、考勤、签工、关联或历史占用使危险恢复整批拒绝，工程量、预算等其他资料也保持原值。

### 工程量迁移范围

已有工程量的项目会在导入计划中显示“工程量区域、模板与完成”。楼栋、楼层、户、模板、房间、分项、阶段、责任范围、完成记录、验收照片与审计记录一起迁入；原有归档和软删除事实保留。合同量、暂估量和现场量分别保留未知与明确零。没有工程量的项目不会自动生成空模板或完成记录。

工程量沿真实项目、班组、工人和合同身份关联。模板仍指向原有稳定 BOQ 身份，后来隐藏的历史关联也保留；当前清单数量、价格和签证变化由当前合同来源提供，不用迁移时副本替代。旧照片有正文时按原字节保留；缺正文时保留文件信息并明确提示缺失，不借其他照片补齐。

试跑会核对工程量内部关系和历史身份。确认时，系统先在独立候选中完成全部工程量写入及字段核对，再一起切换各领域与中央权威。准备或校验失败时保持原数据来源，其他领域也不会提前切换。当前仍为可重置验证实例，不代表生产持久化已交付。

### 标准工序库迁移范围

[#443](https://github.com/zodea/crm-new/issues/443) 将已有标准工序库版本及工序接入本指南的受控迁移流程。库名称、编码、版本、工序顺序、工期、工种、阶段和分项映射、前置关系及置灰状态一起保留；工序库是全局模板，不要求先配置某项目区域。正式库为空时不会自动填入演示工序。

预检发现重复版本、无效工序身份或断裂前置关系时会指出来源并阻止切换，不按相似名称合并。确认后从“标准工序库”查看旧版，再基于任意可见旧版新建下一版；原版仍保持只读。已删除版本的编号不会重新使用。版本使用情况从当前中央 WBS 读取，无法读取时显示未知。

工序库版本与项目排程分别列入迁移计划，先核对版本，再核对下述完整 WBS。新增内部暂估绑定的操作与验证状态见[项目启动与排程指南](./project-start-and-schedule.md)；迁入已有绑定历史不会重复执行绑定动作。当前中央服务仍是可重置验证实例。

回滚只撤回本批迁入工序库，独立中央新版本保留。如果新版还引用即将撤回的来源版本，或其他已接管记录仍依赖该图，系统会阻止整次回滚，当前所有领域保持不变。先核对依赖提示，不要手工删除原版本或修改切换标记。

### 施工排程 WBS 迁移范围

每个已有排程的项目作为一张完整关联图迁入：楼栋分组及范围、任务和分项映射、前置关系、置灰和删除记录、基线、手工进度、楼层计划与人工标记、建组时的工序库快照，以及已有合同绑定的身份和历史。旧的无分组任务也保留，不因当前页面以楼栋分组组织就丢弃。

试跑逐项核对项目、合同、区域、阶段、分项和库版本的明确关系；缺少身份或存在歧义时停止，不用同名对象代替。旧内部暂估已绑定合同、但楼层仍保留暂估量，是正常历史。冻结值中的明确零与缺失分别保留；历史没有记录单位或逐户来源时，会登记资料不足，不以当前模板或合同量反填旧记录。

确认时，排程与工程量在同一候选中完成核对并一起接管；准备失败不会先切走一半资料。确认后从普通“施工进度”打开同一项目，核对分组、日期、基线、手工进度、依赖禁用原因、楼层微调和既有绑定记录，刷新仍须一致。对比工序库使用项目及数量，确认来自同一张中央 WBS。再次确认同批迁移不会覆盖之后的日常更正。

恢复前会检查独立中央新建 WBS 是否还使用本批即将撤回的项目、合同、区域、阶段、分项或库版本；有依赖就阻止整次恢复，当前所有领域保持不变。不能删除独立 WBS 或改工程量完成记录来绕过保护。

### 目标成本预算迁移范围

每个旧预算版本与全部科目、行序、附件关系、已有正文、软删除和可识别操作历史一起迁入。没有项目的草稿、旧科目空名称、未记录的金额与明确零分别保留；原实体已经缺失但历史快照可明确归属的日志仍保留，未知操作人不补造。

预检发现重复当前基线、项目关系歧义或损坏身份时会指出具体来源并阻止切换，不按名称或更新时间猜选。只有路径或文件名的原件保持缺失，不扫描旧电脑目录，不用同名文件替代。确认时预算与同批核心身份一起核对、原子接管，失败不先切走一半。

确认后从普通目标成本列表打开迁入版本，核对头信息、明细、附件与历史，再刷新复查。日常更正和独立新建预算会被保留，同批再次确认不会覆盖它们。恢复旧备份若会破坏已经更正的预算或独立预算对项目等来源的引用，将阻止整次恢复，当前各领域保持不变。操作步骤见[目标成本预算指南](./target-cost.md)。

### 分供方证照迁移范围

旧分供方证照随所属主档一起接管。证照、类别要求、有效期、原件关系与正文、历史 OCR 候选与人工确认、供应商级人工核验凭证及专用审计作为完整关联资料保留；已软删除记录不会变成新的在用证照。日常原件上传、OCR 人工确认与人工核验的操作见[证照指南](./supplier-credential-review.md)，本迁移不重新执行识别或生成新的人工凭证。

预检发现分供方、证照或原件关系缺失、冲突时会阻止切换，不按名称猜测归属。只有旧文件路径而没有正文时，保留路径线索并明确提示原件缺失，不读取原用户目录，也不把文件名计入齐全度。内部唯一识别码与税号保留旧值原义，不根据位数相互搬值；历史未记录的操作人保持未知。

旧“合格”或“退回”只有具备供应商级人工核验凭证、且当前必需资料仍有效齐全时才可保留；单份证照的核验日期不能代替整户凭证。没有该凭证时重新计算资料状态。确认后从普通分供方的“证照附件”核对原件、要求与状态，并返回列表核对营业执照入口；使用方式见[证照与资料核验指南](./supplier-credential-review.md)。

迁移准备或核对失败不会先接管一半资料；同批再次确认不覆盖确认后的日常修改。回滚只撤回未经日常更正的本批证照图，并保留独立中央记录。证照已有日常更正，或独立记录仍依赖即将撤回的主档或原件关系时，整次回滚会被阻止，当前各领域保持不变。

## 二、开始前检查

1. 保存并关闭其他正在编辑的页面，避免把未保存输入误认为已迁移的数据。
2. 关闭顶部“包含测试数据”。迁移只允许读取浏览器的正式 `production` 快照，不能迁移演示数据。
3. 进入“设置 → 数据迁移”。首次打开只显示等待预检，不会读取、备份或导入任何本地记录。
4. 准备好处理预检或对账中显示的问题。系统不会通过名称、编号或金额自动补齐关联。
5. 当前迁移入口只支持浏览器工作区；Tauri 桌面端不会读取 IndexedDB，也不能从此页面执行切换。

## 三、执行迁移

按页面顺序逐步操作，每一步完成后再进入下一步：

1. 点击“运行预检”。系统核对本地来源版本、运行模式，以及当前各类身份和业务实体的记录数；本批新增的辅助合同也会单独列出。
2. 点击“创建不可变备份”。系统会重新读取备份字节并核对预检来源；期间数据若已变化，会停止并要求重新预检。备份 ID 会显示在页面，同一备份不能被后续操作覆盖。
3. 点击“执行 dry-run”。这一步只生成中央映射、导入计划和对账问题，不改变中央数据权威。
4. 查看“迁移对账”。缺失关联、孤儿、软删除、重复来源、数量/金额/计数差异或导入失败都会显示来源、字段、归因和原因。保留源软删除事实是信息性记录，不会单独阻止切换；软删除丢失或其他实际差异会阻止切换。缺少关系的记录不会被模糊匹配；先在源数据中修正，再重新预检和 dry-run。
5. 确认只有可安全映射的记录后，点击“导入可导入记录”。系统会先重新核对当前正式快照是否仍与备份一致；若其他页面在备份后写入了数据，本次导入会停止并要求重新预检和备份。页面会显示每类实体的来源数、可导入数和跳过数，以及中央导入快照；后台还会根据实际写入的中央实体重新核对数量、金额、关系、软删除和孤儿。
6. 对账通过后，点击“确认切换中央后台”。此操作需要预检、不可变备份和对账全部通过；系统会再次核对本地来源，若已变化会撤回中央待确认批次，不会隐藏新写入的本地事实。

确认前，旧库仍是本地来源；确认后，已迁入核心身份、合同、补充协议、甲方变洽签与月度报量的正式读写只能走中央后台。旧 `production` 快照的普通读取和写入会被阻断，不能用旧页面或本地直达路径绕过切换。

## 四、确认后核对

确认切换还会把补充协议与两类甲方单据随所属施工主合同接入中央事实源；旧 `production` 快照不再作为它们的普通正式读写来源。

1. 留在“数据迁移”页，核对中央导入快照中各类实体数量；分别打开其他支出和公司支出合同，检查附件、票款、审计字段，以及其他支出合同的真实项目与分供方链接。
2. 打开“项目信息 → 项目列表”，确认已导入的项目可见；再分别打开施工/分包合同，确认已导入合同与主数据关系稳定。对施工合同抽查一条没有历史变更的 BOQ 行，以及一个已完成但尚未成单的新期次，确认都能进入新建变洽签/月度报量。在施工合同“甲方变洽签”或“验收结算”分区打开已迁入变洽签/月度报量，确认项目、甲方、合同、来源 ID、申报/签证日期、报量取数基准与快照版本、明细及附件正确，返回后仍在原合同分区。未知事实没有被推断填充。
3. 分别进入 `/base/customer`、`/base/supplier`、`/base/crew`、`/base/worker` 与 `/project`，打开迁入记录的编辑页。保存修改后，普通列表使用修改后的内容；同批迁移再次同步不会覆盖该修改。项目客户与工人班组按迁入的稳定 ID 关联；项目分供方关系仍在对应只读入口核对。迁移只补入来源快照明确提供的字段，缺少的业务信息需在普通表单补齐。
4. 刷新浏览器后再次打开“数据迁移”。系统会校验本机迁移标记和中央活动批次；二者不一致时会停止并提示错误，不会静默回退读取旧库。
5. 在回滚窗口截止时间前，保留可追溯的导入批次、备份 ID 和对账结果；不要手动清理浏览器站点数据。

工程量项目另需抽查区域与模板、三量的未知和零、阶段完成时的责任人，以及一份验收照片。普通中央更正保存后，再次确认同一批次不会覆盖更正。月度取数继续使用当前工程量事实，按合同量、暂估量或现场量选择基准；迁移快照不作为另一份日常报量来源。

暂估排程接管后，分别核对一份已有合同绑定和一份尚未绑定的分组；旧绑定只读已有关系与可识别历史。尚未绑定的分组完成后补合同，或已确认导入清单后来更正了楼栋证据，再确认同一批次均须保留这些日常操作。具体绑定操作及本轮验证范围见[项目启动与排程指南](./project-start-and-schedule.md)。

分供方证照另需抽查一份原件，确认刷新后仍可预览和下载；核对类别要求、有效期、人工凭证及历史软删除。缺正文时明确显示缺失；迁入后新上传原件或修改资料要求，再确认同一批次不能覆盖这些日常更正。

目标成本另需核对一份有原件版本及一份缺项目草稿，逐项比较金额空值与真实零、科目行序、当前基线、缺件提示和历史记录。保存一次正常更正后，再次确认同批迁移须保留该更正；不要把重新迁入作为覆盖日常更正的方式。

## 五、回滚

仅在页面显示的回滚窗口内，且确认需要撤销本次切换时执行：

1. 回到“设置 → 数据迁移”。
2. 核对当前批次和回滚截止时间，点击“回滚到本地快照”。
3. 各领域先核对能否回滚；证照已有日常更正或待撤身份仍被独立记录引用时，整批阻止。通过检查后，系统撤销本批接管并恢复受保护的本地备份、清除切换标记，其他独立中央主档保留。
4. 完成后重新检查本地数据。不要用复制浏览器存储、手工改标记等方式模拟回滚。

工程量回滚仅撤回本批迁入的区域、模板、责任与完成事实及其后续更正，其他项目独立新增的工程量保留。如果迁入项目下已有独立新增记录，仍依赖即将撤回的项目或区域，系统会阻止整次回滚并保留当前全部数据来源。此时先核对提示中的记录和批次，处理依赖后再重试；不要手工删除祖先或修改切换标记。

若页面显示“中央已回滚，待恢复本地快照”，保留页面和浏览器数据，按提示再次执行恢复；恢复前不要继续录入或重新发起迁移。对账区优先提示待恢复，历史记录仍可查看。恢复期间不允许预检、备份、试跑或导入。已切换或仍待恢复时，不能另开迁移覆盖当前批次。

## 六、常见提示

| 提示或现象 | 应对方式 |
| --- | --- |
| “请先关闭包含测试数据” | 关闭测试数据并让应用重新加载后，再运行预检。 |
| “找不到可备份的本地 production 数据快照” | 确认当前浏览器仍保存正式本地数据；不要用演示快照替代。 |
| 对账出现缺失关联或孤儿 | 回到旧来源修复明确 ID 关系，重新执行预检、备份和 dry-run；不要改名后重试。 |
| 补充协议父合同旧 ID 同时命中施工和分包合同 | 修正旧来源中的主合同 ID，使其只对应一类主合同；系统不会代选父类型。 |
| 甲方单据的项目或施工合同成为孤儿 | 修正旧来源中的稳定 `project_id` / `contract_id`；不要用项目名、合同编号或金额进行模糊对应。 |
| 已签证 BOQ 变更与锁定台账数量看似不一致 | 先核对 `ledger_id` / 来源 ID；受控迁移会去除同一业务事实的重复投影，不应为对齐数量手工复制单据。 |
| 对账出现数量、金额或计数差异 | 核对来源事实和导入计划，确认差异归因后再决定是否修复来源；不能把未知值改为 0 以求通过。 |
| 工程量历史照片缺少正文 | 保留原文件信息；当前无法预览的照片按明确缺失处理，需要时由业务经办重新上传。 |
| 旧证照只有文件路径或文件名 | 该线索不计入资料齐全度；确认后在对应分供方证照页重新选择真实原件上传。 |
| 旧“合格”迁入后变成待核验或缺失 | 核对整体人工凭证与有效原件；不用单份证照日期或导入状态强行恢复合格。 |
| 工程量独立新增记录阻止回滚 | 原中央来源与其他领域均保持不变；先核对新增记录对迁入项目或区域的依赖，再按批次重试。 |
| 排程冻结数量显示历史不足 | 保留已存数值和旧快照；不要用当前模板、合同量或现场量补造历史。 |
| 独立中央 WBS 阻止恢复 | 核对提示中的项目、合同、区域或库版本依赖；当前资料保持不变，不手工删排程或改切换标记。 |
| 迁入后新增绑定或清单楼栋更正阻止恢复 | 核对当前绑定、原清单和所属批次；系统保留各领域现状，不会先清审计再删除来源。 |
| 刷新后提示本机与中央批次不一致 | 停止录入，保留浏览器数据与提示信息，交由管理员依据批次、备份 ID 和中央快照处理。 |
| 需要继续使用旧数据 | 在回滚窗口内使用“回滚到本地快照”；窗口关闭后不要绕过中央权威。 |
