## 一、当前已可用的客户主链

## 二、查看和查找客户

1. 进入“基础信息 → 客户”。
2. 在搜索框输入客户名称、简称、统一社会信用代码或联系人。搜索和状态筛选作用于中央结果，不只是当前页。
3. 使用“排序”选择最近更新、名称升序或名称降序；使用“档案状态”缩小范围。
4. 点击客户名称或行尾详情图标进入只读详情。列表的编辑图标不可执行，提示需要从详情显式进入编辑。
5. 列表中的统一社会信用代码和联系电话为脱敏显示；需要核对完整主数据时进入详情。

正式数据和测试数据不会混成一个不可区分的来源。顶栏“测试数据”关闭时只显示正式客户；显式开启且具有权限时才显示测试客户。测试客户详情带“测试数据”标识且没有编辑入口。

## 三、查看客户主数据和业务关系

客户详情顶部展示名称、税号或简称、档案状态和数据来源。摘要区展示名下项目数、施工合同数、有效合同额、有效收款和待收差额。

| 页签 | 展示内容 | 关系规则 |
| --- | --- | --- |
| 名下项目 | 项目名称、编码、客户角色、状态、负责人及金额摘要 | 只按稳定客户 ID 读取主客户或次客户关系 |
| 施工合同 | 合同、所属项目、有效合同额、累计收款和待收余额 | 只读取真实施工合同外键，不按客户名称猜测 |
| 收款明细 | 收款单号、日期、项目、合同、付款账户和金额 | 单号按稳定 ID 进入中央只读收款详情；不从合同额推算收款 |

蓝色关系名称只在目标有稳定 ID、路由已登记且用户有权限时出现。“未记录”表示关系外键缺失；“无权限”表示关系存在但不能查看。两者都不会生成死链，也不会泄露受限名称。

## 四、新建和显式编辑正式客户

### 新建正式客户

1. 在客户列表点击工具栏或空状态中的“新建客户”。
2. 填写客户名称、简称、统一社会信用代码、法定代表人、注册地址、开票与银行资料、联系人和联系电话。
3. 需要时添加附件；客户附件上限为 9 份。
4. 点击“保存”。中央后台分配正式客户 ID 后，页面进入该客户详情。
5. 刷新详情或返回列表，确认客户仍然存在。

### 编辑正式客户

1. 从客户列表进入客户详情。
2. 点击详情顶部“编辑”；测试客户没有此入口。
3. 修改字段后点击“保存”。若客户已被另一操作更新，系统停止覆盖并显示版本冲突；选择保留当前内容后再次保存，或改用服务器最新版。
4. 保存成功后回到同一客户详情。标题、主数据和后续列表均以中央读回结果为准。

统一社会信用代码在正式客户间重复时会显示字段错误。中央服务不可用时，客户正式数据不会改变，页面会明确显示保存失败；当前客户表单没有离线自动重放能力。

## 五、返回原列表位置

从列表进入客户详情时，系统记录当前搜索、状态、排序、页码、每页条数、工作区滚动位置和所选行。继续进入编辑并保存，或从收款明细进入只读收款详情再返回客户后，点击“返回客户列表”都会恢复这些状态，并把键盘焦点放回原客户行。

直接打开详情、返回信息已过期或地址包含外部网站时，系统只返回规范客户列表 `/base/customer`。不要手工修改详情地址中的 `origin`；客户 ID 与来源不一致时会显示来源错配，不会按同名客户回退。

## 六、当前边界

### 当前已可用

- 浏览器正式客户中央新建、编辑、版本冲突和保存后读回。
- 正式与测试来源隔离，测试客户只读。
- 客户列表、只读详情、三个关系页签和完整列表返回上下文。
- 缺失关系、无权限关系、客户不存在和来源错配的独立状态。

### 已定稿待开发

- 客户中央删除、软删除恢复及下游影响确认。
- 正式登录、完整 RBAC 和生产持久化后台；当前中央端是可重置的非生产证明实例。
- 收款详情只读查看已可用；收款编辑继续从收款列表的显式编辑动作进入独立表单。
- 班组、工人和分供方等其他基础主数据的同类中央闭环。
