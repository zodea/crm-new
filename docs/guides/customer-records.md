## 一、当前已可用的客户主链

浏览器中的客户列表、客户详情和正式客户新增/编辑现已接入中央后台。正式客户保存后，列表与详情会重新读取中央结果；页面不会用表单草稿伪装保存成功。测试客户保持只读，并与正式客户明确标注来源。

`#450` 新增本机客户磁盘验证路径、访问码、原件下载和软删除恢复，具体步骤及正式写入的备份门禁见[本机客户保存与重新登录](./local-customer-storage.md)。默认开发实例的保存不能据此宣称持久化；本机模式未接管的项目/合同/收款关系明确未知。

## 二、查看和查找客户

1. 进入“基础信息 → 客户”。
2. 在搜索框输入客户名称、简称、统一社会信用代码或联系人。搜索和状态筛选作用于中央结果，不只是当前页。
3. 使用“排序”选择最近更新、名称升序或名称降序；使用“档案状态”缩小范围。
4. 点击客户名称或行尾详情图标进入只读详情。列表的编辑图标不可执行，提示需要从详情显式进入编辑。
5. 列表中的统一社会信用代码和联系电话为脱敏显示；需要核对完整主数据时进入详情。

正式数据和测试数据不会混成一个不可区分的来源。顶栏“测试数据”关闭时只显示正式客户；显式开启且具有权限时才显示测试客户。测试客户详情带“测试数据”标识且没有编辑入口。

## 三、查看客户主数据和业务关系

客户详情顶部展示名称、税号或简称、档案状态和数据来源。摘要区展示名下项目数、施工合同数、有效合同额、有效收款和待收差额。

| 页签 | 展示内容 | 关系规则 |
| --- | --- | --- |
| 名下项目 | 项目名称、编码、客户角色、状态、负责人及金额摘要 | 只按稳定客户 ID 读取主客户或次客户关系 |
| 施工合同 | 合同、所属项目、有效合同额、累计收款和待收余额 | 只读取真实施工合同外键，不按客户名称猜测 |
| 收款明细 | 收款单号、日期、项目、合同、付款账户和金额 | 单号按稳定 ID 进入中央只读收款详情；不从合同额推算收款 |

蓝色关系名称只在目标有稳定 ID、路由已登记且用户有权限时出现。“未记录”表示未登记该关系。无权查看的项目不出现在名下项目列表及数量中；如果整个项目读取被拒绝，关系区显示“无权查看关联项目”，数量显示“—”。

### 保存或导入项目后核对关联

1. 新建项目并选择客户，或使用[项目 Excel 导入](./project-excel-import.md)选择真实客户身份后确认导入。
2. 打开对应客户详情，在“名下项目”核对项目名称、主客户或次客户角色及数量。同一项目只计一次；同名客户按各自身份分别关联。
3. 点击项目名称进入项目详情。即使刷新项目详情，仍可点击“返回客户详情”回到原客户页签、滚动位置及原项目链接。
4. 项目更换客户后，重新进入或刷新相关客户详情，旧客户移除该项目，新客户显示该项目。修改客户名称不会断开既有项目关系。
5. “暂无名下项目”表示已读取且没有可见关联；“关联项目加载失败”表示暂时无法确认结果，点击“重新加载关联项目”后再核对，不把失败当成零项目。

### 保存施工合同后核对客户关系

1. 在施工合同整页表单选择正式项目及该项目当前主客户。刚保存的正式客户和项目会出现在候选中；同名时核对所选记录身份。
2. 保存成功并进入合同详情后，打开对应客户的“施工合同”页签，核对合同名称、金额、日期、状态和所属项目。
3. 点击合同名称进入施工合同详情，再点击“返回客户详情”，会回到原页签、滚动位置和原合同链接。合同详情刷新或显式编辑保存后，这条返回路径继续保留。
4. 合同改名或金额更正后，重新进入或刷新客户详情可见新结果。项目更换客户不会自动改变已存合同甲方；需要更正合同归属时显式编辑合同，保存必须符合项目当前甲方关系。
5. “有效合同额”包括主合同及有效补充协议，草稿合同计数但有效额为零。合同详情的“变更后金额”还可包含已审定变洽签，两者不是同一口径。
6. “施工合同加载失败”或“无权查看施工合同”表示当前无法确认合同集合，数量和相关金额显示“—”。可重试时点击“重新加载施工合同”；不要把失败当作没有合同。

### 核对收款来源与失败反馈

客户的收款明细读取当前可查看的中央收款事实。同一笔收款被多张最终结算引用时只计一次；来源撤回后，刷新客户或收款详情会重新核对，不保留旧记录。尚未记录付款账户时显示“—”。

“暂无收款记录”表示读取成功且当前没有可见记录。“收款明细加载失败”或“无权查看收款明细”表示暂时不能确认收款，相关数量、有效收款和待收差额显示“—”；其他客户资料仍可查看。出现“重新加载收款明细”时可点击或用键盘重试。

普通收款登记、列表、详情、迁移及客户关联已由 #436 接入同一中央收款事实源；不再仅依赖最终结算中的临时来源。当前中央验证链的步骤见[收款登记指南](./receipt-registration.md)，本机正式磁盘接管及上线仍沿 [ARCHITECTURE](../rewrite/ARCHITECTURE.md#runtime-environments)另行验收；没有接通的正式来源继续显示未知。

## 四、新建和显式编辑正式客户

### 新建正式客户

1. 在客户列表点击工具栏或空状态中的“新建客户”。
2. 填写客户名称、简称、统一社会信用代码、法定代表人、注册地址、开票与银行资料、联系人和联系电话。
3. 需要时添加附件；客户附件上限为 9 份。
4. 点击“保存”。中央后台分配正式客户 ID 后，页面进入该客户详情。
5. 刷新详情或返回列表，确认客户仍然存在。

### 编辑正式客户

1. 从客户列表进入客户详情。
2. 点击详情顶部“编辑”；测试客户没有此入口。
3. 修改字段后点击“保存”。若客户已被另一操作更新，系统停止覆盖并显示版本冲突；选择保留当前内容后再次保存，或改用服务器最新版。
4. 保存成功后回到同一客户详情。标题、主数据和后续列表均以中央读回结果为准。

统一社会信用代码在正式客户间重复时会显示字段错误。中央服务不可用时，客户正式数据不会改变，页面会明确显示保存失败；当前客户表单没有离线自动重放能力。

## 五、返回原列表位置

从列表进入客户详情时，系统记录当前搜索、状态、排序、页码、每页条数、工作区滚动位置和所选行。继续进入编辑并保存，或从名下项目、施工合同、收款明细进入对应详情再返回客户后，点击“返回客户列表”都会恢复这些状态，并把键盘焦点放回原客户行。

项目或施工合同详情暂时加载失败时，已记录的有效客户来源仍提供返回入口。直接打开详情、返回信息过期或不合法时，返回对应业务列表；客户关系已变化、原链接不再存在时，返回客户后焦点停在业务关系区。客户详情子表目前展示完整可见集合，没有独立的筛选或分页工具。

直接打开详情、返回信息已过期或地址包含外部网站时，系统只返回规范客户列表 `/base/customer`。不要手工修改详情地址中的 `origin`；客户 ID 与来源不一致时会显示来源错配，不会按同名客户回退。

## 六、当前边界

### 当前已可用

- 浏览器正式客户中央新建、编辑、版本冲突和保存后读回。
- 正式与测试来源隔离，测试客户只读。
- 客户列表、只读详情、三个关系页签和完整列表返回上下文。
- 正式项目新建或 Excel 导入后的关联回读，以及项目详情刷新后的客户往返。
- 正式施工合同保存后的客户回读，以及合同详情刷新、显式编辑后的往返；其他收款正式写源链仍需各自验证。
- 缺失关系、无权限关系、客户不存在和来源错配的独立状态。
- 收款详情只读查看已可用；收款编辑继续从收款列表的显式编辑动作进入独立表单。
- 分供方、班组和工人的已有主档能力分别见对应使用指南，本指南不重复维护它们的实现状态。

### 已定稿待开发

- 客户中央删除、软删除恢复及下游影响确认。

### 验证环境与本轮范围

- 当前中央端是可重置的非生产验证实例。“保存后刷新可读”不等于已完成服务重启持久化、备份恢复和正式部署；这些能力在后置上线关口单独验收。
- 完整登录、账号管理和完整 RBAC 不在本轮范围内；现有操作权限、无权限提示和正式/测试来源隔离仍须有效。
