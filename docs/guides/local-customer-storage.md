# 本机客户保存与重新登录

对应 [#450](https://github.com/zodea/crm-new/issues/450) 的客户首条磁盘保存路径。当前用于独立合成目录验证；正式资料写入仍等待独立介质基线备份及最终上线验收。其他领域的实际环境与未接管边界见 [ARCHITECTURE](../rewrite/ARCHITECTURE.md#runtime-environments)，最终放行直接核对 [#471](https://github.com/zodea/crm-new/issues/471)，客户通过不等于全站上线。

## 进入工作区

维护人完成本机配置后，在这台电脑的固定入口输入访问码。客户审计的操作者来自服务端固定配置，页面不能指定其他人。登录成功后进入客户列表，顶部持续显示维护人和用途；看到“隔离验证工作区”时只使用合成资料。

连续 30 分钟无业务请求或登录达到 8 小时，需要重新登录；页面定时核对状态不会延长期限。退出登录、再次登录和重启服务会撤销旧会话。不要依赖过期后恢复未保存的字段和文件；已成功保存的客户、原件和回执保留在磁盘。

状态核对暂时断线时，页面遮挡操作但保留已输入字段和已选原件；点击“重新核对”或连接恢复后继续。只有后台明确登录已失效才退出业务页面，短暂网络错误不等于退出。

## 客户与原件

1. 从客户列表“新建客户”，按[客户档案指南](./customer-records.md)填写。
2. 附件区显示“原件随客户一同保存”时，可选最多 9 份原件，单份不超过 10 MiB。文件读取完成前不能提交；未保存正文只留当前页面内存。
3. 保存后从详情进入编辑页，使用“下载原件”取回文件。后台检查客户归属、删除状态、大小与摘要。
4. 版本冲突时保留输入，明确选择使用最新内容或基于最新版本继续更正，不自动覆盖。

客户详情中的项目关联在 [#452 项目持久化](./local-project-storage.md)参与者就绪后，按主/次客户稳定关系回读。材采合同日常磁盘验证来源就绪时按实际记录回读，协议、减项和原件沿真实 owner 核验；施工/分包、收款及材采真实收票、付款、结算等尚未接管的正式来源继续明确不可用和未知，不把空数组当成“没有业务”或金额为零。

## 保存提示丢失

发送后浏览器只保留工作区、维护人和页面目标对应的原提交编号，不存客户正文或附件。失败提示不一定代表未保存。

- 页面出现“原提交结果未知”时，点击“核对原提交”。核对完成前不能保存新的内容；已保存的原件不会重复添加，确认未保存时原编号先封存，再允许新的提交。
- 已收到保存回执、但客户重新读取失败时，页面显示“已保存待刷新”。点击“重新读取已保存记录”只重试读取，不再写入，也不自动关闭表单。成功后保留保存期间继续编辑的内容，再次保存才形成新的更正。
- 刷新或服务重启后，重新登录，在客户列表“上次客户提交需要核对”打开对应入口。成功则读回磁盘客户；未保存会明确说明，刷新前字段和附件需重新填写。
- 网络、权限或原件读取失败仍属未知，不自行判为未保存。恢复服务后继续核对，不要清理浏览器存储绕过。

这是结果核对，不是离线保存或自动重放。关闭整个浏览器会话后，已保存事实仍在磁盘，但未核对编号不承诺自动恢复；先从客户列表核对实际记录，避免重复新建。

## 删除与恢复

详情“客户保存与恢复”提供删除确认；取消不修改客户。客户仍被有效项目、施工合同或开票申请引用时不能删除，提示会列出各类记录的数量，需先处理这些记录。确认后正常列表移除，原件保留。列表下方“已删除客户”可打开原档案并恢复。删除期间不能编辑或下载，恢复后才能继续；单独删除的附件不会随客户恢复而自动恢复。

## 维护边界

运行选型与备份权威见 [ADR 0021](../adr/0021-single-operator-windows-production-storage.md)。固定 Node `24.12.0`，该版本 `node:sqlite` 仍为实验 API，升级先验证副本。真实配置与访问码只留本机受控位置，不入仓库或对话。

| 配置 | 要求 |
| --- | --- |
| `CRM_RUN_MODE` | `production` 启用磁盘和保护；缺省为开发模式，拼写错误拒绝 |
| `CRM_DATA_DIRECTORY` | 已存在、可读写的本机绝对目录，不得为网络共享或链接 |
| `CRM_WORKSPACE_ID` / `CRM_OWNER_ID` | 固定工作区与唯一维护人，必须匹配库内登记 |
| `CRM_DATA_PURPOSE` | 合成验证为 `verification`；缺省 `production`，首次业务写入保持关闭 |
| `CRM_PUBLIC_ORIGIN` / `NITRO_HOST` | 固定 `http://127.0.0.1:端口` / `127.0.0.1` |
| `CRM_ACCESS_CODE_HASH` | scrypt 盐与摘要，后台校验格式，不保存明文 |

数据目录中的 `ruihang.sqlite` 同时包含客户、原件、审计和回执。运行时可能有 WAL/SHM，不能只复制活动主文件充当可恢复备份。备份和隔离验证见 [PG-02 使用指南](./local-backup-and-restore.md)；没有绕过基线备份和最终上线验收的启用开关。

配置不全、不可写、损坏、版本不兼容或身份/用途不匹配时停止处理，不回退测试数据。不要删除现有数据库排错，也不要将正式目录改成验证用途；保留原库与原件，按维护流程核对。
