## 一、当前可用能力

浏览器中的识别归档、归档库、详情、打印和原件导出读取同一份已保存记录。遇到来源或权限错误时按页面提示重新读取；系统不会从同名本机档案自动补齐。旧本机数据需经过“本地数据迁移”的预检、备份、对账和明确确认，不能直接当作已经迁入。

| 能力 | 当前进度 |
| --- | --- |
| 查看送货单归档记录 | 已实现 |
| 按项目树、日期范围和关键词筛选 | 已实现 |
| 展开送货单中的材料明细行 | 已实现 |
| 按当前筛选结果导出原件包 ZIP（含 Excel 明细） | 已实现 |
| 缺少原件、未区分分供方和数量/金额缺失提示 | 已实现 |
| PDF 原件整份原样保留、共用原件去重 | 已实现 |
| PNG/JPG 图片另行生成只含图片的 PDF | 已实现（用户可选，依赖当前运行环境图片渲染能力） |
| 多份 PDF 保持原对象的无损合并 | 待后续依赖选型与实现；当前不重建、不合并 PDF 原件 |

## 二、识别与人工归档边界（#253 已收口）

- 所有 OCR 结果先生成“待人工归档”草稿，不自动归档。
- 标准版式可以自动预处理；手写、低清、字段不足或非标准单据进入人工处理队列。
- 缺少单价或金额时，人工查看原件并确认送货事实后可以先归档；系统标记“价格待补录”，该行在补录并确认有效单价前不得进入价格分析。
- 数量×单价与金额不一致时标记“金额待复核”；人工确认并填写原因后才能归档。
- 供应商或日期缺失时不得自动补全；单号缺失可以人工确认后归档，并标记“原件无单号”。
- 每行材料的名称、单位和非零数量必须人工确认；相同文件只识别一次。

## 三、查看与筛选归档记录

1. 进入“材料管理 → 送货单归档库”。归档库只展示已经归档、可追溯的送货单记录；识别处理中记录仍在处理队列中。
2. 可选择项目树节点，输入送货单号、项目、分供方或原件文件名进行搜索。
3. 需要缩小时间范围时，填写开始日期和结束日期；筛选会同时作用于列表和后续导出。
4. 展开一条记录可查看该送货单下的材料、规格、单位、数量、单价和金额等明细。

## 四、导出送货单原件包

1. 先按项目、日期或关键词筛选出需要交付的记录。
2. 如需把 PNG/JPG 图片另行封装到一个 PDF，勾选“图片另生成 PDF”。该选项只处理图片，不处理 PDF 原件。
3. 点击“导出原件包”，系统下载当前筛选结果的 ZIP。
4. ZIP 固定包含 `送货单明细.xlsx` 和 `导出说明.txt`；原始 PDF 放在 `原件/PDF/`，原始图片放在 `原件/图片/`。勾选图片转换且存在可转换图片时，另有 `图片原件合并.pdf`。
5. Excel 按材料明细行展开，包含送货单号、日期、项目、分供方、材料、规格、单位、数量、单价、金额、原件文件和异常说明，并保留数值与日期格式。
6. 多页 PDF 和多张送货单共用的 PDF 都以原始字节整份保留；共用源只入包一次，不拆页、不重排、不伪造页码。缺少原件的记录会同时写入 Excel 异常说明和包内导出说明。

## 五、使用边界

- 当前没有安全且无需新增生产依赖的 PDF 对象级合并能力，因此不会把多份 PDF 合成一个新 PDF，也不会用 Canvas/JPEG 栅格化重建。真正保持原对象与页面结构的多 PDF 合并仍待后续实现。
- “图片另生成 PDF”只支持可安全渲染的 PNG/JPG。运行环境不支持图片渲染时会明确报错，不会把失败误报为已合并。
- 送货单识别结果仍需人工确认，OCR 只能提供候选字段，不替代原件核对。
- 如果原件未随记录保存，或一张送货单无法明确区分分供方，导出结果会在“异常提示”列标记；这类记录仍会导出，但不应直接作为最终结算依据。
- 文件夹整理和批量调整归档归属仍属于后续定稿功能；当前导出目录是固定保真结构，不是可配置的档案整理树。

## 六、人工归档与刷新

1. 在“乙供材管理 → 送货单识别”上传完整 PDF 或图片。一个文件可识别出多张逻辑送货单，逐张核对，不拆分或重建 PDF 原件。
2. 对照原件，选定项目、分供方和送货日期，核对每条材料名称、单位及非零数量。系统不自动补分供方或当天日期。
3. 处理金额异常并填写原因。缺价格可明确确认后归档为“价格待补录”；无单号须确认原件确实无单号。
4. 点击“确认人工归档”，再次确认已查看原件。成功后记录进入归档库；这不表示已经入库、形成有效到货或可办理材料结算。
5. 分供方别名在归档后单独保存。若页面提示别名失败，已归档记录不受影响，可点击“重试保存别名”；多个失败项逐项处理。
6. 识别区和编辑表单属于写入页面，刷新不会恢复未保存草稿。刷新回到安全页面后，从菜单重新进入识别区；已归档的待打印任务会重新读取。离开前先保存需要保留的人工核对结果。

项目建议来自此前已人工确认的送货原文，仍须人工选定；旧本机项目别名尚未完整迁入，不应认为所有旧写法都已记住。

## 七、修订、历史与补原件

1. 从归档库的送货单号进入详情，核对当前明细与左侧原件。点击“下载原件”取得完整文件；多页 PDF 保持原页数和顺序。
2. 点击“编辑”进入整页表单。修正单头、归属或材料行，填写“修订原因”，保存并确认修改。失败时人工稿保留。
3. 如果提示记录已被更新，点击“重新核对当前记录”，对照只读的当前字段和材料明细调整下方人工稿。点击“采用已核对的当前版本”并明确确认后，人工稿仍保持原样，再自行保存。取消核对不会更新保存基准，也不会丢掉稿件；重新读取失败时先原地重试。
4. 返回详情，点击“查看修订历史”，选择版本及“修改前/修改后”。历史只读，显示原因、操作者、时间及当时留存的明细与原件引用。
5. 缺原件时点击“补传原件”；已有原件需更正时点击“替换原件”。选择 PDF 或图片，填写原件修订原因，再点击“确认保存原件”。补传建立新的原件引用，材料明细不随之改变，旧原件保留在历史中。
6. 当前无权限、文件缺失或校验失败时页面显示原因，按提示重新读取。不要用同名文件替代来源核对。旧历史若没有可信的版本或归属证据，只保留待核验留痕，不提供未经核实的历史正文。

一份原件可供多张逻辑送货共用；修改其中一张明细不会覆盖另一张或原始文件。历史缺分供方的记录继续提示“未区分分供方”；要提交新的人工修订，须按原件补齐当前必需事实。

## 八、打印与导出结果

- “打开打印”只打开原件。打印机确实输出后，另点“登记已打印”；取消或打印失败时不登记，任务继续保留。
- “排除打印”表示本文件不在本次打印范围，不能当作已打印。同一原件的逻辑记录共同处置；后来引用不同原件的记录分别显示。
- 原件包按当前筛选范围生成，逐条重新核对原件读取权限。共用原件只放一份，缺原件写入说明；任一读取失败会提示，不能把不完整输出当作成功。
- 选择保存位置或等待文件时可以取消。切换来源或离开页面后，旧的读取结果不会继续写出文件。

## 九、尚未完成的范围

有效到货头、库存流转、材料结算资格及旧项目别名完整迁移继续按各自任务实施。当前浏览器验证实例不等于生产可靠保存；服务重启、故障恢复、正式备份和部署属于后续上线关口。历史原件关联缺证的记录须另行人工核对，不能从本说明推定已经补证。
