# 睿璟数据质量、逻辑差异与责任归因

## 1. 归因类别

| 类别 | 含义 | 处理原则 |
|---|---|---|
| 项目问题 | `crm-new` 当前实现或目标文档不足以表达已确认业务 | 建 issue、迁移或改查询 |
| Excel 问题 | 源工作簿存在静态值、错误关联、缺失来源或公式噪声 | 清洗、补录或保留待处理 |
| 口径差异 | 双方业务都成立，但名称、粒度或时间点不同 | 建显式映射，不判为错误 |
| 来源缺失 | 业务应有数据但当前未提供 | 显示待补录，禁止填 0 |

## 2. 项目问题

| 编号 | 现状 | 影响 | 必须修正 |
|---|---|---|---|
| P-01 | `DATABASE.md` 旧约定把劳务/专业分包归到“人工” | 合同劳务、专业分包与直接工资混淆 | 改为五类合同 + 工人工资独立成本 |
| P-02 | 当前 `payment_records.payment_application_id` 是单外键 | 无法表达一笔支付记录对应多张申请 | 增加支付分摊表，改为多对多 |
| P-03 | `payment_applications.paid_amount/actual_payment` 可保存手写值 | 实付存在双事实源 | 停止手写，以已确认支付分摊派生 |
| P-04 | 项目经营汇总从 `payment_applications.actual_payment` 求和 | 与银行账单权威规则冲突 | 改查 PaymentRecordAllocation |
| P-05 | 支出合同缺少通用补充协议子表 | 相同合同号多份补充协议只能重复成平级合同 | 增加 `contract_supplements` |
| P-06 | `contracts.kind` 只有施工/分包/材采 | 机械、其他缺少清晰合同归属 | 增加 `其他支出` 或稳定 `cost_category` |
| P-07 | 工资页面仍显示“待实现” | 动态成本无法纳入直接工人工资 | 完成 #117 三态发放闭环 |
| P-08 | 当前导入中心没有合同、结算、付款、支付记录模板 | 无法直接迁入本工作簿 | 增加实体导入配置和来源追溯 |
| P-09 | 旧实际成本约定可能把材料付款与送货金额同时归集 | 动态成本重复计算 | 统一改为结算成本口径 |
| P-10 | 目标文档与物理迁移版本不同步 | 文档可表达但运行库不能落地 | 在同一切片补 schema、store、query、test |

## 3. Excel 问题

| 编号 | 现状 | 影响 | 处理 |
|---|---|---|---|
| E-01 | 分供方汇总使用“供应商名称” `SUMIF` | 重名、别名或改名会错并 | 迁移后用 `supplier_id` |
| E-02 | 合同类型取“供应商名称”的首个匹配值 | 一个分供方多合同类型时误分类 | 按 `contract_id.cost_category` 聚合 |
| E-03 | 汇总页存在无公式静态风险指标 | 不能追溯口径 | 未定义前不迁移数值 |
| E-04 | `C13/C14` 链接到支出合同/结算总计却标成对上产值 | 收入与成本语义错位 | 不导入，等待客户确认收入源单 |
| E-05 | 空值、0、待补录混用 | 无法区分真实零与未知 | 导入时保留完整性状态 |
| E-06 | 付款批次尾部存在公式和格式行 | 按 used range 导入会产生假记录 | 按业务必填字段判有效行 |
| E-07 | 第 231 条申请金额 95,000 元但无回单/实际付款 | 可能把申请误当实付 | 不创建已确认支付 |
| E-08 | 5 笔退往来款合计 5,950,000 元有流出明细，原流入缺失 | 资金净额无法闭合 | 往来款保持待补录 |
| E-09 | 汇总页显示往来收款 5,850,000、往来付款 0，与明细不一致 | `J23` 仅是旧汇总显示结果 | 系统导入后重新对账 |
| E-10 | 票税栏只有资料状态，无票面金额和税额 | 不能推算进销项票税 | 待补录发票实体 |
| E-11 | 浮点公式产生极小尾差 | 金额可能显示非两位小数 | 迁移统一四舍五入为分 |
| E-12 | 合同累计列、剩余列和付款列均为公式副本 | 可能与源单重复 | 只作对账，不导入 |

## 4. 口径差异

| 编号 | Excel | crm-new 统一口径 | 处理 |
|---|---|---|---|
| M-01 | 包工包料 | 专业分包 | 显式映射 |
| M-02 | 劳务 | 合同劳务 | 不得映射为工人工资 |
| M-03 | 租赁 | 机械 | 显式映射 |
| M-04 | 材料/走账材料/部分走账材料 | 材料大类 | 保留原细类 |
| M-05 | 空/其他/未分类/不签合同 | 其他大类 | 保留分类状态供后续处理 |
| M-06 | F15 现有六行没有单独工资行 | 动态成本必须含直接工资 | 页面增加工资项，F15 继续统一合计 |
| M-07 | 工资无逐人银行回单 | 工资确认发放即付款事实 | 工资走例外成本事件 |
| M-08 | 付款批次把回单与申请压在一行 | 支付记录与申请多对多 | 拆成 PaymentRecord + Allocation |

## 5. 来源缺失

以下项在当前数据集中不得显示为真实 0：

- 费用报销；
- 直接工人工资历史；
- 我方向客户开具的销项发票金额和税额；
- 分供方进项发票金额和税额；
- 客户确认产值/结算收入；
- 5 笔退往来款对应的原始流入；
- 投标保证金、履约保证金和备用金的完整收付明细；
- 第 231 条付款申请对应的真实支付记录。

库存是“暂不统计”，资金效能是“待定义”，两者与“待补录”不同。

## 6. 首个样本对账基准

睿璟样本的合同、结算、支付、凭证和旧汇总显示值统一在[验收清单](ruijing-acceptance.md)维护。本文件只记录差异成因和处理流程，不复制金额；系统不得牺牲源单真实性去强行复现旧汇总。

## 7. 差异处理状态机

```text
发现差异
  → 自动归因建议
  → 人工确认归因
  → 修项目 / 清洗 Excel / 补来源 / 确认口径映射
  → 重跑导入预演
  → 重跑汇总对账
  → 差异关闭
```

每条差异至少保存指标、源行、系统记录、Excel 值、系统值、差额、归因、处理人和关闭说明。
