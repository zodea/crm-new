# 睿璟迁移与通用经营汇总验收清单

> 本清单保存原始样本对账标准，复核基线由 [#403](https://github.com/zodea/crm-new/issues/403) 确定；未勾选不表示当前代码全部未实现。验收时记录提交、环境、来源与结果，执行顺序见[当前承接入口](../implementation/project-operating-summary-work-breakdown.md)。样本数值不得硬编码到产品或提交真实凭证。

## 1. Schema 与迁移

- [ ] `contracts` 可表达五类支出合同，保留 Excel 原始细类和分类状态。
- [ ] 支出合同存在一对多 `contract_supplements`。
- [ ] `payment_records` 不再用单个 `payment_application_id` 表达关系。
- [ ] 已建立 `payment_record_application_allocations`，含唯一约束、外键、软删除和索引。
- [ ] `payment_applications.paid_amount/actual_payment` 已停止手写，并完成存量对账迁移。
- [ ] OCR 原值、置信度、人工修订、确认人和确认时间可审计。
- [ ] 工资确认发放可以生成工资成本事件，且不伪造银行回单。
- [ ] 费用报销确认后可以进入动态成本。

## 2. 导入

- [ ] 支持 Project、Supplier、Contract、Supplement、Settlement、PaymentApplication、PaymentRecord、Allocation 分实体导入。
- [ ] 导入预演不会创建数据。
- [ ] 每条记录保存文件、工作表、行号和批次。
- [ ] 空白公式行、合计行和样式行不被识别为业务行。
- [ ] 相同文件和批次重复执行不会重复创建记录。
- [ ] 分供方和合同通过 ID 关联，不用展示名称作外键。
- [ ] 未分类、不签合同和空合同类型均保留原始状态。
- [ ] 第 231 条 95,000 元申请不进入已确认支付记录。

## 3. 支付闭环

- [ ] 230 份付款凭证与 230 条可确认支付记录一一核对。
- [ ] 每笔已确认支付记录的分摊合计等于银行回单金额。
- [ ] 凭证 62 可关联两张付款申请，合计为 98,246.58 元。
- [ ] 同一付款申请可以被多笔支付分摊。
- [ ] 付款申请已付金额与支付分摊实时一致。
- [ ] 删除、撤回或调整分摊后，申请已付金额和项目汇总同步变化。
- [ ] OCR 未人工确认的记录不进入已付和现金流汇总。
- [ ] 手工录入的支付记录同样要求人工确认。

## 4. 经营汇总

- [ ] 五类支出合同合计 26,112,536.26 元。
- [ ] 五类合同结算合计 7,697,157.23 元。
- [ ] 五类合同银行付款合计 23,473,231.18 元。
- [ ] 每个总额等于分类之和，分类能下钻到源单。
- [ ] 动态成本不使用合同额、付款额或送货单金额替代结算额。
- [ ] 工资确认发放与合同劳务分别展示，汇总时只在动态成本总额相加。
- [ ] 缺少工资或费用报销时，动态成本显示 `partial` 和缺失来源。
- [ ] 缺票税、客户确认收入时显示待补录，不显示 0。
- [ ] 本次经营汇总样本的库存指标显示暂不统计、资金效能显示待定义；不以此排除物资模块的库存业务。
- [ ] 金额统一两位小数，不出现浮点尾差。

## 5. 资金与对账

- [ ] 迁移报告记录旧汇总 `J23=2,519,077.81`、`J24=-3,330,922.19`。
- [ ] 新系统按已确认明细重新计算收支差额和工程款余缺。
- [ ] 往来款 5 笔流出 5,950,000 元与缺失流入被列为未关闭差异。
- [ ] 未关闭资金差异不会被静态数值覆盖。
- [ ] “真实零发生”和“来源未取得”在 API 和页面均可区分。

## 6. 页面

- [ ] 项目详情显示合同、动态成本、合同付款、票税和资金卡片。
- [ ] 动态成本包含五类结算、工人工资、费用报销七个组成项。
- [ ] 分供方汇总支持按分供方和合同双层下钻。
- [ ] 支付详情同时显示银行凭证、OCR/人工确认状态和付款申请分摊。
- [ ] 汇总卡片显示截止时间和完整性状态。
- [ ] 任何金额穿透都能回到真实源单，0 或空值不伪装为链接。

## 7. 自动化测试最低集

- [ ] 合同类型映射参数化测试覆盖全部 Excel 原值。
- [ ] 动态成本测试覆盖结算、工资、报销及缺失状态。
- [ ] 支付分摊测试覆盖 1:1、1:N、N:1、超分摊、少分摊和撤回。
- [ ] OCR 未确认不计入汇总。
- [ ] 工资已发放计入成本和支付，但不进入支付记录表。
- [ ] 导入有效行判定测试覆盖尾部公式噪声。
- [ ] 分供方同名、别名和一个分供方多合同类型不会错并。
- [ ] 软删除父子可见性和分摊聚合测试通过。
- [ ] 睿璟样本金额回归测试通过。

## 8. 完成定义

只有满足以下条件，才能把本批次标记为“迁移验收完成”：

1. 可追溯的合同、结算和支付记录基准全部对平；
2. 每笔确认支付分摊平衡；
3. 项目实现问题已有代码和自动化测试；
4. Excel 问题已清洗或登记为明确待补录；
5. 页面只读汇总与数据库查询结果一致；
6. 未定义和暂不统计项没有被伪造数值。

该样本验收不覆盖全部正式上线条件。已接管实体须走中央命令与查询验证；可重置实例或浏览器本地数据对平不能证明生产持久化、备份恢复和部署已通过，后者由 [#416](https://github.com/zodea/crm-new/issues/416) 单独验收。
