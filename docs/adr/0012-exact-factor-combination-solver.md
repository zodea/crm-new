# 开票因子采用精确加法组合求解器

> 状态：已采纳（2026-07-16）
> 来源：GitHub Issue #102 与 `红圈系统/sum_combination_solver_ui.html`。

原开票因子页用主线程 DFS 枚举目标金额 1% 范围内的近似方案，金额直接使用 JavaScript 浮点数。该实现既无法保证财务金额精确，也缺少小数数量、包含/排除条件、完整解计数和可取消的长计算。

**决策**：开票因子改用独立 Web Worker 承载的精确加法组合求解器：

- 目标值与因子统一四舍五入为“分”，核心求解过程只使用整数；仅返回恰好等于目标值的组合。
- 未启用小数时数量为整数；启用后按 `1 / gcd(因子分值, 100)` 生成数量步长，确保每个“因子 × 数量”都恰为整分。
- 同值因子以后输入配置覆盖前输入配置；支持最大数量、必须包含、排除因子和最多 5000 条展示结果。
- 求解流程采用 GCD 缩减、后缀最大值剪枝、逐层可达性表和 DFS 枚举；内存不足时切换轻量剪枝。可承受时用滚动 DP 统计完整解数。
- 单次计算时限为 10 秒。可达性或计数阶段超时后继续用已有信息枚举少量部分解，并明确标记结果可能不完整；用户取消时直接终止本次 Worker。
- 页面状态与 Worker 生命周期由 `useFactorSolver()` 所有；纯算法留在 `app/lib/finance/factor-combination.ts`，Worker 只做消息边界与异常归一化。
- 目标值、返回上限和因子配置写入 `sum-solver-state`，读取时兼容参考 HTML 的旧字段 `f/m/d`。
- 税额计算同样以“分”为单位。不含税金额四舍五入到分，税额用含税金额减不含税金额反算，保证勾稽一致。

**界面边界**：页面视觉继续遵循 ADR 0007 与 ADR 0008。因子配置、结果和税额工具放在一个统一工作台内；品牌蓝只用于关键操作，轻量结果表使用原生语义化 `<table>`。

**后果**：旧的近似 1% 方案、名称/单位字段和主线程同步枚举全部退役。页面蓝本只记录用户可见规则与布局，算法、线程和持久化实现以本 ADR 为唯一权威源。
