# 浮层组合采用单交互平面与模态栈契约

> 状态：已采纳（2026-07-26）
> 来源：Issue #166；扩展阶段见 #168，迁移与收缩阶段见 #169–#172
> 补充：ADR 0008 的 reka-ui / vue-sonner 底座继续有效；本 ADR 定义应用内的组合关系。

## 背景

应用同时存在 Dialog、Confirm、FormModal、Drawer/Sheet、Popover、Select、Lookup、Tooltip、Toast、页签菜单和页面内全屏编辑。此前层级按组件种类分配不同数值，不能表达“从某个来源浮层打开的子浮层必须覆盖来源浮层”。结果包括 Drawer 内 Dialog 落到来源面板下方、子选择器与模态遮罩关系不稳定，以及视觉最上层和键盘焦点层不一致。

reka-ui 的模态滚动锁只作用于 `body`，而当前应用实际滚动容器是应用外壳内部的工作区；因此即使 `body` 已锁，背景工作区仍可能滚动。

## 决策

### 1. 生产交互浮层共享一个带栈槽的层叠平面

Dialog、Drawer/Sheet、Popover、Select、Lookup、Tooltip 和页签菜单使用同一个语义浮层平面。组件种类不决定高低；模态按实际打开顺序登记到全局栈，并在同一平面内取得小步进槽位：

- 第一层模态使用平面基值，后打开的嵌套模态每层递增 10；Toast 与交互平面之间预留足够空间。
- 同一模态的 backdrop 与 surface 使用同一栈槽，portal 内 backdrop 先渲染、surface 后渲染。
- Popover、Select、Lookup 和 Tooltip 从所属模态注入的栈槽取值；页面直属浮层使用基值。
- 模态打开前已经存在的无关页面浮层位于其之前，因此不能越过模态遮罩。
- 模态的 inert、焦点陷阱和外部指针禁用阻止背景界面在模态期间再打开无关浮层。

Vue Teleport 的节点位置由组件树决定，并不可靠地等于运行时打开顺序，因此不能只依赖同值 z-index 下的 DOM 顺序。栈槽只表达实际嵌套深度，不恢复“组件种类越特殊，数值越大”的旧体系。

### 2. Toast 是显式的消息平面

Toast 位于交互浮层平面之上，保证系统结果和撤回操作在模态期间仍可读、可命中。Toast 不参与模态焦点陷阱，不获得 Esc 关闭优先权，也不能借此恢复背景页面交互。

### 3. 页面内全屏仍属于页面平面

数据网格等页面内全屏编辑只是页面呈现模式，不是模态。它位于应用外壳之上、生产交互浮层之下；打开 Dialog 时必须被遮罩覆盖。

### 4. 应用工作区由单宿主按模态栈锁定

每个通用模态只登记自身打开状态，不直接修改工作区 DOM。应用外壳作为唯一宿主，根据当前活动模态数量统一锁定或解锁内部工作区：

- 第一个模态打开时锁定工作区。
- 嵌套模态关闭但父模态仍存在时保持锁定。
- 最后一个模态关闭时恢复工作区原滚动能力和位置。

`body` 的锁定、inert、焦点陷阱、Esc 和焦点返回继续由 reka-ui 负责。

### 5. 层级只通过语义令牌接入

生产代码不得新增裸全局 z-index。局部表格表头、时间线等组件内部层级不属于本契约。开发工具只在 `import.meta.dev` 为真时挂载，并使用低于生产交互平面的 `--z-devtools`，不能阻断生产浮层验收。

本次迁移已完成 expand–migrate–contract：

1. #168 增加新契约、语义令牌和模态栈，并在扩展阶段保留旧别名。
2. #169–#171 依次迁移责任配置、Dialog 子浮层、Sheet 与项目切换器。
3. #172 收敛 Toast、页签菜单、全屏编辑和开发面板，删除旧别名，并增加源码契约守卫防止回流。

## 后果

- 嵌套关系由实际打开顺序和栈槽决定，不再需要为每种组件组合持续发明更大的数值。
- 通用 Dialog 与应用外壳之间新增一个很小的全局模态登记接口；业务弹窗无需了解滚动容器。
- 浏览器回归必须同时断言遮挡、工作区滚动、Esc 归属和焦点返回，静态搜索只能辅助检查令牌治理。
- Issue 83 的集中令牌化目标被本契约吸收，但其“保持旧层叠关系”不再适用于迁移后的生产浮层。
- vue-sonner 的默认超大 z-index 被显式覆盖为 `--z-toast`；消息仍可操作，但不会脱离应用的层级合同。
