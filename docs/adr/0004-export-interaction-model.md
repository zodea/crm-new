# 导出交互模型:直接保存 vs 配置导出页签

> 状态：已采纳（2026-07-04；2026-07-13 补充直接保存运行环境；2026-07-14 补充配置导出路由与写盘边界；2026-08-11 补充业务 XLSX 样式窄例外）

「全局导出规范」要求所有模块共用一套交互口径,但不要求所有导出都先配置目录。将复杂配置塞进居中弹窗会遮挡用户要对照的信息,也容易被误关闭。

无需分类的导出若也套完整配置,则交互过重。原「完成水波动效」方案已随全局水波废弃一并取消。

## 决策

导出按「**导出前是否需要配置目录结构**」分两条路。文件数量不参与判定。

1. **直接保存 (`direct-save`)**:无需目录分类时,选择目标文件夹并写入。不开页签,不显示配置 UI;单文件只是典型场景。
2. **配置导出 (`config-tab`)**:需要目录分类时,打开独立「导出配置」页签。页签先配置最多两级目录与命名规则,开始后原地切换为读数据→生成→写盘进度。

`useKitUI().exportFile()` 以 `requiresDirectoryStructure` 作为唯一分流键。`false`/缺省走直接保存,`true` 走配置页签;`openExportTab()` 是调用方明确打开配置页签的别名。

### 业务 XLSX 内容/样式窄例外

XLSX 的内容与样式设置（如行高、列宽、字体、边框、数字格式、冻结行和合并规则）不属于目录结构配置。业务模块可以在与当前数据同屏的导出预览中编辑这类设置，且预览草稿必须与实际生成的 XLSX 使用同一份配置。

此例外不改变保存分流：目录层级、文件命名和最终写盘仍统一由 `direct-save` / `config-tab` 负责，业务预览不得自行选择目录、拼写盘路径或复制写盘反馈。需要跨会话复用的默认样式由对应领域 Pinia store 经 SQLite 持久化（浏览器开发态沿用数据库 fallback）；组件只持有本次编辑草稿并调用 store action。

该例外只覆盖与文件内容直接对应、必须对照数据验收的 XLSX 设置，不授权业务模块为任意导出自建配置弹窗，也不绕过 KitUI 的 Dialog、可达性和安全交互约束。

## 直接保存的运行环境

- 浏览器优先使用 File System Access API 选择目录并写入。不支持时退化为普通下载,落点必须如实显示为「浏览器下载」。
- 用户取消目录选择时静默结束,不显示成功、失败或取消 toast。
- 写盘期间只显示右下 process 道 loading;成功后 dismiss,不转为 process success。
- 最终唯一成功反馈是右上 system 道 toast:「已导出到 X 文件夹」。X 为真实目录或「浏览器下载」。
- 磁盘已有同名文件时依次加 ` (2)`、` (3)` 序号,绝不覆盖——该写盘契约由直接保存与配置导出共用。

## 配置导出的路由与上下文

所有配置导出共用 `/export/config/:jobId`。发起方先生成 `jobId`,再将源文件、可选字段和默认规则注册到 transient Pinia context,页签只携带身份,不在 URL 复制大批量数据。

该 context 只存活于当前应用会话。刷新页签或从历史记录直达时上下文失效,页面显示明确空态,要求用户回到来源页重新发起;不伪造可继续的任务。

配置页签计入 [[页签导航]] 15 个上限。打开被阻断时不注册残留 context;页签关闭或导出成功后释放对应 context。

## 配置导出的路径与写盘

- 目录结构最多两级。命名规则与目录规则先编译为完整相对路径,配置页实时预览首个文件的结果。
- 路径段必须清理 Windows 非法字符、设备保留名、穿越片段与超长内容。同一目录的同名文件依次加 ` (2)`、` (3)` 等序号,不得覆盖。
- 配置导出必须保留目录结构。支持目录写入的 File System Access API 可以完成;普通浏览器下载 fallback 不可以。
- 若当前环境只能普通下载,写盘步必须失败并说明需使用支持目录访问的浏览器。页签保留,允许从写盘步重试;不得降级后伪报成功。

## 进度与反馈

配置页的「开始导出」和「重试失败步骤」统一使用 `KitButton`。点开始后配置锁定,原页切换为三步进度;失败时标记当前步,之前已完成的步骤保留,重试只重启失败步。

写盘步重试续写:重试时若选择同一落点,跳过上次已成功写出的文件,只补写剩余文件,不把已写文件落成 ` (2)` 副本;换落点则整批重写。

多阶段展示由通用 `ProcessStepper` 承载,状态为 pending / active / completed / failed。该组件不绑定导出领域,后续 #81 导入流程可复用。

导出成功后只显示一条 system 道成功 toast:「已导出到 X 文件夹」,然后自动关闭页签。失败不关闭页签,不叠加其他成功反馈,不播放 ripple 或其他完成动效。

## 考虑过的替代

- 全部走居中配置弹窗:遮挡信息,提交失败或点遮罩外容易误关,否决。
- 单文件也套完整配置:过度,且需维护多套 UI,否决。
- 配置导出在不支持目录的浏览器里拆成多个普通下载:丢失目录语义且容易误报成功,否决。
- 完成播蓝色水波动效:全局废弃,改为静态 toast 成功。

## 后果

- 调用方只判断是否需要目录分类；除上述业务 XLSX 内容/样式窄例外外，不自建导出弹窗或业务专用配置页。
- 通用路由与 transient context 避免在 URL 与全局持久化层重复大批量文件,代价是刷新后必须重新发起。
- 配置页签与列表/详情页共享 15 个上限,故完成后必须自动关闭,不长期占位。
- 桌面端（Tauri）已于 2026-10 退役,直接保存只在浏览器中进行。
