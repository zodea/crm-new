# 导出交互模型:直接保存 vs 配置导出页签

> 状态：已采纳（2026-07-04）

「全局导出规范」要求所有模块导出共用一套交互(文件夹选择 + 两级结构可配 + 命名规则可配 + 预览 + 进度)。若一律塞进居中弹窗,会遮罩挡住用户想边导边看的信息,且提交失败或点遮罩外易误触关闭;若给单文件也套完整配置,又是杀鸡用牛刀、还要维护多套配置 UI。原「完成水波动效」方案(见 CONTEXT.md 旧「全局导出规范」)已随全局水波废弃一并取消。

**决策**:导出按「**导出前是否需要配置目录结构**」分两条路。

1. **直接保存**(单文件 / 无需分类):点导出直接弹**系统保存文件夹选择器**,选定即导。不开页签、无配置 UI。
2. **配置导出**(多文件且需按类分两级目录,如批量导出分供方合同、采购合同):点导出打开**独立「导出配置」页签**——两级文件夹结构 + 命名规则 + 带预览,点开始后**在同一页签内**转进度(进度条 / stepper:读数据→生成→写盘)。

**统一约定**:

- **完成落点 = toast 成功弹窗**(system 道),**无任何动效**。
- 配置 UI 只做这一套(在页签里),所有需配置的导出复用,不重复造。
- 导出配置页签**算 [[页签导航]] 15 上限**,成功后**自动关闭**;失败保留该页签、标明失败步、可重试。
- 单文件的进度轻走右下 process 道 toast(Sonner promise);多文件进度在页签内。

**考虑过的替代**:

- 全部走居中配置弹窗(遮罩挡信息、提交失败/点外误关,否决——正是改用页签的动因)。
- 单文件也套完整配置弹窗(过度、且要维护多套 UI,否决——改直接弹系统文件夹选择器)。
- 完成播蓝色水波动效(CSS 版效果差、GIF 版性价比低,全局废弃,改静态 toast 成功)。

**后果**:

- 判定分流的钥匙是「是否需要目录分类」,不是文件数多少——需分类即开页签,不需分类即直接存。
- 导出配置页签是一个可被任意模块打开的通用路由(带导出上下文参数),不是每模块各写一个。
- 「导出配置」页签受 15 上限约束,与列表/详情页争额度,故必须完成即自动关闭,避免长期占位。
