# 内部暂估排程允许先建计划、后绑定合同

> 状态：已采纳（2026-07-28，用户确认）
> 来源：Issue #191

## 背景

新项目从立项到施工合同签订之间仍需要安排楼栋、工序和计划日期。原规则要求楼栋分组先绑定一份已拆表的施工合同，虽然保证了范围可追溯，却让前期计划只能在线下维护，签约后还要重新录入。

## 决策

楼栋分组允许选择“内部暂估排程”作为范围依据：没有施工合同时，用户先手工维护项目的楼栋、楼层、户、户型模板和暂估工程量，再建立 WBS。每个分组同一时刻只能处于“内部暂估”或“合同清单”一种依据；内部暂估分组不得显示为合同范围已确认。

签约后，用户必须显式选择同项目且类型为“施工”的合同。系统先比较暂估范围与已确认合同清单的楼栋覆盖、分项映射和数量差异；分组内存在合同未明确覆盖的楼栋时阻止完成绑定，要求移除、拆分或补齐合同清单证据。合同包含但分组未采用的楼栋只作提示，不强制纳入。绑定成功后保留原分组、工序、基线、完成事实和审计历史，不静默覆盖暂估量。

## 后果

- `schedule_groups.contract_id` 改为条件必填，并新增明确的排程依据；既有分组迁移为“合同清单”。
- 项目必须提供完整的“楼栋 → 楼层 → 户”手工配置入口，工程量管理继续允许无清单时维护手工分项和暂估量。
- 新建楼栋分组采用“范围 → 工序 → 确认”三步向导；第一步选择合同清单或内部暂估，第三步明确标示数据依据。
- 合同绑定是单独的领域动作和差异确认流程，不等同于直接修改 `contract_id`。

## 后续确认（2026-10-13，用户确认）

合同清单未覆盖分组楼栋时，处理方式是给合同清单补上缺少的楼栋：经“补齐合同楼栋证据”更正已确认导入基准行的楼栋后重新预览绑定。不移除分组楼栋，也不新增拆分分组能力。“决策”中“移除、拆分”的说法以本节为准，现行流程见[施工进度规格 §四](../rewrite/pages/schedule-progress.md#四模型依赖)。
