# 业务实体新增/编辑默认使用整页表单

> 状态：已采纳（2026-07-18）；设计稿与 Nuxt F1–F5 已落地（2026-07-26）
> 来源：用户反馈「设计稿很多新增、修改界面不够齐全，填写的内容很少」+ `/grill-me` 九问定稿；过程决议已并入本 ADR，历史从 Git 查看。
> 对标依据：红圈截图实拍（付款申请/支出合同/收票登记/分供方表单逐字段提取）。
> 实装状态：设计稿 37 条表单路由已全量落地；Nuxt F1–F5 已完成基础主数据、合同/结算、资金、物资与甲方/分包单据，并完成响应式验收（提交 `08aa191`、`386ce13`、`6fd2afc`、`cb2ee9d`、`3a345f2`、`ef909e9`）。字段与关系仍以 [DATABASE §2 逐实体定义](../rewrite/DATABASE.md#-2-全部实体清单)及 [§2.10 表单覆盖与来源批次](../rewrite/DATABASE.md#210-整页表单覆盖与来源迁移批次) 为准。

> 后续适用边界：以上是整页表单基线的历史实现证据，不表示每个业务生命周期、中央保存和生产持久化均已闭合。设计稿注册器、mock 附件和通用状态注入仅属历史原型；已接入中央的页面入口、允许动作及状态以 [ADR 0020](./0020-browser-authority-and-demo-workspace-boundary.md)、[`NAVIGATION.md`](../rewrite/NAVIGATION.md)和 [`COMMANDS.md`](../rewrite/COMMANDS.md)为准，不能因通用“保存并提交”文案伪造审批状态或绕过显式编辑入口。

## 决策

**业务实体新增/编辑默认使用独立路由整页表单**。行级明细、确认等轻量操作可用行内编辑或弹窗；改变实体表单形态前说明场景、理由与影响，经用户确认后实施。

### 1. 挂法与架构

- **每实体独立表单路由、新开页签**：路由名 `xxxForm`，新建共用一个页签、编辑按对象 id 去重；页签题「新建·xxx / 编辑·xxx」；表单路由点亮其来源列表的侧栏项。
- 字段组件和校验逻辑按职责复用，不在弹窗与整页各维护一套。具体页面入口与动作直接查 [NAVIGATION](../rewrite/NAVIGATION.md) 和 [COMMANDS](../rewrite/COMMANDS.md)，不将设计稿注册器作为生产实现要求。

### 2. 字段规模

- 字段与业务边界按现行页面规格和 DATABASE，运行参考只辅助布局及密度核对，不按历史字段数量机械补齐。实体引用用真实身份检索与级联校验；聚合值只读派生，不保存第二份金额。
- 附件必须接通领域文件能力与真实反馈，不能以 mock 上传框声明已实现；系统信息仅显示可证明的真实来源。

### 3. 明细网格

- 铺给确有明细行的单据：材采合同（10 列精选+导入按钮）、付款申请（关联结算+关联发票）、甲方变洽签（变更行）、甲方报量（报量行）、库存盘点、材料到货。施工/分包合同不加（清单走拆表链路）。
- 能力：增删复制 + 行内编辑 + 派生列（数量×单价）+ Σ汇总行 + **EXCEL 粘贴（TSV 按可编辑列序批量插行）** + **全屏编辑**（DOM 原位搬移，编辑态不丢）。
- 红圈 21 列中依赖跨单据聚合的只读勾稽列（剩余可签量/累计下料量等）**不摆空架子**，等数据勾稽链落地后补。
- 明细与头字段的存储关系按对应数据模型处理，不沿用设计稿 `spec.coerce` 拼接或聚合来替代正式关系。

### 4. 新建三段式（类型选择 → 整页表单）

- **付款申请**：`typeSelect` 按[付款页面](../rewrite/pages/finance-payment.md)的现行业务类型 → 按类型显隐分区（有合同类出「合同情况带出」+「关联结算」网格；预付款类出「预付款情况」；公司付款不挂项目）。
- **分供方**：`typeSelect` 用本项目七类——**材料供应商/劳务分包商/专业分包商/设备供应商/检测供应商/个人/其他**（不抄红圈「大宗/房东」分类）。
- 其余实体不做三段式（合同 kind 由路由分流；变更 4 类保持表单内 select）。

### 5. 版式（必须满足 ADR 0013 响应式契约）

- 宽屏左锚点导航用有界宽度并 sticky，滚动联动高亮；**<3 分区或窄容器时隐藏**（分区卡片标题即导航替身）。
- 每个 section 一张圆角卡片（ADR 0007）；字段栅格**最多两列、按最小可读宽度（`repeat(auto-fit, minmax(280px,1fr))`）自动降单列**。
- 底部吸底动作条，窄屏允许换行、主操作可达；内容区 `max-width: 1080px` 仅作可读上限、宽度流式。
- 面包屑「← 返回列表」；编辑同页标题「编辑 · xxx」。

### 6. 保存动作五件套与草稿

- 按实体能力提供取消、保存草稿、保存并新建、保存并提交和保存；不存在的领域动作不显示。草稿校验和提交状态由该领域命令决定，不能统一写成“审批中”。取消时保护未保存输入；保存成功后再执行新建或关闭。“保存后关闭”默认勾选，不勾则保留已保存的编辑页。
- 保存草稿在未改动时禁用；保存中禁用重复操作。
- 必填双通道校验：红框 + 字段下红字 + system warning toast「⟨字段⟩：为必填项（等 N 处）」。
- 新建默认值由对应领域显式提供，不能由浏览器 select 首项隐式决定业务值。
- 本决策不新增审批流程；状态与动作服从已确认的领域契约。

### 7. 草稿三入口

草稿标识、筛选与续填入口按对应页面和 NAVIGATION 实现；存在草稿不自动授权整行跳编辑，也不依赖设计稿 `statusKey` 推导正式状态。

### 8. 页签切换保值（硬性要求）

表单页签切走再切回，填写内容（含明细网格行）按页签缓存原样恢复；仅关闭页签/返回列表弹「放弃修改?」拦截。保存/放弃后清缓存。

### 9. 数据与实施纪律

- 设计演示使用匿名合成数据；真实参考资料不上传、不进入仓库。设计稿 mock 不作为生产持久化依据。
- 已接管领域的保存沿既定 Repository/HTTP/command 边界，未接管和桌面适配沿 ADR 0020；不要求建立平行 SQLite 正式写源。

## 后果

- **弹窗从「表单主形态」退位**：`KitUI.formModal` 保留为行级对象与确认等轻量任务。
- **Nuxt 组合目标已从「弹窗增强」迁移为整页表单壳**：KitLookup、明细网格、typeSelect 与保存动作组继续作为共享能力，改变既定形态须经用户确认。
- 设计稿控件与分区以 `kit/forms/*.jsx` 为准；业务字段、边界与验收以 `docs/rewrite/pages/` 为准；列、外键、子表和迁移批次以 [DATABASE §2 逐实体定义](../rewrite/DATABASE.md#-2-全部实体清单)及 [§2.10 表单覆盖与来源批次](../rewrite/DATABASE.md#210-整页表单覆盖与来源迁移批次) 为准。用户可编辑业务字段默认持久化及付款申请勾稽继续遵守 [ADR 0015](0015-form-persistence-and-payment-reconciliation.md)。
- 后续若某实体确需退回弹窗（高频轻量录入），说明具体理由与影响，经用户确认后调整，不整体回退。
