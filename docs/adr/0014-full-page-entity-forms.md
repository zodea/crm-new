# 新增/编辑一律整页表单（取代弹窗为主形态）

> 状态：已采纳（2026-07-18）
> 来源：用户反馈「设计稿很多新增、修改界面不够齐全，填写的内容很少」+ `/grill-me` 九问定稿（原 `docs/dc-rebuild/2026-07-18-表单补全整页化-grill决议.md`，已按设计入口规则并入本 ADR 后删除，过程见 Git 历史）。
> 对标依据：[红圈补采差距清单 §1/§2/§6](../dc-rebuild/2026-07-11-红圈补采差距清单.md) + 红圈截图实拍（付款申请/支出合同/收票登记/分供方 表单逐字段提取）。
> 实装状态：设计稿侧已全量落地并推送线上设计项目（37 条表单路由，`DC重构设计源码/kit/forms/*.jsx`）；**Vue 侧未动**，实装以设计稿为蓝本。字段回写权威文档见 [#116](https://github.com/zodea/crm-new/issues/116)。

## 决策

**全部业务实体的新增/编辑一律采用整页表单**（红圈式：独立路由、新开页签），弹窗仅保留给行级小对象（清单分项、班组内工人配置、改归属等）与后续按需退化的场景。

### 1. 挂法与架构

- **每实体独立表单路由、新开页签**：路由名 `xxxForm`，新建共用一个页签、编辑按对象 id 去重；页签题「新建·xxx / 编辑·xxx」；表单路由点亮其来源列表的侧栏项。
- 表单规格按域分文件放 `kit/forms/`（FinanceForms / ContractForms / OwnerDocForms / MaterialForms / BaseForms），经 `window.KitFormUtil.registerForm(route, page, specFn)` 注册进 `window.KIT_FORM_SPECS`；应用壳一个统一分发入口（`isEntityForm` → `EntityFormScreen`）。
- **弹窗与整页共用一套字段渲染**：formModal 控件层抽成 `KitUI.buildFormBody`（grid 布局=弹窗，cards 布局=整页分区卡片+锚点）。
- 列表接线：`EntityListScreen` meta 扩展 `formRoute`（新建/编辑跳整页）、`editFormRoute`（仅编辑，如付款管理）、`typeSelect`（新建三段式第一段）、`statusKey`（草稿落点）、`formOnly`（仅表单字段，不占表格列）。

### 2. 字段规模

- 业务字段**照红圈全量补**（支出合同 33 头字段、付款申请 45、分供方 30 量级）；实体引用一律检索下拉（lookup：过滤+高亮+✕清空，级联 `options(vals)` + `dependsOn` 依赖拦截）；聚合值只读带出（`type:"readonly"` + `compute` 实时重算，默认不回写 store）。
- **附件位保留**（`type:"file"` mock：虚线框「拖拽或点击上传 (0/15)」+ chip 删除）；**系统信息组砍**（负责人/创建人等，等真实后端）；移动端专属（地图定位）砍。

### 3. 明细网格

- 铺给确有明细行的单据：材采合同（10 列精选+导入按钮）、付款申请（关联结算+关联发票）、甲方变洽签（变更行）、甲方报量（报量行）、库存盘点、材料到货。施工/分包合同不加（清单走拆表链路）。
- 能力：增删复制 + 行内编辑 + 派生列（数量×单价）+ Σ汇总行 + **EXCEL 粘贴（TSV 按可编辑列序批量插行）** + **全屏编辑**（DOM 原位搬移，编辑态不丢）。
- 红圈 21 列中依赖跨单据聚合的只读勾稽列（剩余可签量/累计下料量等）**不摆空架子**，等数据勾稽链落地后补。
- 单行模型实体（材料到货/库存盘点）：明细行经 `spec.coerce` 聚合回写头字段（material 拼接/Σqty/Σamount），列表列不空。

### 4. 新建三段式（类型选择 → 整页表单）

- **付款申请**：`typeSelect` 8 业务类型 → 按类型显隐分区（有合同类出「合同情况带出」+「关联结算」网格；预付款类出「预付款情况」；公司付款不挂项目）。
- **分供方**：`typeSelect` 用本项目七类——**材料供应商/劳务分包商/专业分包商/设备供应商/检测供应商/个人/其他**（CONTEXT.md「分供方」词条权威 7 类；不抄红圈「大宗/房东」分类）。
- 其余实体不做三段式（合同 kind 由路由分流；变更 4 类保持表单内 select）。

### 5. 版式（必须满足 ADR 0013 响应式契约）

- 宽屏左锚点导航用有界宽度并 sticky，滚动联动高亮；**<3 分区或窄容器时隐藏**（分区卡片标题即导航替身）。
- 每个 section 一张圆角卡片（ADR 0007）；字段栅格**最多两列、按最小可读宽度（`repeat(auto-fit, minmax(280px,1fr))`）自动降单列**。
- 底部吸底动作条，窄屏允许换行、主操作可达；内容区 `max-width: 1080px` 仅作可读上限、宽度流式。
- 面包屑「← 返回列表」；编辑同页标题「编辑 · xxx」。

### 6. 保存动作五件套与草稿

- 取消（dirty→「放弃修改」确认）/ **保存草稿**（跳必填校验、未改动置灰三态、`statusKey` 写「草稿」）/ 保存并新建（落库后原地重开空表单）/ **保存并提交**（`statusKey` 写「审批中」）/ 保存（主色）。左下「【保存】后关闭」勾选（默认勾；不勾=保存后留页转编辑态）。
- 必填双通道校验：红框 + 字段下红字 + system warning toast「⟨字段⟩：为必填项（等 N 处）」。
- 新建初始值 = `newDefaults()` 合并进字段（select 默认项/自动单号可见可改；不合并会被浏览器 select 首项劫持）。
- 审批流节点图/时间线不在本决策（差距清单 §5 另课题），本轮只落状态字段。

### 7. 草稿三入口

①列表状态列灰「草稿」徽标（与审批徽标同体系）；②视图行固定「草稿 N」chip（0 条也显示，`statusKey` 自动注入）；③草稿行整行点击直接进整页表单续填（普通行点击进详情）。

### 8. 页签切换保值（硬性要求）

表单页签切走再切回，填写内容（含明细网格行）按页签缓存原样恢复（`KIT_FORM_CACHE`）；仅关闭页签/返回列表弹「放弃修改?」拦截。保存/放弃后清缓存。

### 9. 数据与推送纪律

- 编辑回显：data.js 精选回填（每个重点实体 1~2 行代表性假数据；量级/写法风格提炼自 gitignored 真实数据蓝本，**值全部匿名虚构**）；`data.local.js` 本体绝不动、绝不上传。
- DesignSync 推送不含 `data.local.js`；Vue 项目 `app/` 零改动（本决策为设计稿蓝本，Vue 实装另开工序）。

## 后果

- **弹窗从「表单主形态」退位**：`KitUI.formModal` 保留为行级对象与兜底（`buildFormBody` grid 布局）；差距清单 §1-6「大单据改整页」全域兑现且范围扩大到全部实体。
- **Vue 侧原语 issue 基准变化**（#74/#79/#92-96）：Wave2 原语（KitLookup/KitEditGrid/typeSelect/KitFormFooter）继续有效，但组合目标从「弹窗四增强」改为整页表单壳；已在对应 issue 评论。
- 表单字段唯一现行来源 = `kit/forms/*.jsx`，页面蓝本与 DATABASE.md 的回写/入库评审由 [#116](https://github.com/zodea/crm-new/issues/116) 跟踪（相关文档已打横幅）。
- 后续若某实体确需退回弹窗（高频轻量录入），按「够用就停」原则个案评审，不整体回退。
