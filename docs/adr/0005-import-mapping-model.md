# 通用导入映射:模板驱动 + 实体触发 + 独立页签

> 状态：已采纳（2026-07-04；2026-07-14 补充通用路由/实体注册表与重试续导）

新系统需在项目中/末期把旧数据(红圈或 Excel)迁移进来。这类「通用表格导入」与[[识别中心]]的 OCR 识别、清单拆表是**不同的入库路径**:识别类走各自专属流程(识别是动作、台账是资产),清单拆表因「归一化 vs 保真」的领域权衡另在 boq-import.md 处理,二者都**不套**通用映射原语。通用导入若做成自由映射(源列→任意目标),旧数据落不进规范结构;若做统一全局入口,又要先判断「这批数据属于哪个实体」——判断成本高。

**决策**:`import-mapping` 原语 = **模板驱动 + 目标实体触发 + 独立页签**。

- **模板驱动**：系统为已支持实体预定义主要字段模板，源列映射到模板字段，不自由映射。实体字段、必填和关系以 [DATABASE](../rewrite/DATABASE.md) 与对应页面规格为准；红圈或既有文件分析帮助确认来源列匹配，不反向覆盖已确认方案。
- **实体触发**:从目标实体的列表页触发(如分供方列表→导入),**目标模板隐含,不做统一导入入口**;不属于该实体的行在预览步**直接删掉**即可。
- **独立页签**:导入是复杂流程——越复杂越少用弹窗,故走独立页签(不遮罩挡信息、提交失败不误触关闭),与[[页签导航]]的 15 上限同管、成功自动关闭。
- **三步 stepper**:上传(拖 Excel/CSV)→ 映射(左源列↔右模板字段两栏 + 智能预匹配)→ 预览/导入(行预览 + 进度条,与导出 stepper 同源)。
- **映射三色态**:`--brand` 已匹配 / `--warn` 待确认 / `--danger` 必填缺失;必填未映上**拦住不进导入步**。
- **通用路由 + 静态注册表**:所有导入映射共用 `/import/mapping/:entity`,实体键即路由参数;模板字段与逐行入库函数在代码内静态登记(`app/lib/kit/import-entities.ts`),刷新后仍可解析,不需要 transient 上下文(与 ADR 0004 导出的 jobId + transient context 不同——导入的数据来自页签内上传,触发方只携带实体身份)。
- **解析口径 = 所见即所得**:上传解析返回原始表头(不裁剪、重复表头按 `_1` 后缀消歧,列名与数据行键逐字一致)与按单元格显示格式转文本的行值(日期不落成 Excel 序列号);无 BOM CSV 默认按 UTF-8 读,表头出现替换符时自动按 GB18030 回退(中文 Excel「另存为 CSV」常见)。
- **映射版式以模板字段为主轴**:映射步为「模板字段清单逐行对照源列下拉」——必填门控以字段为清单,较「源列在左」的对照更直接;同一源列可供多个字段使用,但界面须显式提示。
- **失败重试 = 续导**:导入步逐行入库,失败停在当前行并保留页签;重试从失败行继续,已成功行不重复入库(与 ADR 0004 导出重试续写同思路)。

**考虑过的替代**:

- 统一全局导入入口(要先判断数据属哪个实体,复杂,否决——改实体触发)。
- 弹窗承载(复杂流程用弹窗遮罩挡信息、易误关,否决——改页签,与导出配置同理)。
- 无模板自由映射(旧数据落不进规范结构,否决——改模板驱动)。
- 让识别类/清单拆表复用本原语(它们是识别/解析路径,不是列映射,否决)。

**后果**:

- 各实体导入模板须与当前字段/关系契约一致，支持范围以页面规格与静态注册表为准，不能因原型存在就认定真实入库和恢复已接通。
- 导入页签与列表/详情页争 15 上限,故完成即自动关闭。
- 「预览步可删非归属行」是实体触发模式的配套——因触发即锁定实体,混入的异实体行靠人工剔除,不做自动归类。
- 每个实体导入模板预留一列「外部旧ID / 匹配标识」(仿红圈 `field3__c 匹配标识`),存源系统主键,用于迁移对账、二次修正、去重。
- 采纳时红圈分析覆盖分供方、项目、施工合同、支出合同、收支清单行、材料送货和发票台账；当时班组/工人与施工记录的模板属于待核实项。该记录只保留历史证据范围，当前支持实体及已确认业务决定直达 DATABASE / 页面规格，不把旧待办重复当作本轮待决定问题。
