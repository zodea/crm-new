# 全站界面对标采用运行参考与瑞航设计双源基准

> 状态：已采纳（2026-07-17）
> 来源：用户指令（2026-07-17）——「所有开发界面布局，统一按线上 claude.ai/design『瑞航CRM-NEW』`app.dc.html` 的布局排版、颜色统一；框架组件不符则替换」。
> 补充裁定（2026-07-18）——设计稿只定义视觉层级与宽屏构图，**不是固定画布合同**；生产项目必须自适应并响应容器/视口，不能用固定长宽或永不变化的列模板复刻截图。
> 补充裁定（2026-07-27，Issue #181）——#181 取代 #110 对运行参考的有限解释：有直接对应页时，登录态红圈 CRM 是**构图、信息密度、控件状态与安全交互路径**的运行态参考；`app.dc.html` 保留瑞航品牌、DC 独有能力和无直接参考页的当前方案。参考站不得覆盖瑞航字段含义、数据、权限或领域状态机。
> 取代：[ADR 0011](0011-redesign-application-shell.md) 的**视觉与布局**条款（其行为能力条款保留，见下）。

## 背景

ADR 0011（issue #82）将应用外壳定为「深蓝侧栏 `#162238` + 54px 顶栏 + 36px Chrome 式页签」，并声明外壳不在设计稿对照范围内（DESIGN-TASTE §8.1「有意分叉」）。此后线上 Claude Design 一直是用户视觉验收的满意基准，外壳与内容区双轨基准造成「线上满意、本地有出入」的长期观感割裂。#110 曾把登录态参考限制在表面密度；#181 进一步要求真实 app 对照直接参考页逐屏收敛，因此需要明确运行参考与瑞航设计稿各自的权威边界。

## 决策

界面对标采用以下权威链：

1. 当前功能范围按用户指令确定，字段含义和状态机查 `docs/rewrite/pages/`、`DATABASE.md` 与 `CONTEXT.md`；需求歧义直接问用户。
2. 有直接对应页时，登录态运行参考决定构图、信息密度、控件状态和安全可观察的交互路径；证据等级与只读边界登记在 `docs/design/runtime-reference-audit.md`。
3. `DC重构设计源码/app.dc.html`、`kit/*.jsx` 与 `_ds/.../tokens/*.css` 决定瑞航品牌、DC 独有能力、无直接参考页的当前方案和全站设计令牌。
4. 新增/编辑业务实体继续遵守 ADR 0014 的独立路由整页表单，不能因参考站使用弹窗而改变产品边界。

运行参考与设计稿中某一视口的像素长宽都只是参考样态；若其固定尺寸写法与下述响应式或可达性契约冲突，**以本 ADR 的契约为准，并在同一工作单元补齐设计与实现**。

### 内容表面与密度补充（2026-07-27）

- Panel / MetricGrid / 表格承载面统一使用 `--radius-card: 4px`、`1px --line` 和无卡片阴影；可点面板只变边框或底色，不再上浮或升级阴影。
- 按钮、输入和筛选使用 `--radius-btn: 4px`，小控件用 `--radius-sm: 3px`；`--radius-pill` 保留给计数、进度及明确需要胶囊的非状态标识。业务状态标签采用下述 2026-09-08 补充裁定。
- SectionHeader 使用不超过 34px 的 `--surface-2` 紧凑层级条，保留瑞航蓝竖标；业务 SegTab 高 32px，仍为下划线式，不改变页签顺序和行为。
- 依据登录态运行参考中采购合同与分供方列表的只读实测，vxe-table 表头与数据行统一 36px，表头 13/700，正文 14px；列宽手柄只位于当前列表头右边缘，宽表仅在自身容器横滚，分页继续使用左统计、右操作的 `--surface-2` 汇总条。公共实现契约见 `docs/design/kit-ui-component-specs.md` 第 12 节。
- 颜色令牌、字段含义和业务行为冻结；共用观感只通过共享令牌与通用原语传播。有直接证据的页面按运行参考收敛模块顺序与信息流，无直接证据时沿用瑞航设计稿，并用运行态测试锁定新信息流。

### 列表内容与状态标签补充（2026-09-08）

用户在 [#404 本轮反馈](https://github.com/zodea/crm-new/issues/404#issuecomment-5582280040) 要求全站逐页对应表头、搜索、工具、状态和列内容，并确认默认完整展示业务适用的参考列。已有“最少列组”、列表状态纯文字和状态胶囊要求据此收敛：默认列及查询合同看 [CRM 列表模式](../rewrite/CRM-PATTERNS.md#1-列表页)，表格业务状态采用紧凑浅底、小圆角、明确文字的标签，具体配方看[组件规格](../design/kit-ui-component-specs.md)。类别、来源、计数等非状态标识不因名称为 chip 而自动迁移。

这项决定统一展示方式；字段含义、真实状态及已定排除仍遵循本 ADR 的权威链。完整适用列的代价由表内横滚和真实列设置承担，不靠通用列替代专属字段。实施按页面与动态类型分批验证，文档定稿不等于所有调用点已经迁移。

### 外壳规格（2026-09-08 按直接复刻授权更新）

用户确认此前偏差仍明显，要求直接复刻。旧白底宽侧栏、双行导航和高顶栏在 [#404 留证](https://github.com/zodea/crm-new/issues/404#issuecomment-5582911938) 后由本节替代；瑞航品牌及既有外壳行为保留。

- **侧栏**：展开 208px / 收起 48px，深海军蓝实色。用户在同日后续反馈确认保留深色，但原 12px 菜单过小，因此可读性优先于此前 176px 紧凑复刻：菜单和搜索统一 14px，菜单图标 18px、行高 38px，普通文字使用更明亮的浅色。品牌头保留瑞航名称与蓝色标记；菜单为单行图标加名称，不恢复重复副标题及大汉字方块。选中项使用蓝色浅亮背景与左缘标记；待建项保留清晰文字和明确标识，不再整体降低透明度。导航结构、展开状态、搜索和侧栏固定能力沿用现行实现，所有页面共用同一侧栏。
- **顶栏**：40px 白底、细下边线，单行标题与日期、数据来源和应用工具；取消重复业务副标及毛玻璃。
- **页签栏**：32px，标签紧凑单行，活动页签使用品牌色；横滚限定在页签容器内。关闭、刷新、页签上限和缓存行为不变。
- **内容区**：使用响应式 gutter，桌面收敛到 12px 左右的紧凑留白；连续列表保持平整白底。仅内容区纵滚，表格在自身容器内横滚。

### 响应式与自适应契约（2026-07-18 补充）

本节是全站布局的强制验收口径，适用于 Nuxt、当前 `app` 设计稿以及后续新增页面：

1. **运行参考与设计稿都不是固定画布。** 页面默认使用流式容器，不得把参考视口转换成固定页面宽度、固定页面高度、整体缩放画布或任何宽度下永不变化的列模板。`max-width` 只表示可读宽度上限，不能与固定 `width` 混用来锁死页面。
2. **CSS 布局优先。** 使用 Grid/Flex、`minmax()`、`clamp()`、媒体查询或容器查询响应可用空间；重复卡片可用 `auto-fit` / `auto-fill`，不再全局禁止。只有确有阅读顺序的语义栏位才可显式定义宽屏列数，但必须同时给出降列、堆叠、分段 Tab 或 Sheet 的窄容器退化。禁止用全局 `window.resize` 状态驱动普通布局；仅图表、Canvas 等必须重绘的介质可使用 `ResizeObserver`。
3. **按可用空间而非截图尺寸重排。** 宽屏多栏只表示首选构图。卡片、字段、工具条和按钮组应在达到最小可读宽度前自动换行或降列；三栏核对工作台、树表详情和左右侧栏在平板/手机必须切为堆叠、可切换分区或 Sheet，不能只继续压缩列宽。
4. **高度由内容与动态视口共同决定。** 禁止以 `100vh - 常量` 再叠加大 `min-height` 锁死工作台。全高场景使用 `dvh` / `svh`、`min-height:0` 和局部滚动；内容增长、软键盘与浏览器工具栏变化时，主操作仍须可达。
5. **滚动边界明确。** `body` / 应用工作区不得产生横向滚动。表格、矩阵、甘特、时间线、A4 预览等密集数据面允许在**自身标识清楚的容器**内横滚；不得靠裁切、缩小字号或省略金额来消除溢出。业务 SegTab 默认换行；只有应用外壳路由页签按本 ADR 使用自身横向滚动。
6. **固定值只服务语义。** 侧栏展开/收起宽度、顶栏/页签高度、按钮/图标尺寸、表格行高与语义列最小宽、A4 比例等可作为组件令牌；抽屉、弹窗、栏位使用 `min()` / `max()` / `clamp()` 或最小/最大边界。上述固定值不得升级为固定页面画布或固定业务区长宽。
7. **内容扩张不得破版。** 长名称可换行或在可恢复完整值（如 `title` / tooltip）的场景截断；金额与关键编号不得因窄屏显示不全。浏览器缩放至 200% 时不得出现文字重叠、内容不可达或关键操作被裁切。
8. **最低验证矩阵。** 每个代表性页面至少在 390、768、1024、1280/1440px 内容视口检查：无页面级横滚；导航、筛选、主 CTA、表单字段和确认动作可达；多栏按约定重排；局部横滚容器不撑破页面。自动化应断言 `document.documentElement.scrollWidth <= window.innerWidth`，并单独验证允许横滚的密集数据容器。

### 保留自 ADR 0011 的行为能力（不受本 ADR 影响）

路由驱动页签 + 纯状态机权威（右键四类关闭、刷新只失效当前实例、最多 15 个业务页签、关闭同步清缓存）；通知中心右侧抽屉与 Pinia store；侧栏固定/分组展开状态持久化；<1024px 侧栏转 reka-ui Sheet；导航搜索。**行为底座继续遵循 ADR 0008（reka-ui）/ ADR 0009（vxe-table）。**

### 框架组件替换原则

框架/库组件（shadcn-vue、reka-ui、vxe-table、vue-sonner 等）的**默认观感与本 ADR 的现行基准冲突时，一律以现行基准为准**：优先通过令牌桥接与变体定制对齐（如 #109 五变体、#110 Panel）；定制无法达成时替换实现（自绘或换件），交互可达性（焦点/键盘/aria）不得回退。**不允许**「以框架默认样式为由」偏离基准。

### 通用组件沉淀与渐进迁移

设计稿对齐不得退化为业务页面内的一次性样式复刻。按钮、弹窗壳、表格尺度与单元格、状态标签、工具栏等稳定的跨领域能力，应优先沉淀到 `app/components/ui/*` 或 `app/components/shared/*` 的现有组件；确无合适入口时再增加职责清晰的通用原语。WBS、甘特、领域表单等承载特定业务语义的结构继续归领域组件所有，不因视觉相似而强行抽象。

迁移采用**改到哪、迁到哪**的渐进方式：当前任务触及的界面立即消费新通用能力并完成逐屏对照，未触及界面不在同一轮无差别重刷；通用组件 API 优先保持向后兼容，后续界面整改时直接复用，使设计标准自然扩展到全站。只有 issue 明确要求全站切换时，才允许一次性改变全局默认观感。通用组件自身通过 `/dev/kit-ui` 或组件测试验证，仍不能替代业务页面在参考视口与响应式矩阵中的视觉验收。

### 颜色与排版

内容区品牌令牌权威源不变：`DC重构设计源码/_ds/.../tokens/content-v5.css`（`app/assets/css/tokens.css` 首行 @import 引入）。侧栏由 `--shell-*` 映射深海军蓝与浅色文字；顶栏及内容区继续使用白底和瑞航蓝。正文基准 14px；参考式密集列表可用 12px 正文、32px 行高，常规表格保留 36px，舒适模式可增高。几何调整不能降低可读性或焦点可见性。

## 后果

- DESIGN-TASTE §8.1「有意分叉」表中**外壳行作废**——外壳纳入逐屏对照范围，对照基准同内容区。
- ADR 0011 的旧视觉尺寸以及本 ADR 历史白底单字方块方案均不再作为实施目标；外壳以本节最新规格为准。
- 实施拆分：外壳重构（侧栏/顶栏/页签视觉迁移）+ #181 子票的全站布局逐屏对照，按运行参考证据等级实施。
- 外壳颜色桥接和尺寸令牌随本 ADR 的现行外壳规格同步；令牌各自保持单一权威定义与生成清单一致，本文的历史方案不再作为实施尺寸。
