# 红圈补采差距清单（2026-07-11 走查轮）

> 本轮目的：对照红圈线上系统，找出 DC 设计稿在**数据交互、界面跳转、数据展示深度、弹窗完善度**上的差距。
> 采集样本：一个全流程真实项目（数据本体在 gitignored 的 `红圈系统/` 补采文档与 `DC重构设计源码/数据蓝本/`，本文只写结构结论，不含真实业务数据）。
> 下轮实装路径：真实数据 → `kit/data.local.js`（gitignored 双轨，`data.js` 留虚构兜底）。

## 0. 本轮最重要的一句话

红圈的「深」不在单页，而在**每个数字都属于一条可穿透的勾稽链**：
`目标成本(清单项) → 支出合同 → 结算(额度) → 付款申请 → 支付`（支出侧）与 `合同 → 报量(收入结算) → 开票 → 收款`（收入侧），再汇聚回项目详情的经营数据面板。DC 现在的假数据互相不认识，这是「简陋感」的根源——补数据关联比补样式优先。

## 2. 列表页模板差距

- **视图切换器**（预置业务视图，如付款申请的「全部待追回发票付款申请单」）；
- **左侧分类树**：合同状态（履约/中止/废除/终止）、变更类型、结算业务类型、发票类型——几乎每个列表都有一棵；
- **服务端底部汇总行**（sum/avg/min/max/count，随筛选联动）；
- 「含下级」部门范围开关；列头漏斗筛选；导出/导入/新建；20/页分页+跳页。
- DC 现状：仅搜索+分页。差距最大的三件：**左树、汇总行、视图**。

## 3. 项目详情 = 数据枢纽（DC ProjectSubTables 蓝本）

- **11 个关联 Tab**（比首采记录的 8 个多）：详细资料 / 成本预算 / 施工合同管理 / 支出合同管理 / 票税管理 / 资金管理 / 往来款 / 扣返款 / 支付明细 / 物资管理 / 竣工验收及保修。每 Tab = 按项目过滤的下游对象列表 + 各自汇总行 + 新建入口。
- **经营数据三组指标卡**（项目经营数据/往来款/票据信息），每指标带 ⓘ 口径说明；全部是下游单据回写的**只读派生值**（项目对象无 edit 权限），勾稽公式已实测验证（可用资金余额、变更后合同金额、增值税、税负率）。
- **业务流程阶段步进器**：六阶段+每阶段任务清单（任务名∣职责人说明）+完成计数；阶段流转由单据审批自动驱动+可手动。
- **右栏**：项目组成员(业务角色) / 文件 / **评论（@全员浮层、Ctrl+V 贴图）** / 跟进人（转移负责人/分配负责权） / 动态（审计日志）。
- DC 动作：10 Tab 占位换成真实关联视图；经营数据面板每个数字可点击穿透到来源 Tab。

## 4. 金额勾稽链（数据蓝本核心，DC 数据层的目标形态）

**收入侧**：施工合同（可多份，含税金额合计=项目主合同金额）→ 报量单（对象实名「收入结算」，一期一单）→ 开票（一期一票，发票挂开票申请+合同）→ 收款登记（带 before/after 累计快照）。差额即「开票未收款」。
**支出侧**：目标成本（清单树，含税合价=Σ顶层类目）→ 支出合同（**分包/材采/租赁/其他统一对象**，F_bizType 区分；补充协议=独立合同行+原合同反链）→ 支出结算（过程/完工结算，可超合同额）→ 付款申请（8 类型；关联结算额度「剩余可支付」+关联发票「剩余未关联」+罚扣转扣）→ 支付。
**交叉关联**：付款申请挂**目标成本清单项**（成本预算列路径），汇成目标成本的「已申请付款金额」「实际发生成本」「成本占比%」；未挂清单项的进「**未关联数据池**」（详情页红色入口计数）。
**联营语义**（DC 缺失概念）：客户收款全进公司 → 公司「退往来款」给联营方（往来收付对象）→ 工程款支付由联营方线下承担，公司「支付明细」为 0；我方乙方主体=「相关方 stakeholder」对象。

## 5. 审批呈现

流程图（节点+人+状态）+ 右栏时间线；**同人相邻节点自动通过**（「审批人与上一节点审批人相同，自动通过」）；单据「第 N 次提交」版次徽标；列表「当前审批人」列；审批状态色徽（已通过/审批中/已驳回）。DC 无审批概念——演示版至少要有状态徽标+时间线呈现。

## 6. 业务分类词表（可直接抄进 DC 枚举）

- 付款申请 8 类型：有合同（人材料分包）/ 无合同（人材料分包）/ 有合同（人分包）预付款 / 有合同（材料）预付款 / 无合同（材料）预付款 / 项目（管理费）/ 项目（项目费用）/ 公司付款。
- 收入侧变更 4 类：变更洽商 / 现场签证 / 索赔 / 材料认价（+由「指令单」立项）。
- 支出侧变更 4 类（责任归属）：业主变签 / 项目管理人员失误（无效成本）/ 原班组错误或仅施工部分 / 有成本预算但未归类。
- 结算：过程结算 / 完工结算（收入侧另有 最终结算 视图）；分包结算业务类型：专业分包 / 劳务分包 / 零星用工。
- 分供方：类别（劳务分包商/材料供应商/设备供应商/其他，多选）+ 业务类型（公司分供方/零星供应商）。
- 收票分类：项目有合同收票 等；发票类型树：增值税专票/普票/火车票/航空行程单/其他。

## 7. 事实性发现（影响 DC 造数策略）

- **收尾链（竣工验收/最终结算/保修到期确认单）与收入侧变洽签、项目罚扣、甲方罚扣单在红圈全公司均 0 条**——阶段状态靠手动。DC 对应屏按「结构+空态」实装即可，不造假数据。
- 样本项目材料不走仓储台账（乙供材下料/到货/领用/盘点全空），直接「材采合同→结算→付款」。仓储子页低优先。
- 项目对象只读（无编辑入口），一切经营数字由单据回写——DC 项目详情不需要「编辑经营数据」。
