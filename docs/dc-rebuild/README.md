# DC 设计稿重构 — 总览与进度

> 对象：claude.ai/design 项目「瑞航CRM-NEW」的 `app.dc.html` 单页设计稿
> 目标：以 `docs/rewrite/pages/*.md` 为内容蓝本，把各页面按统一的「疏朗仪表盘」风格重构，消除「各页各做一套」的割裂感
> 开始：2026-06-30 · 本目录为实施记录

---

## 一、背景与核心决策

### 1.1 问题
- 原 `app.dc.html` 侧边栏列出了完整导航，但 `<main>` 只渲染了 5 个路由，其余页面点击空白（已先补齐接入）。
- 更关键：**各页面风格不统一**——首页/工程量是用户亲自调过的「圆角卡片 + 阴影 + 充足留白」现代仪表盘风，而发票/分供方/工人等列表页还是「密集表格台账 + 横条工具栏」的旧 CRM 风，两种风格并存 = 割裂。

### 1.2 风格基准（已与用户确认）
**以首页 `HomeScreenNew` + 工程量 `QuantityScreenV2` 为唯一视觉基准**，所有页面向其看齐。

> ⚠️ 注意：`docs/rewrite/DESIGN-SYSTEM.md` §1.2 / §3.2 / §4.1 写的是「内容区扁平、无圆角、无阴影」的旧 CRM 规范，**已与实际实现和用户要求脱节**。实际 `_ds_bundle.js` 里的 `Panel`/`StatCard` 组件早已是圆角 12px + 阴影。本轮以「首页/工程量」为准，`DESIGN-SYSTEM.md` 冲突条款暂不更新（用户要求），但**不要再照旧 DESIGN-SYSTEM 的扁平规范做**。详见 [STYLE-GUIDE.md](./STYLE-GUIDE.md)。

### 1.3 内容蓝本
每个页面的 Tab 结构、字段、列表列、筛选、详情页设计，**严格按 `docs/rewrite/pages/*.md` 实现**（不只是套皮，结构也要对齐 md）。

### 反馈轮 7（2026-07-03：grill 定稿中 —— 识别中心 + 合同留底 + 发票排版/台账拆分 + 送货单归档）

#### A. 信息架构（最高层决策）
- 新建侧边栏菜单组**「识别中心」**：发票识别（上传+校对排版）/ 送货单识别（处理区）/ 清单拆表 / OCR 设置。台账不跟着走：发票台账留资金管理、送货单归档库留乙供材管理、清单管理独立页留分包及人工（#38）。原则：**识别是动作、台账是资产——动作集中、资产归域**。
- 红圈研究结论（红圈系统/08-资金管理 收票登记）：无 OCR，纯登记台账；但**每张发票登记那刻强制归属**（四分类：项目有/无合同收票 × 公司有/无合同收票，有合同直接挂合同）→ 台账项目列/合同列全是蓝链。DC 学它的强制归属，识别层（OCR+排版打印）是 DC 的增值。

#### B. 合同（施工合同留底 + 清单拆表）
- 「合同」双层定义：**施工合同 = 项目留底文件**（文书本身不做统计）；**合同工程量清单 = 合同的附件**，所有数据统计在清单上。本轮只做甲方侧（项目详情 Tab ③），支出合同不挂文件。
- 分层：**Tab ③ = 文件柜**（合同行可传合同扫描件在线预览 + 清单附件；清单拆表后只显状态 chip「已拆表 · N 行」，点击跳清单管理页）；**清单管理独立页 = 数据工作台**（#38 承接拆表结果 + 分项目录 + 三量 + 变更单 + 报量）。
- 合同文书「读取」= **纯预览留底**，合同行字段手工填写，不做 OCR。
- 清单拆表 = **三步向导**：① 上传（自动识别格式类 A–E，boq-import.md）→ ② 确认页（聚合人工确认节点：户型×套数对照、单套量×套数差额、镜像归并、零量行取舍）→ ③ 拆表结果预览（统一清单行模型 + 来源追溯键）→ 入库清单页。Mock 样例 = **合和七期（B 类，最复杂）**。
- **#38 解除 blocked**：所谓"等模板"的模板分析已完成（boq-import.md，7 份真实合同 5 类格式）。

#### C. 发票
- 「两页打印」定义澄清 = **每页 2 张的 A4 排版**；根因：#41 重做校对界面时蓝本 §5.4 排版预览整体丢失，打印退化为单张直打。
- 校对页加**子模式切换「字段校对 / 打印排版」**（布局草图已确认）：
  - 字段校对（默认）：列表单行化收窄至 18%、原图放大至 40%、右栏 9 字段改**两列紧凑网格**、置信度=边框色+角标百分比、绿字段不放确认按钮、货物明细默认折叠；底部操作条 [废弃]…[重新识别][归档入账]，**打印按钮撤出本模式**。
  - 打印排版：恢复蓝本 §5.4 全部交互——每页 1/2/4 张（默认 2 张上下）、缩略勾选+全选、右键单张旋转、整页旋转、翻页、底部常显「已勾 N 张·M 页 A4·金额合计」；打印流程 = 生成 PDF→系统打印→确认弹窗→printCount+1。台账「打印 PDF」入口跳转此模式。
- 页面拆分：**发票识别**（识别中心：上传+校对排版同页）与**发票台账**（资金管理：列表/打印/修改三种呈现）两个独立页面。
- 台账单张编辑 = **应用内页签**（接 #40 红圈式页签导航）：开「发票 #xxxxx」页签，左原图右字段表单，改完关页签回台账——不再与校对与排版冲突。
- 项目归属：不在台账里"设置"，**归档那刻强制选定**（学红圈）；无项目禁止归档/导入（CONTEXT.md「归档」）。
- 发票识别页布局（grill 定稿）：**取消独立上传 Tab**，单一校对工作台 = 整页；上传入口 = 左栏顶部「+ 上传发票」按钮 + **全页拖拽**（虚线遮罩提示）；上传后文件直落左栏列表原地显示「识别中 N%」；「按购买方金额汇总表」彻底撤掉。
- 发票台账三呈现（grill 定稿，草图已确认）：
  - **列表（默认=总览）**：左树右表。左树**只到项目一级**（根「全部」默认选中 / 各项目 / ⚠未归项目），只带张数不带金额；供应商、发票类型走列头筛选。**表格↔卡片视图切换**（卡片=发票预览大图，便于快速删除）。**无常驻金额汇总**——只有勾选时底部才浮出「已选 N 张·合计 ¥xx」（用户明确反对到处展示总金额）。

#### D. 送货单
- **双区拆分**：处理区（识别中心·送货单识别，只放待识别/识别中/待核对）+ **归档库**（乙供材管理，**左树右列表**：工地→分供方→月份，点树节点出文件列表）。首页平铺态废除。
- 归档规则（CONTEXT.md「归档」已记）：核对完成即自动归档；**核对是归档唯一前置**；未指定项目禁止导入（批量/单个同拦截）。
- 导出/归档文件夹层级：**项目→分供方**；分供方排序按其**合同签订日期升序**（合同优先做，签约顺序即分供方优先级）。
- 文件树可调整（grill 定稿）：
  - **整理树（识别阶段）**：拖拽文件移组、分组↔工地升降级、重命名、新建/删除节点（蓝本阶段二全量恢复）。
  - **归档库左树**：两级**项目→分供方**（无月份层，日期走文件列表的年月日区间筛选）；分供方按合同签订日期升序；每项目下设 ⚠**「未区分分供方」**兜底节点；**所有节点带文件数量角标（只数量不金额）**；节点可**手动新建**（从分供方库选）+ 归档时自动创建缺失节点；文件可拖拽改归属。
  - **分供方名模糊纠错**：识别/文件夹推断的公司名在分供方库模糊匹配给建议、一键替换（识别阶段与归档后编辑通用）。
  - **归档不是终态**：归档库文件仍可改归属/字段，但任何修改弹**二次确认弹窗**（识别难免出错，留改错通道）。
- **OCR 设置**（grill 定稿，独立设置页；版式参考 ppocrv6-studio，已派 3 agent 源码级核实）：**单页竖排区块布局**（不用多 Tab），每个配置项下一行说明文案解释影响，滑块带实时数值回显；底部「恢复默认」（带 confirm）+「保存」（toast「已保存，引擎已重载」）。区块：
  - ① **识别引擎（按单据类型分）**：发票/送货单/清单各一行引擎选择（本地 PaddleOCR / 云端 PaddleOCR-VL / 大模型视觉）；**送货单强制云端**（用户拍板）。
  - ② **云端与大模型接入**：API 地址 + 密钥 + 模型名 + 「测试连接」（跑样例图看结果）。
  - ③ **本地引擎参数**（学 studio）：模型档位（轻量/标准/高精度 select + 说明）、检测参数滑块（二值化阈值/框置信度/外扩比例/最大边长）、失败自动旋转重试（**本地引擎内部行为**，云端 VL 自带自动旋转不配置）。
  - ④ **置信度与流程**：绿/黄分档阈值滑块（说明文案明示「仅作参考着色，判决权在人」）。降级链：主引擎失败回落顺序（云端→本地→人工）。
- **「全绿自动通过」降级为标记**（发票/送货单统一）：全绿只标「建议通过」，不自动走核对完成；人工点「批量通过」一次放行。黄/红字段经人工确认/修正变绿后，同样进入批量通过的范围。

#### E. 归属拦截与出口（grill 定稿）
