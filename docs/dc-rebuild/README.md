## 一、背景与核心决策

### 1.1 问题
- 原 `app.dc.html` 侧边栏列出了完整导航，但 `<main>` 只渲染了 5 个路由，其余页面点击空白（已先补齐接入）。
- 更关键：**各页面风格不统一**——首页/工程量是用户亲自调过的「圆角卡片 + 阴影 + 充足留白」现代仪表盘风，而发票/分供方/工人等列表页还是「密集表格台账 + 横条工具栏」的旧 CRM 风，两种风格并存 = 割裂。

### 1.2 风格基准（已与用户确认）
**以首页 `HomeScreenNew` + 工程量 `QuantityScreenV2` 为唯一视觉基准**，所有页面向其看齐。

> ⚠️ 视觉风格基准 = 圆角卡片 + 阴影，以 [ADR 0007](../adr/0007-unified-visual-style-rounded-cards.md) 为准（DESIGN-SYSTEM.md 的扁平旧条款已作废）；dc-rebuild 组件级细化见 [STYLE-GUIDE.md](./STYLE-GUIDE.md)。

### 1.3 内容蓝本
每个页面的 Tab 结构、字段、列表列、筛选、详情页设计，**严格按 `docs/rewrite/pages/*.md` 实现**（不只是套皮，结构也要对齐 md）。

### 反馈轮 7（2026-07-03：grill 定稿中 —— 识别中心 + 合同留底 + 发票排版/台账拆分 + 送货单归档）

> 状态：**grill 进行中**，以下为已拍板决策；开放问题见末尾清单。术语已回写 CONTEXT.md（施工合同 / 归档 / 识别中心）。蓝本（finance-invoice.md / material-delivery.md / project-info.md）与新架构冲突的条款**待 grill 结束后回写**。

#### A. 信息架构（最高层决策）
- 新建侧边栏菜单组**「识别中心」**：发票识别（上传+校对排版）/ 送货单识别（处理区）/ 清单拆表 / OCR 设置。台账不跟着走：发票台账留资金管理、送货单归档库留乙供材管理、清单管理独立页留分包及人工（#38）。原则：**识别是动作、台账是资产——动作集中、资产归域**。
- 红圈研究结论（红圈系统/08-资金管理 收票登记）：无 OCR，纯登记台账；但**每张发票登记那刻强制归属**（四分类：项目有/无合同收票 × 公司有/无合同收票，有合同直接挂合同）→ 台账项目列/合同列全是蓝链。DC 学它的强制归属，识别层（OCR+排版打印）是 DC 的增值。

#### B. 合同（施工合同留底 + 清单拆表）
- 「合同」双层定义：**施工合同 = 项目留底文件**（文书本身不做统计）；**合同工程量清单 = 合同的附件**，所有数据统计在清单上。本轮只做甲方侧（项目详情 Tab ③），支出合同不挂文件。
- 分层：**Tab ③ = 文件柜**（合同行可传合同扫描件在线预览 + 清单附件；清单拆表后只显状态 chip「已拆表 · N 行」，点击跳清单管理页）；**清单管理独立页 = 数据工作台**（#38 承接拆表结果 + 分项目录 + 三量 + 变更单 + 报量）。
- 合同文书「读取」= **纯预览留底**，合同行字段手工填写，不做 OCR。
- 清单拆表 = **三步向导**：① 上传（自动识别格式类 A–E，boq-import.md）→ ② 确认页（聚合人工确认节点：户型×套数对照、单套量×套数差额、镜像归并、零量行取舍）→ ③ 拆表结果预览（统一清单行模型 + 来源追溯键）→ 入库清单页。Mock 样例 = **合和七期（B 类，最复杂）**。
