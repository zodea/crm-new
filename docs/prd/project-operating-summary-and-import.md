# PRD：通用项目经营汇总与实体迁移

> 基线：`crm-new` 本地 `main@09971b01`
> 首个验收数据集：车陂商业大楼项目
> 关联：ADR 0015、`CONTEXT.md`、`docs/rewrite/DATABASE.md`

## 1. 目标

在 `crm-new` 中建立一套通用、可追溯的项目经营汇总能力，并将现有 Excel 按实体迁入系统。系统不保存一份可人工改写的“汇总表副本”，而是根据业务源单实时计算汇总。

成功标准：

- 每个汇总金额可下钻到源单；
- 合同、结算、付款、工资和报销口径不混用；
- 未取得数据与真实零发生可以区分；
- 同一笔支付记录可以分摊到多张付款申请；
- Excel 中已发现的公式、静态值和明细矛盾不会被静默带入系统；
- 首个样本的可追溯合同、结算和合同付款数据能够对平。

## 2. 范围

### 2.1 本期范围

- 项目基本资料与施工合同；
- 支出合同主合同、补充协议及五类汇总；
- 支出结算及动态成本；
- 付款申请、发票勾稽、支付记录及支付分摊；
- 工人工资确认发放形成动态成本；
- 费用报销作为动态成本来源；
- 项目收款、往来款、保证金、备用金等资金流；
- 项目经营汇总页、分类明细下钻、完整性状态；
- Excel 分实体导入、校验、预演和对账。

### 2.2 本期不做

- 库存余额、材料转入和材料转出；
- 资金效能 `J25` 的数值计算；
- 工人工资税额及由我方开具发票的流程；
- 根据合同税率、文件名称或业务常识推算缺失发票金额；
- 自动认可 OCR 结果；
- 把 Excel 已用区域中的空白公式行导入为业务记录。

## 3. 统一术语

本 PRD 统一使用 [`CONTEXT.md`](../../CONTEXT.md) 中的“专业分包”“合同劳务”“工人工资”“动态成本”“支付记录”“支付分摊”“分供方”和“客户”等术语，不在二级文档重复定义。Excel 原始名称与系统术语的对应关系见[睿璟工作簿映射](../migration/ruijing-workbook-mapping.md)。

## 4. 核心业务规则

### R-01 支出合同五类

系统报告维度固定为：

1. 专业分包；
2. 合同劳务；
3. 材料；
4. 机械；
5. 其他。

项目当前 `contracts.kind/sub_kind` 仍可用于界面分组，但必须提供稳定的 `cost_category` 作为经营汇总维度。禁止继续使用“劳务/专业分包 → 人工”的旧映射。

### R-02 主合同与补充协议

- 一个支出合同可有多份补充协议；
- 主合同金额与补充协议金额分别保存；
- 经营口径的合同额为主合同加有效补充协议，不通过重复合同号和名称猜测；
- Excel 的同合同号多行迁移时，必须先确认主记录，其余记录迁为补充协议或标记待人工确认。

### R-03 合同、结算、付款分离

合同、结算、付款申请和支付记录的领域含义统一见 [`CONTEXT.md`](../../CONTEXT.md)，数据来源与派生约束统一见 [`DATABASE.md §10.1-10.4`](../rewrite/DATABASE.md)。页面必须把四类金额分栏展示并提供各自的源单下钻，不允许用户用一种金额回填另一种金额。

### R-04 支付事实与确认

普通合同付款的事实来源、OCR 人工确认、去重和汇总准入规则统一执行 [ADR 0015 决策 5](../adr/0015-form-persistence-and-payment-reconciliation.md)。产品必须提供支付记录识别/手录、人工核对、确认、撤回和异常提示能力。

### R-05 支付记录与付款申请分摊

支付记录与付款申请的多对多关系、分摊守恒、已付/未付派生及旧字段退出写路径统一执行 [ADR 0015 决策 6](../adr/0015-form-persistence-and-payment-reconciliation.md)。页面必须支持查看和编辑分摊，并将付款申请的已付金额作为只读派生值。睿璟样本的数值验收见[验收清单](../migration/ruijing-acceptance.md)，本 PRD 不复制样本基准。

### R-06 付款申请与发票多对多

付款申请与发票的关系及约束统一执行 [ADR 0015 决策 3-4](../adr/0015-form-persistence-and-payment-reconciliation.md)。页面必须支持多行关联、显示剩余额度并处理临时新增支付内容造成的多笔发票。

### R-07 工人工资例外

工人工资的领域边界见 [`CONTEXT.md`](../../CONTEXT.md)，状态、成本与支付事实统一见 [`DATABASE.md §10.3`](../rewrite/DATABASE.md) 和 #117。产品必须把工人工资与合同劳务分开展示，并提供工资确认发放及历史快照查询，不要求逐工人支付记录。

### R-08 动态成本

动态成本定义见 [`CONTEXT.md`](../../CONTEXT.md)，计算与禁止混入口径见 [`DATABASE.md §10.4`](../rewrite/DATABASE.md)。页面必须展示分类构成、完整性状态和源单下钻；睿璟样本只在[验收清单](../migration/ruijing-acceptance.md)维护。

### R-09 资金指标

资金指标公式统一见 [`DATABASE.md §10.6`](../rewrite/DATABASE.md)。页面必须展示流入、流出、收支差额和工程款余缺，并允许下钻到资金源单；迁移前显示值只在[验收清单](../migration/ruijing-acceptance.md)维护，差异进入对账队列。

### R-10 票税、动态效益和完整性

票税实体口径沿用现有票税域；动态效益公式见 [`DATABASE.md §10.4`](../rewrite/DATABASE.md)，完整性状态见 [`DATABASE.md §10.5`](../rewrite/DATABASE.md)。页面必须区分待补录、不适用、尚未定义和真实零值，不自行补零或推算票税。

## 5. 汇总页输出

### 5.1 支出合同

显示五类合同额、占比和总额。每个金额可下钻到合同及补充协议。

### 5.2 动态成本

显示五类合同结算、工人工资、费用报销、总额及完整性。占比统一以当前动态成本为分母；若数据不完整，比例标注“基于已录入数据”。

### 5.3 合同付款

显示五类已确认支付分摊金额及合计。分类继承关联合同的 `cost_category`，不得从付款用途文本猜测。

### 5.4 分供方汇总

至少显示合同额、结算额、付款额、合同未付、结算未付、收票额、进项税额。查询主键必须是 `supplier_id + contract_id`；展示时才按分供方汇总，不以名称作为关联键。

### 5.5 状态

接口形状和状态语义统一见 [`DATABASE.md §10.5`](../rewrite/DATABASE.md)。页面必须呈现指标状态、缺失来源、汇总截止时间和源单下钻入口。

## 6. 导入流程

1. 选择项目或先导入项目；
2. 上传 Excel，识别工作表；
3. 按实体预览：分供方、施工合同、支出合同、补充协议、结算、付款申请、支付记录、支付分摊、往来款；
4. 自动映射后人工确认低置信字段；
5. 执行预演，列出错误、警告、重复和待补录；
6. 先迁主数据，再迁业务单据和分摊；
7. 生成导入批次及逐行来源追溯；
8. 运行经营汇总对账；
9. 差异未清零前允许保存批次，但不得标记“迁移验收完成”。

## 7. 非功能要求

- 金额计算使用整数分或等价十进制定点，页面统一两位小数；
- 导入和分摊保存使用数据库事务；
- 所有业务查询遵守软删除和祖先可见性规则；
- 每个导入实体保存源文件、工作表、行号和导入批次；
- 相同导入批次可安全重试，不重复创建记录；
- 汇总查询不得读取人工维护的静态总额；
- OCR 原图、识别结果、人工修订和确认人均可审计。

## 8. 实施切片

1. 修正合同分类与补充协议模型；
2. 增加支付记录—付款申请多对多分摊并迁移旧已付字段；
3. 完成工资确认发放与费用报销成本事件；
4. 建立统一经营汇总查询和完整性状态；
5. 增加 Excel 实体导入模板和预演；
6. 导入睿璟样本并完成差异对账；
7. 将项目详情页接入新汇总查询并完成穿透。
