# 待调整项汇总 — 用户反馈 2026-06-26

## 一、分供方状态流转重大调整

原设计的五阶段（collecting → ready → claiming → paid → settled）需要重构为更完整的审批链。

### 新流程（按顺序）

1. **分供方资料提交** → **分供方确认流程**（有审核人员，审核人暂定后续补充）
2. **合同确认流程**（分供方确认通过后才进入）
   - 关联项目
   - 甲方
   - 分供方
   - 合同类型
   - 合同金额
   - 税额
   - 开票产品明细（清单格式，支持从 Excel 复制粘贴）
   - 押金
   - 需有审核人员确认
3. **请款流程**（合同通过后才可进入）
   - 此阶段需插入**发票流程**和**付款流程**
   - 需新开**财务专属界面**（具体内容后续补充）
4. **结算**（全部请款完结后才进入，终态）

### 关键变化

- 每个流程节点都有**审核人员**（角色/人员待定，后续补充）
- 增加了「分供方确认」环节，不再是直接标记资料齐全就进下一步
- 合同环节细化，新增：合同类型、税额、开票产品明细（清单）、押金
- 开票产品明细支持从 Excel 复制粘贴导入
- 财务相关（发票+付款）需要独立界面，不混在分供方详情里
- 结算条件变为「全部请款完结」，不是单次付款后即可结算

- [ ] 发票流程与付款流程的详细拆解
- [ ] 各审批节点的驳回/退回规则

## 二、施工项目 & 工人补充

### 2.1 区域结构补充

现有四层树「楼栋 → 楼层 → 户 → 房间」中的**房间**层需要细化部位：
- 客厅、厨房、阳台、厕所等
- （设计文档中已有 Room 概念但需要确认是否就是这个意思，还是需要再加一层"部位"）

### 2.2 工人文件存储

现有工人数据模型几乎全是字面字段（文本），缺少**文件保存字段**：
- 身份证扫描件
- 证书原件扫描件
- 合同扫描件
- 其他附件
- 需要实际的文件存储路径，不只是 certs[] 里的 relPath

### 2.3 工资发放确认

现有设计只覆盖了「计算工资」环节，缺少**工资发放确认**流程：
- 计算完成后需要有确认/审批步骤
- 具体流程待补充

### 2.4 考勤与工资挂钩

考勤不是独立模块，必须与工资发放流程联动：
- 发放工资前需核对考勤天数
- 考勤数据作为工资计算的输入依据
- 两者需要在界面上有明确的关联入口
