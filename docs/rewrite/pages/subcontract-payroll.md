# 工资核算与考勤工作台

> 路由：`/subcontract/payroll`、`/subcontract/payroll/new`、`/subcontract/payroll/:id`、`/subcontract/attendance`、`/subcontract/daywork`
> 当前模块复核：[#412](https://github.com/zodea/crm-new/issues/412)；业务边界见 [`CONTEXT.md`](../../../CONTEXT.md)，#117 / #198 为历史决议来源。
> 既有实现范围（本轮按 #412 重新验证）：负责人请款簿三态、累计应付防重复、A 户型派生、C1 逐人考勤工资、C2 逐日签工、月度/结算/尾款档、来源版本复核、组内实际发放分配、发放快照、A4/Excel 冻结快照导出与考勤月矩阵。B 类已定退役；遗留编码只用于历史兼容和迁移，不是待开发格式。

## 一、现行操作契约

### 工资核算

1. 按项目、月份、班组、状态筛选负责人请款簿；负责人和候选成员只显示当前项目责任范围内人员。列表只承担筛选、汇总和台账阅读，不在列表内展开大型建单表单。
2. 点击“新建工资草稿”进入 `/subcontract/payroll/new` 独立整页建单；项目、月份和班组随来源 query 带入，取消或成功后返回原筛选范围。建单时选择请款负责人、同班组成员和已实现格式族（A/C1/C2）。A 支持月度/结算/尾款；C1 只开放月度考勤工资；C2 只开放月度签工工资并固定按已确认工数 100% 核算。B 类不得显示为“后续”待开发选项；#412 核实遗留入口退役、存量迁移与成本隔离，界面、store、服务和输出层均不得绕过。
3. A 类月度进度草稿可明确选择“暂估量”或“现场复核量”；结算档固定按现场复核量×95%，尾款档固定按现场复核量×100%。
4. 合同量不会出现在工资取数选项中，只用于收入、量差和毛利对照。
5. A 草稿按项目责任范围读取工程量；核对现场量时只统计工资月份之前已经完成的报量工序，不能把“已指派但未施工”当成应付。缺少所选量口径时整单报错，不允许部分行静默通过。
6. C1 从当月考勤汇总日工和加班；至少有一条当月考勤才能建单。日薪优先读取每名工人档案，档案未配置时才使用建单表单的兜底标准；无考勤成员也随草稿固化零数量费率行，后补考勤不会被错误改成负责人单价或 0 单价。
7. 负责人、成员、班组必须匹配工人档案及当前项目责任；服务层再次校验，不依赖界面下拉过滤。
8. A 类应发金额按“当前累计现场复核工资×档位比例－同负责人同格式此前已发累计”计算；发放事务内再次重算此前已发，避免两张先核对单依次发放时重复付款。C1 / C2 按各自当月考勤或已确认签工核算，不套用 A 类累计档位公式；同一来源事实不得重复计薪。本次应发为 0 或实际发放超过本次应发时禁止发放。
9. “核对”重新读取现场复核量、C1 考勤或 C2 已确认签工，保存来源版本与来源更新时间。
10. “确认已发放”使用轻量弹窗登记实际总额和组内收款分配。默认全部给负责人，也可拆分给全部成员；零金额成员仍须保留，分配合计不等于实际总额时不能提交。
11. 发放前再次计算来源指纹；来源变化时单据持久标记“需重核”并禁止发放。实际总额、按整数分保存的组内分配和状态更新在同一事务落库。发放快照保存项目/班组/负责人显示名、来源版本/时间、累计应付、此前已发、实际金额、组内成员姓名与分配、操作者、提交时间、明细及 C2 完整签工记录；读取已发单时以快照为准。旧历史单没有分配事实时明确显示“历史单未记录组内分配”，不推测为负责人收款。
12. 只有已发放单可以打印或导出：A/C1 输出工资表，C2 输出零星用工记录表与工资表；工资表自带工人签字按手印列和四方签字位。Excel 使用同一冻结快照输出发放汇总、工资明细、组内分配，C2 额外输出零星签工。打印动作只调用系统打印窗口，不改工资状态。

状态机：

```text
草稿（A 暂估/现场二选一；C1 读考勤；C2 读已确认签工）
  → 核对（强制刷新对应真实来源）
  → 已核对（登记实际总额并完成组内收款分配）
  → 已发放（现场量、金额和分配快照只读）
```

### 考勤

1. 按项目、月份、班组筛选。
2. 工人 × 日期矩阵读取 `attendance_records`。
3. 点击日期单元格录入正常工时、加班工时和施工内容；日期必须真实存在，正常与加班合计不得超过 24 小时；同一工人同一天再次保存为覆盖更新。
4. 31 天矩阵只在自己的容器横向滚动，页面根节点不横滚；首列工人姓名冻结。
5. 从“全部班组”视图录入时按工人档案自动保存班组归属；C2 签工负责人/成员的单元格置为不可编辑。
6. C1 工资发放后，该负责人及成员当月考勤锁定；当前不允许把后补工时静默塞进已发快照，后续调整单能力另行实现。
7. 页面汇总只读取当前筛选下的真实名册、考勤人日、正常工时、加班工时和锁定人数；无项目、无工人、读取失败和保存失败分别显示，不用演示数字补位。保存失败保留当前单元格输入供修正。

### C2 零星签工

1. 在 `/subcontract/daywork` 按项目、月份、班组维护逐日签工；每条记录包含日期、施工内容、起止时间、用工人、整工/半工、证明人和确认日期。
2. 待确认记录保留在签工台账但不进入工资；可在记录行点“编辑”，补齐证明人和确认日期后转为已确认。已确认记录才是 C2 唯一计薪来源。
3. C2 请款主体配置按“项目 × 负责人”保存默认大工单价和可编辑确认规则；建单时复用，修改配置会进入来源指纹。
4. 同一人员同月只能走考勤或 C2 签工之一；两条入口在同一写事务内双向校验。同一人员同日时段不能重叠，整工/半工合计不得超过 1 工。
5. 每条签工事实只能归属一张有效 C2 工资单，不能跨负责人重复计薪。C2 已发放后，关联签工事实不可移动或修改，补签需走后续调整流程。
6. C2 工资按人员汇总已确认工数；月与月独立，不扣减上月签工工资。签工内容、时段、证明人或主体费率/规则变化都会触发重新核对；重核采用当前配置，并在发放快照保存实际采用的配置。

## 二、跨页来源上下文与运行态空态

工资域跨页来源上下文固定为 `project`、`month`、`crew`、`status` 四项 query。它们只恢复筛选，不参与工资单、考勤或签工实体身份；任何未知值都必须按现有选项和格式规则丢弃，不能据名称猜 ID。

| 来源 | 目标 | 必须恢复的结果 |
|---|---|---|
| 工资台账 | 新建工资草稿 | 预填项目、月份、班组；取消或成功后返回原四项筛选 |
| 工资台账 | 考勤 | 恢复项目、月份、班组，并保留工资状态用于返回 |
| 考勤 | C2 零星签工 | 恢复同一项目、月份、班组和返回状态 |
| 工资台账 | 请款簿详情 | 详情返回原四项筛选，而不是无条件返回工资根路由 |
| 工资台账 / 签工 | 相互返回 | 不得退回默认项目、当前月或全部班组 |

2026-08-13 的本地只读走查记录前两条通过，当时发现：`/subcontract/daywork` 仍忽略来源 query，且其“打开考勤 / 返回工资核算”只指向根路由；`/subcontract/payroll/:id` 的返回也固定为工资根路由。这些是历史缺口，须在 #412 按当前提交重新验证来源恢复；不能据旧记录判定目前仍未实现，也不改变工资状态机。

2026-08-13 初始 JSON seed 未覆盖工资、考勤或签工；没有真实事实时保持空态，不补 Mock 成功记录。已有领域/组件测试是历史验证来源，#412 仍须按当前提交验证冻结快照、C1/C2 互斥、已发月份封锁及来源往返；非空运行验收使用隔离确定性夹具或授权迁移样本。

## 三、业务边界

- 工资单主体是“请款负责人 × 月份 × 格式族 × 档位”，不是单个组员各自一张单。
- 合同量不是工人工资应付量，禁止静默回退。
- A 类核对和发放固定使用现场复核量；C1 使用真实考勤，C2 使用已确认签工。
- 已发放金额以实际登记值为准；动态成本和工资支付只读取 `status='released'` 的 `actual_amount`。
- 组内分配只解释一笔工资实际由谁收款，不生成第二笔工资成本，也不改变工资行的个人核算参考值。
- 独立“工资进度款工具”已退役，工资域只保留本工作台入口。
