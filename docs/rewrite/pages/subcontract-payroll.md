## 一、现行操作契约

### 工资核算

1. 按项目、月份、班组、状态筛选负责人请款簿；A 使用可证明的当前项目责任范围，C1 使用有效工人档案当前项目或可证明的有效现场责任，不以工程量或 BOQ 存在作为考勤前提。列表只承担筛选、汇总和台账阅读，不在列表内展开大型建单表单。
2. 点击“新建工资草稿”进入 `/subcontract/payroll/new` 独立整页建单；项目、月份和班组随来源 query 带入，取消或成功后返回原筛选范围。建单时选择请款负责人、同班组成员和已实现格式族（A/C1/C2）。A 支持月度/结算/尾款；C1 只开放月度考勤工资；C2 只开放月度签工工资并固定按已确认工数 100% 核算。B 类不得显示为“后续”待开发选项；历史记录明确只读，改价、核对、发放和新工资输出入口均拒绝，不重新解释原金额、状态或快照。#412 继续核实存量迁移与成本隔离，不能以界面退役代替其验收。
3. A 类草稿、核对和发放均从已完成施工事实与现场量形成，不再以暂估量生成。月度比例为单据参数，默认沿用同主体上月有效月度单据保存的比例：草稿和已核对单读取保存头，已发读取冻结比例，明确 0 保留；上月结算单不能覆盖月度比例，无上月月度记录才使用明确建档配置。结算档默认 95% 可改，尾款档固定 100%。该口径沿 #412 继承的 #287 最终决议及 [#117 比例决定](https://github.com/zodea/crm-new/issues/117#issuecomment-5015356993)；旧本地计算分支尚存的差异由 A 中央核算切片纠正，不能把只读接管当作已修复核算。
4. 合同量不会出现在工资取数选项中，只用于收入、量差和毛利对照。
5. A 草稿按项目责任范围读取工程量；核对现场量时只统计工资当月及以前已经完成的报量工序，不能把“已指派但未施工”当成应付。缺少所选量口径时整单报错，不允许部分行静默通过。
6. C1 按原逐日考勤核算正常及加班工资；至少一条当月真实考勤才能建单，全零记录可保留零草稿并核对，零应发不可发放。合法日薪优先读取每名工人档案，档案缺值才采用工资域明确保存的个人兜底；独立配置加班时薪优先，未配置才用该人日薪÷8。正常工资为正常工时÷8×本人日薪，加班工资为加班工时×本人加班时薪，最终金额到分，原工时和费率不提前舍入：7.5 小时、日薪 480 得 450；日薪 481、正常 8 加班 2 得 601.25，独立加班价 55 时得 591。7.51 工时须完整可见；明确 0 不等于缺配置。全成员各自保留正常和加班两行，无考勤成员也保本人零数量与标准，后补后重核不继承负责人单价。

   C1 的取数口径显示“真实考勤”，明细显示“考勤数量”，核对动作显示“核对考勤”或“重新核对考勤”；核对后未发考勤仍可依法修正并触发重核，不能用“锁定”让人误认为已经发放冻结。不得把兼容存储值 `quantity_source=field` 解释为现场工程量。个人费率配置为独立整页，清楚区分档案值、有效值与原保存的兜底/加班输入。
7. 负责人、成员、班组必须匹配工人档案及对应格式的项目资格；服务层再次校验，不依赖界面下拉过滤。C1 不从合同乙方、同名供应商或 BOQ 推断用工关系。
8. A 类应发金额按“当前累计现场复核工资×档位比例－同负责人同格式此前已发累计”计算；发放事务内再次重算此前已发，避免两张先核对单依次发放时重复付款。C1 / C2 按各自当月考勤或已确认签工核算，不套用 A 类累计档位公式；同一来源事实不得重复计薪。本次应发为 0 或实际发放超过本次应发时禁止发放。
9. “核对”重新读取现场复核量、C1 考勤或 C2 已确认签工，保存来源版本与来源更新时间。
10. “确认已发放”使用轻量弹窗登记实际总额和组内收款分配。默认全部给负责人，也可拆分给全部成员；零金额成员仍须保留，分配合计不等于实际总额时不能提交。
11. 发放前再次计算来源指纹；来源变化时单据持久标记“需重核”并禁止发放。实际总额、按整数分保存的组内分配和状态更新在同一事务落库。发放快照保存项目/班组/负责人显示名、来源版本/时间、各类型适用金额、组内成员姓名与实分配、操作者、提交时间及明细；C1 另存完整逐日考勤和个人费率出处，C2 另存完整签工记录。读取已发单时以快照为准。旧历史单没有分配事实时明确显示“历史单未记录组内分配”，不推测为负责人收款。
12. 只有证据完整的已发放单可以打印或导出：A 输出工资表，C1 配对输出工资表与考勤表，C2 配对输出零星用工记录表与工资表；工资表自带工人签字按手印列和四方签字位。Excel 使用同一冻结快照输出发放汇总、工资明细、组内分配，C1 额外输出逐日考勤，C2 额外输出零星签工。输出不读取当前名册、费率或考勤补旧快照；单据配对不代替后续整月/全周期工作簿。打印只调用系统打印窗口，不改工资状态。

状态机：

```text
草稿（A 读已完成施工与现场量；C1 读考勤；C2 读已确认签工）
  → 核对（强制刷新对应真实来源）
  → 已核对（登记实际总额并完成组内收款分配）
  → 已发放（现场量、金额和分配快照只读）
```

### 考勤

1. 按项目、月份、班组筛选。
2. 工人 × 日期矩阵读取 `attendance_records`。
3. 点击日期单元格录入正常工时、加班工时和施工内容；日期必须真实存在，工时有限非负，正常与加班合计不得超过 24 小时。项目、工人和日期相同的合法重存保原记录 ID；转组后从新组同日写入须拒绝，不能改挂原班组或另建第二条。空格为无记录，未保存的默认 8 小时不自动成为考勤。
4. 31 天矩阵只在自己的容器横向滚动，页面根节点不横滚；首列工人姓名冻结。
5. 从“全部班组”视图录入时按工人档案自动保存班组归属；同项目同人同月的 C2 独立待确认/已确认签工、有效工资主体全成员及已发月锁都会阻止新考勤，不能借不同班组筛选绕过。A 与 C1 同人同月不互斥。
6. C1 工资发放后，该负责人及成员当月考勤锁定；当前不允许把后补工时静默塞进已发快照，后续调整单能力另行实现。
7. 页面汇总只读取当前筛选下的真实名册、考勤人日、正常工时、加班工时和锁定人数；无项目、无工人、读取失败和保存失败分别显示，不用演示数字补位。保存失败保留当前单元格输入供修正。
8. 历史记录与当前名册资格分别显示；改名、转组或离场后，原组范围内仍能查看原考勤和当前不可写原因，不能把历史行消失当成没有考勤。未知、真实零、已删除和坏来源分别说明，旧冲突历史不自动删一方。
9. 换范围、切单元格或离开时保护未保存输入。原提交结果未知时只核对原命令；成功后冷读失败或暂时撤权不代表未保存。返回工资恢复原稳定单据或草稿，四项 query 只决定筛选范围。

### C2 零星签工

1. 在 `/subcontract/daywork` 按项目、月份、班组维护逐日签工；每条记录包含日期、施工内容、起止时间、用工人、整工/半工、证明人和确认日期。
2. 待确认记录保留在签工台账但不进入工资；可在记录行点“编辑”，补齐证明人和确认日期后转为已确认。已确认记录才是 C2 唯一计薪来源。
3. C2 请款主体配置按“项目 × 负责人”保存默认大工单价和可编辑确认规则；建单时复用，修改配置会进入来源指纹。
4. 同一人员同月只能走考勤或 C2 签工之一；两条入口在同一写事务内双向校验。同一人员同日时段不能重叠，整工/半工合计不得超过 1 工。
5. 每条签工事实只能归属一张有效 C2 工资单，不能跨负责人重复计薪。C2 已发放后，关联签工事实不可移动或修改，补签需走后续调整流程。
6. C2 工资按人员汇总已确认工数；月与月独立，不扣减上月签工工资。签工内容、时段、证明人或主体费率/规则变化都会触发重新核对；重核采用当前配置，并在发放快照保存实际采用的配置。

## 二、跨页来源上下文与运行态空态

工资域跨页来源上下文固定为 `project`、`month`、`crew`、`status` 四项 query。它们只恢复筛选，不参与工资单、考勤或签工实体身份；任何未知值都必须按现有选项和格式规则丢弃，不能据名称猜 ID。

| 来源 | 目标 | 必须恢复的结果 |
|---|---|---|
| 工资台账 | 新建工资草稿 | 预填项目、月份、班组；取消或成功后返回原四项筛选 |
| 工资台账 | 考勤 | 恢复项目、月份、班组，并保留工资状态用于返回 |
| 考勤 | C2 零星签工 | 恢复同一项目、月份、班组和返回状态 |
| 工资台账 | 请款簿详情 | 详情返回原四项筛选，而不是无条件返回工资根路由 |
| 工资台账 / 签工 | 相互返回 | 不得退回默认项目、当前月或全部班组 |

签工的 `draft/confirmed` 确认状态只筛选签工记录，与返回工资时的 `draft/checked/released` 状态分别保存；在签工中改变项目、月份或班组后，返回工资与考勤采用当前范围，工资状态沿用来源。详情的来源 query 只用于返回，实体读取始终使用路由中的工资单 ID。

同路径页签复用时，工资、考勤与签工接收新的来源 query；不能只在首次挂载恢复。原来源切回不重置签工未保存输入，换项目、月份或班组时使用该范围的新表单，旧范围编辑不串入。

出现任一工资来源键即按来源恢复：省略或为空的 `crew` 表示全部班组，省略、为空或非法的 `status` 表示全部工资状态，不得恢复旧筛选；只有完全没有四项来源键的普通入口沿用缓存。项目和班组须按已读选项归一；中央深链未知项目显示失效原因，不切换到默认项目。旧桌面本地入口暂保留原默认首项目规则，不能将该行为带回中央来源。

2026-08-13 初始 JSON seed 未覆盖工资、考勤或签工；没有真实事实时保持空态，不补 Mock 成功记录。已有领域/组件测试是历史验证来源，#412 仍须按当前提交验证冻结快照、C1/C2 互斥、已发月份封锁及来源往返；非空运行验收使用隔离确定性夹具或授权迁移样本。

## 三、业务边界

- 工资单主体是“请款负责人 × 月份 × 格式族 × 档位”，不是单个组员各自一张单。
- 合同量不是工人工资应付量，禁止静默回退。
- A 类核对和发放固定使用现场复核量；C1 使用真实考勤，C2 使用已确认签工。
- 原已发放金额以原实际登记和冻结为准；工人工资成本及工资已付读取原发放、真实补退和有效错记冲销的同源实际净额。核算更正、成员分配和后月处理关系不另计现金，见 [DATABASE](../DATABASE.md#工资更正实际补退与后月处理412p4)。
- 组内分配只解释一笔工资实际由谁收款，不生成第二笔工资成本，也不改变工资行的个人核算参考值。
- 独立“工资进度款工具”已退役，工资域只保留本工作台入口。

## 四、本轮复核与既定排除

[#412](https://github.com/zodea/crm-new/issues/412) 逐项验证 A / C1 / C2 的来源、精度、防双计、来源变更重核、已发锁定、更正与回读。独立更正的业务规则已经继承，中央命令尚未接通时明确不可用，不能直接改已发快照。#117 已定的房补、管理费、户级空鼓扣款、批量资金建议及完整工作簿保留后续实施义务，不因核心历史只读完成而取消；逐期范围见[工资承接规格](../../research/issue-review-2026-09-11/payroll-central-spec-draft.md#纵向分期与依赖)。

B 类退役不重开选型；施工 BOQ 仍是合同收入清单，不得按合同或名称猜工人工资责任。完整审批、人员账号权限和后台扩张沿用总图排除；正式持久化、备份与部署走后置上线门。

## 五、独立更正与实际收付（P4）

P4 已通过本地中央实例验收，证据见[更正与实际收付记录](../../design/evidence/issue-412-payroll-adjustments/README.md)。原已发详情保留原签收和成员分配，追加独立更正历史及收付入口。更正新建/编辑分别使用 `/subcontract/payroll/adjustments/new` 与 `/subcontract/payroll/adjustments/form/:id`，已确认详情使用 `/subcontract/payroll/adjustments/:id`；补退及错记冲销分别使用 `/subcontract/payroll/payments/new` 与 `/subcontract/payroll/payments/reversal/new`，确认事实在 `/subcontract/payroll/payments/:eventId` 只读查看。

这些整页表单分开确认核算与实际收付；固定原工资、采用依据和原提交，未知结果或成功后读取失败仍保留待核对状态。后月应用在 A/C1/C2 原实际发放步骤明确选择，只与成功发放一起提交。历史成员和原单锁不解除，原签字金额不改。

`/subcontract/payroll/payments` 提供按稳定项目的只读台账，可从工人、班组、项目、预算与付款分区进入。来源 query 只恢复返回范围，实体始终按稳定 ID 与 origin 读取；预算入口同时校验原预算项目与版本返回。工资分区不灌入付款申请、银行流水或往来余额。

具体操作、金额例子和失败处理只维护在[工资更正与实际收付指南](../../guides/payroll-adjustments.md)；数据字段与命令分别以 DATABASE / COMMANDS 为准。
