> 路由: `/schedule` · `/schedule/:pid`
> 页面: `pages/schedule/index.vue` · `pages/schedule/[pid].vue`
> 蓝本来源: `docs/合和新城7期施工进度计划表 （户内）2026.04.22.pdf`（MS-Project 式现场进度计划表规范）

> 定位: **工期 × 工程量** 这条线的组织主轴，替代原首页硬编码里程碑卡 + 独立楼层甘特的割裂形态。

## 一、定位与核心决策

作为**施工方**做整个工程的进度把控与成本控制。红圈 API 偏合同/材料台账（甲方成本视角），本模块补齐施工方最缺的一环：**把"计划工期"和"现场实际工程量"绑在同一条时间线上，随施工实时看提前/延后与成本偏差**。

核心原则（grill 已定）：

1. **一条时间线**：计划里程碑/工序 + 实际工程量推进 + today 线，叠在同一横轴（旬/月），不再头部一个时间节点、下面一个只读展示。
2. **工序挂计划，进度取工程量**：工序存计划起止/工期/依赖；能对应分项的工序，实际进度由工程量完成率**自动**算；无工程量的工序手动填。
3. **分组级一根条 + 下钻**：甘特按 `楼栋分组 × 工序` 每格一根条 + 完成率；点工序下钻到工程量矩阵（筛到该分组 + 该分项）。
4. **成本双层**：首页项目级 目标 vs 实际；下钻工序时挂到分项、与材料联动。
5. **机械费**：设备租赁归支出合同/其他合同，作机械费科目归集，不单独建模块。

## 二、WBS 三层结构

照 PDF 规范，排程是三层 WBS：

```
项目（合和新城7期精装修工程 · 184 工作日 · 2026-05-01~10-31）
├── 楼栋分组 户内10栋-22栋（summary · 171 工作日）
│   ├── 工序 放线及新建墙体（30 工作日 · 5/6~6/4）
│   ├── 工序 给排水安装（30 工作日 · 5/8~6/6）
│   ├── … 22 道工序 …
│   └── 工序 开荒保洁（8 工作日 · 10/16~10/23）
└── 楼栋分组 户内23栋-30栋（summary · 149 工作日）
    └── … 同 22 道工序，计划错后 …
```

- **项目行 / 楼栋分组行**：summary，工期与起止由子工序汇总（min 开始、max 完成），不单独录。
- **工序行**：排程原子单位，人工录计划或从工序标准库带出。
- **楼栋分组**：跨多栋楼的分段（10-22栋 = 13 栋）。分组与工程量的 `楼栋` 通过 `schedule_group_buildings` 关联（一分组含多栋）。

## 四、数据模型（SQLite）

> 实体关系与外键统一在 `DATABASE.md` 维护，本节只给业务字段。

### schedule_groups（楼栋分组）

```sql
CREATE TABLE schedule_groups (
  id           TEXT PRIMARY KEY,     -- "sg_<ts>_<seq>"
  projectId    TEXT NOT NULL,        -- → projects.id
  name         TEXT NOT NULL,        -- "户内10栋-22栋"
  sortOrder    INTEGER DEFAULT 0,
  createdAt    TEXT, updatedAt TEXT, deleted_at TEXT
);
```

### schedule_group_buildings（分组×楼栋，多对多）

```sql
CREATE TABLE schedule_group_buildings (
  id         TEXT PRIMARY KEY,
  groupId    TEXT NOT NULL,          -- → schedule_groups.id
  buildingId TEXT NOT NULL,          -- → buildings.id（工程量树的楼栋）
  UNIQUE(groupId, buildingId)
);
```

### schedule_tasks（工序 / 排程任务）

```sql
CREATE TABLE schedule_tasks (
  id             TEXT PRIMARY KEY,   -- "st_<ts>_<seq>"
  projectId      TEXT NOT NULL,
  groupId        TEXT,               -- → schedule_groups.id（工序归属分组；项目/分组 summary 行为 NULL）
  parentId       TEXT,               -- 自关联，支持 WBS 层级（项目→分组→工序）
  name           TEXT NOT NULL,      -- "墙砖粘贴"
  wbsType        TEXT NOT NULL,      -- 'project' | 'group' | 'task' | 'milestone'
  durationDays   INTEGER,            -- 工期（工作日）
  plannedStart   TEXT,               -- 计划开始 yyyy-mm-dd
  plannedFinish  TEXT,               -- 计划完成 yyyy-mm-dd
  actualStart    TEXT,               -- 实际开始（首个工程量完成日 / 手动）
  actualFinish   TEXT,               -- 实际完成
  hasQty         INTEGER DEFAULT 0,  -- 1=进度自动取工程量, 0=手动
  manualProgress REAL,               -- hasQty=0 时的手动进度 0~1
  itemName       TEXT,               -- 冗余：对应分项名（hasQty=1）
  trade          TEXT,               -- 归属工种（泥水/油漆/…）
  sortOrder      INTEGER DEFAULT 0,  -- 工序序位（决定默认前后置）
  note           TEXT,
  createdAt TEXT, updatedAt TEXT, deleted_at TEXT
);
```

### task_dependencies（工序前后置依赖）

```sql
CREATE TABLE task_dependencies (
  id         TEXT PRIMARY KEY,
  predId     TEXT NOT NULL,          -- 前置工序 → schedule_tasks.id
  succId     TEXT NOT NULL,          -- 后置工序 → schedule_tasks.id
  type       TEXT DEFAULT 'FS',      -- FS(完成-开始) | SS | FF | SF
  lagDays    INTEGER DEFAULT 0,      -- 搭接/延后天数（可负=搭接）
  UNIQUE(predId, succId)
);
```

### task_item_map（工序 ↔ 工程量分项）

```sql
CREATE TABLE task_item_map (
  id        TEXT PRIMARY KEY,
  taskId    TEXT NOT NULL,           -- → schedule_tasks.id
  itemName  TEXT NOT NULL,           -- 对应分项名（墙砖/地砖/防水/腻子/乳胶漆…）
  weight    REAL DEFAULT 1,          -- 多工序共享一分项时的权重（腻子一遍0.5/二遍0.5）
  UNIQUE(taskId, itemName)
);
```

> 工序标准库本身作为 seed 常量（`工序模板`），新建分组时批量实例化为 `schedule_tasks`。

## 五、进度计算（计划 vs 实际）

### 5.1 实际完成率（hasQty=1 的工序）

某工序（如 10-22栋·墙砖粘贴）的实际完成率 =
```
该分组所有楼栋下，该分项(墙砖)【已有 completedMonth 的房间数】
÷ 该分项在该分组的【总应做房间数】
```
即复用 `quantities.completedMonth`（工程量矩阵着色的同一字段），不新增录入口。

- `actualStart` = 该分项在该分组内最早 completedMonth 对应日；`actualFinish` = 全部完成时的最晚月。
- 未完成时 `actualFinish` 空，进度线画到"当前完成率"处。

### 5.2 手动进度（hasQty=0 的工序）

放线/给排水/电线/空调/门/柜/开关/洁具/保洁等无计量口径的工序，进度取 `manualProgress`（在工序行或弹窗直接填 0~100%）。

### 5.3 提前/延后

```
计划应完成率 = clamp((today - plannedStart) / (plannedFinish - plannedStart), 0, 1)
偏差 = 实际完成率 − 计划应完成率
偏差 > 0 → 提前；< 0 → 延后；换算天数 = 偏差 × 工期
```
分组行、项目行的偏差按子工序**工期加权**汇总。

## 六、成本对比（目标 vs 实际 · 人材机）

### 6.1 首页 · 项目级

| 科目 | 目标（预算） | 实际（发生） |
|---|---|---|
| 人工 | 目标成本清单·人工 | 分包结算 + 零星用工结算（劳务分包/计件计时工资） |
| 材料 | 目标成本清单·材料 | 材料采购结算（乙供材+甲供材）+ 送货单 |
| 机械 | 目标成本清单·机械 | 设备租赁结算 + 零星机械结算 |
| 其他 | 目标成本清单·其他 | 费用报销 + 其他支出 |
| **合计** | 目标成本总额 | 累计支出 |

对比呈现：目标 vs 实际 双色柱 + 偏差率；结合进度算**已完成产值 vs 已发生成本**（挣值/成本超支预警）。

### 6.2 下钻 · 工序→分项级（与材料联动）

点工序进入工程量矩阵后，该分项每格（房间×分项）可展开：
- **人工**：该房间该分项施工人的工资（工程量 × 分项单价）。
- **材料**：该分项对应的材料消耗（送货单/领用挂到分项）——这是"与材料联动"的落点，需 `送货单/材料领用` 增加 `itemName` 归集维度。
- **机械**：分摊（若该工序用到设备租赁，按面积/工期分摊）。
- 目标：分项目标单价 × 工程量；实际：三项之和；差 = 盈亏。

> 材料联动为二期深化（送货单/领用增加分项归集字段），首期先打通 人工 + 进度，材料/机械先到项目级。

## 九、验收要点

1. 首页只有**一张**时间线，计划工序 + 实际完成率 + today 线同屏可见，能一眼看提前/延后。
2. 工序进度：hasQty=1 自动取工程量完成率，hasQty=0 手动填，二者在同一甘特无缝。
3. 点任一工序能下钻到工程量矩阵并筛到对应分组+分项。
4. ~~首页项目级 目标 vs 实际（人材机）成本对比可见。~~ **作废（反馈轮 8）**：首页不放成本对比，对比看工程量清单。
5. 独立进度页可编辑 WBS：调计划、连依赖、套工序模板建分组。
6. 楼栋分组跨多栋，与工程量树的楼栋关联正确。
7. 工序标准库 22 道可作模板复用，分项映射可调。
