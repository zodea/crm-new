## 一、定位与核心决策

作为**施工方**做整个工程的进度把控与成本控制。红圈 API 偏合同/材料台账（甲方成本视角），本模块补齐施工方最缺的一环：**把"计划工期"和"现场实际工程量"绑在同一条时间线上，随施工实时看提前/延后与成本偏差**。

核心原则（grill 已定）：

1. **一条时间线**：计划里程碑/工序 + 实际工程量推进 + today 线，叠在同一横轴（旬/月），不再头部一个时间节点、下面一个只读展示。
2. **工序挂计划，进度取阶段完成**：工序维护计划起止/工期/依赖，并引用稳定工序阶段；有工程量来源的工序按户 × 工序阶段完成事实**自动**算，不能从责任配置或分项共享完成率推断；无工程量来源的工序手动填。
3. **分组级一根条 + 下钻**：甘特按 `楼栋分组 × 工序阶段` 每格一根条 + 完成率；点工序下钻到工程量矩阵（筛到该分组 + 该阶段及映射分项）。
4. **成本分层**：项目与目标成本页按正式事实对比预算和实际；工序下钻仅在稳定来源映射存在时关联分项和材料。首页展示范围以 [首页蓝本](./homepage-dashboard.md) 为准，不由排程页额外增加成本卡。
5. **机械费**：设备租赁归支出合同/其他合同，作机械费科目归集，不单独建模块。
6. **建组依据二选一**：已签约时，以一份施工合同的《合同工程量清单》结构化拆表结果为边界；未签约时，可按 [ADR 0017](../../adr/0017-provisional-schedule-before-contract.md) 从项目手工维护的区域与暂估工程量建立内部暂估排程。一个分组同一时刻只能使用一种依据；签约后通过显式绑定动作校验范围、分项和数量差异，合同分组仍禁止跨合同混组。

## 二、WBS 三层结构

照 PDF 规范，排程是三层 WBS：

```
项目（合和新城7期精装修工程 · 184 工作日 · 2026-05-01~10-31）
├── 楼栋分组 户内10栋-22栋（summary · 171 工作日）
│   ├── 工序 放线及新建墙体（30 工作日 · 5/6~6/4）
│   ├── 工序 给排水安装（30 工作日 · 5/8~6/6）
│   ├── … 22 道工序 …
│   └── 工序 开荒保洁（8 工作日 · 10/16~10/23）
└── 楼栋分组 户内23栋-30栋（summary · 149 工作日）
    └── … 同 22 道工序，计划错后 …
```

- **项目行 / 楼栋分组行**：summary，工期与起止由子工序汇总（min 开始、max 完成），不单独录。
- **工序行**：排程原子单位，人工录计划或从工序标准库带出。
- **楼栋分组**：跨多栋楼的分段（10-22栋 = 13 栋）。合同清单分组的候选楼栋来自该合同所挂《合同工程量清单》的拆表结果；内部暂估分组的候选楼栋来自项目手工维护的区域树。二者不得在同一分组混用；关联模型见 `DATABASE.md`。

## 四、模型依赖

排程实体、字段、外键和索引只在 [DATABASE.md §2.7 / §3.5](../DATABASE.md) 维护；阶段完成与工程量的职责边界只在 [ADR 0010](../../adr/0010-quantity-matrix-and-construction-record-model.md) 维护，本页不复制 schema。

页面只依赖以下可观察行为：

- 新建楼栋分组第一步必须选择范围依据：
  - **合同清单**：选择且只绑定一份施工合同，再读取该合同的清单拆表结果，并展示合同范围、已纳入进度、未纳入和超合同范围；只有清单行的显式楼栋字段可作为覆盖证据，户型只在已确认楼栋内部筛选适用楼层，空白通用行或项目内复用的同名户型均不能反推合同楼栋。合同扫描件只作留底，不能作为每次建组时的临时识别源，不能跨合同混组。
  - **内部暂估**：没有施工合同时，从项目区域树选择楼栋，并只读取户型模板中的手工分项与暂估量。界面持续显示“待绑定合同”，不得把暂估范围或暂估量标为合同确认值。
- 内部暂估的数量接线必须可解释：
  - 只汇总当前所选楼栋下，已配置户型模板的户及其有效暂估分项；不读取合同量或现场复核量兜底。
  - 第一步楼栋卡显示户数、已接暂估分项数和暂估量汇总；缺户、缺户型或没有有效暂估分项时明确标为阻断。
  - 当前项目没有区域，或区域中没有可排程楼栋时，不展示可继续提交的空选择器；提供“配置项目区域”入口，直达 `/subcontract/quantity/region?project=<projectId>&origin=<origin>&return=schedule&resume=region`。进入前按当前会话、来源和项目保存范围依据、分组名称、日期、楼栋和工序草稿，不能让同 ID 的不同来源共享输入。
  - 从区域配置返回后重新读取楼栋、户型和暂估量，保留仍然有效的项目、范围依据和表单草稿；已不存在的楼栋选择必须移除并说明。
- 内部暂估按所选楼栋逐栋校验楼层、户、户型、有效分项和启用工序映射；不能用其他楼栋的数量覆盖空楼栋。
- 内部暂估分组绑定合同时，先生成楼栋覆盖、分项映射和数量差异清单。预览与最终绑定统一读取已有楼层冻结数量及逐户/单位完整性证据，不随户型模板后续修改漂移；分项或 BOQ 行软删除也不隐藏排程自有楼层计划。只有同分项、同单位且双方完整时才显示确定差异，旧数值缺历史证据时不能补零或回填。分组内存在合同未明确覆盖的楼栋时阻止完成绑定，沿合法整页入口补齐来源证据后返回；不隐式移除楼栋，也不新增拆分能力绕过阻断。绑定成功保留原分组、工序、基线、完成事实和审计历史，不以合同识别值静默覆盖暂估量。具体来源资格、命令和运行状态见 [#445](../../design/evidence/issue-445/README.md)。
- 新建楼栋分组时可套用稳定工序模板，随后独立调整工期、前后置关系和排序。
- 自动进度工序必须选择一个稳定工序阶段；手动进度工序不要求阶段来源。
- 同一工程量分项可供多个工序阶段读取适用范围，但各阶段的完成率和完成日期仍独立。
- 工序引用的 BOQ 分项按所选楼栋逐层生成计划窗口；默认按楼层自下而上、在工序计划工期内均摊，现场只需微调个别楼层，计划所有权与持久化定义仍只见 `DATABASE.md`。
- 排程只读工程量域的完成结果，不提供第二个阶段完成录入口。

## 五、进度计算（计划 vs 实际）

### 5.1 自动进度工序的实际完成率

某工序（如 10-22栋·墙砖粘贴）的实际完成率 =
```
该分组所有楼栋下，该工序阶段【已完成户数】
÷ 该工序阶段在该分组的【总应做户数】
```
完成事实来自工程量域，不新增排程录入口。总应做户数由该工序与户型模板的分项适用范围圈定；若阶段不依赖计量分项，则该任务必须改为手动进度。

- 实际开始取该阶段在分组内最早完成日期；实际完成取全部应做户完成时的最晚完成日期。
- 尚未全部完成时不显示实际完成日期，进度线画到“当前完成率”处。
- 墙砖/地砖、一遍/二遍腻子分别使用各自工序阶段；即使映射同一个计量分项，也不得共享完成率。

### 5.2 手动进度工序

放线/给排水/电线/空调/门/柜/开关/洁具/保洁等无计量口径的工序，在工序行或弹窗直接填 0~100%。

### 5.3 提前/延后

```
计划应完成率 = clamp((today - plannedStart) / (plannedFinish - plannedStart), 0, 1)
偏差 = 实际完成率 − 计划应完成率
偏差 > 0 → 提前；< 0 → 延后；换算天数 = 偏差 × 工期
```
分组行、项目行的偏差按子工序**工期加权**汇总。

## 六、成本对比与来源边界

### 6.1 项目级预算与实际

科目、预算版本及实际成本口径只引用 [目标成本蓝本](./target-cost.md)、[数据模型 §2.8](../DATABASE.md#28-目标成本类成本控制基线)与 [领域术语](../../../CONTEXT.md)。项目展示入口按 [项目蓝本](./project-info.md)，首页按 [首页蓝本](./homepage-dashboard.md)；排程不另算一份成本，也不增加首页成本条。

合同劳务与工人工资分别归集，合同承诺、结算成本、支付及收货各取真实来源。甲供材和送货单不叠加为第二笔材料成本。来源未接齐时保留缺口，不用预算、工程量或进度比例倒推实际成本、余额及挣值。

### 6.2 下钻 · 工序→分项级（与材料联动）

工序至工程量矩阵的当前可用往返见 §7.3。分项成本与材料联动仍由 #412 / #411 承接，须先具备稳定分项身份、明确归属、已确认实际来源及可追溯分摊；不能以 `itemName` 同名、面积或工期猜接和摊派。

直接工资只消费工资域的已发事实；工程量与单价的计算结果不是已经支付的工资。材料/机械只有项目级事实时保留项目级核对，不伪造房间或分项实际成本。本段收敛旧成本提案的冲突口径，分项联动的未完成义务仍保留，不能因预算版本中央接管完成而勾销。

### 7.2 独立「施工进度」页（侧边栏新增）

完整可编辑 WBS：树表左侧（项目/分组/工序 + 工期 + 计划起止）+ 右侧甘特（可拖拽调计划、设置依赖）。中央工具包括新建分组、工序库、基线和任务维护；新绑定施工合同由 #445 接通，导入 PDF/Project 不因旧工具图标存在而算作已实现。

首页与独立施工进度页共用同一个 WBS Tree + 甘特渲染核心：独立页保留固定的项目汇总行，楼栋分组与工序由可访问 Tree 管理；首次进入项目只展开第一个分组，当前会话按项目及来源记忆展开状态，外部定位目标时自动展开。只有分组箭头与名称区域触发展开/收起，指标、甘特和“添加工序”必须隔离事件；显式 `from=home` 的首页来源页保持只读，独立排程页承载中央写入，不能仅因有 `origin` 参数就切成首页入口。today 线始终读取用户本机系统日期并传给中央读模型，不复制设计稿演示日期或服务器时区日期。长列表先使用普通 Tree，只有运行态出现可复现的性能或滚动问题时才启用虚拟列表。

新建楼栋分组使用三步向导，避免范围表单与所选版本的工序清单横向铺在同一屏：

1. **范围**：选择项目与“合同清单 / 内部暂估”依据，选择施工合同或项目楼栋，填写分组名称和计划开始日期。内部暂估楼栋同时显示户型覆盖、暂估分项和数量汇总；缺少项目区域时直接进入“楼栋 → 楼层 → 户”配置，不显示可提交的空表。
2. **工序**：默认套用所选稳定工序库；甘特可拖整条调整锚点、拖右缘调整工期，下面的表格继续精确录入。点“设置前置工序”打开行级轻量弹窗，只列日期更早候选。调期或排序冲突必须先确认；取消不变，确认后只置灰并保留关系，生成项目依赖后仍可恢复。
3. **确认**：集中展示项目、分组、楼栋范围、数据依据、工序数、计划周期、依赖冲突、覆盖差异，以及内部暂估的户数/分项数/数量汇总。内部暂估必须明确显示“待绑定合同”；所有阻断项解决后才生成。

生成失败时停留在第三步，保留范围、工序日期、依赖和汇总结果，并在页内展示可读错误与“重试生成”动作；重试前重新校验项目区域、合同清单和工序库版本，不能因重复点击产生两份分组。用户返回前两步修正后，第三步汇总必须随草稿重新计算。

项目切换统一使用 [ProjectSwitcher](../../design/kit-ui-component-specs.md#08--项目切换器-project-switcher--已定案2026-07-22)：无论项目数量多少都保持「当前项目触发器 → 可搜索选择面板」同一任务模型，不保留设计稿当前三个项目按钮的数量特例。

工序前后置依赖首期开放 FS + lag 设置。工序详情只显示紧凑摘要，编辑时先关闭详情再打开单层领域弹窗；候选只列同一楼栋分组且计划开始早于当前工序者。弹窗实时计算最早允许开始日与冲突天数，循环依赖阻断保存。现行交互以本页、ADR 0017 / 0018 和 [KitUI 组件契约](../../design/kit-ui-component-specs.md) 为准；[历史依赖补图任务书](https://github.com/zodea/crm-new/blob/c16869fcbf954dddd46143839afe5790f3828f1a/docs/research/schedule-dependency-editor-brief.md) 仅作设计证据，视觉优先级按 ADR 0013。

甘特工序条支持整体拖动计划区间、从右缘调整完成日。若调整后的日期破坏现有依赖，必须先经 KitUI `confirm(simple)` 明示受影响关系；用户取消则不写库，确认后只软禁用并置灰冲突关系，不物理删除。置灰关系通过操作日志的 `operator=schedule:conflict-reschedule` 与用户主动移除区分；主动移除仍留日志，但不进入冲突恢复列表。置灰关系显示禁用原因、时间与审计凭据；恢复前重新校验计划日期、循环依赖以及后续工序是否已有其他活跃前置，任一不满足均拒绝恢复。

### 7.3 工程量矩阵 · 下钻联动

工程量矩阵接收以下排程来源上下文：

- 身份与过滤：`project`、`origin`、`group`、`buildings`、`task`、`stage`、`item`；仅稳定 ID 参与读取。
- 只读说明：`groupName`、`taskName`、`itemName`、`planStart`、`planFinish`、`from=schedule`；名称与日期只用于来源提示，不能替代 ID 或写回排程。
- 首次进入按分组楼栋、阶段、映射分项收窄矩阵；没有显式月份时才用计划月份初始化。来源横幅明确显示工序与计划区间，后续选择的月份、视图、工种和责任户条件在冷刷新与返回后继续保留。
- 户详情返回矩阵时保留完整排程来源链；矩阵返回排程时恢复同一项目、来源、分组及工序，并保留有效筛选。首页来源仍返回只读入口。无效项目、分组、任务、阶段、楼栋或分项显示真实空/错态，不回退到名称相同的对象，也不把失效限制扩大为全项目。

2026-08-13 本地生产只读走查已验证“卫生间回填及防水 → 工程量矩阵 → 返回同一工序”往返；未触发工序调整、阶段登记或任何保存动作。

### 7.4 项目详情 · 驾驶舱区块

项目详情的进度、目标与实际成本投影按 [项目蓝本](./project-info.md) 复核；没有真实来源时显示缺源。#408 / #412 联验展示入口和数据口径，本页不额外授予新增卡片或汇总副本的实施范围。

## 九、验收要点

1. 首页只有**一张**时间线，计划工序 + 实际完成率 + today 线同屏可见，能一眼看提前/延后。
2. 工序进度：自动进度按工序阶段聚合户完成率，手动进度直接填；同工种不同阶段互不串值。
3. 有真实阶段与分项映射的工序可下钻矩阵并恢复来源；无映射的手动工序不生成假链接。
4. 成本对比只消费正式来源，首页展示范围与首页蓝本一致。
5. 独立进度页可编辑 WBS：调计划、连依赖、套工序模板建分组。
6. 楼栋分组跨多栋，与工程量树的楼栋关联正确；合同清单模式能识别已纳入、未纳入与超合同范围，内部暂估模式只能读取项目手工区域与暂估量并持续提示待绑定合同。
7. 工序标准库 22 道可作模板复用，分项映射可调。
8. BOQ 分项能进入排程查看其楼层计划；修改单层日期只标记该层为人工微调，其余自动层仍随工序窗口重排。
9. 内部暂估分组绑定合同前展示楼栋、分项和数量差异；合同未覆盖的分组楼栋会阻断绑定，绑定成功不改变既有任务、基线与完成事实身份。
10. 新建楼栋分组按“范围 → 工序 → 确认”三步完成；内部暂估数量可追溯到所选楼栋、户型模板和暂估分项，无区域时可直达配置，生成失败时草稿不丢且可重试。
11. 标准工序库列表和整页表单可从施工进度、建组第二步进入；旧版不被改写，禁用前置关系保存、重载、建组后仍保持可审计。
12. 在 390 / 768 / 1024 / 1280-1440px 下页面本身不产生横向滚动；WBS、甘特、模板表和确认汇总只在各自容器内退化或滚动。
