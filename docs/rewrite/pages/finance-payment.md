# 付款申请 — 8 类业务表单 + 结算/发票勾稽

> 路由：`/finance/payment` · `/finance/payment/new` · `/finance/payment/:id`
> 设计来源：`DC重构设计源码/kit/PayApplyScreen.jsx` · `kit/forms/FinanceForms.jsx` 的 `payApplyForm`
> 表单形态：[ADR 0014](../../adr/0014-full-page-entity-forms.md) 整页实体表单
> 持久化与勾稽：[ADR 0015](../../adr/0015-form-persistence-and-payment-reconciliation.md)
> 数据模型：[DATABASE.md §2.4 / §3.3 / §4.2.1](../DATABASE.md)

付款申请是支出侧起点。页面按业务类型显隐字段，但所有类型共享同一表单流程；关联结算和关联发票必须选择真实源单，不接受自由文本假关联。

---

## 一、业务类型

新建第一步使用 `typeSelect` 选择：

1. 有合同-人工
2. 有合同-材料
3. 有合同-分包
4. 无合同-零星采购
5. 预付款
6. 管理费
7. 项目费用
8. 公司付款

三类“有合同”显示合同情况和关联结算；预付款显示合同情况和预付款情况；公司付款不挂项目。类型一经产生真实分摊或支付记录，不允许直接改为不兼容类型，需撤销关联后再改。

## 二、表单分区

### 1. 基本信息

| 字段 | 控件/规则 |
|---|---|
| 付款申请编号 | 留空自动生成 |
| 付款申请名称 | 必填 |
| 业务类型 | 由新建第一步确定；设计稿中的只读业务类型镜像不重复保存 |
| 项目名称 | lookup；公司付款隐藏 |
| 收款单位 | lookup；按类型校验是否必填 |
| 关联合同 | 项目级联 lookup；三类有合同/预付款显示 |
| 成本分类 | 乙供材料/劳务分包/专业分包/机械租赁/管理费/项目费用/其他 |
| 申请金额 | 必填，正数 |
| 申请日期 | 必填 |
| 申请人 | 文本/人员选择 |
| 回票类型 | 先票后款/先款后票/无需发票 |
| 付款内容 | 多行文本 |
| 附件 | 最多 15 份 |

上述控件如何持久化、附件归属和字段例外统一见 ADR 0015 与 `DATABASE.md`，本页只维护交互和校验。

### 2. 合同情况（只读带出）

变更后合同金额、往期已结算、往期已付款和付款合同占比均从关联合同及其聚合查询实时计算，不作为用户可编辑字段。

### 3. 预付款情况

仅预付款类型显示“本次扣除预付款金额”和“扣除说明”；“是否预付款”由业务类型派生，不让用户重复填写。

### 4. 关联结算

仅三类有合同付款显示。新增行必须从当前项目/合同的真实结算单中选择：

- 结算单号、结算名称、含税结算金额只读从真实支出结算源单带出；项目/合同不匹配的源单不可选。
- 用户只编辑“本次关联金额”和备注；真实来源与分摊模型见 ADR 0015 和 `DATABASE.md`。
- 同一付款申请不得重复选择同一结算单。
- 草稿允许 `申请金额 − Σ关联结算金额 ≠ 0`，页面常驻显示差额。
- 保存并提交时必须 `Σ关联结算金额 = 申请金额`；无关联结算区的类型不执行此规则。

### 5. 关联发票

`无需发票`隐藏并禁用本区，其他回票类型从真实发票台账选择：

- 发票号码、开票日期、含税金额只读从真实进项发票带出。
- 用户只编辑“本次关联金额”和备注；真实来源与分摊模型见 ADR 0015 和 `DATABASE.md`。
- `先票后款`：提交时 `Σ本次关联发票金额 = 申请金额`。
- `先款后票`：提交时允许 0 张发票；详情持续显示 `待回票金额 = max(申请金额 − Σ关联发票金额, 0)`，后续补关联。
- `无需发票`：不得存在有效发票分摊；从其他类型切入前必须先撤销关联。
- 同一发票跨全部付款申请的有效关联金额合计不得超过含税金额；额度不足时拒绝保存并显示剩余可关联金额，并发提交也不能突破该上限。

### 6. 审批与支付

本期批复金额、已付金额、支付状态和备注遵守 ADR 0015 的“可编辑即默认入库”。支付流水与付款申请的关联见 `DATABASE.md`；后续若以流水聚合替代申请头已付金额，应另立迁移决策，不在页面维护第二份静默口径。

## 三、保存与提交

### 保存草稿

- 允许业务必填字段暂空、结算/发票金额不平。
- 页面必须显示结算差额、发票差额或待回票金额，不能以保存成功掩盖未勾稽。
- 保存必须是原子操作：任一分区失败时不显示成功，也不留下部分更新；事务写入拓扑只在 ADR 0015 与 `DATABASE.md` 维护。

### 保存并提交

除字段必填外，按顺序校验：

1. 类型、项目/合同/收款单位组合合法。
2. 三类有合同的结算分摊合计等于申请金额。
3. 回票类型规则成立。
4. 每张发票跨申请累计关联不超含税金额。
5. `无需发票`不存在有效发票分摊。

失败时定位到对应分区和行，不部分提交。

---

## 四、列表与详情

- 默认视图可继续按待追回发票筛选，但显示值必须由回票类型与待回票金额派生。
- 列表至少展示编号、名称、类型、项目/收款单位、申请/批复/已付金额、回票状态、支付状态、申请日期。
- 详情分别显示合同聚合、结算分摊、发票分摊与支付记录；源单号使用 EntityLink，下钻到真实源单。
- 金额穿透遵守全站 MoneyLink 契约，0/空退化为普通文本。

## 五、与工资进度款边界

#117 的负责人请款簿在“已发放”时自动生成一条类别为工人工资的支出记录，携带请款主体、月份和实际发放金额。该集成不自动伪造合同付款申请，也不套本页的结算/发票分摊规则；若未来需要工资发放走付款申请审批，必须在 #117 与本页之间另定义显式转换 action。

---

## 六、验收要点

- 所有 lookup 保存真实 ID，结算/发票源字段不可手填。
- 草稿不平可保存且差额可见；提交态按类型严格勾稽。
- `先款后票`可无票提交并能后补，待回票金额实时减少。
- `无需发票`无法误挂发票。
- 同一发票跨付款申请不会超额关联，并发保存也受事务保护。
- 刷新后所有用户可编辑字段、分摊行和附件引用均恢复；只读聚合不落副本。
