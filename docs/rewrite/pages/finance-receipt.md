# 收款与往来收付 — 实际资金流入/非合同往来

> 表单蓝本：`receiptForm`、`currentForm`
> 持久化权威：`DATABASE.md` 的 `receipt_registrations` / `current_transactions`

## 一、收款登记

浏览器列表 `/finance/receipt`、新建 `/finance/receipt/new`、只读详情 `/finance/receipt/:id?origin=:dataOrigin` 与编辑 `/finance/receipt/form/:id?origin=real` 共用普通收款中央来源（#436）。详情身份只由收款稳定 ID 与来源确定，未填客户的草稿也可读取；`returnTo` 等 query 仅表达来源上下文。编辑由当前真实写权限控制，查看不得复用表单壳。

| 分区 | 字段与规则 |
|---|---|
| 基本信息 | 收款单号、收款日期*、项目*、施工合同（项目级联）、付款方客户*、付款方账号 |
| 金额与方式 | 收款金额*、收款方式、承兑汇票号、汇票到期日、收款期次、银行流水号 |
| 合同情况 | 变更后合同金额、合同累计收款、收款/合同占比、开票未收款；全部只读派生 |
| 凭证附件 | 收款回单、其他附件 |
| 经办与备注 | 经办人、审核状态、备注 |

项目、施工合同和付款方客户均保存真实 ID。收款金额是资金流入事实；合同累计收款从有效收款登记聚合，不回写合同静态金额。

当前普通收款只支持项目主客户作为付款方，是实现范围而非法律上的必然等同。合同债务人与实际付款人可能不同（[民法典第523条](https://www.samr.gov.cn/zw/zfxxgk/fdzdgknr/bgt/art/2023/art_60fb3863b7364b759123a42d1df568ca.html)）；第三方代付尚未在本流程建模，不能用“客户2”或改写签约客户冒充支持。

废料出售、赔偿、非主客户付款等真实收款已纳入目标范围；真实付款人、合同债务客户、来源性质及单笔去重只在 [DATABASE：其他收款与真实付款人](../DATABASE.md#receipt-other-sources)定义。下述普通收款校验仍是当前实现，目标尚未完整接通，本轮不新增可操作流程。

`draft` 允许尚未填写项目、客户、日期和金额，空金额与明确零分别保留；`save` / `submit` 要求真实日期、合法项目主客户和正金额，施工合同可选，选定时必须属于同一项目/客户。`draft` 写草稿，`save` 保留已有合法状态（新建默认草稿），`submit` 写已提交。保存并新建、保存后关闭和取消遵守各自动作；不新增确认、撤回确认、退款、红冲或作废流程。银行流水号非空时按正式收款查重。网络失败保留本页输入和附件，重复提交同一意图不重复记款；版本冲突由用户核对最新版后显式处理。命令边界见 [COMMANDS](../COMMANDS.md#普通收款登记命令436)。

附件正文与收款在同一命令中保存；详情按当前收款与附件身份校验后预览/下载，删除和恢复在表单保存时生效。缺少历史正文时显示不可读原因，不以旧设备路径生成成功入口。从客户、施工合同、项目或最终结算进入后，返回恢复合法的来源筛选、分页、锚点与局部滚动；来源失效或读权撤回时显示问题，不能借旧缓存继续显示金额或写入。

## 二、往来收付

| 分区 | 字段与规则 |
|---|---|
| 基本信息 | 单据编号、收付方向*、项目*、往来分供方*、采用时名称及历史原文、款项性质 |
| 金额与方式 | 金额*、收付方式、日期*、银行流水号 |
| 经办与备注 | 经办人、备注、凭证附件 |

收与付共用一个列表和表单，方向作为稳定业务字段保存。非合同往来不得混入合同收款或支付记录；资金汇总按方向分别计入。

独立 Native v56 往来表单从同库分供方清单选择稳定身份，个人临时金沿该目录建档；草稿转正式时重新核实当前候选，采用时名称保留，历史原往来文字不按同名猜接。工资付款及各实际资金事实的归属直接按 [DATABASE](../DATABASE.md#actual-counterparty-identities)，不在本页另建工资支付来源。正式浏览器往来已由 F3 持久参与者承接，读取和写入按当前工作区、来源与权限验证；Native 原记录及旧文字经显式迁入保全，不据演示或旧缓存开放正式写入。具体运行职责和接通范围见 [ARCHITECTURE](../ARCHITECTURE.md#implementation-gaps)，原命令及迁入边界见 [COMMANDS](../COMMANDS.md#implementation-gaps)。

## 三、验收

1. 合同级联只展示所选项目的施工合同。
2. 回单与其他附件刷新后可预览、下载和软删除。
3. 往来方向编辑后资金汇总同步切换且不重复计数。

## 四、运行态对标与读模型（2026-08-13）

直接证据见 `runtime-reference-audit.md` 的 `R-FINANCE-FLOW-LIVE`。

- 收款登记专属列表包含收款编号、项目、收款分类、付款单位、合同、日期、金额、支付方式、收款类型和累计合同收款；编号进入只读详情，详情继续展示合同原额/变更额、含/不含本次的累计收款、质保/变现口径、凭证和系统信息。列表读模型至少返回 `id/no/project/customer/contract/category/receiptDate/amount/paymentMethod/receiptType/cumulativeContractReceipt`。
- 往来收款与往来付款在参考界面拆成两张列表：收款侧包含款项类型、付款单位和创建审计；付款侧包含审批、业务类型、收款单位、申请人/日期/金额、生效、支付、实付和余额。本地可继续共享 `current_transactions`，但读模型必须按 `direction` 投影不同字段，而不是用一套“关联方/类型”列吞掉语义。
- 往来收款编号已确认进入只读详情；本轮未从往来付款编号形成可靠详情，因此不把未知详情结构写成目标事实。项目与已主数据化的往来方按 [READ-MODELS.md](../READ-MODELS.md) 返回来源感知实体引用；Native 已保存的 `supplierId` 与冻结名可读取，旧 `counterparty` 原文只显示，不据名称生成蓝链。

当前收款分类 `category`、收款类型 `receiptType` 在已存储事实中均不存在，#436 的读 DTO 明确返回 `null`、列表和详情显示“未记录”；不能以收款方式或审核状态代填。合同原额、变更额、含/不含本次的有效累计来自同一当前施工合同和原始收款事实。质保及变现口径尚无对应可读事实，显示未知及原因，不从登记金额推断。

2026-08-13 的 SQLite 演示样本只证明当时的数据路径。#436 已按上述边界接入普通收款的中央全链；往来收/付仍由 [#413](https://github.com/zodea/crm-new/issues/413) 独立承接。浏览器可重置实例不代表 #416 的生产持久化、备份部署已验收。具体操作见[收款登记使用指南](../../guides/receipt-registration.md)。
