### 只读跳转合同

1. 列表的蓝色单据名称或编号先进入独立只读详情；编辑只由明确的“编辑”动作进入整页表单。该次四类材料列表把名称和“查看/编辑”都直接送进编辑表单，不符合该边界。
2. 项目、分供方、材料采购合同、源单据、送货单、仓库、班组合同和结算名称都是关系入口；目标存在时按真实 ID 下钻，目标为空时展示“未记录”，不得用名称搜索猜 ID。
3. 材料采购合同详情的“物资管理”汇总该合同下的新/历史入库、直入直出和新/历史出库；本地已有 `contract_id → material_requisitions/material_arrivals` 查询基础，但当前下钻仍进入编辑表单，且没有送货归档、出库批次和结算分摊关系。
4. 送货单号进入 `/material/delivery/archive/:id`；归档详情中的项目、分供方继续进入各自详情。材料价格来源使用 `deliveryRecordId + deliveryLineId` 回到同一送货单，合作合同使用 `contractId` 回到合同详情。
5. 任一详情返回列表时必须恢复来源路由、项目/状态/分类筛选、搜索、分页和滚动位置；不得只写死返回域首页。建议统一携带 `from` 或可序列化的列表 query，不把展示名称当返回键。
6. 甲供材五类列表的单据编号/名称同样先进入独立只读详情；该次本地 `/owner-material/*/:id` 全部直接复用编辑表单，必须把“查看”与明确的“编辑”动作分开。参考列表没有记录，因此本轮只锁定入口边界，不外推未知详情页签或审批动作。
7. 甲供材到货的源单据、项目、分供方、送货单和仓库，甲供材领用的项目、分供方、班组与班组合同，以及直入直出的项目、仓库、分供方和送货单都是候选关系字段；只有后端返回稳定 ID 时才渲染蓝链，缺 ID 时显示“未记录”而不是名称搜索结果。
8. 项目详情“物资总计划 / 物资需用计划 / 入库单”使用 `projectId` 作为受限来源上下文；单据下钻后返回原项目、原页签、原子表、筛选、页码和滚动位置。全局列表下钻则返回原全局列表，两个来源不能共用写死返回地址。
9. 参考项目右侧成员编号为可见关系入口，文件名、附件、送货单照片和加号/操作列属于文件或写动作；本轮只登记其位置与字段，不点击、不下载。本地文件继续只读 `file_refs(owner_type, owner_id, category)`，没有正文时展示缺失原因，不生成替代文件。

### 历史运行缺口的承接

2026-08-13 小规模测试库曾暴露：材料与甲供材列表缺专属列、名称进入编辑、返回丢上下文、仓库/计划/到货来源缺稳定关系，以及 `reviewed` 与 `done` 混用导致价格分析漏数。这些是该次观测，不能判为当前状态；[#411](https://github.com/zodea/crm-new/issues/411) 先核实当前提交和迁移，再实施仍存在的差异。

历史 seed 不含真实原件的样本只覆盖缺源场景；非空验收需隔离确定性数据覆盖有效到货、库存、价格和来源往返。正式源不自动灌样本，已迁移浏览器领域不绕中央回退 SQLite。仓库、供货方、总计划头/行及有效到货关系已定，不因旧测试库缺表重新裁定。

### 已定身份链与本轮验证

[#411](https://github.com/zodea/crm-new/issues/411) 继承已采纳的身份决议，逐项验落实，不重新选择模型：

- 物理原件与逻辑送货单分开，一份原件可含多张逻辑单据；有效态逻辑送货单与到货头 1:1，材料明细只保留一份事实。
- 缺原件或偏差未闭合的记录标为未闭合；归档持久化不等于仓库入库，不能仅凭 `archived=1` 生成库存或有效到货资格。
- 仓库使用稳定 ID；领用、直入直出、盘点与调拨按真实来源和仓库关系复核，不按名称或金额近似配对。
- 甲供材供货方已定为 Party 的甲方指定供货角色；项目客户不自动成为供货方。总计划有独立头和明细，后续单据引用稳定 `planLineId`；三量按计划行归集，不用“项目 + 材料名 + 单位”拼身份。
- 材料结算唯一归 [#409](https://github.com/zodea/crm-new/issues/409)；本模块提供有效到货来源，联验到货不重复纳入、后续批次及结算更正后的回读。

表、外键、状态与迁移只在 [DATABASE.md](../DATABASE.md) 维护；关系、金额、来源、空态和权限语义见 [READ-MODELS.md](../READ-MODELS.md)，写入见 [COMMANDS.md](../COMMANDS.md)。本页不保留独立 DTO 副本。参考空表未证明的红圈明细仍属未观察，不影响瑞航已定身份规则。

## 三、材料单价分析

路由 `/material/price` 按真实 owner 读取报价、合同原行和已核对送货原行，不另建价格副本。送货趋势和官方参考区域保持各自的有效样本范围；无法可信读取的来源独立显示缺口。

**独立报价入口：**`/material/quotations` 为清单，`/material/quotations/form/[[id]]` 为整页新增/编辑，`/material/quotations/[id]?version=…` 为冻结版本及原件详情，`/material/quotations/import` 为完整来源图迁入与原编号核对。中央实际 `material-quotations` owner 复用单库事务及共享原件正文；新建不要求先签合同。通用报价和未建档报价方按原文保存，未核实关系保持未关联，逻辑身份、原件及计数例外直接见[独立报价定义](../DATABASE.md#quotation-target)。Native v58 负责结构与既有图保全；尚无可信本地操作者绑定，新报价读写入口明确不可用，不能借浏览器身份写本地。

**综合价格范围：**原价视图分别标明未签约询价、合同约定价和实际送货价；各家展示范围、来源归属和比较条件直接见 [DATABASE：材采价格来源](../DATABASE.md#material-price-sources)。报价每次修订形成可追溯的头、行和版本价格点，原报价日期未知时保留未知。筛选项目时呈现通用报价或明确属于该项目的报价，适用范围未知的资料不冒充项目报价；筛选分供方只使用真实稳定 ID，未关联资料仍保留原文入口。单位换算按[权威换算规则](../DATABASE.md#contract-price-unit-conversion)临时显示，材料和价格条件未齐不输出同条件价差。下列送货趋势最多同时 4 家的限制不限制综合原价的保存或展示数量；官方信息价继续独立展示。

**迁入操作：**选择旧桌面版留下的完整 SQLite 一致快照，页面核对原头/行 ID、所有冻结版本、共享原件正文与摘要、原命令及封存编号。原项目、分供方分别选择当前真实目标记录，逐条确认后迁入；目标目录或记录版本变化时重新读取并确认。同一不可变迁入回执封存实际 SQLite 摘要、原图和明确对应记录，原始资料继续在冻结版本显示，已确认的当前关联用于筛选和后续编辑。迁入和核验在同一个报价 owner 的事务完成，结果未知只核对原编号，失败保留原库。原件不另存第二份正文，来源身份不按名称推断，已有中央报价不覆盖。未完整核验迁入的非空图阻止平台切换，按现有备份恢复路径保留来源库；字段、证据和迁移约束直达[报价权威定义](../DATABASE.md#quotation-target)。

- 一般材料身份由归一后的“材料名称 + 规格 + 单位”共同确定；`米/m`、`㎡/m²`、`m³/方` 等常见单位写法归一后参与检索和分组。
- 电线电缆优先解析稳定的“型号 + 芯数 + 截面 + 单位”身份。当前已实现 BV、BVR、YJV：BV 全称/简称，以及规格写在名称或规格栏中的 `2.5`、`2.5mm2`、`1×2.5`、`1*2.5` 会归一显示为 `BV 电线 · 1×2.5 mm²`；BVR、YJV 保持各自型号，不与 BV 合并。
- 只规范化精确的基础型号与单一“芯数 × 截面”规格。`ZR-BV`、`NH-BV`、`YJV22` 等型号变体保留原材料身份，不并入基础型号；`4×25+1×16` 等复合规格也不截断归并。上述未支持身份均不关联普通 BV 官方价格。
- `米/m` 归一为 `m`，`千米/km` 归一为 `km`；两种量级始终保持独立，系统不把 `km` 自动改成 `m`，也不静默换算送货单市场单价。
- 归一身份同时保留稳定匹配键，与[广州官方价格信息](https://zfcj.gz.gov.cn/zwgk/zsdwxxgkzl/jsgczjglz/jgxx/)中的材料编码、规格和单位做严格映射；分类命中本身不得产生价格。
- 瓷砖、墙砖和地砖归入装饰装修材料；砌筑砖、砌块和水泥归入水泥、砂石及混凝土制品，不因名称都含“砖”而混为同一大类。
- 当前已核实并接入“铜芯聚氯乙烯绝缘电线 BV 1×2.5 mm²”（编码 `280304800070120011`）2026 年 2–6 月税前综合价，原单位为千米，官方事实页面统一换算为元/米后与市场中位价展示趋势和最新偏差。只有规范身份精确等于 `BV + 1 芯 + 2.5 mm² + m` 才匹配该价格；BVR、YJV、BV 其他芯数/截面及千米口径市场价均不得套价。其他材料仅展示十二大类归属及官方来源入口，不推断未核实价格。
- 官方信息价事实保留数据源、分类、月份、材料编码、材料名称、规格、原单位、归一单位、价格和原文链接；信息价是市场综合参考，不是政府定价。
- 搜索支持材料名称、规格和单位；`2.5mm2` 与 `1×2.5 mm²` 等等价截面写法使用同一归一规则。选中一种材料后才展示对应分析，不再铺一张全材料×全厂家假矩阵。
- 同一厂家存在多个日期价格点时展示时间趋势，最多同时显示 4 家厂家；否则按每家最新有效价格做横向比较。
- 横向比较展示最低价、中位价、价差、价格日期和来源送货单；趋势图保留每个价格点的送货单来源。
- 运费、搬运费、上楼费、装卸费和吊装费等费用行不作为材料参与单价比较。
- 页面底部只读汇总所选材料涉及厂家签订过的材采合同，按厂家和项目展示合同数、合同名称、金额与签订日期，并可下钻合同详情。

## 四、共同规则

- 项目、合同、分供方、Party 供货方、班组、仓库、下料单及计划行均保存真实 ID，缺失关系明确显示待配置。
- 独立报价的可空项目/报价方关系、未知价格条件与其他物资单据不同，按 [DATABASE 报价实体例外](../DATABASE.md#quotation-target)处理，不套用正式到货或库存门槛。
- 明细网格落子表；附件走 `file_refs`。
- 单据头和明细由同一个事务保存；删除使用软删除并同步重算派生量。
- 草稿允许不完整；入库、生效或确认动作校验必填、正数量及上游关系。

## 五、验收

1. 10 条整页表单刷新后字段、明细和附件保持。
2. 到货—下料、领用—库存、甲供三量均可追溯，不用头字段手工补累计。
3. 与 #409 联验有效到货的结算纳入、更正回读，再与 #413 联验付款申请来源。
