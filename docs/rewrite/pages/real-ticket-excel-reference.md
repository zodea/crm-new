## 二、格式参照

### 2.1 通用版式

- 普通费用发票 sheet 通常第 1 行是标题，第 2 行是表头，第 3 行开始是数据。
- 标题多为“费用报销发票”，使用合并单元格横跨主体字段；`专用发票` 的标题为“增值税普通发票签收表（2022年5月-2022年7月）”。
- 表头居中、可换行、四边细边框；数据行居中，长文本允许换行。
- 普通 sheet 的标题字号约 16、表头约 14、数据约 12；`专用发票` 为更密集的约 10 号表头/数据。
- 字体主体为等线；标题加粗。源文件未使用大面积填充色，主要靠细边框、字号和合并关系区分层级。
- 参考品牌角色：正文文字为黑色，强调色使用模板的 `primary/accent1`（观测值为蓝色）；生成器不应把颜色写成业务字段，也不应把 CSS 预览误当成 XLSX 样式。

### 2.2 数字、日期和票号

| 数据类型 | 源文件参照 | 开发规则 |
| --- | --- | --- |
| 日期 | `yyyy"年"m"月"d"日";@` | 保留原始显示文本和规范化日期；无法规范化时进入异常，不用当前日期或文件名补值 |
| 金额 | `0.00_);[Red]\(0.00\)` | 以数值保存，保留两位小数；负数红色括号显示，不能把金额写成带货币符号的文本 |
| 发票号码/代码 | `@` | 按文本保存，保留前导零和长数字精度，禁止按普通数字转换 |
| 普通文本 | `General` | 保留原始内容；空白、换行和备注不应在导入时静默丢失 |

源数据同时存在真正的 Excel 日期单元格和文本日期，例如 `力沣` 中出现 `2026/03/29` 文本；支付日期还可能包含多行日期。导入模型需要同时保留 `rawDisplayValue` 与规范字段，不能只依赖 Excel 单元格类型。

### 2.3 合并单元格

源文件存在两类合并：

1. **标题合并**：如 `A1:I1`、`A1:F1`、`A1:L1`，用于标题带。
2. **数据区纵向合并**：如百信的 `A10:A13`、`E10:E13`，以及瑞航的 `H39:H43`、`J39:J42`、`I39:I40`，用于同一票据/同一分组的视觉归属。

导入时必须把合并区域展开到每一条业务行，不能把合并后的空白单元格误判为缺失；同时保留 `mergeRange` 作为来源布局元数据。导出样式配置支持：

- 表头固定范围合并，例如 `A1:C1`；
- 数据行按指定字段对连续相同值自动纵向合并；
- 合并前先完成排序和数据行定位，避免固定坐标随行数变化而错位。

### 2.4 行高、列宽和边框

- 标题行约 20；表头约 17.5；包含长文本或合并内容的数据行常用约 32。
- 常见列宽参照：日期约 15–17，公司名称约 24–32，费用名称约 14–17，发票号码约 11–23，金额约 10–11，备注约 14–15。
- `专用发票` 使用更密集的列宽：单位/公司名称约 30，金额/税额/价税合计约 9–10，备注和签收列更窄。
- 默认表格边框为四边细线；生成配置应允许表头/数据行分别设置边框、线型和颜色。

## 三、公式兼容性结论

### 3.1 公式本身不是 WPS 专有公式

源文件共观察到 21 个公式，使用的函数只有：

- `SUM`
- `SUMIF`
- 普通 sheet 间单元格引用

例如：

```excel
=SUMIF(H:H,"赵东",F:F)+SUM(K:K)
=SUM(F3:F35)
=百信!F45
```

这些函数和整列引用属于 Office/WPS 都常见的基础公式，不是 WPS 私有函数。源文件的计算属性为 `fullCalcOnLoad=True`，WPS 已保存的缓存值可正常读取：`汇总` 页缓存值为 `12451.36、0、6973.62、8106.27、0、0、0、0`，总计 `27531.25`。

### 3.2 `#NAME?` 的来源

开发侧解析器对 `汇总!B1:B8` 的未加引号中文 sheet 引用会显示 `#NAME?`；用等价的带引号形式即可正常解析：

```excel
='百信'!F45
```

因此，当前问题应归类为**跨解析器的 sheet 引用写法兼容问题**，不是源工作簿中的 WPS 专有公式，也不是缓存值损坏。

生成或重写公式时统一采用：

```excel
='工作表名称'!A1
```

即使 sheet 名当前没有空格，也始终加单引号。导入回读同时保存原始公式、计算值和解析状态；不能用解析器的 `#NAME?` 覆盖源文件已有的缓存值。

### 3.3 整列引用的工程处理

`SUMIF(H:H,"赵东",F:F)` 在 Office/WPS 中合法，但生成的新文件不应继续扩大整列计算范围。新导出应使用当前数据区的有界范围，例如 `H3:H104`、`F3:F104`，降低重算成本并避免把合计行再次纳入公式。

## 四、不是公式错误的业务口径

`汇总` 页并不是引用每个 sheet 的“全部合计”：

- 百信引用 `F45`（缓存 `12451.36`），而“全部合计”在 `F46`（缓存 `21366.67`）；
- 瑞航引用 `F105`（缓存 `8106.27`），而“全部合计”在 `F106`（缓存 `34754.32`）；
- 百信、瑞航、力沣的“总数”公式按付款账户/实付字段筛出“赵东”子集，再加实付列。

这说明汇总页当前表达的是“指定付款口径/实付口径”，不是所有发票的全量金额。#254 的导入映射和 #257 的守恒校验必须把以下两个指标分开：

1. `scopeTotal`：源 sheet 当前“总数”口径；
2. `allRowsTotal`：所有有效数据行的全量合计。

如果产品要展示全量总额，应另行引用“全部合计”或由系统按有效行重算，不能把 `汇总` 页当前的 `总数` 直接当成全量真值。

## 五、已发现的数据质量边界

- 不同 sheet 字段不齐全，珠海、铂金、电白一建等 sheet 可能只有部分历史字段或空模板行。
- 发票号码存在空值、合并续行和重复号候选；重复不能静默合并，必须保留来源 sheet/行号并进入复核。
- 日期、付款日期和备注可能是多行文本；导入需保留原文并显式标记无法规范化的值。
- 合计行、空白预留行和汇总 sheet 不是普通业务明细，导入时必须按结构识别排除，不能仅按 `usedRange` 或行号判断有效数据。
- 解析器或 Office 重算失败时，必须同时展示“源文件缓存值”和“当前解析状态”，不得用错误状态覆盖可追溯的源值。

## 六、对 #254/#255/#257 的开发约束

### #254 Excel 导入导出回读

- 导入来源键至少包含：源文件、sheet、原始行号、原始列名/单元格显示值；合并区域额外记录 `mergeRange`。
- 发票专用模板按 sheet 结构映射，不把 9 个 sheet 强行压成单一固定表头。
- 重导以业务自然键和来源键双重去重；重复号、缺号、缺归属和公式异常进入逐行拒绝/复核清单。
- 回读比较业务值、公式文本、缓存值、sheet 名、行列结构和样式关键属性；不要只比较导出的页面截图。

### #255 Excel 样式配置

- 配置范围包含：行高、列宽、表头/数据行字体、四边框与线型、数字/日期格式、冻结首行。
- 合并支持固定表头范围和连续相同字段的纵向合并。
- 样式配置必须作用于实际 XLSX 生成，不得只改变网页预览 CSS；生成后必须回读验证 `mergedCells`、列宽、行高、字体、边框和 number format。

### #257 数据守恒

- 归档、台账、价格分析和打印队列统一使用人工确认后的当前值；原始 OCR、人工修订和来源信息单独留痕。
- 金额校验同时保存源文件口径、系统全量口径和人工修订原因。
- 任何未核对、缺归属、重复自然键、缺核心字段或金额异常的记录，不得静默进入终态。
