# 基础信息/客户 — 甲方主数据 + 开票资料

> 表单蓝本：`customerForm`（ADR 0014）
> 持久化权威：中央 Customer Repository / HTTP operation；实体字段仍以 `DATABASE.md` 的 `customers` / `file_refs` 为准

## 定位

客户是项目和施工合同引用的甲方主数据。项目、施工合同、收款登记、开票申请中的客户 lookup 必须保存 `customer_id`，不得只保存名称副本。

### PG-01 本机存储切片（#450）

本机模式沿同一 Repository/HTTP 入口接管磁盘事实；开发模式保留既有验证实例。登录进入客户列表，退出及过期阻断业务，操作者为后台唯一 owner。原件、回执、版本、审计与客户同事务；物理定义见 [DATABASE](../DATABASE.md#pg-01-本机客户持久参与者450)。本票只开放合成验证目录写入，正式用途等待基线备份和上线关口。

编辑页支持真实原件保存与下载；详情增加删除/恢复，列表增加已删除客户及原提交核对入口。取消删除不修改状态，恢复父客户不自动恢复单独删除的附件。删除期间拒绝编辑及原件下载，后台重验版本与会话。

浏览器只保留原命令编号，字段和原件不进入浏览器存储。刷新后不恢复未保存正文：成功须读回原客户，未应用须封存原键防迟到写入，未知继续阻断新动作。未接管正式关联返回不可用与未知，不用开发实例补关系。步骤见[本机客户指南](../../guides/local-customer-storage.md)。

## 列表

客户列表只从 `CustomerReadRepository → HTTP → /api/read/customers` 读取，提供名称/简称/税号/联系人搜索、状态筛选、最近更新或名称排序、分页、筛选空态和加载失败重试。客户名称与行级详情动作按中央返回的稳定 ID 和 `dataOrigin` 进入 `/base/customer/:id?origin=...`；列表不直接编辑，正式编辑必须从只读详情显式进入独立整页表单。统一社会信用代码与联系电话在列表中脱敏显示。

列表列为：客户名称、简称、统一社会信用代码、联系人、联系电话、状态、操作。密集表格只在自身容器横向滚动，长名称截断时必须可读取完整值。

## 新增/编辑

| 分区 | 字段与规则 |
|---|---|
| 基础信息 | 客户名称*、简称（支持多个）、统一社会信用代码、法定代表人、注册地址 |
| 开票与银行 | 开票名称、开户行、银行账号 |
| 联系与备注 | 联系人*、联系电话、备注、开票资料附件（最多 9 份） |

浏览器正式客户表单只经 `CustomerCommandStore → CustomerCommandRepository → HTTP` 保存；新建 ID 由服务端分配，编辑携带 `baseVersion`，冲突时禁止静默覆盖。简称使用中英文逗号或顿号分隔，保存后参与客户检索。附件以命令变更集和 `file_refs` 元数据维护，不在客户头保存文件数组。测试客户只读，Tauri 仍保留既有本地适配路径。

## 详情

生产详情路由为 `/base/customer/:id?origin=:dataOrigin`，顶部展示客户名称、税号/简称摘要、来源、状态、正式客户编辑入口，以及名下项目、施工合同、有效合同额、有效收款和待收差额。详情必须用 `(dataOrigin,id)` 查询；来源错配、记录缺失和权限拒绝分别展示，不按同名客户回退。

业务关系使用三个可深链页签：

- 名下项目：从现有中央项目命令及已确认迁移的同一事实快照，按 `customerId` / `secondaryCustomerId` 和 `dataOrigin` 反向投影。新建、Excel 导入和更换客户后重新进入或刷新即回读最新关系；同项目同时匹配两种角色只展示一次，主客户优先。同名不同 ID 不互接，客户改名不改变引用。项目名进入真实项目详情。
- 施工合同：复用施工合同中央主读源的完整事实、权限和来源版本，按合同自身 `customerId` 与 `dataOrigin` 关联。新保存、改名、金额或归属更正后重新进入/刷新客户即回读；同名客户不互接，项目更换主/次客户不自动移动已存合同。缺少合同客户 ID 时不按项目或名称兜底。有效合同额为主合同金额加有效补充协议，草稿合同可见且计数、有效额为零；不包含甲方变洽签。合同名进入同来源的施工专属详情，所属项目另有独立入口。
- 收款明细：只读取当前中央来源中的已有收款事实，不从合同额推算收款，也不把固定样例当作正式记录。当前已接入最终结算引用的有效收款，按收款 ID 去重；普通收款表单的中央写源仍由 #413 承接。单号进入 `/finance/receipt/:id` 中央只读详情，项目和合同进入各自详情，收款详情返回当前客户的收款页签。

页签状态写入 `?tab=contracts|receipts`；默认名下项目不保留多余 query。客户关系下的项目目标只接受与当前 `(customerId,dataOrigin,tab)` 一致的受限详情返回地址，来源错配或额外 query 不进入目标。页签支持 Tab 聚焦、左右方向键切换与 Enter/Space 激活。没有关系数据时分别展示领域空态，不制造合同、收款或成功状态。

关联项目列表、页签计数与摘要数来自同一可读集合；受限单记录不输出身份、占位行或数量。整个项目读取无权或不可用时，项目数为未知，关系区显示明确反馈；暂不可用支持重试，客户主数据仍可阅读。DTO 契约见 [READ-MODELS](../READ-MODELS.md#客户关联项目)。不以演示记录或本地 SQL 补正式关联。

项目往返保留当前客户业务页签、关系区横滚、工作区纵滚和原项目链接焦点，并继续透传客户列表上下文。详情子表目前未启用筛选/分页，不新增或假称恢复不存在的工具。刷新、直接深链、读取失败和失效上下文按 [客户关联项目返回契约](../NAVIGATION.md#客户关联项目返回) 执行。

施工合同源无权或暂不可用时，合同关系区显示独立问题态，可重试时提供“重新加载施工合同”；合同数量、有效合同额、待收差额以及项目行中的合同计数/金额均为未知，不显示假零。客户主数据和独立可读项目仍可查看，受限合同不输出身份/金额或占位行。契约见 [客户关联施工合同](../READ-MODELS.md#客户关联施工合同)。

收款源无权或暂不可用时，收款关系区显示独立问题态，可重试时提供重新加载；有效收款、收款数量及依赖差额均为未知，项目/合同行的收款金额也不得泄漏旧值。源撤回后客户关系和收款详情同时移除记录。契约见 [客户已有中央收款来源](../READ-MODELS.md#客户已有中央收款来源)。

客户→施工合同→返回客户复用关系视图上下文，保留当前页签、父列表状态、纵横滚动与原合同链接焦点。合同详情刷新、显式编辑保存后仍返回原客户；合同归属更正或原行消失时保留来源详情并聚焦关系区。受限返回与失效处理见 [施工合同客户来源返回](../NAVIGATION.md#施工合同客户来源返回)。

从列表打开详情时保存白名单返回上下文：搜索、状态、排序、页码、每页条数、应用滚动和行焦点。详情进入编辑、保存并刷新同一客户后，该上下文继续保留；返回列表恢复原位置。直达详情、过期上下文或伪造外部地址只返回 canonical `/base/customer`。

## 可观察行为

- 客户名称和简称均可检索；选择结果显示客户名称，保存真实客户 ID。
- 客户被项目或施工合同引用后仍可改显示名，既有引用不受影响。
- 客户删除不在当前中央命令切片；列表不展示可执行删除动作。后续实现仍须采用软删除，并在存在活跃项目或施工合同时阻止直接删除和展示影响范围。

## 验收

1. 新增、编辑、刷新后所有可编辑字段与附件保持。
2. 项目/施工合同中的客户关联不依赖同名文本。
3. 客户名、简称、税号均可用于检索，重复税号给出冲突提示。
