## 定位

工人是跨项目共享的基础主数据。该模块维护个人与用工信息，并从工程量、考勤、签工、工资和项目扣罚中读取真实业务事实。详情页不负责录入或审批这些业务事实。

| 本模块负责 | 跳转到业务模块处理 |
|---|---|
| 新增、编辑工人档案 | 工程量责任与完成情况 |
| 设置班组、当前项目和在场状态 | 考勤与签工录入 |
| 查看工人能力、附件和关联人员 | 工资单核对与发放 |
| 汇总工人的项目、工资和扣罚事实 | 扣罚录入、整改与扣款 |

### 浏览器中央边界

- 浏览器列表、详情和表单只经 `CrewWorkerReadRepository` / `CrewWorkerCommandRepository` 与 `/api/read|commands/workers` 访问正式工人，不回退 production SQLite。
- 详情按 `(dataOrigin,id)` 定位；测试工人只读，正式/测试班组、项目和事实不得跨来源拼接。
- 所属班组、当前项目、责任单元、工资单、扣罚单和关联人员一律使用稳定 ID；同名实体保持独立。
- 列表进入详情时携搜索、工种、排序、页码和来源行的安全 `returnTo`；工人与班组互跳，以及项目、责任单元、工资单、扣罚单下钻，均可返回原详情。
- 浏览器中央附件边界尚未接入时不回退本地证书附件。Tauri 继续使用现有 SQLite 和 `file_refs`。

## 真实关系

工人页面只使用当前数据库中已存在的关系：

| 信息 | 数据来源 |
|---|---|
| 工人档案 | `workers` |
| 所属班组 | `workers.crew_id → crews.id` |
| 当前项目 | `workers.current_project_id → projects.id` |
| 亲属组 | `workers.family_group_id` |
| 历史一对一关联（只读兼容） | `workers.linked_worker_id → workers.id` |
| 能力范围 | 工人和班组的 `trade_capabilities`、`item_capabilities` |
| 附件 | `file_refs`，其中 `owner_type = 'worker'`、`owner_id = workers.id` |
| 工程量责任 | `unit_assignments`、`unit_assignment_scopes`、`unit_stage_completions` |
| 考勤 | `attendance_records` |
| 签工 | `signed_daywork_records` |
| 工资 | `wage_statements`、`wage_statement_members`、`wage_statement_lines`、`wage_statement_allocations` |
| 项目扣罚 | `penalty_records`，匹配 `workerId` 或 `responsibleWorkerId` |

附件当前只保存文件元数据和分类，不提供证书细分类、有效期或到期提醒。需要这些能力时，应先扩展权威数据模型，再实现界面。

## 列表页 `/base/worker`

列表用于搜索、筛选和进入工人档案。姓名进入详情，新增和编辑使用独立整页表单。

核心显示字段：

- 姓名、主工种、所属班组、当前项目
- 档案状态与在场状态
- 联系电话、身份证号
- 进场/退场日期、安全教育状态

“档案状态”来自 `workers.status`，表示草稿、提交、审核或停用等记录生命周期；“在场状态”来自 `workers.project_status`，表示工人在项目现场的状态。两者不得合并为同一个状态。

电话和身份证号在列表与详情均使用脱敏值，表格只在自己的区域横向滚动，不得造成整页横向溢出。

## 新增 / 编辑

表单遵循 ADR 0014，使用独立路由整页编辑，并按以下区域组织：

| 区域 | 字段 |
|---|---|
| 个人信息 | 姓名、性别、身份证号、联系电话、籍贯、紧急联系人、紧急电话 |
| 银行信息 | 开户行、银行卡号、银行行号 |
| 工作信息 | 主工种、能力范围、技能等级、参考日工资、所属班组 |
| 项目分配 | 当前项目、在场状态、进场日期、退场日期、安全教育 |
| 其他 | 亲属组、附件、备注 |

班组和项目保存真实 ID；浏览器选择器同样只查询中央正式来源。浏览器保存经中央命令信封、服务端分配 ID、幂等 `commandId` 与 `baseVersion` 乐观锁完成。银行行号目前为普通可编辑字段，不承诺自动匹配外部银行行号库。

## 详情页 `/base/worker/:id`

### 页面结构

详情页采用连续区块，而非 Tab：

1. 顶部显示姓名、工种、班组，并分别显示档案状态和在场状态。
2. 摘要显示参与项目、责任户、考勤、确认签工、已记录个人收款和项目扣罚金额。
3. “个人主数据”显示身份、联系方式、用工信息、能力与附件。
4. “项目与工程量责任”显示项目来源和直接责任单元。
5. “考勤、签工、工资与扣罚”显示真实业务记录。
6. 右栏显示所属班组和亲属/历史关联人员；窄屏时随主内容自然换行。

### 隐私显示

详情页不得直接展示以下完整值：

| 字段 | 显示规则 |
|---|---|
| 身份证号 | 仅保留前 4 位和后 4 位 |
| 联系电话、紧急电话 | 仅保留前 3 位和后 4 位 |
| 紧急联系人姓名 | 仅保留首字符，其余使用星号 |
| 银行账号 | 仅保留前 4 位和后 4 位 |

空值统一显示 `—`。编辑表单仍读取原值，但不得通过只读详情泄露完整敏感信息。

### 项目与工程量责任

项目关联由以下真实记录合并去重：

- 当前项目
- 工程量责任
- 考勤
- 签工
- 工资单
- 项目扣罚

每个项目保留其来源标签并跳转 `/project/:projectId`。直接责任单元显示楼栋、楼层、户、工种、责任范围和已完成阶段数，使用 `/subcontract/quantity/:projectId/:unitId` 下钻。中央关系入口会携工人来源主体，目标先显示只读事实详情，不回退本地编辑态。

### 工资

工资关联包括工人作为班组长、工资单成员或工资清单行责任人的记录。每份工资单可跳转 `/subcontract/payroll/:statementId`，中央关系入口默认显示当前工人的只读单据事实并可返回来源。

- 个人清单金额来自该工人的 `wage_statement_lines`。
- 个人收款来自 `wage_statement_allocations`。
- 没有个人分配记录时显示“历史未记录”，不得用整单金额反推。
- 摘要只累计已发放工资单中已有明确个人分配的金额。

### 项目扣罚

扣罚区读取 `penalty_records` 中 `workerId` 或 `responsibleWorkerId` 指向当前工人的记录，并展示日期、项目、来源、位置、原因、金额和状态。

- 项目跳转 `/project/:projectId`。
- 扣罚源单跳转 `/project/penalty/:penaltyId`。
- 扣罚只读展示，录入、整改和扣款在项目扣罚模块完成。
- 被软删除的扣罚或被软删除祖先下的记录不得暴露。

### 班组与关联人员

- 所属班组跳转 `/base/crew/:crewId`。
- 同 `family_group_id` 的其他工人显示为“亲属组”。
- `linked_worker_id` 只作为历史兼容关系读取，不作为新的主关系设计。
- 关联人员跳转 `/base/worker/:workerId`，不参与工资合并或金额核算。

## 验收

1. 档案状态和在场状态分别显示，语义不混用。
2. 电话、紧急联系人、身份证号和银行账号没有完整值泄露。
3. 工程量责任、工资单和扣罚均来自真实表，且可进入已有详情路由。
4. 没有个人工资分配时显示“历史未记录”，不反推金额。
5. 工人直接扣罚与责任人扣罚均可读取，软删除记录被过滤。
6. 无业务事实时各区块显示明确空态，不制造项目、金额或关系。
7. 在 390、768、1024、1280–1440px 下页面不横向溢出；密集表格只在自身区域滚动。
