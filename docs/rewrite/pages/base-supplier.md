## 定位

**Supplier（分供方）** 是跨项目共享的基础主数据。负责公司资料、证照附件、开票/银行信息、联系人、资料审核状态和跨项目只读汇总。

当前浏览器主链已接入连续列表工作面、六个详情页签与真实辅助区，并在 #418 布局基础上补齐列表列、查询、状态标签、列设置、导入和劳务范围；该批运行范围见 [#419 / #421 证据入口](../../design/evidence/issue-419/README.md)。#446 接通正式中央身份的独立证照原件、资料要求和人工核验，#447 补齐中央 OCR 候选、人工确认回填及税务核验；测试身份经授权后只读。验收范围分别见 [#446](../../design/evidence/issue-446/README.md) 与 [#447](../../design/evidence/issue-447/README.md)。当前可重置实例不代表生产持久化或 [#407](https://github.com/zodea/crm-new/issues/407) 全模块复核完成。

边界原则：

| 在本页面做 | 不在本页面做 |
|---|---|
| 新增/编辑分供方主数据 | 新建采购合同（见[核心合同](./core-contracts.md)） |
| 上传、识别、审核证照 | 填写付款申请（见[付款申请](./finance-payment.md)） |
| 查看跨项目汇总，跳转源单据 | 登记发票（见[发票台账](./finance-invoice.md)） |
| 管理文件结构（上传/下载/浏览） | 录入实际支付（见[支付记录](./finance-records.md)） |

## 一、业务流程

```
主档与合作身份建档 ──→ 合作文件与真实源单汇总 ──→ 下钻合同、申请、发票与支付
       │
       └──→ 证照管理 ──→ 资料齐全待核验 ──→ 人工核验合格或退回
                ↑                              │
                └──────── 退回补充 ────────────┘
```

合作身份建档和证照核验是两条关联流程。依 [#281 最终交付](https://github.com/zodea/crm-new/issues/281#issuecomment-5434305726) 与 [COMMANDS.md](../COMMANDS.md)，从合作文件导入可在人工确认后原子创建资料状态为 `incomplete` 的最小分供方及合作关系；导入文件不自动成为证照。合作建档不代表证照合格，也不代替合同、付款等源模块的准入校验；`qualified/rejected` 仍只由既定人工核验产生。

## 三、列表页 `/base/supplier`

### 工具栏

```
全部分供方              [搜索关键词] [刷新] [排序] [筛选] [列设置] [导入] [新建]
```

工具栏采用单行紧凑布局，类别与资料状态收进筛选浮层；窄屏有序换行。表格默认完整列，32px紧凑行、20条分页，列设置可隐藏可选列、切换44px舒适行并恢复默认。名称在宽屏固定左侧，窄屏随表格横滚；操作固定右侧。刷新保留当前条件，失败时显示错误并保留可辨认的已有列表。列表导入现已接入中央逐行命令，契约见 [COMMANDS.md](../COMMANDS.md)；导出及中央删除仍由 #407/#406 承接。

### 列表逐项对应（2026-09-08 实施）

本节承接用户的直接复刻要求，调查与冲突证据见 [#404](https://github.com/zodea/crm-new/issues/404#issuecomment-5582280040)，分供方实施归 [#407](https://github.com/zodea/crm-new/issues/407)，文件能力归 [#406](https://github.com/zodea/crm-new/issues/406)。列、状态、搜索、表头查询和列设置已接入实际界面；营业执照读面与其他未接功能按下表明确保留边界，不将布局通过当成全模块完成。

默认展示全部适用的参考业务列，瑞航资料核验、合作项目及金额列按业务含义分组；不因宽度不足隐藏统计列。768px及以上名称固定左侧，操作固定右侧；窄屏释放左侧固定，确保可读宽度。宽表只在自身区域横向滚动，列设置持久保存当前浏览器视图偏好，恢复默认重新显示完整列。

默认顺序固定为：序号 → 分供方名称 → 分供方类别 → 唯一识别码 → 统一社会信用代码 → 简称 → 注册地址 → 主要联系人 → 联系方式 → 资料状态 → 纳税人类型 → 主营业务 → 劳务承包范围 → 开户行 → 银行账号 → 经营类型 → 累计结算金额 → 累计合同金额 → 有效合同额 → 确认实付 → 合作项目数 → 营业执照 → 操作。资料状态只出现一次；已排除的上级供应商、参考审批状态及参考业务分类不占空列。尚未接入的字段必须在实施票保留缺口，不用无数据占位列声称实现；金额如经权威口径证明等义，合并须记录依据并同步本顺序。

#### 资料状态与名称单元格

- 列表、详情摘要及资料筛选已消费同一个真实状态键与映射，使用 `KitStatusTag` 区分资料缺失、齐全待核验、合格、退回；旧 `complete` 二态判断已移除。未知值显示中性“未知状态”，不修改源状态。状态机及人工核验凭证规则只看第六节与数据权威。
- 标签外观、长文案和可达性统一遵循[公共状态原语合同第 16 节](../../design/kit-ui-component-specs.md)，本页不重复定义尺寸或色值；本批接入不代表其他页面已经迁移。
- 名称链接、普通文本、状态标签和行级操作有清晰区别。空值使用统一空值展示；名称过长时不挤压相邻列，完整名称可通过可达的提示读取，详情返回恢复原查询与行焦点。

#### 可操作表头与搜索联动

以下表头入口已接入中央查询：对完整允许集合先筛选、排序，再分页；金额与项目数按数值比较，编码按文本处理。营业执照筛选由 #446 接入同一中央证照投影；没有查看证照权限的主档行仍可读取，营业执照显示暂不可用。

| 列 | 当前表头筛选 | 当前排序 |
| --- | --- | --- |
| 分供方名称 | 文本包含 | 名称升/降序，已有排序能力 |
| 分供方类别、资料状态 | 各自完整 facet 多选，同列任一项匹配，与工具栏同步；档案本身的类别仍为单值 | 类别升序已有；资料状态不提供排序 |
| 唯一识别码、统一社会信用代码、简称、注册地址、主要联系人、联系方式、主营业务、开户行、银行账号、经营类型 | 各自文本包含；查询只使用 capability 允许检索的值，不以条件试探被遮罩原值 | 本轮不提供列排序 |
| 纳税人类型 | 完整 facet 多选，未核验作为真实状态 | 本轮不提供列排序 |
| 累计结算金额、累计合同金额、有效合同额、确认实付、合作项目数 | 最小/最大数值区间，边界包含；空值与零值分开 | 各自数值升/降序，稳定身份作同值次序 |
| 营业执照 | “有原件”“缺少原件”“不可用”的完整状态选项；读取失败或无权限不冒充“缺失” | 不提供列排序 |
| 序号、操作 | 不提供筛选 | 不提供排序 |

劳务承包范围使用独立文本包含条件，不提供列排序，也不借用主营业务。对没有筛选/排序能力的格仅展示标题；列宽手柄仍遵循公共表格合同。

固定枚举提供复选、全选、清空和应用；同一字段按并集、不同字段按交集匹配。旧单值地址仍可恢复，多值地址保存全部选择。相同数据来源内的后台查询保留已读取的表格与焦点，首次读取或切换正式/测试范围仍显示真实加载态，不能短暂露出上一个来源的数据。公共交互及可读性规则见 [DESIGN-SYSTEM 列表模式](../DESIGN-SYSTEM.md#a01-list-pattern)与[查询控件](../DESIGN-SYSTEM.md#a01-query-controls)。

- 具有真实筛选或排序能力的表头必须显式显示相应图标、可聚焦操作和准确名称，选中后能辨认当前条件或排序方向；无该能力的列不放装饰性漏斗或箭头。列宽调整保留右边界命中区与悬停提示，和筛选、排序操作分开。
- 表头筛选、工具栏筛选、关键词、排序和分页共享同一查询状态。受控分页按[公共表格规格第 12 节](../../design/kit-ui-component-specs.md)使用完整集合 facet 与远程筛选，不从当前页反推选项或只筛当前页。条件改变回到第 1 页；清除条件同步清除表头选中态、筛选图标和查询模型。
- 当前关键词搜索已包含劳务承包范围；完整检索字段、脱敏后的可检索值、列条件和同查询汇总只见[分供方读取契约](../READ-MODELS.md#33-分供方列表查询与跨域事实)。搜索、表头和工具条件共同进入完整集合查询，不能以旧五字段范围或当前页数据解释现行行为。
- 组合条件、分页、清空、返回和视口等已执行结果统一见[本批验收入口](../../design/evidence/issue-419/README.md)，不在规格内保留过时样本条数。后续导出仍须复用同一查询契约，当前未接入的导出不计为已验收；刷新失败及其他未覆盖情形保持各自证据状态。

## 四、新增/编辑

采用 ADR 0014 整页表单；新建前先通过统一 KitUI 类型选择框选择该 ADR 规定的七类，确认后进入整页表单。类型带入表单，但仍可在未产生业务引用前修正。短分供方表单不显示左侧分区导航，字段使用两列网格（窄屏单列）、内容区纵向滚动和固定底部操作栏。

| 分区 | 字段 |
|---|---|
| 基础信息 | 公司全称*、简称别名、分供方类别*、经营类型、唯一识别码、统一社会信用代码、法定代表人、注册资金、注册日期、注册地址、纳税人类型、评价等级、主营业务、劳务承包范围 |
| 联系人信息 | 主要联系人*、联系人电话、职务、公司电话 |
| 开票信息 | 开票名称、开户行、银行账号、开票地址及电话 |
| 证照资料引导 | 表单不保存第二套普通附件；主数据保存后进入详情“证照附件”，统一维护真实文件、OCR、有效期、资料要求和人工核验 |
| 状态与备注 | 资料状态（按资料规则与人工审核动作产生）、备注 |

`approvalStatus` 不作为本表单普通字段。`credentialStatus` 中 `incomplete/reviewing` 由资料规则自动计算，`qualified/rejected` 只能由人工核验动作产生；设计稿普通 select 不得绕过 #13 的审核凭证要求。

**劳务承包范围（2026-09-08 已接入）**：基础信息在主营业务之后提供独立可选多行输入，详情和列表读取同一个 `laborScope`，查询见第三节。省略保留、显式清空及不影响资料核验的规则只见 [COMMANDS.md](../COMMANDS.md) 与 [DATABASE.md](../DATABASE.md)；保存、清空和再次编辑的真实回读已列入本批证据。[分供方使用指南](../../guides/supplier-records.md)及对应 PDF 已同步当前能力。

### 地址、电话与纳税人类型口径

- `address` 是营业执照登记的住所/注册地址；不得用经营地址、收件地址或开票地址覆盖。
- `invoiceAddress` 是分供方确认使用的开票资料地址，常与注册地址一致，但不是同一个字段。允许点击“同注册地址”做一次性复制，复制后仍可独立编辑；选填且不参与资料齐全度。
- `phone` 是公司电话/开票资料电话，选填；与主要联系人手机 `contactPhone` 分开，不参与资料齐全度、提交审核或合格判断。
- `taxpayerType` 选填且新建默认“未核验”，不得默认“一般纳税人”。字段旁提供“复制税号”和“打开广东税务查询”，跳转[广东省电子税务局一般纳税人资格查询](https://etax.guangdong.chinatax.gov.cn:8443/xxbg/view/zhsffw/#/query/ybnsrzgcx)。用户在官网完成验证码和查询，回到应用后人工确认结果并记录核验时间；应用不抓取网页、不绕过验证码。“未查到”只记为待确认，不自动判为小规模纳税人。

## 六、证照管理与审核

以下为证照专用流程的规则。#446 的浏览器正式身份可上传原件、维护类别/有效期/要求、人工通过或退回、软删除与撤回；#447 补齐显式原件识别、稍后核对、确认回填和人工税务核验。浏览器演示来源须后台授权且只读；中央上传不自动调用 OCR。操作见[证照使用指南](../../guides/supplier-credential-review.md)，当前中央可重置实例不代表生产持久化已交付。

证照页把实际空态、读取失败、无权、错来源和记录失效分开呈现；失败不能推导为“未上传”。原件上传与证照、关系、适用审计一并保存，服务端复验真实类型、签名及 20 MB 上限；预览/下载重新检查当前分供方与证照的所有权。类别和有效期在行级轻量操作中维护，不新增业务实体大弹窗。当前记录变化导致版本冲突时保留输入并重读；响应不确定时核对原提交，重试不生成第二份身份。A/B、来源或页签切换后不应用旧请求结果，返回保持合法来源及父列表上下文。

### 证照清单

| 类别 | 默认要求 | OCR 回填 / 说明 |
|---|---|---|
| 营业执照 | 必需 | 公司全称、税号、法人、注册地址 |
| 法人身份证 | 必需 | 法人姓名、证件有效期 |
| 银行账户资料 | 必需 | 开户行、银行账号；兼容“银行开户许可证 / 开户许可证 / 基本存款账户信息 / 基本存款账户信息表” |
| 签约代表身份证 | 不适用 | 仅在签约代表与法人不同且业务明确要求时改为“需提供” |
| 资质证书 | 不适用 | 仅特定品牌、专业类别、项目或合同明确要求时改为“需提供” |
| 品牌授权书/品牌授权证明 | 不适用 | 两个名称视为同一类别；仅明确要求授权关系时改为“需提供” |
| 合同模板 / 完税证明 / 过往业绩合同 / 施工照片 / 其他 | 可选 | 默认不影响资料齐全度 |

条件资料的要求状态与文件是否已收到分开保存：默认“不适用”，人工改为“需提供”时必须填写原因，之后缺失或过期才影响资料齐全度；不得为了让状态变绿而制造现实中不存在的证照。营业执照、法人身份证、银行账户资料是固定必需项，界面与后台均禁止降为可选或不适用。

### OCR 回填规则

1. 使用系统设置中已配置的 PaddleOCR-VL 服务识别当前授权原件，识别失败保留原件；上传或迁移不自动发起识别。
2. 按关键词提出类别建议，类别冲突默认保留当前；只有人工确认才改变类别。
3. 先保存原始候选、置信度和待核对状态，未确认不改主档；空字段也须经本次人工确认后回填。
4. 每个目标字段提供保留当前、采用具体候选或人工修正。与已有值冲突时明确提示，由人工决定是否替换；同一原件的矛盾税号不能静默择一。
5. 新识别的统一社会信用代码与纳税人识别号目标为 `taxNo`；`uniqueCode` 是内部码。历史结构化候选保留原字段含义，旧内部码候选不得直接采用，只能保留当前或明确人工修正，不按长度搬值。
6. 稍后核对、冷刷新和重新进入保留原始候选；再次识别保留上次确认痕迹。确认时后台重验当前原件、识别快照、主档及双版本，一同保存确认事实与主档变更。
7. 并发变化保留本次选择，重读后再次人工核对；响应不确定先恢复同一提交。税号及内部码继续沿主档重复校验，失败不产生部分确认。

### credentialStatus 流转

以下表格维护真实资料变更和人工核验动作；当前有效性、历史凭证与主动警告分离见 [READ-MODELS](../READ-MODELS.md#supplier-expiry-warnings)。读取已按同一上海业务日纯派生，不撤销人工历史；中央界面分别显示当前结论及历次核验，关键资料真实写动作使旧结论退出当前有效依据并保留历史。

> ✅ Issue #13 已确认：资料齐全不等于合格，必须经过人工核验。内部值 `reviewing` 的界面文案统一显示“齐全待核验”。
>
> 数据底座已由迁移 v36 落地：证照原件只有在有效 `file_refs + file_payloads` 下才算已收到；legacy 桌面路径只保留迁移线索，不授予应用读取权限，用户必须重新选择原件上传。原始 OCR、待核对状态与人工确认值分列保存，“稍后核对”或重启后仍可继续；OCR 类别与当前类别冲突时默认保留当前类别并记录决定。OCR 更新只写不含正文的专用脱敏审计；逐类别要求、按 `Asia/Shanghai` 业务日期计算的有效期和供应商级人工核验凭证参与同一状态机。存量 `qualified/rejected` 没有供应商级凭证时会重算为 `incomplete/reviewing`。

> 供应商主数据、人工资料核验和纳税人核验只写 `supplier_audits` 脱敏审计，记录动作、结果、来源类别、变更字段名、备注是否存在和时间，不复制税号、银行账号、OCR 或备注正文。浏览器由中央主档命令与证照领域在同一原子边界核对主档和证照事实。列表、详情与证照页按同一天上海业务日重算当前状态。普通表单、store 和导入不能直接制造 `qualified/rejected`。

| 动作 | 结果 |
|---|---|
| 影响必需资料的文件、类别、有效期或要求变化 | 旧人工结论归档为历史后重算：必需资料缺失或过期 → `incomplete`；全部满足 → `reviewing` |
| 人工核验通过 | 仅 `reviewing` 可执行；→ `qualified`，记录核验时间和备注 |
| 人工退回 | 仅 `reviewing` 可执行；→ `rejected`，退回原因必填 |
| 修正退回问题 | 按资料规则重新计算为 `incomplete` 或 `reviewing`，不得自动恢复 `qualified` |

已有人工结论后，如必需资料的文件、分类、有效期、要求状态或相关 OCR 确认值发生变化，原核验结论失效并重新计算。主档 `name / uniqueCode / taxNo / legalRep / address / bank / bankAccount` 真实变化同样失效；普通编辑与逐行导入共同执行。仅修改不参与齐全度的可选资料、劳务范围、备注或时间戳不撤销结论，要求值未改变而仅改原因也不误失效。未填写截止日期沿已有有效性规则处理；不能自行增加新的失效门槛。人工确认必须复验当时主档、原件及要求版本，不以旧页面的“齐全”代替当前事实。

证照软删除后原件不可作为当前证照读取；撤回以同一证照、对应审计和准确删除边界恢复，不复制身份。删除 A、撤回 A、再删除 B 后，旧 A 撤回不能恢复 B。受控旧图迁入保留原件正文、要求、原始及确认 OCR、整体人工凭证、专用审计和软删除；缺正文路径只保留线索，历史操作者未知不补当前用户，缺整体凭证的旧人工态按当前规则重算。数据与迁移字段只见 [DATABASE](../DATABASE.md)，命令原子与幂等边界只见 [COMMANDS](../COMMANDS.md)。

## 七、跨项目只读汇总

详情汇总放在辅助区“往期合作情况”，不直接编辑源数据；列表按第三节读取相同身份与口径的指标，不另建累计值来源。“合作项目、累计合同金额、累计结算金额、累计收票金额、累计付款金额”在详情具备对应查看能力时保留固定入口并同步 `?tab=` 深链；点击后滚动到主区域导航并聚焦选中页签，既有 `origin/returnTo` 等来源参数保持不变。“应付金额”只展示。入口对应的真实关系暂时没有记录时仍进入目标 Tab 的真实空态，不用 mock 填充。项目、合同、付款申请和发票明细继续通过蓝色链接穿透真实源记录。

业务口径：合作项目按稳定 ProjectSupplier 关系计数；合同只纳入非草稿、未失效或作废的有效合同及有效增补，结算只累计已确认记录，收票只累计已归档发票，付款只累计已确认支付对该分供方付款申请的真实分摊；应付为有效合同额减确认实付，只读且不可穿透。金额未知与已读取空集合必须区分，不使用主档旧累计值推算。

当前已接来源、空值完整度和读取实现统一见[分供方读取契约](../READ-MODELS.md#33-分供方列表查询与跨域事实)与[正式读取范围](../READ-MODELS.md#pg-04-本机分供方读取453)。正式合同和结算分区呈现已核实来源的小计与缺口，付款从真实已确认支付及原分摊读取；项目名称可读不把缺失合作关系填成零。营业执照继续遵循第三节的证照专用读面边界，不以主档字段或图标代替真实文件。

## 八、验收要点

1. 浏览器 `/base/supplier` 的列表、详情和正式主档新增/编辑只走中央 Repository、HTTP 与命令边界
2. 合同、请款、收票、付款的新增和审批在各自业务模块完成
3. 证照 OCR 冲突不覆盖人工字段
4. 详情页汇总数字必须能追溯源单据（带筛选条件跳转）
5. 同一个 Supplier 可关联多个项目，主数据只维护一份
6. `approvalStatus` V1 预留不启用；资料缺失/齐全状态自动计算，但 `qualified/rejected` 必须由人工核验产生并可追溯
7. 主档默认详细资料，三个资料分区与五类业务事实分别展示；窄屏辅助区下移，金额跳转后选中页签进入视口且获得焦点
8. 开票资料地址和公司电话允许留空，不影响资料齐全度；注册地址与开票资料地址独立保存
9. 资质证书、品牌授权书默认不适用，只有明确标记“需提供”后才参与缺失/过期判断
10. 纳税人类型默认未核验；广东税务入口只做“复制税号 + 打开官网 + 人工确认”，不得爬取或绕过验证码
11. “基本存款账户信息”能够满足“银行账户资料”要求，不因历史名称不同误报缺失
12. 四类业务深链刷新后保留原页签，辅助合同返回保留来源；列表、详情、表单的实际四档视口验证按 #418 留证，不能用公共壳接入替代逐页验收

## 九、参考系统差异裁定（Issue #193）

- 不采用“上级供应商”或 `parentSupplierId`：瑞航分供方是终端签约对象，不建立母子挂靠。
- 不引入“大宗供应商”或历史四类；新建与表单使用权威七类单值，列表筛选可在同源七类中多选以查询多个类别，不改变实体类别归属。
