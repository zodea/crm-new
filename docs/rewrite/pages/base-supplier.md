## 定位

**Supplier（分供方）** 是跨项目共享的基础主数据。负责公司资料、证照附件、开票/银行信息、联系人、资料审核状态和跨项目只读汇总。

当前浏览器主链的布局按 [#418](https://github.com/zodea/crm-new/issues/418) 同步：连续列表工作面、六个详情页签与真实辅助区已接入。证照完整写流程仍属于 Tauri 正式本地身份，浏览器正式中央身份等待专用存储接入、测试身份只读；下述证照规则不能解释为浏览器主档详情已提供上传和审核。本批不改变中央事实、能力判断或生产持久化边界，也不代表 [#407](https://github.com/zodea/crm-new/issues/407) 全模块复核完成。

边界原则：

| 在本页面做 | 不在本页面做 |
|---|---|
| 新增/编辑分供方主数据 | 新建采购合同（见[核心合同](./core-contracts.md)） |
| 上传、识别、审核证照 | 填写付款申请（见[付款申请](./finance-payment.md)） |
| 查看跨项目汇总，跳转源单据 | 登记发票（见[发票台账](./finance-invoice.md)） |
| 管理文件结构（上传/下载/浏览） | 录入实际支付（见[支付记录](./finance-records.md)） |

## 一、业务流程

```
主档与合作身份建档 ──→ 合作文件与真实源单汇总 ──→ 下钻合同、申请、发票与支付
       │
       └──→ 证照管理 ──→ 资料齐全待核验 ──→ 人工核验合格或退回
                ↑                              │
                └──────── 退回补充 ────────────┘
```

合作身份建档和证照核验是两条关联流程。依 [#281 最终交付](https://github.com/zodea/crm-new/issues/281#issuecomment-5434305726) 与 [COMMANDS.md](../COMMANDS.md)，从合作文件导入可在人工确认后原子创建资料状态为 `incomplete` 的最小分供方及合作关系；导入文件不自动成为证照。合作建档不代表证照合格，也不代替合同、付款等源模块的准入校验；`qualified/rejected` 仍只由既定人工核验产生。

### 本轮定稿待实现：列表逐项对应

本节承接用户于 2026-09-08 对名称列、状态标签、可操作表头、搜索联动及右侧工具的补充要求，调查与冲突证据见 [#404](https://github.com/zodea/crm-new/issues/404#issuecomment-5582280040)，分供方实施与未决业务口径归 [#407](https://github.com/zodea/crm-new/issues/407)，文件能力归 [#406](https://github.com/zodea/crm-new/issues/406)。**以下为本轮目标规格，不代表这些字段、工具或状态展示已经全部可用。** 上方“当前中央列表列”继续描述现有列范围；不得把阶段实现范围当成最终删减依据。

默认展示全部适用的参考业务列，瑞航已有的资料核验、合作项目及金额列继续保留，并按业务含义分组；不因宽度不足静默隐藏统计列。名称固定左侧，操作固定右侧，宽表只在自身区域横向滚动。列设置可供用户调整自己的视图，不能用默认隐藏代替本轮逐项对应。

默认顺序固定为：序号 → 分供方名称 → 分供方类别 → 唯一识别码 → 统一社会信用代码 → 简称 → 注册地址 → 主要联系人 → 联系方式 → 资料状态 → 纳税人类型 → 主营业务 → 劳务承包范围 → 开户行 → 银行账号 → 经营类型 → 累计结算金额 → 累计合同金额 → 有效合同额 → 确认实付 → 合作项目数 → 营业执照 → 操作。资料状态只出现一次；已排除的上级供应商、参考审批状态及参考业务分类不占空列。尚未接入的字段必须在实施票保留缺口，不用无数据占位列声称实现；金额如经权威口径证明等义，合并须记录依据并同步本顺序。

#### 资料状态与名称单元格

- 列表、详情摘要及资料筛选消费同一个真实状态键与状态映射，保持资料缺失、齐全待核验、合格、退回四态可区分；状态机及人工核验凭证规则只看第六节与数据权威。
- 当前列表的文案已读取状态映射，但颜色把除 `complete` 外的状态统一处理为警示色；详情又把非 `complete` 统一显示为“资料待完善”。这是待修正的显示错误，不能通过修改真实状态消除视觉差异。
- 标签使用公共状态原语，按直接参考校准紧凑尺寸、小圆角、内边距和语义色；不能在列表中分别手写一套颜色判断。保留文字，不能只靠颜色判断状态。
- 名称链接、普通文本、状态标签和行级操作有清晰区别。空值使用统一空值展示；名称过长时不挤压相邻列，完整名称可通过可达的提示读取，详情返回恢复原查询与行焦点。

- 具有真实筛选或排序能力的表头必须显式显示相应图标、可聚焦操作和准确名称，选中后能辨认当前条件或排序方向；无该能力的列不放装饰性漏斗或箭头。列宽调整保留右边界命中区与悬停提示，和筛选、排序操作分开。
- 表头筛选、工具栏筛选、关键词、排序和分页共享同一查询状态。受控分页按[公共表格规格第 12 节](../../design/kit-ui-component-specs.md)使用完整集合 facet 与远程筛选，不从当前页反推选项或只筛当前页。条件改变回到第 1 页；清除条件同步清除表头选中态、筛选图标和查询模型。
- 当前搜索已接通中央查询，范围为名称、简称、内部编码、税号和主要联系人；已有防抖、分页重置与同一筛选集合的汇总。2026-09-08 本地运行核验了 11 条缩至 1 条、数量与汇总及分页同步、清空后恢复 11 条；该证据不外推成所有筛选和状态已验收。
- 本轮继续验证组合筛选、无结果、清空、切页、详情返回、查询中断和刷新失败。搜索结果、表格、总数、金额汇总及后续导出使用同一完整查询范围；刷新保留当前查询，失败时保留可辨认的已有内容及重试入口。

采用 ADR 0014 整页表单；新建前先通过统一 KitUI 类型选择框选择 CONTEXT.md 权威七类，确认后进入整页表单。类型带入表单，但仍可在未产生业务引用前修正。短分供方表单不显示左侧分区导航，字段使用两列网格（窄屏单列）、内容区纵向滚动和固定底部操作栏。

| 分区 | 字段 |
|---|---|
| 基础信息 | 公司全称*、简称别名、分供方类别*、经营类型、唯一识别码、统一社会信用代码、法定代表人、注册资金、注册日期、注册地址、纳税人类型、评价等级、主营业务 |
| 联系人信息 | 主要联系人*、联系人电话、职务、公司电话 |
| 开票信息 | 开票名称、开户行、银行账号、开票地址及电话 |
| 证照资料引导 | 表单不保存第二套普通附件；主数据保存后进入详情“证照附件”，统一维护真实文件、OCR、有效期、资料要求和人工核验 |
| 状态与备注 | 资料状态（按资料规则与人工审核动作产生）、备注 |

`approvalStatus` 不作为本表单普通字段。`credentialStatus` 中 `incomplete/reviewing` 由资料规则自动计算，`qualified/rejected` 只能由人工核验动作产生；设计稿普通 select 不得绕过 #13 的审核凭证要求。

**劳务承包范围（2026-09-08 定稿待实现）**：在基础信息的主营业务之后增加可选多行文本，与主营业务独立保存。新增、编辑、取消、版本冲突与失败反馈沿现有主档流程；保存或显式清空后，列表、详细资料和再次打开的编辑表单读回同一个 `laborScope`。列表默认列及独立筛选按第三节；有权限的关键词查询同时支持该字段。详情在主营业务之后展示，长值可恢复完整内容，旧记录空值显示 `—`。本项不新增资料核验动作；实施时同步分供方使用指南及 PDF，不将这段目标描述当成当前已可填写。

### 地址、电话与纳税人类型口径

- `address` 是营业执照登记的住所/注册地址；不得用经营地址、收件地址或开票地址覆盖。
- `invoiceAddress` 是分供方确认使用的开票资料地址，常与注册地址一致，但不是同一个字段。允许点击“同注册地址”做一次性复制，复制后仍可独立编辑；选填且不参与资料齐全度。
- `phone` 是公司电话/开票资料电话，选填；与主要联系人手机 `contactPhone` 分开，不参与资料齐全度、提交审核或合格判断。
- `taxpayerType` 选填且新建默认“未核验”，不得默认“一般纳税人”。字段旁提供“复制税号”和“打开广东税务查询”，跳转[广东省电子税务局一般纳税人资格查询](https://etax.guangdong.chinatax.gov.cn:8443/xxbg/view/zhsffw/#/query/ybnsrzgcx)。用户在官网完成验证码和查询，回到应用后人工确认结果并记录核验时间；应用不抓取网页、不绕过验证码。“未查到”只记为待确认，不自动判为小规模纳税人。

### 新增来源

1. 手动新建
2. Excel 导入
3. 从已入账发票销售方收集候选分供方
4. 从送货单识别结果归并公司名称

## 五、详情页 `/base/supplier/:id`

### 标题与简要元信息

```
[← 返回来源] 分供方名称 [资料状态] [正式/测试数据] [已有页面操作]
类别 / 评价 / 主要联系人 / 联系电话 / 详细地址
主区域：页签 → 当前资料或事实表       辅助区：往期合作 / 档案 / 已接入关联
```

使用 `EntityDetailShell compact`，标题与元信息保持紧凑；长名称允许换行。顶部保留现有“分包变洽签”“证照附件”“编辑”入口及各自能力判断，测试主档只读。不为对齐参考新增未接入的工商查询、审批或评论动作。

### 浏览器中央详情（6 个页签）

| # | Tab / query 值 | 内容 | 操作边界 |
|---|---|---|---|
| 1 | 详细资料 / `overview` | 基础信息、联系人信息、开票信息三个只读分区，开户资料归入开票信息 | 无有效 `tab` 时默认；手动选择时移除 `tab` query |
| 2 | 合作项目 / `projects` | ProjectSupplier 稳定关系 | 点击项目进入 `/project/:pid/supplier/:sid` |
| 3 | 支出合同 / `contracts` | 有效合同与有效补充协议金额 | 合同和项目有稳定身份时穿透 |
| 4 | 支出结算 / `settlements` | 已登记的支出结算事实 | 0 条也进入真实空态；没有 canonical 详情路由的结算行保持不可导航 |
| 5 | 收票登记 / `invoices` | 仅已归档发票 | 发票、项目和合同分别按稳定身份解析 |
| 6 | 付款管理 / `payments` | 付款申请及已确认支付分摊 | 申请进入只读付款申请详情；实付不从申请金额推算 |

页签位于主区域顶部。完整主数据只在“详细资料”显示，业务页签直接呈现对应事实表；简要元信息与辅助区保持可见。资料分区复用 `ReadOnlySection`，字段含义仍以第二节权威源为准，原始值的脱敏和金额格式由领域页负责。正式分供方只能从详情顶部显式进入独立整页表单。浏览器中央主链不读取旧 `supplier-detail` store。证照上传、OCR 与人工核验从 `/base/supplier/credential/:id` 独立路由进入既有证照专用文件/审计边界；该路由不回退成事实页签，也不把证照改造成中央主档附件命令。尚未接入该专用存储的中央主档必须显示明确不可用状态，禁止写入平行正式主数据。

> 当前实现（#277、#319）：材料采购合同详情使用稳定 `supplierId + dataOrigin` 进入本页 `contracts|settlements|invoices|payments` 四类事实页签，事实为 `0` 时仍显示专属空态。#277 已验证受控迁入的正式合同与分供方共用同一中央身份，正式材采合同按 `supplier_id` 回流本页合同事实；结算事实为真实 `0` 时仍可进入空表。仅接受白名单页签与经验证的同源材采合同返回地址；返回时恢复原合同页签，并继续沿材采列表、项目详情和项目列表的嵌套上下文逐级恢复。该入口不引入新的供应商聚合来源，也不扩展库存、交付或结算核心。

> 父级闭合（#281）：项目分供方工作台的分供方身份卡只按稳定 `supplierId` 与同一 `dataOrigin` 进入本页，并携双父 ID 和原工作台页签形成的受限 `returnTo`。详情刷新后仍可显式返回工作台；目标分供方 ID、来源或额外 query 错配时退回规范分供方列表，不恢复伪造来源。

## 六、证照管理与审核

以下为既有证照专用流程的规则；当前完整可写链限定 Tauri 正式本地身份。浏览器正式身份待接入、测试身份只读，详见[证照使用指南](../../guides/supplier-credential-review.md)。中央主档的资料完整性展示不能替代本节的人工核验结论。

### 证照清单

| 类别 | 默认要求 | OCR 回填 / 说明 |
|---|---|---|
| 营业执照 | 必需 | 公司全称、税号、法人、注册地址 |
| 法人身份证 | 必需 | 法人姓名、证件有效期 |
| 银行账户资料 | 必需 | 开户行、银行账号；兼容“银行开户许可证 / 开户许可证 / 基本存款账户信息 / 基本存款账户信息表” |
| 签约代表身份证 | 不适用 | 仅在签约代表与法人不同且业务明确要求时改为“需提供” |
| 资质证书 | 不适用 | 仅特定品牌、专业类别、项目或合同明确要求时改为“需提供” |
| 品牌授权书/品牌授权证明 | 不适用 | 两个名称视为同一类别；仅明确要求授权关系时改为“需提供” |
| 合同模板 / 完税证明 / 过往业绩合同 / 施工照片 / 其他 | 可选 | 默认不影响资料齐全度 |

条件资料的要求状态与文件是否已收到分开保存：默认“不适用”，人工改为“需提供”后，缺失或过期才影响资料齐全度；不得为了让状态变绿而制造现实中不存在的证照。

### OCR 回填规则

1. 使用系统设置中已配置的 PaddleOCR-VL 服务识别证照内容
2. 按关键词自动归类证照类别
3. 只回填空字段，不覆盖已填值
4. 与已填值冲突时高亮提示（绿框 + "请核对"），由人工决定是否替换
5. 所有识别值允许人工修改

### credentialStatus 流转

> ✅ Issue #13 已确认：资料齐全不等于合格，必须经过人工核验。内部值 `reviewing` 的界面文案统一显示“齐全待核验”。
>
> 数据底座已由迁移 v36 落地：证照原件只有在有效 `file_refs + file_payloads` 下才算已收到；legacy 桌面路径只保留迁移线索，不授予应用读取权限，用户必须重新选择原件上传。原始 OCR、待核对状态与人工确认值分列保存，“稍后核对”或重启后仍可继续；OCR 类别与当前类别冲突时默认保留当前类别并记录决定。OCR 更新只写不含正文的专用脱敏审计；逐类别要求、按 `Asia/Shanghai` 业务日期计算的有效期和供应商级人工核验凭证参与同一状态机。存量 `qualified/rejected` 没有供应商级凭证时会重算为 `incomplete/reviewing`。

> 供应商主数据、人工资料核验和纳税人核验只写 `supplier_audits` 脱敏审计，记录动作、结果、来源类别、变更字段名、备注是否存在和时间，不复制税号、银行账号、OCR 或备注正文。关键工商/银行字段由数据库触发器统一使旧人工结论失效；列表加载还会按当天上海业务日淘汰已经过期的 `qualified`。普通表单、store 和导入不能直接制造 `qualified/rejected`。

| 动作 | 结果 |
|---|---|
| 上传/删除文件，或修改类别、有效期、条件要求 | 自动重算：必需资料缺失或过期 → `incomplete`；全部满足 → `reviewing` |
| 人工核验通过 | 仅 `reviewing` 可执行；→ `qualified`，记录核验时间和备注 |
| 人工退回 | → `rejected`，退回原因必填 |
| 修正退回问题 | 按资料规则重新计算为 `incomplete` 或 `reviewing`，不得自动恢复 `qualified` |

已人工合格后，如必需资料的文件、分类、有效期、要求状态或相关 OCR 确认值发生变化，原核验结论失效并重新计算；只修改不参与齐全度的可选资料，不应无故撤销合格。

## 七、跨项目只读汇总

详情汇总放在辅助区“往期合作情况”，不直接编辑源数据；列表按第三节读取相同身份与口径的指标，不另建累计值来源。“合作项目、累计合同金额、累计结算金额、累计收票金额、累计付款金额”在详情具备对应查看能力时保留固定入口并同步 `?tab=` 深链；点击后滚动到主区域导航并聚焦选中页签，既有 `origin/returnTo` 等来源参数保持不变。“应付金额”只展示。入口对应的真实关系暂时没有记录时仍进入目标 Tab 的真实空态，不用 mock 填充。项目、合同、付款申请和发票明细继续通过蓝色链接穿透真实源记录。

| 指标 | 计算来源 |
|---|---|
| 合作项目数 | COUNT(ProjectSupplier WHERE supplierId) |
| 合同数 / 累计合同金额 | 采购合同表（→ `contracts`） |
| 累计结算金额 | 已确认支出结算事实（→ `settlements`）；不得使用合同旧累计字段 |
| 累计收票金额 / 税额 | 已归档发票表（→ `invoices`） |
| 累计付款金额 | 已确认支付记录对付款申请的真实分摊（→ `payments`） |
| 应付金额 | 累计合同金额 − 累计付款金额（只读、不穿透） |

## 八、验收要点

1. 浏览器 `/base/supplier` 的列表、详情和正式主档新增/编辑只走中央 Repository、HTTP 与命令边界
2. 合同、请款、收票、付款的新增和审批在各自业务模块完成
3. 证照 OCR 冲突不覆盖人工字段
4. 详情页汇总数字必须能追溯源单据（带筛选条件跳转）
5. 同一个 Supplier 可关联多个项目，主数据只维护一份
6. `approvalStatus` V1 预留不启用；资料缺失/齐全状态自动计算，但 `qualified/rejected` 必须由人工核验产生并可追溯
7. 主档默认详细资料，三个资料分区与五类业务事实分别展示；窄屏辅助区下移，金额跳转后选中页签进入视口且获得焦点
8. 开票资料地址和公司电话允许留空，不影响资料齐全度；注册地址与开票资料地址独立保存
9. 资质证书、品牌授权书默认不适用，只有明确标记“需提供”后才参与缺失/过期判断
10. 纳税人类型默认未核验；广东税务入口只做“复制税号 + 打开官网 + 人工确认”，不得爬取或绕过验证码
11. “基本存款账户信息”能够满足“银行账户资料”要求，不因历史名称不同误报缺失
12. 四类业务深链刷新后保留原页签，辅助合同返回保留来源；列表、详情、表单的实际四档视口验证按 #418 留证，不能用公共壳接入替代逐页验收

## 九、参考系统差异裁定（Issue #193）

- 不采用“上级供应商”或 `parentSupplierId`：瑞航分供方是终端签约对象，不建立母子挂靠。
- 不引入“大宗供应商”、历史四类或多选类型；新建、筛选和表单统一使用权威七类单选。
- 不照抄参考系统的审批人、评论、跟进人、动态和供应商层级；`approvalStatus` V1 不在表单展示或驱动资料状态。
- 不增加列表左分类树，不把整页表单改回弹窗；宽表只在自身区域横向滚动。
- 列表与详情只脱敏展示税号、手机号和银行账号；编辑表单保留业务维护所需原值。
- 证照专用页按证照类别组织文件，依环境与身份边界提供真实原件预览和下载；无法读取的 legacy 路径只提示重新上传。#418 后主档详情辅助区只呈现往期合作、档案与已接入关联，不复制证照管理或审批占位。
