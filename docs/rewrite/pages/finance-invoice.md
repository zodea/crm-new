> 词义见 [CONTEXT.md](../../../CONTEXT.md)，字段/关系见 [DATABASE.md](../DATABASE.md)，读写契约见 [READ-MODELS.md](../READ-MODELS.md) 与 [COMMANDS.md](../COMMANDS.md)。本页不保存第二份 Invoice 类型或状态表。

## 一、页面与参考边界

| 页面 | 入口与职责 |
|---|---|
| 发票识别 `/finance/invoice` | 资金管理下的上传、识别、人工校对工作台；打印排版为工作台子模式 |
| 发票台账 `/finance/ledger` | 资金管理下的归档资产列表、筛选、关系查看、打印及导入导出 |
| 单张发票 `/finance/invoice/:id` | 显式编辑进入整页表单，保存/取消恢复来源；作为只读关系目标前须通过独立只读能力验证 |
| 开票因子 `/finance/invoice/factor` | 独立精确计算工具，不写入发票或开票事实 |
| OCR 设置 | 设置模块中的真实识别能力配置，不恢复已退役的“识别中心”导航组 |

发票识别、打印排版及因子工具没有安全确认的一一对应红圈页面，使用 DC 与本页规则。红圈“收票登记”只提供台账相邻证据：票种分类树、专属宽表及项目/合同/开票单位/票款关系；不能据此推导 OCR、归档、下载或审批写入流程。证据见 [运行参考 R-FINANCE-FLOW-LIVE](../../design/runtime-reference-audit.md)，视觉优先级按 [ADR 0013](../../adr/0013-align-all-ui-to-online-design.md)。

## 二、业务流程与状态

扫描件：上传 → OCR 生成待核对草稿 → 人工核对/修订 → 选择项目或个人开支 → 用户归档 → 台账。打印是可独立执行的可选操作，不是归档前置，也不触发归档。

历史 Excel：台账导入入口 → 字段映射 → 逐行校验/重复预览 → 人工确认导入 → 合法行归档。缺归属和冲突行明确拒绝或留待复核，不因来源是 Excel 绕过归档条件。

- 依 [ADR 0001](../../adr/0001-invoice-single-table.md)，识别中间态与归档台账共用 `invoices`，不恢复 `ticket_registrations`，不再询问两表是否合并。
- 人工核对与归档分开；台账资格是 `accountStatus='archived'`，未归档是 `none`。不得继续使用旧 `confirmed` 归档值，或按 `source='excel'` 直接纳入台账。
- OCR 置信度只用于提示，全绿也不自动确认/归档。黄红字段修订或人工确认后仍须执行明确归档动作。
- “建议通过”指有置信度数据且逐字段均为绿档，人工确认或修正后变绿同样有效；“批量通过”由用户触发，范围为识别完成、非重复、未归档扫描件中的全绿票或已校对票，对归属可解析为真实项目或个人开支的票补确认并归档，缺归属的排除并列明原因。
- 项目与个人开支是两类有效归属。票面备注、公司名和文件名只提供匹配建议；用户采用真实项目 ID 前不写关系、不自动创建项目。
- 打印计数与归档、审核状态分开。原始 OCR、人工当前值和来源信息分别留痕。重识别结果可以覆盖当前字段（含未保存的人工修改），但不能静默覆盖：覆盖后的值与识别前不同时，须逐项提示变动字段及原值、新值（用户 2026-10-08 确认）。
- 支付申请、已确认支付及其分摊各有独立事实；收票不等于付款，开票申请不等于实际开票。

## 三、识别与人工校对工作台

上传入口放在队列顶部，并支持全页拖拽。文件原地进入队列显示识别进度，不跳到独立上传 Tab，也不附加与上传无关的购买方金额汇总表。

宽屏按“左列表 / 中原图 / 右字段”组织，参考比例约 18% / 40% / 42%；各栏保护最小可读宽度，字段最多两列。窄屏切换分段或单列流程，同一文件选择、修订草稿及滚动位置保持。实际支持的格式、数量和容量从当前上传契约核验，不从旧设计承诺推断。

- 队列显示文件/发票身份、OCR 进度、待核对、失败与待打印状态；多文件失败不吞掉已完成文件。
- 原图与字段联动，支持查看 PDF/图片、放大和人工旋转辅助核对；预览不修改原件。
- 单头字段按数据库权威分组展示票号、日期、购销方及税号、票种、金额税率、归属和备注；票号按文本保留前导零和长号精度。
- 货物明细默认折叠，展开后独立滚动；人工修订金额与识别原值可辨，勾稽错误定位具体行。
- 置信度使用边框、文字/图标及角标共同表达，不能只依赖颜色。购方缺税号提示核对；重复票号展示已存在记录及冲突原因。
- 校对模式底栏保留废弃、重新识别和符合当前状态的“确认 / 归档”动作；打印按钮只在打印模式提供。
- 保存、识别或归档失败保留选中项与输入，提供可解释错误和重试；取消或带未保存改动离开按现有离开保护处理。

### 重复与更正

| 场景 | 处理边界 |
|---|---|
| 扫描识别后命中已有发票号 | 按现行去重规则标记并给出原记录，不静默新增第二张有效票 |
| Excel 命中已有记录 | 预览拟补充的空字段；冲突项需人工处理，不覆盖已有人工值 |
| 扫描件匹配既有 Excel 记录 | 核实身份后关联原件，不复制台账行；关联失败可重试且不留半记录 |
| 重识别 | 成功后以识别结果覆盖当前字段，并逐项列出与识别前不同的字段（原值 → 新值），由用户核对后保存或继续修改；首次识别不提示；失败不丢原件或现有值 |
| 已归档编辑 | 显式进入整页编辑；校验归属、重复、金额及有效票款引用，保存后回读台账和来源汇总 |
| 删除 | 按 [ADR 0003](../../adr/0003-confirm-dialog-deletion-model.md) 确认、软删除与撤销；下游引用受现行命令约束，不直接改汇总副本 |

重复键和更正允许状态以数据/命令权威为准；#413 复核各失败、重试与下游重算路径，不能凭列表相似度决定实体身份。

## 四、归档台账

默认左树右表，树只到项目一级，含全部、各项目、个人开支和存量未归属异常节点；节点显示数量，不常驻叠加金额卡。未归属异常节点用于纠正历史数据，不是绕过当前归档门槛的出口。

搜索支持票号、购销方、项目与备注，并提供日期范围；供应商、票种等筛选通过列头表达。表格/预览卡片切换保持相同筛选与选择；只有勾选时显示“已选数量与合计”，分页统计要区分当前页、当前筛选和全量。

专属列按当前读模型展示票号、日期、购销方、含税金额、税额、票种、来源、归属、打印状态，以及合同/付款关联余额等适用列。项目、分供方、合同和付款申请只通过带来源的稳定实体引用解析目标，不能返回名称后由前端猜路由；缺源、权限不可见和未接能力分别显示。

- 归档台账只消费同一 `invoices` 事实，不把草稿、仅已核对或重复记录当有效入账。
- 关联金额从付款申请—发票分摊实时读取；申请金额与银行已支付金额分开，不能将剩余可关联金额解释为实际未付款。
- 行内“编辑”进入 `/finance/invoice/:id` 整页表单；查看源单先校验只读目标，不以名称点击隐式进入写态。返回恢复树节点、筛选、页码、选中行及焦点。
- 无原件的 Excel 发票禁止查看原件及加入打印范围，并明确原因：打印列表中不可勾选并显示原因，打印面板列出全部未打印票号及原因。不能把整行所有数据选择和导出能力一并禁用。
- 已归档记录的归属、金额、关联或删除变化后重读台账及关联页面，失败不显示成功，不用前端本地副本补中央事实。

## 五、打印、导出与导入

### 打印排版

识别与台账复用同一排版组件。支持每页 1 张、默认 2 张上下、4 张四宫格；选择列表与 A4 页联动，提供全选、翻页、放大、单张旋转和整页旋转。操作需有键盘入口，不能只有右键。

勾选有原件的发票 → 预览排版 → 生成 PDF → 系统打印 → 用户明确登记已打印。仅打开/关闭系统打印或生成 PDF 不增加计数；用户确认后更新打印次数与最后打印时间，取消/失败继续保留原状态。打印不改审核或归档结果。

### 导出与 Excel

- 打印 PDF、原件包和 Excel 是三种不同输出；纯数据发票仍可导出 Excel。原件按原始格式保留，不把预览图当原件。
- 需要用户配置目录/命名时依 [ADR 0004](../../adr/0004-export-interaction-model.md) 进入独立导出配置页签；直接输出的格式使用直接保存。系统目录选择与业务配置分开，不新造高级导出弹窗。
- 发票原件目录可按购方、票种、月份、项目组织；命名维度按现有配置契约核实，未接能力不得显示为已可用。
- Excel 导入依 [ADR 0005](../../adr/0005-import-mapping-model.md) 从台账进入上传 → 映射 → 预览/导入流程。缺归属、重复、日期/金额错误逐行说明；重试不重复写入已成功记录。
- 结构、合并区域、公式与回读规则见 [真实票据 Excel 参考](./real-ticket-excel-reference.md)。该文件是历史样本结构证据，不能拿样本缓存金额替代业务事实或当前验收。

### 台账 XLSX 边框配置（#437）

导出同屏预览提供“表头边框”和“数据行边框”两组，每组上、下、左、右可独立选择线型与颜色。默认四边细线；预览使用合法 CSS 线宽与线型，实际文件使用对应 Open XML 边框。已有配置中的合法复合线型原值保留，网页用相近虚线显示，不宣称 Office/WPS 双引擎视觉一致。

配置以 `headerBorder` / `dataBorder` 表达分组，未提供的组、边和字段先继承旧 `border`，再使用默认值；显式分组值优先。标题与合计仍使用旧 `border`。旧配置的字体、行高、列宽、格式、冻结及合并开关保持原意；旧调用方在默认配置上修改 `border` 后也应继续生效。

颜色接受 6 位 RGB 或 8 位 ARGB，可带 `#`；明确清空颜色表示黑色，持久化后不能重新继承旧彩色值。非法颜色或线型必须提示并保留输入，不保存或生成文件。

组件仅保留导出草稿，预览和实际 XLSX 共用该配置；保存为默认必须经现有 Pinia action 与本机设置表。取消或恢复默认都不改已保存值，恢复默认后只有再次点击保存才覆盖默认设置；保存失败保留草稿和先前默认值，允许重试。编辑已保存草稿后撤下“已保存”提示。预览列序与导出列契约共用，票种、金额和合计必须对应正确表头。实际文件验收逐角色回读 `styles.xml` 与工作表单元格样式引用，不能用 CSS 或单元格值替代。

金额格式控件必须显示当前保存值，默认格式使用共用格式常量；非内置格式作为自定义选项原值保留。默认文件名按打开预览时的用户本地日历日生成，预览与实际下载名称一致，不能因 UTC 转换落到前一天。

## 六、OCR 设置边界

引擎、预处理、隐私和参数只以 [ADR 0006](../../adr/0006-ocr-paddleocr-vl-single-model.md) 为准。页面只允许编辑实际进入调用链的文档能力与有界超时，并显示发票/送货单/清单的真实接入状态。

设置尚未成功读取或重读失败时，不能把默认值标为已保存，也不能编辑、恢复默认或保存；提供独立重读动作。保存失败保留草稿并允许重试，运行状态检测不能代替设置读取。当前操作说明见 [OCR 设置指南](../../guides/ocr-settings.md)。

Access Token 与 API 地址继续由服务端私有配置持有，不在浏览器读取、回显或保存。固定模型名称由安全状态接口只读展示，不允许由页面提交或修改。不能把传统 PP-OCRv6 ONNX 参数伪装成 PaddleOCR-VL 云端参数。配置保存位置与回读经现行设置 Repository 核实，不由本页指定浏览器 SQLite 作为正式业务回退。

## 七、开票因子计算器 `/finance/invoice/factor`

独立页面，按 [ADR 0012](../../adr/0012-exact-factor-combination-solver.md) 的本地计算语义求解**恰好等于目标值**的加法组合；不再返回 1% 范围内的近似方案。

### 布局：税额顶栏与左右工作区

```
┌────────────────── 税额计算 ──────────────────────────────────┐
│ 含税金额 │ 税率 │ 价税合计 │ 不含税金额 │ 税额 │ 大写        │
└─────────────────────────────────────────────────────────────┘
┌──────────────────┐  ┌────────────────────────────────────────┐
│ 开票因子（单价）  │  │ 精确组合结果 / 本轮目标                │
│ 因子值 / 最大数量 │  │ 结果摘要（总数/截断/耗时）             │
│ 小数 / 删除 / 添加│  │ #│表达式│使用项│总数                    │
│ 必须包含 / 排除   │  │ 表达式和单项均可点击复制               │
│ 返回数量 / 计算   │  │                                        │
└──────────────────┘  └────────────────────────────────────────┘
```

视觉与共用金额沿用 [#204 最终决定](https://github.com/zodea/crm-new/issues/204#issuecomment-5145177434)，由 [#432](https://github.com/zodea/crm-new/issues/432) 落实；它已推翻早期三段式稿。顶部税额栏与下方两个面板按 DC `CalcScreen.jsx` 留间距；桌面左栏约 330px，右侧占剩余空间。小屏按“税额 → 因子与控制 → 结果”单列排列，金额和大写可在各自格内换行。

桌面工作台使用应用当前可用高度，因子配置和结果列表分别在自身区域滚动；组合数量不撑出视口。表头在结果区内吸顶，密集表格只在自身横向滚动。

含税金额是唯一求解目标。首次默认 128640、因子 640/960（均不限数量、不勾小数），手动计算得到 68 条精确解；首次不自动求解。只给没有保存过的配置或缺失字段补默认，已存旧默认、自定义值、明确留空与空因子列表均保留。已有结果显示该轮实际目标，修改输入后不能把旧结果标成新目标。

### 精确求解规则

1. 目标值和因子先统一四舍五入为“分”，后续计算全程使用整数，禁止浮点近似。
2. 同值因子重复输入时，后输入项覆盖前输入项；展示顺序仍按首次输入位置。
3. 未勾选“小数”时数量只能为整数；勾选后可使用小数数量，但每一步都必须保证 `因子 × 数量` 恰为整分。步长口径见 [ADR 0012](../../adr/0012-exact-factor-combination-solver.md)。
4. 最大次数/数量留空表示不设上限；整数项的上限向下取整，小数项按其精确步长换算。
5. “必须包含”表示该因子至少使用一个最小步长；“排除因子”在本次求解中完全移除。已有计算结果后，筛选条件变化会在 300ms 防抖后重算；首次仍手动计算。
6. 结果只展示精确解。表达式如 `2×1 + 4×2`；小数数量项附带精确金额，如 `2.5×0.5(=1.25)`。

### 计算反馈

- 计算时限：10 秒；重算期间保留上一轮结果，直到 Worker 返回后原子替换。150ms 内完成时不切换按钮文案、不清空结果、不显示遮罩；超过 150ms 才显示计算遮罩，遮罩内实时显示耗时并可取消。
- 默认返回：100 条；硬上限：5000 条。
- 可完整统计时显示精确总解数；规模过大或超时时明确标记“总数未统计/结果可能不完整”。

算法、线程边界、超时降级与持久化决策统一见 [ADR 0012](../../adr/0012-exact-factor-combination-solver.md)，本页面蓝本不复制实现细节。

### 税额计算

共用含税金额先转成“分”，输入后即时更新价税合计、不含税金额、税额与含税金额大写四格；每格作为一个可聚焦按钮复制完整值。空金额不计算，也不能复制伪零。税率只接受 `1-13` 的正整数，越界即时收敛到边界，小数不进入计算状态。不含税金额四舍五入到分，税额用“含税金额 - 不含税金额”反算，确保勾稽一致。长数字和大写在各自格内换行；使用步骤见[因子与税额指南](../../guides/invoice-factor.md)。

## 八、本轮验收与待核实项

1. 识别、人工核对、归属、归档和打印状态分别验证，低置信度、全绿、缺归属、重复和纯 Excel 记录均有明确结果。
2. 新增/编辑使用整页；只读目标、列表返回、未保存离开、错误重试、真实空态与权限反馈在四档视口可用。
