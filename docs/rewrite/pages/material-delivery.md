# 送货单识别 — 上传·识别·归档·打印

> 路由: `/material/delivery`
> 页面: `app/pages/material/delivery/index.vue` → `app/components/delivery/DeliveryRecognitionScreen.vue`
> 来源: 现有 DeliveryView + delivery store 代码分析；2026-07-17 已接入真实 OCR 闭环
> 真实票据 Excel 结构、合并单元格和导入导出兼容规则见 [`real-ticket-excel-reference.md`](./real-ticket-excel-reference.md)。

> **现行 IA：处理区与归档库双区。** 权威见 `CONTEXT.md`「归档」词条、[#42](https://github.com/zodea/crm-new/issues/42) 与 [#113](https://github.com/zodea/crm-new/issues/113)：
> - **处理区 = 送货单识别**（乙供材管理 · route `delivery`，本页下文的上传/整理树/识别/核对流程）：放**待识别 / 识别中 / 待核对 / 待打印**；归档后原件仍留在待打印范围，直到收到打印成功回执或被明确排除。
> - **归档库 = 送货单归档库**（乙供材管理 · route `deliveryArchive`，设计稿 `kit/DeliveryArchiveScreen.jsx`）：已归档件的**左树右列表**。左树两级 **项目 → 分供方**（分供方按其合同**签订日期升序**），每项目下设 ⚠**「未区分分供方」**兜底节点；**所有节点带文件数量角标（只数量不金额）**；点树节点出该节点文件列表。
> - **归档规则**：核对是归档前置但不等于自动归档；归属信息齐全并由用户触发归档后才进入归档库。未指定项目**禁止归档**（批量/单个同拦截）。
> - **归档与仓储分开**：归档写入人工确认后的送货单头、材料明细和原件关系；有效态逻辑送货单与到货头 1:1，明细只保留一份事实。缺原件或偏差未闭合须标明未闭合，不能仅凭 `archived=1` 生成有效到货或库存。单价分析只读取人工确认的有效单价，“价格待补录”行暂不进入分析。
> - **打印独立处置**：新归档默认待打印。“打开打印”只打开原件/系统打印窗口，不改变状态；打印机实际输出后由用户另点“登记已打印”才移出队列，手动排除只记已排除。同一上传文件即使识别出多张送货单，也按持久化打印批次恢复为一个任务。
> - **归档不是终态**：单条归档记录可从详情或整页编辑入口改归属/字段，任何修改一律弹**二次确认**（识别难免出错，留改错通道）。文件拖拽批量改归属、批量归属调整和手动新建归档节点暂不属于当前实现，后续另立工作项。
> - **分供方名模糊纠错**：识别/文件夹推断的公司名在分供方库模糊匹配 → 只给建议，必须人工采用后才绑定；确认的 OCR 写法记入分供方别名。
> - 当前先上传识别，在核对归档前强制选择项目。旧“上传先拦归属 / 文件夹整理树 / 分区”的六阶段计划不再作为实施规格；可选批量整理能力由 [#411](https://github.com/zodea/crm-new/issues/411) 先调查现状与已定范围。

> **历史实现记录（2026-08-11，待 #411 按当前提交复核）**：处理区已经打通上传、裁边扶正、OCR、表格解析、三栏核对、归档持久化和跨刷新待打印队列；打印采用“打开原件 → 用户完成系统打印 → 明确回执”的保守闭环。归档库已经可以按当前筛选导出固定结构 ZIP：Excel 明细、原始 PDF/图片、缺失留痕，以及用户可选的只含图片的合并 PDF。文件夹整理树、批量改归属、可配置导出目录，以及多份 PDF 保持原对象的无损合并仍属后续工作。OCR 模型、隐私边界、Token 与预处理策略只以 [ADR-0006](../../adr/0006-ocr-paddleocr-vl-single-model.md) 为准；原件保真边界以 [ADR-0019](../../adr/0019-delivery-export-source-preservation.md) 为准。

> **#253 人工校对边界（2026-08-07 已收口）**：所有 OCR 结果先生成“待人工归档”草稿，不因置信度或版式标准而自动归档。标准版式可自动预处理；手写、低清、字段不足或非标准单据进入人工处理队列。缺单价或金额时，经人工查看原件并确认送货事实后可先归档，但必须标记“价格待补录”，且在补录并确认有效单价前不得进入价格分析；数量×单价与金额不一致时标记“金额待复核”，人工确认并填写原因后才能归档。供应商或日期缺失不得自动补全；单号缺失可在人工确认后归档并标记“原件无单号”。每行材料名称、单位和非零数量必须人工确认；相同文件正常上传去重，不重复建单。显式失败重试或重新识别需受控且不能覆盖人工稿。

> **2026-08-13 运行态补验**：参考站当前菜单没有可安全确认的一一对应“送货单识别/归档库/材料价格”页面，因此这些瑞航独有工具继续以本地 DC 与本规格为视觉和业务权威，不从相邻页面外推上传、OCR、归档、下载或导出行为。相邻的材料到货列表可见“源单据、送货单编号、合同、分供方、仓库、结算/付款状态”，材采合同详情的“物资管理”又按新/历史入库、直入直出、新/历史出库聚合，证明送货归档必须成为到货链的可追溯来源，而不是另一套孤立台账。完整只读证据见 [`material-management.md`](./material-management.md) 与 [运行态参考审计](../../design/runtime-reference-audit.md)。

## 历史缺口与已定关系

- 2026-08-13 测试库观测有 3 个 `archived=1` 送货单头和 4 条材料明细；2 个头已绑定分供方并含有效单价，另 1 个进入“未区分分供方”。三条记录都没有持久化原件正文，详情正确显示“缺原件/补传原件”状态。
- 归档库列表、送货单号详情、项目详情、分供方详情，以及单价分析中的来源送货单/历史材采合同下钻均已存在；列表返回详情后仍需恢复原项目—分供方树节点、搜索、日期和分页上下文。
- 2026-08-13 走查中，`delivery_records.ocr_status` 持久化人工核对完成态为 `reviewed`，`buildMaterialPriceCatalog()` 却在收到 `ocrStatus` 时只接受 `done`。当时 `/material/price` 将上述已有价格事实全部过滤并显示“尚无可分析的材料价格”。#411 应先核实当前提交是否已消除该词汇差异；识别完成与人工核对仍需分开，兼容存量数据，不补 Mock 绕过。
- `#411` 已继承“物理原件 ≠ 逻辑送货单；有效态逻辑单据与到货头 1:1；明细单一事实”的决议，当前只核验迁移与实现，不重开 FK/桥表选择。送货单号、材料名和金额相似都不能代替真实 ID。

## 一、交互流程

### 第一步 · 上传队列

拖拽或选择受支持文件后原地进入队列，显示文件、进度与待处理状态；上传不因未选项目而被提前拦截。文件身份去重与多单识别分别处理，不能把一份物理原件直接等同于一张逻辑送货单。

### 第二步 · OCR 识别

```
触发: "识别全部" 或 单张识别
  └─ 调用统一 recognizeDocument(file) 接口
      ├─ 图片与可解析的单页 PDF 可生成裁边扶正 PNG 派生件；多页/解析失败 PDF 保持原文件
      ├─ 输出 Markdown / HTML 表格 / layout regions
      └─ 失败显式报错并允许会话内重试

结果写入:
  ├─ 公司原文与主数据匹配建议（冲突须人工采用）
  ├─ 日期、单号、明细行
  ├─ 单据类型：送货单 or 收据
  └─ 状态: done / error / ocrPartial
```

### 第三步 · 人工校对与问题处理

使用现行原图与字段工作区修改公司原文、日期、单号及材料明细，绑定项目与分供方；不沿用旧 `FileCard / PartitionBar` 分区拖拽规格。识别失败可重试，无法读取可人工录入；公司冲突只提示真实候选并由用户采用，部分识别保留已识别内容。

问题筛选显示缺字段、金额待复核、原件缺失及身份偏差。可归档例外与阻断条件按下方“未完善检测规则”分别提示，不把缺单价、无单号和未确认数量当作同一种错误。

### 第四步 · 归档与打印

归属齐全且符合人工核对门槛后，由用户触发归档进入归档库。归档写入、有效到货闭合、库存派生及价格分析分别验证，不把同一个成功消息解释成全部完成；价格待补录行不进入价格分析。打印保持独立状态机。

| 路径 | 操作契约 |
|------|------|
| 核对并归档 | 强制选择项目；把人工确认后的单头、材料明细和原件写入 `delivery_records` / `delivery_lines` / `file_refs`；到货闭合与库存资格另按物资规则核验 |
| 分供方未命中 | 允许归到项目下“未区分分供方”，保留 OCR 供应商原文供后续纠正 |
| 待打印 | 归档后默认保留在打印工作队列；同一上传文件的多张识别单共享 `print_batch_id`，跨刷新仍恢复为一个任务 |
| 打开打印 | 只打开原件和系统打印窗口，不写打印状态；取消、失败或关闭窗口都继续保留 |
| 登记已打印 | 打印机实际输出后由用户单独确认；整批记录都仍为 `pending` 才原子写 `printed` 并移出队列 |
| 排除打印 | 用户明确不打印时写 `excluded` 并移出待打印范围；`printedAt` 保持为空 |

## 二、归档手工新增与编辑

`deliveryArchiveForm` 是归档库统一的整页表单入口：`/material/delivery/archive/form` 手工新增，`/material/delivery/archive/form/:id` 编辑既有记录。列表的“新增送货单”和行内“编辑”、详情页“编辑”都导航到该整页路由，不再打开大型弹窗。编辑既有归档时保存前使用二次确认；手工新增保存后即归档并进入材料台账。

| 分区 | 字段与规则 |
|---|---|
| 档案信息 | 仅编辑既有记录时显示文件名、OCR 识别公司与原件只读留痕 |
| 归属 | 新归档/修订必须人工选择项目*、分供方*；既有缺失记录保留“未区分分供方”待核验，均从当前来源 lookup |
| 单据字段 | 送货单号、送货日期、材料摘要、单据金额 |
| 备注 | 备注 |

改项目/分供方后重新校验去重自然键；材料摘要和单据金额保存人工核对结果，材料行仍是唯一送货明细；到货闭合、库存与单价分析按各自资格投影，不复制可编辑明细。

## #441 浏览器中央来源与修订

当前浏览器的识别归档、整页手工新增/编辑、归档库、当前/历史详情、原件预览/下载、打印处置和原件包都从同一中央送货领域读回。项目/分供方候选来自当前中央上下文，归档树使用当前材采合同签订日期排序；读取失败显式重试，不能退回同名本地项目或样本。Tauri 旧适配与受控迁移输入保持独立，当前中央实例不代表生产重启持久化。

新归档和修订均须人工选择有效分供方及送货日期；“未区分分供方”保留用于既有缺失记录，不能作为新归档跳过校对的选项。结构化编辑必须填写修订原因并二次确认；失败保留当前页人工稿，历史版本只读。明确版本冲突后可“重新核对当前记录”，展示只读当前字段及材料行；人工稿与原因保留，只有用户明确确认才采用已核对版本作为下一次保存基准。取消不抬版本，重读失败先关闭保存入口再原地重试；离页、切换来源、失去写权限或确认期间版本再次变化均不应用旧核对结果。补传或替换原件填写原因、建立新资产引用，旧字节保留；没有可信历史原件关联时显示缺失或待核验，不借当前原件补成旧版本。

识别工作区属于写态，刷新按页签规则回到安全页面；重新进入处理区读取已归档待打印队列，未保存 OCR/人工草稿不承诺跨刷新恢复。一份明确原件的多条逻辑送货共用当前资产；后续引用不同资产时打印分组分别保留。打开打印不算已打印；原件包逐逻辑记录重新验权并保留完整 PDF，目录选择或导出取消不产生假成功。

当前项目建议只从已人工确认送货的工地原文和项目 ID 派生，仍需人工选定；旧项目别名迁移未完成。分供方别名在归档成功后独立保存，失败不撤销已成功归档，并提供单独重试。旧项目子表读者已用显式来源适配；当前中央项目详情的完整送货入口仍由 #411 后续承接，不能以旧组件存在宣称已接入。

受控迁移按现有预检、备份、对账、确认和回滚入口承接头/行/原件/打印/历史留痕；缺正文、孤儿或错配有明确结果。无法证实历史版本或祖先归属的旧原件仅受保护保全，待人工核对；不伪造修订，不开放未经证明的历史正文。到货、库存和结算资格继续独立验收。

## 四、归档库原件包导出

归档库当前工具栏按页面筛选结果直接生成 ZIP，不进入 ADR 0004 的可配置目录页签。包内包含：

- `送货单明细.xlsx`：按材料明细行展开，并记录缺原件、共用原件、未区分分供方和价格缺失等异常。
- `导出说明.txt`：说明本次保真范围、图片转换结果和缺原件记录。
- `原件/PDF/`：每份 PDF 原件以原始字节整份保留；多页不拆分，共用源只入包一次。
- `原件/图片/`：图片保持原格式。用户勾选“图片另生成 PDF”且存在可转换的 PNG/JPG 时，包内另有只含图片的 `图片原件合并.pdf`。

当前不把 PDF 原件加入图片合并件，也不通过 Canvas/JPEG 重建 PDF。多份 PDF 真正保持原对象与页面结构的合并仍待后续依赖选型与实现；当前能力不得表述为“所有原件已合并 PDF”。

## 六、未完善检测规则

- 项目、至少一条材料行、材料名称、单位和非零数量必须完成核对；错误定位到具体字段或行。
- 缺单价/金额允许人工查看原件、确认送货事实后归档，并标“价格待补录”；量价不符须人工确认并记录原因。
- 缺供应商或日期不自动补齐；供应商尚未匹配可进入“未区分分供方”。原件无单号经人工确认后明确标记，不用自动造号掩盖。
- 原件缺失、身份错配或到货偏差未闭合单独显示，不能因价格已补而自动获得库存或结算资格。
- 识别失败、部分识别、冲突、保存失败分别给出重试/人工处理入口；重新识别不清空人工修改。
- `#411` 按当前提交验证更正后的归档、到货、价格与返回上下文；材料结算只由 #409 承接。
