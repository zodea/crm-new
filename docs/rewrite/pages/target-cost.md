# 目标成本 — 项目预算基线

> 表单蓝本：`targetCostForm`（ADR 0014）
> 持久化权威：`DATABASE.md` 的 `target_costs` / `target_cost_items`
> 路由：`/project/target-cost` · `/project/target-cost/form/:id?` · `/project/target-cost/:id`
> 参考边界：已观察红圈目标成本列表与只读详情，按 [运行参考 R-TARGET-COST-LIVE](../../design/runtime-reference-audit.md) 对齐构图、密度和安全下钻；表单没有直接运行证据，沿用 DC 与本地业务契约，不外推审批、导入或写操作。当前复核由 [#412](https://github.com/zodea/crm-new/issues/412) 承接。

## 定位

目标成本是项目动态成本对比的预算基线。版本头、科目明细和正式成本事实分开管理：

- 列表用于定位项目版本、当前基线和金额基准。
- 整页表单只维护版本头与金额基准。
- 专用详情页维护当前版本的科目明细，并只读对比正式合同、已确认结算、有效工资实际事实和独立原费用。

不能用表单头的“已签合同额”录入值替代正式合同聚合，也不能把成本对比反写成预算明细。

## 列表

- 单行工具栏提供关键词、项目、当前基线/历史版本和状态筛选；筛选只改变当前结果集。
- 名称进入专用详情，编辑进入整页表单。
- 表格展示版本名、项目、当前基线、含税合价、已签合同额、状态和更新时间；金额均来自目标成本版本头。
- 结果按最近更新排序并在本地分页。筛选无结果时提供清除条件；没有任何版本时提供新建入口。
- 无项目草稿保留独立行和明确提示；已删除版本有独立筛选与恢复入口，不混入活跃版本。中央预算读取不依赖工程量权限；无项目目录权限时不提供完整项目 lookup 候选，也不能据此隐藏本来有权读取的无项目草稿。已有可读预算可显示自身关联项目名称，并据当前预算结果集筛选；内部项目资格数据不得另行暴露无预算关联的目录，项目详情跳转仍核对目标权限。
- 密集表格只在自身区域横向滚动，页面在 390 / 768 / 1024 / 1280–1440px 不产生横向滚动。

## 新增/编辑

| 分区 | 字段与规则 |
|---|---|
| 基本信息 | 版本名、项目（lookup）、当前对比基线；保存草稿可未填，非草稿保存必须完整 |
| 金额基准 | 合同收入、计划利润、已签合同额、含税合价、无税合价、税额 |
| 备注 | 备注；提示科目明细在详情页维护 |

## 科目明细

详情页的“科目明细”是当前版本唯一维护入口，使用可编辑明细网格：

| 字段 | 规则 |
|---|---|
| 成本科目 | 必须从专业分包、合同劳务、材料、机械、工人工资、费用报销、其他中选择 |
| 分项名称 | 必填 |
| 单位 | 可空 |
| 数量 / 单价 | 可空；填写时必须是非负数 |
| 目标金额 | 必填且非负 |
| 备注 | 可空 |

- 新增、编辑和删除在同一份草稿中完成；点击保存后按当前行序统一事务写入。
- 已删除行软删除并保留操作日志；既有行只能更新当前版本下仍有效的明细，禁止跨版本改写。
- 目标金额为独立确认值，不强制等于数量乘单价。旧库合法的空分项名、空数量/单价和真实零原样保留；主动编辑后按当前必填规则核对，不为迁入补造分项名。
- 明细校验或保存失败时保留草稿，把成本科目、分项名称、数量、单价和金额错误回填到对应行与单元格，并聚焦首错；不能只发全局消息或先清空界面再报告失败。
- 编辑中通过返回列表、查看项目、编辑版本、浏览器后退或同详情参数切换离开时，统一确认是否放弃；拒绝后保持原草稿，保存成功后解除离开保护。
- 没有明细时展示可解释空态，仍可直接进入编辑。

## 详情与成本对比

- 顶部摘要明确区分“科目明细合计”“含税预算基准”“动态成本”“累计支付”。
- “成本对比”只读正式源单并按成本科目聚合；合同、结算、工资、付款或报销有真实路由时提供穿透入口。
- 历史版本始终读取自身 `target_cost_items`；项目正式成本事实仍按该版本所属项目实时聚合，不偷换为当前基线明细。
- 动态成本、已签和累计支付分别按真实来源状态读取；同一支付在合同及结算出现时按稳定来源身份去重，合法独立分摊分别核对。跨科目或金额冲突保留未知，不自行选择一边。
- 来源完整、仅部分已知、未接入、无权与不可用分别说明；只有确定为零才显示零。实际成本不完整时不计算剩余预算和偏差；分母为零或未知时不计算比率。
- 当前 Native 详情和项目成本分类表已保留空合同/协议金额、损坏目标金额及缺预算基准，分别显示可证小计与来源缺口；工资 P4 完整实际源未接入，旧已发工资头不充当完整成本或支付。原费用清偿防重复和实际源资格直接见 [DATABASE](../DATABASE.md#104-动态成本与合同付款)。
- 缺失版本显示返回列表入口；已删除版本只读归档并提供合规恢复；加载失败保留重试动作。源单下钻携带原项目、来源及预算版本，返回后恢复原入口；没有真实可访问对象时不生成假链接。

## 规则

- 项目 lookup 保存 `project_id`；保存草稿时可暂缺，保存/提交时必填且必须命中活跃项目。
- 同一项目最多一条活跃记录为“当前对比基线”；切换时在一个事务内取消旧基线。
- 基线切换保留旧、新两版的真实审计；删除当前基线后允许暂时没有基线，不自动挑选替代。恢复旧基线与现有基线冲突时拒绝抢占。草稿基线不参与正式成本控制。
- 金额允许草稿为空；提交时必须为非负数。含税、无税和税额只作勾稽提示，不强制覆盖人工确认值。
- 项目成本对比读取当前基线及其 `target_cost_items`，不读取其他历史版本。
- 科目明细保存与版本头保存是两个明确动作；编辑明细不静默提交或改写版本头状态。
- 每个打开的版本头/明细页独立保存版本身份、读取依据及草稿。普通列表刷新不更新旧草稿的提交依据；版本冲突需要显式核对。切换、停用页签或同路由更换版本后，迟到结果不能改写另一版草稿。
- 提交结果未知时保留原命令、正文和附件字节并恢复原提交；不能用新输入替换原正文。成功但回读失败只重试读取，不重新创建。离开、关闭和刷新统一保护未保存输入。
- 有直接参考的列表与详情按 ADR 0013 对齐红圈；DC 继续决定品牌及无直接参考的表单。#191 是历史实现来源，`covered` 仅表示设计覆盖，不能代替 #412 对真实数据、明细事务和运行交互的本轮验收。

## 原件、审计与受控接管

- 版本头附件由预算命令核对权限及归属，真实正文、元数据、软删除与审计在同一事务保存；不能把另一版本的文件读写到当前版本。
- 旧文件路径只在迁移原图及审计留痕，客户端不据此读取本机文件。缺少正文明确标为缺件；未知大小/上传时间保持未知，损坏正文不能伪报普通缺件。
- 历史用可读动作、变更项、时间与真实经办人展示；缺少历史资料说明未知，不编造姓名、时间或变更值。
- 每个旧预算版本连同科目顺序、原件、空值、删除历史与可识别审计独立迁入；项目不必已有工程量，无项目草稿仍可接管。项目映射、重复基线或完整图损坏在预检阻断。
- 重复确认同批来源保留后续日常更正。恢复若会删除预算日常事实、独立版本或当前/历史项目引用，整批拒绝，其他中央域也不能先行变化。
- 浏览器中央接管与桌面适配边界仍按 [ADR 0020](../../adr/0020-browser-authority-and-demo-workspace-boundary.md)；本地验证实例不证明生产持久化已交付。具体实施验收见 [#412 预算证据](../../design/evidence/issue-412-target-cost/README.md)。

## 验收

1. 刷新后金额基准、基线选择和已保存科目明细保持。
2. 同项目不会出现两条当前基线。
3. 列表筛选、分页、名称详情和编辑入口可达；空数据与筛选无结果可区分。
4. 详情可维护当前版本科目明细；校验失败或保存失败不丢草稿并定位首个错误；带未保存草稿离开时统一确认。
5. 成本对比只读取正式源单，预算版本与实际来源保持可区分。
6. 列表、表单、详情和明细网格在四档视口无页面级横向滚动，键盘可完成筛选、页签切换、编辑和保存。
7. 无项目及空金额草稿、真实零、历史空分项名和缺件经完整迁移后冷读保持；重复确认和危险恢复符合来源保护规则。
8. A/B 多版本独立草稿、迟到响应、版本冲突、未知结果恢复及附件失败均不改错版本或丢失输入。
9. 实际来源去重、合法分摊及缺口可解释，源单与预算往返保持同一项目和版本；不能以单个来源通过代验完整工资、材料及财务成本链。
