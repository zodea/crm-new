# 工程量管理 — 户型模板 + 指派矩阵 + 阶段完成

> 路由：`/subcontract/quantity` · `/subcontract/quantity/template` · `/subcontract/quantity/region` · `/subcontract/quantity/stages` · `/subcontract/quantity/:pid/:uid`（`uid` = 户 ID）
> 页面：`pages/subcontract/quantity/index.vue` · `pages/subcontract/quantity/region.vue` · `pages/subcontract/quantity/[pid]/[uid].vue`
> 架构决策：[ADR 0010](../../adr/0010-quantity-matrix-and-construction-record-model.md)
> 数据模型：[DATABASE.md §2.6 / §3.4 / §4.7](../DATABASE.md)
> 术语：`CONTEXT.md`（户型模板 / 工程量指派 / 阶段完成 / 施工记录）

详情加载必须校验 `uid` 对应户经楼层、楼栋归属的项目等于 `pid`；参数不匹配按无权威目标处理，不能把 `pid` 当装饰参数。

本页是工程量域唯一写入面。量、责任和完成分开管理：量在户型模板层共享，人员/班组责任按户 × 工种，完成事实按户 × 工序阶段。工资、施工进度、首页甘特、月度报量和施工记录只能消费本模块的派生查询，不得各建副本。

## 一、区域与户型模板

区域树为“楼栋 → 楼层 → 户”；户挂一个项目内户型模板，并通过活链接看到模板房间。房间不逐户复制：模板房间拥有稳定身份，某户的一间房由“户 + 模板房间”共同指认。楼层结构可复制到其他楼层，但复制只产生区域初始快照，不建立跨楼层联动。

“项目区域”使用独立整页表单，不依赖施工合同。空项目可依次新增楼栋、楼层和户；同级编码唯一，户型模板必须属于当前项目。区域新增与户型模板入口互相返回，补齐户后可回工程量矩阵继续责任配置，也可直接进入新建楼栋分组。矩阵归档后区域结构锁定，不允许继续新增。

户型模板维护“房间 × 工种 × 分项 × 三量”：

- 合同量：有合同清单时从 `boq_lines` 按户型导入；无清单可手工填写。施工前阅读态有合同量时优先展示；人工修正必须同时展示识别原值和当前值。合同量用于合同约定、收入、量差和毛利对照，不得作为工人工资应付量。
- 暂估量：现场尚未核定时用于工资草稿/预付，可人工调整。
- 现场量：最终工资结算使用；保存现场复核计算式和计算结果。单元格阅读态显示计算结果，点击或键盘进入编辑态才显示算式；支持中文备注、全角运算符、括号与四则运算，解析失败时保持算式可见供修正，且不得覆盖上一份有效结果。
- 工资量选择只允许暂估量或现场量，缺失时显式提示，不得使用合同量或跨口径静默回退；最终结算固定取现场量。
- 模板是活链接：保存后所有挂靠户实时读取同一结构与三量；“借用另一户型”只做一次性快照复制。
- 房间显示名不是关联键；改名不得改变既有个人责任范围，模板房间新增/软删实时作用于全部挂靠户。
- 没有天然房间粒度的整户/分部项归到模板内稳定的“整户范围”，不能用空房间或临时名称占位。
- 编辑先进入草稿，只有“保存模板”才更新正式版本；离开未保存草稿需确认。

## 二、量差总表

工程量矩阵工具栏提供“量差总表”，只读消费户、户型模板三量、甲方合同清单和已审批变更，不保存第二份量差事实：

- 按实际户挂靠的户型模板明细汇总为“楼栋 × 分项”，支持楼栋、分部、工种和分项筛选。
- 合同量包含已审批数量变更；合同单价采用已审批的最新调价。草稿或未审批变更不进入正式量差。基础合同量可随实际户按楼栋展开；已审批变更没有楼栋归属字段时只计一次，并单列“待分摊签证”，不得复制到每一户或猜分到楼栋。
- 签证只调整合同量。“待分摊签证”行在暂估量或现场量口径下按缺所选量呈现并排除出可计算合计，不得填 0 充数——否则会凭空生成等额“结余”。该行只在合同量口径下量差为 0。
- 对比口径可切换合同量、暂估量或现场量；量差为“所选量 − 合同量”，量差金额走甲方合同单价轨。多合同单价按原明细分别计算后汇总，不拿班组工资单价替代。
- 缺合同量、所选量或合同单价时明确标出缺失行，并从可计算合计中排除；不得自动回退为另一口径。
- 宽表只在 Dialog 内部横向滚动；页面同时显示当前范围、可计算金额、缺值行数和源数据更新时间。

工资轨仍只允许暂估量或现场量，最终结算固定现场量；量差总表可查看合同量不等于工资可以选择合同量。

### 取数基准的单一定义

基准枚举、列名映射与显示名只在 `app/lib/quantity/basis.ts` 定义一份，量差总表、进度款报量和工资轨都从这里取；界面不另造标签，SQL 不自行拼列名。工资轨的“禁止合同量”收窄规则由 `app/lib/quantity/wage-source.ts` 单独承载，不在基准模块放宽。

### 进度款报量的基准接线

月度报量与甲方报量单消费同一派生查询，按生成时选定的基准取数：

- 生成月度报量时显式选择合同量、暂估量或现场量，缺省现场量；所选基准冻结进 `monthly_statements.quantity_basis`，已生成单据不随后续基准或三量变化漂移。
- 派生只读所选基准自己的列。缺量以缺量条数显式回传，不回退到另一口径，也不按 0 计入自动量。
- 正式生成时若所选基准缺量，直接报“<基准名>缺失：<分项>”阻断，不生成金额偏低且事后无从追溯的报量单。
- 甲方报量单的合同清单行带出缺量标注；缺量行照常带入明细，不因自动量为 0 被过滤掉。

## 三、矩阵视角

### 当前来源与整页入口（#442）

浏览器正式项目通过中央目录、Repository 与命令读取和保存；同 ID 的正式与演示项目按来源区分。演示只读适配与桌面本地适配边界以 [ADR 0020](../../adr/0020-browser-authority-and-demo-workspace-boundary.md) 为准，正式失败不得回退到本地快照。切换来源、离页或权限变化时，旧请求不得覆盖当前事实或恢复旧写入动作。

“户型模板”“项目区域”“阶段配置”打开独立整页。模板编辑加载时固定的版本用于保存，取消、失败或重新核验权限不得用新版本覆盖草稿基线。模板量的清单关联必须从当前项目合同的稳定 BOQ 候选明确选择；原识别量与用户输入量分开显示，解除关联后旧识别量标为“原识别值”。具体数据及保存规则链接 [DATABASE](../DATABASE.md) 与 [COMMANDS](../COMMANDS.md)，不按名称补稳定身份。

新项目先保存模板分项，再进入阶段配置显式建立阶段及分项映射。普通阶段默认不成为报量阶段；逐分项明确选择唯一报量阶段，也可明确不指定。同一分项可参与多个阶段进度。逐行保存报量选择时，其他行尚未保存的选择必须保留。人工进度阶段与按户完成阶段的边界、稳定阶段身份及归档确认遵循 [ADR 0010](../../adr/0010-quantity-matrix-and-construction-record-model.md)。使用步骤见[工程量中央流程指南](../../guides/quantity-central-workflow.md)。

页面顶部提供项目、楼栋、月份筛选，以及“工种矩阵 / 班组矩阵”切换。主体为楼层 × 房号的可点击网格。

### 工种矩阵

- 每格先回答“是否已有责任人”和“各阶段完成到哪里”，不把同工种全部阶段压成一个完成率。
- 月份颜色来自阶段完成日期；同格存在多个完成月份时显示最近阶段状态，完整时间线在详情展开。
- 墙砖/地砖、一遍/二遍腻子分别显示与筛选，不能共享完成标记。

### 班组矩阵

- 按班组或个人查看其负责的户和已完成阶段。
- 批量指派按楼层、房号分组；尚未指派的户可选，已归其他负责人的户禁用。
- 修改已有归属前显示原责任人、受影响阶段与历史记录，经确认后走领域 action；不得用批量入口静默覆盖。

### 极简总览

默认格只显示是否有人施工、当前阶段摘要和异常点。hover / focus 蒙板提供“配置”和“详情”两个入口；详情使用独立页签，不使用拥挤实体弹窗。

## 四、责任配置

责任边界以 ADR 0010 和 `DATABASE.md` 为准，本页只规定配置体验：

- 先选工种，再按楼层或房号批量选择户；每个候选格显示当前责任人。
- 个人计件可继续打开模板房间与分项范围选择器，但批量入口仍以户为操作单元。
- 已有归属被替换前，确认页必须列出原责任人和受影响户；取消后保留当前筛选与选择。
- 责任人或个人范围任一变化，确认后均软删旧责任（旧范围随父级保留并隐藏）并新建责任/范围，不原地改写；历史完成仍显示完成当时的责任与范围。
- 责任配置区不提供“完成月份”或“整个工种已完成”字段；完成登记从下一分区进入。

## 五、阶段完成

完成事实的权威粒度、照片归属和写入约束见 ADR 0010 与 `DATABASE.md`；页面按工序阶段提供独立登记入口。

### 单阶段完成

1. 选择工序阶段与户；默认带出该户当前工种责任人。只有该阶段任一分项在当前户型存在可见量明细时才允许新登记；模板后来调整不吞掉既有历史事实。
2. 填完成日期；页面同时显示该阶段对应的量与计划区间。
3. 缺验收照片时提供“取消 / 保存到草稿”，不丢输入。
4. 上一阶段未完成或缺照片只显示风险提示，不硬锁本次登记。

### 整个工种批量完成

批量入口必须先展开该工种的全部适用阶段，并在确认页逐项列出；用户可排除尚未完成的阶段。提交结果仍按阶段分别回显，不能只显示一个工种级结果。

阶段进度卡读取领域层统一提供的阶段进度，不在页面重新统计；同一分项映射多个阶段时仍显示多张独立进度卡。

月度量与阶段进度是两种口径：多阶段仍分别算进度，但月度报量须保证每个分项只计取一次；具体数据模型与约束见 [DATABASE.md](../DATABASE.md) 和 [ADR 0010](../../adr/0010-quantity-matrix-and-construction-record-model.md)。

## 六、详情与施工记录

户详情独立页签按“工种 → 工序阶段 → 完成日期”展示：

- 同屏区分当前责任与完成时执行责任，并展示三量、阶段状态、完成日期和验收照片；已完成行按审计引用显示当时责任/范围，房间显示名与三量仍读取当前模板。数据来源契约见 ADR 0010。
- 展示分项小计、全户合计和 `(合同单价 − 班组单价) × 量` 毛利参考。
- 阶段小计与全户合计按明确计量单位分别计算，全户按稳定房间 ID＋分项 ID 去重；缺量、明确零和已知部分遵循 [读模型空值契约](../READ-MODELS.md#24-可空值与聚合完整性)，未标明单位不提供可误用合计。操作见[合计与导出指南](../../guides/quantity-totals-and-export.md)。
- 工人/班组详情消费同一派生接口查看只读施工记录；施工记录不落独立表、不设独立导入模板。
- 日常验收照片不进入工人证照；整改/罚单照片继续归对应整改或罚单实体。

## 七、导入、导出与归档

- 导入走 ADR 0005 映射页签，分别提供“模板量、责任配置、阶段完成”三类目标；旧合一行仅允许进入迁移预检，不可直接写入。
- 导出走 ADR 0004，页面、工资预览和导出必须复用同一派生查询。
- 月度完成量按月份、显式报量阶段与单位分行，三量数值、完整度和已知部分分别导出。跨单位行的完成户数不可相加冒充项目完成户总数，阶段完成户数仍看阶段进度。
- 项目矩阵可归档锁定；归档后改模板、指派或完成事实均需二次确认并记录操作日志。
- 已发放工资按 #117 月度快照固定，矩阵后改不追溯历史发放。

## 九、验收要点

- 户型模板活链接与借用快照语义可区分；清单量手改留识别原值。
- 责任配置和阶段完成使用不同入口，修改责任不会把阶段自动标成完成。
- 墙砖/地砖、一遍/二遍腻子在界面可分别完成，并显示不同完成率、完成日期和照片。
- “整个工种批量完成”的确认页逐阶段列项，保存后也逐阶段回显。
- 缺照片只能取消或存草稿；后续工序不被硬锁。
- 施工记录、工资预览、排程和月度报量展示一致，不因页面切换出现不同口径。
- 矩阵在窄视口只允许自身局部横滚，页面无横向滚动；键盘可到达格子操作与详情入口。
- 量差总表与工资预览读取同一三量权威源；合同价轨与班组工资价轨不混用，缺值不静默回退。
