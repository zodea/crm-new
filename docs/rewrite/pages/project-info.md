## 定位

项目是全系统的核心关联实体。项目详情页是整个系统的**经营驾驶舱**——顶部汇总面板的每个数值都从下方 Tab 的业务数据自动聚合计算。

### 项目 Excel 导入

#423 在列表恢复有权限时可用的“导入项目”，进入独立 `/import/mapping/project` 页签；历史深链复用同一边界。使用现有三步界面（上传并选择 Sheet → 映射 → 人工预览与确认），来源行、真实客户 ID、归一阶段和拒绝原因可核对。导入期间不能修改映射；成功项目提供详情或返回列表；部分成功、响应丢失、回读失败与取消都有明确结果，成功行重试不重复创建。表格只能自身横滚，步骤切换焦点到标题，来源切换继续使用全局确认浮层。

字段、关系、状态、权限、防重与错误语义见 [中央命令契约](../COMMANDS.md#项目-excel-导入423)，来源保留范围见 [DATABASE §10.7](../DATABASE.md#107-导入追溯与差异表)，操作见[使用指南](../../guides/project-excel-import.md)，实际验证见[证据](../../design/evidence/issue-423/project-import-verification.md)。没有直接对应参考导入页的运行证据，继续使用本地 `ImportMappingScreen.jsx` 与 ADR 0005 三步蓝本，不宣称复刻参考站导入内部流程。

### 新增/编辑项目

采用 ADR 0014 整页表单。

浏览器整页项目表单由 `ProjectCommandStore` 经中央 HTTP 预载和保存；Tauri 仍保留既有本地写路径。新建由服务端分配不透明 ID，编辑用 `baseVersion` 防止覆盖。冲突时重读最新表单并由用户选择。开发测试实例保留既有本地草稿；本机正式模式仅保存待核对的原提交编号，字段和原件只留当前页面内存，重启后依据同库回执恢复原记录。客户候选在浏览器读取同一中央客户来源。完整契约见 [`COMMANDS.md`](../COMMANDS.md)，操作见[本机项目指南](../../guides/local-project-storage.md)。

本机项目软删除后从正常列表移除；旧详情地址仍保留只读资料和明确“项目已删除”提示，专用于恢复，编辑入口在删除状态明确为未删除前不出现。删除期间表单和原件接口拒绝读取，恢复保留原项目身份、版本链和每份附件自己的删除状态；不存在的 ID 仍为 not-found，不打开空表单。列表提供待核对提交和已删除项目入口。未接管的正式经营、合同、工资与预算来源不得由开发实例或零值补齐。

从测试数据行进入时，详情向后台提交 origin 意图并由后台按 `(dataOrigin,id)` 校验；删除、伪造或追加 URL 参数都不能重新标记来源。获准的测试详情持续显示“测试数据”并只呈现中央基础资料；编辑入口及可能改变阶段、文件或关系的业务模块不挂载。`origin=demo` 的项目表单显示禁止状态；删除 origin 后后台仍只查正式来源，不会将演示 ID 加载进正式写入表单。开启测试数据叠加不会禁止显式 `origin=real` 的正式项目编辑。

项目列表生成的来源感知详情 URL 可以直接打开和刷新。项目 ID 存在但 URL 来源与中央身份不一致时，详情显示“项目身份与来源不匹配”；指定来源下没有该 ID 时显示“项目不存在或当前来源不可见”。两种状态都不按项目名称查找替代记录，也不会打开空白新建表单。#289 / #313 已实现列表搜索、阶段、排序、列筛选、页码、每页条数、应用页签、滚动和焦点的完整往返恢复；原行不存在时焦点降级到列表标题。

## 三、顶部汇总面板

### 3.1 项目经营数据

顶部经营区当前展示主合同金额、增补合同金额、变洽签审定金额、变更后合同金额、项目收款、确认支付、往来收付款、管理费完整性和已知资金余额。管理费没有权威来源时必须显示 `—`；相应余额明确标为“已知资金余额”，不得把未知管理费按 0 处理后冒充完整可用资金。

字段来源与既有聚合见 [`DATABASE.md §4.1`](../DATABASE.md)，新增成本与资金公式见 [`DATABASE.md §10.4-10.6`](../DATABASE.md)。本页只规定卡片顺序、状态呈现和下钻交互，不维护公式副本。

### 3.2 票据信息

票据信息区展示销项票额、销项税额、进项票额、进项税额、增值税和税负率。计算口径只在 [`DATABASE.md §4.2`](../DATABASE.md) 维护；金额卡仍使用统一状态与下钻契约。

### 3.3 支出合同与动态成本分类

经营汇总以 [`CONTEXT.md`](../../../CONTEXT.md) 的成本术语和 [`DATABASE.md §10.4`](../DATABASE.md) 的归集口径为准，界面并排展示合同额、动态成本和付款三个维度。合同劳务与工人工资必须使用独立行，点击金额进入对应源单列表。

### 3.4 指标完整性

每张金额卡按 [`DATABASE.md §10.5`](../DATABASE.md) 的 `OperatingMetric` 契约显示状态、汇总截止时间、缺失来源和下钻入口。界面不得把空值强制格式化为 0，并须为不同状态提供可辨识的中文标签。

| 交付 | 5 | 工期一览表、工期延期说明工联单、范围界面确认文件、无甩项确认工联单、结算封板图 |
| 保修 | 0 | 动态 |

### 4.2 每个任务的文件管理

每个阶段任务 = 一个文件上传槽位：

```ts
interface PhaseTask {
  id: string
  phaseIndex: number         // 0-5 对应六个阶段
  taskIndex: number          // 阶段内序号
  title: string              // "施工组织设计方案"
  description: string        // "资料员扫描上传并存档"
  responsible: string        // 负责角色: 资料员/设计师
  files: FileRef[]           // 已上传的文件列表
  status: 'pending' | 'uploaded' | 'confirmed'
}

interface FileRef {
  id: string
  fileName: string
  fileSize: number
  uploader: string           // 上传人
  uploadedAt: string         // 上传时间
  storagePath: string        // Tauri 文件系统路径
}
```

### 4.3 阶段状态规则

- 绿色✓ = 该阶段所有任务均已有有效文件或已经人工确认归档
- 蓝色◐ = 当前活跃阶段（部分任务完成）
- 灰色○ = 未开始
- 进度显示: `已完成数/总任务数`

### 4.4 项目文件柜

项目文件柜不建立第二套文件记录，而是按当前项目的阶段任务聚合有效 `file_refs`。每份文件保留阶段、任务、分类、上传人和上传时间，可从任务行或项目文件柜预览、下载；删除任一入口的文件都会同步影响另一入口及阶段进度。

### 4.5 项目档案包

项目详情顶部“导出档案包”使用当前项目的真实关系快照生成 ZIP。导出范围只从下列关系进入，不按文件名、路径或金额文本猜测归属：

- 项目基本信息、阶段任务及其 `file_refs`；
- 项目分供方、施工/支出合同、请款、发票、支付、结算、到货和相关项目单据；
- 通过项目关系可证明的分供方证照（当前仅进入目录清单供查看，不进入 ZIP 原件导出）；
- 通过项目当前关系、工资/考勤/签工或户分配可证明的班组与工人资料。

ZIP 目录固定为 `00_档案说明与清单`、`01_项目信息与工程档案`、`02_分供方/01_甲供材`、`02_分供方/02_乙供材`、`03_班组与工人` 和 `99_待归类`；阶段目录按六阶段稳定编号。甲供材已定接入 Party 供货方；缺少真实关系的存量记录继续使用 `甲供材供货单位待配置`，不冒用 `developer`、客户或自定义名称；#408 / #411 验证真实关系接入。核心资料默认勾选；证照与工人个人资料在目录中可查看，但当前不参与原件导出，导出下载权限后续单独配置。`99_待归类` 暂时保留，名称自定义能力后续再配置。原件正文缺失的 `file_refs` 只进入文件清单并标明原因，不生成空白替代文件；同名文件、非法路径和重复导出均使用稳定可解释的归一化规则。

> 详情各分区经所属领域 Repository 读取；已接管浏览器领域遵守 ADR 0020 中央唯一来源，不回退 SQLite。#180 是历史接线记录，#408 须逐分区复核当前来源、空态、关系和回读；未接目标明确不可用。项目详情保持只读，写操作进入各自源单流程；草稿可供核对但不进入正式金额合计，源单变更或软删后重读同一事实源。

- 每个真实子表有独立的搜索、列筛选、分页和筛选结果合计
- 项目详情保持只读；新增、编辑、审批和导出继续进入对应业务源单流程

- 有底部汇总行的子表显示合计金额
- 子表标题显示记录数: `收款登记(12)`

### 响应式

响应式强制口径见 [ADR 0013](../../adr/0013-align-all-ui-to-online-design.md)。宽屏经营数据/票据最多 6 列；`6` 只是语义最大列数，组件按最小可读宽度自动降为 3/2/1 列，不以固定两排模板锁定。业务 SegTab 允许换行，禁止页面级横向滚动；子表只在自身数据容器内横滚。最低在 390 / 768 / 1024 / 1440px 验证摘要、阶段时间线、Tab、主操作和全部字段可达。

## 八、工程量评估

这是整个系统最大的单页，涉及：
- 3 个汇总面板（经营数据 + 往来款 + 票据信息）
- 1 个阶段时间线 + 文件管理
- 10 个 Tab × 平均 3 个子表 ≈ **25+ 个独立数据表**
- 子表只读查看、搜索、筛选、汇总及按能力导出；新增、编辑、删除与既定状态动作进入源模块
- 顶部面板的 15+ 个字段需要实时聚合计算

复核顺序按 #408 逐分区确认显示、来源、下钻与返回，再与源模块联验变更后的回读；不以已有框架或子表数量判定闭合。
