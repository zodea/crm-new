# CRM 界面模式

本文定义跨业务域稳定复用的界面结构。形状和色值看 [`DESIGN-SYSTEM.md`](./DESIGN-SYSTEM.md)，页面字段看 [`pages/`](./pages/)。有直接对应页时的构图、密度、控件状态与安全路径按 [ADR 0013](../adr/0013-align-all-ui-to-online-design.md) 和[运行参考证据](../design/runtime-reference-audit.md)；瑞航品牌、独有能力与无直接参考页的方案看 `DC重构设计源码/app.dc.html`。

## 0. 界面信息显隐（本轮定稿待实现，2026-09-08）

用户明确要求减少实际页面上的解释性文字，按参考界面仅保留少量必要常驻信息，其余有用说明就近按需展开。本节约束产品界面的默认展示，不要求删减使用指南、业务规格或其他文档中的必要解释；也不表示现有页面已完成清理。

| 信息 | 默认处理 |
| --- | --- |
| 完成当前任务所必需的信息 | 常驻标题、字段名、真实值、单位、操作和必要状态；错误、必填/校验、无权限、失败及重试、未保存提醒、危险操作影响和防止选错来源的提示保持可见，不藏到问号后 |
| 按需理解的信息 | 字段释义、金额口径、低频帮助放到相邻的问号入口；短说明用 tooltip，较长内容或包含链接/操作时用 popover，交互见[组件规格第 17 节](../design/kit-ui-component-specs.md) |
| 不帮助用户判断或操作的信息 | 重复标题、复述字段值的句子、开发/架构说明、占位解说和无实际内容的介绍直接从界面删除，不把整段无用文字搬进浮窗 |

- 常驻文案须简短且就近；同一区域已有明确标题时，不再附加同义副标题或“下方展示……”式段落。问号只为确有解释需求的内容出现，不给每个显然的字段机械添加。
- 来源用紧凑且可辨认的标识表达；需要补充释义时按需展开，不重复整段来源介绍。涉及来源差异、只读或操作限制的必要识别信息和即时反馈仍保留在相应对象或动作旁。
- 列表、详情及子表、整页表单、工作台与各动态类型逐页核对默认态和说明展开态；确认必要信息可见、删除的文案确属冗余、帮助入口可达且不遮挡任务。调整共享原语不能代替每页对照与运行验收。

## 1. 列表页

标准顺序：

```text
标题 / 视图在左，搜索与主要动作在右
同一工作面内的次行筛选（需要时）
数据表格或卡片
汇总与分页
```

- 默认完整展示参考页中适用于瑞航业务的列，保留参考顺序和信息密度；瑞航独有列接在对应语义分组后。既定排除项继续按领域规格排除，不为缩短表格默认隐藏其他适用列；宽表在表格内部横滚。逐页字段映射只记入对应[页面规格](./pages/)。
- 筛选、搜索、排序、分页、汇总和导出读取同一查询状态，具体合同见下文；金额汇总不能绕过当前筛选。
- 实体名用实体穿透，聚合金额用金额穿透；无有效目标时显示普通文本。
- 表格操作具有明确可访问名称；只放图标时仍需 tooltip/aria-label。
- 空态解释为什么为空并给出下一步；不能用“成功 toast”代替真实新建/导入能力。
- 已有连续工作面的页面使用 `ListShell continuous`，不再把标题、筛选和表格拆成独立卡片；窄屏工具有序换行，横向滚动限定在表格内。壳不接管查询、分页、汇总口径或来源恢复。插槽与嵌入式筛选条只看[组件规格第 13 节](../design/kit-ui-component-specs.md)。

[#418](https://github.com/zodea/crm-new/issues/418) 本批接入共用财务/物资列表、施工合同、分供方、项目和材料采购合同列表。该范围表示结构接入；逐页运行参考采证与未接入的领域能力仍由对应模块复核，不能据此认定全站复刻完成。

### 1.1 全站逐页对应（本轮定稿待实现，2026-09-08）

本轮以用户圈出的分供方名称、审批状态 tag 和整行表头为优先复核点，并将同一核对方法应用到全站每个界面。默认列合同已由用户确认；与此前“最少列组”及“状态色纯文字化”的冲突依据见 [#404 记录](https://github.com/zodea/crm-new/issues/404#issuecomment-5582280040)。本节描述目标，不表示既有列表、共享壳或原语已全部达到目标。

每个列表须在所属页面规格中逐项维护两张对应表：

- **列对应表**：参考列/顺序、瑞航字段与权威来源、默认展示或既定排除依据、内容格式/空值、实体链接或普通文本、状态语义、筛选/排序能力、当前差异与验收证据。
- **工具对应表**：参考工具位置与已核实名称、瑞航对应操作、操作范围与结果、权限及暂不可用原因、当前实现状态和验收证据。搜索右侧的每个入口分别占一行，不能合写为“工具栏已完成”。参考图标含义未核实时记“待采证”，不凭外形猜功能；当前能力缺失记“待实现/待依赖”，不自动变成永久排除。

有直接参考页时按其布局、控件状态与安全操作路径逐屏核对；无直接参考页时使用既定 DC 基准，并明确证据来源。公共组件验收、模板迁移或代表页通过均不能代替其他页面的运行验收。

### 1.2 搜索与查询联动（本轮定稿待实现）

- 每页明确搜索涵盖的字段和匹配方式；输入框必须作用于下方当前业务范围的完整记录集合。远程分页不得只筛当前页；确属完整本地集合的小表才可在本地完成同一查询。
- 关键词输入确认后短防抖提交，Enter 立即提交，清空恢复无关键词条件；中文输入法组合期间不提交半成品或把候选确认误作搜索提交。搜索、列筛选、工具栏筛选及排序共用一个查询状态，重复入口显示同一活动条件，不各自维护隐藏筛选。
- 条件变化回到第 1 页；翻页与改变每页条数保留条件。刷新重新请求当前条件，保留可用页码；数据减少导致越界时回到有效页。总条数与汇总使用同一匹配集合；跨页排序由完整集合执行，不能逐页各排各的。
- 导出使用点击时确定的同一查询及排序，默认导出该查询的完整匹配集合；若领域支持仅导出勾选记录，必须明确标注范围与数量。不能把当前页切片冒充全部筛选结果；目录、命名与写盘沿用既定导出合同。
- 最新请求胜出：过期响应不得覆盖新关键词对应的数据、数量、汇总、筛选选项或加载态。首次加载、无数据、无匹配结果、失败和权限不足分别呈现；保留旧数据的刷新失败必须说明其并非新查询成功结果，禁止显示成功反馈。
- 从详情或编辑返回列表，恢复来源的关键词、列/工具栏条件、排序、页码和可恢复的滚动位置；保存后按该条件重新核对结果，不能为了显示刚保存的记录暗中清除条件。来源参数和权限范围继续遵守领域导航合同。

### 1.3 搜索右侧工具的能力边界（本轮定稿待实现）

以下为公共行为边界，并非要求所有页面都放同一组按钮；每页须依据参考证据与瑞航适用能力逐项填写对应表。暂不可用的必要入口应在规格中保留差距；实际界面若显示禁用态，必须解释原因，不允许装饰性假按钮。

| 工具 | 公共行为边界 |
| --- | --- |
| 刷新 | 重新读取当前查询，保留条件、排序和有效页码；展示加载与失败反馈，不以清空条件或成功 toast 代替刷新 |
| 排序 | 显示当前字段与方向，能恢复默认顺序；表头与工具入口操作同一排序。可排序字段、默认次序及稳定翻页规则由页面和查询层确定 |
| 筛选 | 明确可筛字段与活动条件，可单项/全部清除；表头与工具入口操作同一筛选，清除时同步表格内部选中态 |
| 列设置 | 只改变展示顺序、显隐及允许调整的固定列/列宽，不改变查询数据或业务权限；提供恢复参考默认列的入口。视图偏好按当前设备、工作区、实际页面/类型和列版本隔离保存，刷新或重新打开恢复；新增列沿新默认值补入，失效列配置丢弃，读写失败仍可用默认视图并明确提示。仅保存列标识与布局，不保存业务行、关键词或敏感值；不扩大为账号云同步，本轮不声称已有公共 API |
| 导入 | 从当前实体进入既定模板、映射、校验及真实入库流程；成功返回来源列表并按原查询刷新，不用固定示例行或 toast 冒充导入 |
| 导出 | 遵守第 1.2 节查询范围及既定导出合同；保留权限过滤，失败可重试，不导出未经授权或仅展示占位的值 |
| 新增 | 进入对应独立整页表单；有业务类型首段时沿既定选择流程，保存后恢复来源上下文；不得用无实际保存的弹窗占位 |

表头可操作标记、键盘和状态 tag 的组件合同只看[组件规格第 12、16 节](../design/kit-ui-component-specs.md)。各页面至少运行验证：默认列与真实内容、筛选/排序活动态和清除、中文关键词/Enter/清空、跨页匹配与汇总/导出范围、快速连续搜索、空结果与失败重试、工具逐项结果、详情返回，以及规定视口内横滚/键盘/浮层边界。

## 2. 详情页

详情页组织为：

```text
标题与主要动作
简要元信息 / 关键摘要
主区域：资料或业务 Tab → 当前分区 / 事实表
辅助区：真实可用的合作摘要、档案、文件或关联入口
```

- 摘要只放高频判断信息；更多字段进入分区。
- 派生金额和状态必须由真实下游单据计算，并可穿透到来源。
- 关联 Tab 读取同一实体关系，不为展示维护第二份 mock。
- 资料作为一级页签时，完整资料只在该页签显示，业务表格前不重复完整资料。默认页签、URL 深链和金额入口由领域页决定；金额跳转应将目标导航滚入视口并聚焦当前页签，同时保留已有来源参数。
- 宽屏可采用主内容 + 辅助栏；当前 `EntityDetailShell` 在容器不足时将辅助栏堆到主内容下方，不把整页详情自动转成 Sheet。`compact` 与 `navigation`、`ReadOnlySection` 的布局合同见[组件规格第 10、14 节](../design/kit-ui-component-specs.md)。
- 审批、评论、动态或文件能力尚未接入时不为外观造空白占位；证照等专用工作流仍走已定义的独立页面。
- “详情已存在”不等于“闭环”：伪造零值、未接数据却伪装为空的 Tab、只弹 toast 的动作仍记为已搭未闭环；权威查询成功返回的真实零值或空集合是合法状态。

## 3. 整页表单

业务实体新增/编辑遵守 ADR 0014：

```text
返回来源列表 / 面包屑
标题和实体状态
可选分区锚点
分区卡片（字段最多两列，按 ADR 0014 的最小可读宽度降为单列）
明细网格（确有子表时）
sticky 保存动作组
```

- 新建与编辑使用独立路由和应用页签；同一实体编辑页按 id 去重。
- 可编辑字段默认持久化；只读派生值不复制进第二份余额。
- 保存草稿、保存并新建、保存并提交、保存、取消/放弃等动作使用共享合同。
- 必填失败同时提供字段级错误和全局摘要；焦点移到首个错误。
- dirty 状态在路由离开、关闭应用页签和返回列表时统一拦截。
- 行级小对象可用 Dialog；不要把完整业务实体降回大弹窗。
- `EntityFormShell` 已由共用财务/物资整页表单复用，字段网格最多两列，按自身容器降列；分区导航、明细局部滚动与保存动作的组件合同见[组件规格第 11 节](../design/kit-ui-component-specs.md)。本轮结构调整保留原领域字段、校验、保存和 dirty 语义，不宣告所有表单逐页复核完成。

## 4. 工作台

OCR、归档、排版等多区工作台通常包含队列、原件/主视图和校对/操作区：

- 所有分区共享当前实体 id 和草稿状态，不各自复制选择。
- 宽屏允许多栏，窄屏改为分段切换或 Sheet；切换时组件状态不得丢失。
- 上传、识别、核对、归档是独立状态转换。核对完成不代表自动归档。
- process toast 只报告过程；真正成功必须由 store/数据库状态变化证明。

## 5. 树与矩阵

- 项目→分供方、楼栋→楼层→户等层级使用真实 id，显示名变化不改变引用。
- 树选择与右侧列表过滤保持同一状态源。
- 大矩阵只在自身区域横向/纵向滚动；页面和背景工作区不与模态内容竞争滚动。
- 局部网格按容器宽度响应，不能因整个浏览器到达 `xl` 就强制多列。

## 6. 状态与动作

- 状态徽标表达事实，不把按钮的可用性伪装成状态。业务状态的统一目标为紧凑浅底小圆角 tag，具体语义与边界见[组件规格第 16 节](../design/kit-ui-component-specs.md)；本轮定稿待实现，不以视觉对齐新增完整审批流程。
- destructive 操作先确认；完成后按领域约束提供撤回。
- loading、空态、错误、无权限和只读都必须有不同呈现。
- 审批、归档、支付等不可逆或高影响动作写明对象和影响范围。
- 占位交互只能用于明确的开发阶段，不得计入闭环完成度。

## 7. 浮层

- Popover / Select / Tooltip 属于触发它的 Dialog 或 Sheet 的交互子树。
- 模态打开后背景 inert、不可点击、不可滚动；关闭后焦点和滚动位置恢复。
- 一个任务只允许一个主要滚动区；长表单使用明确的内容滚动区和稳定操作区。
- 嵌套模态必须有业务必要性，优先用同一模态内步骤、Popover 或 Sheet。

## 8. 验收

每个页面同时验证：

1. 视觉：与当前设计稿同屏比较。
2. 行为：真实 store/数据库状态变化，不只看 toast。
3. 导航：来源、详情、编辑和穿透的页签归属正确。
4. 响应式：390 / 768 / 1024 / 1280–1440px 与 200% 等效宽度。
5. 可达性：Tab 顺序、focus-visible、Esc、焦点返回、可访问名称。
6. 滚动与浮层：页面无横滚、密集区局部滚动、背景锁定、子浮层层次正确。
7. 信息显隐：按第 0 节逐页核对常驻内容、必要反馈和按需帮助；同时验证 hover、键盘及触摸路径，不能只凭页面文字变少判定完成。
