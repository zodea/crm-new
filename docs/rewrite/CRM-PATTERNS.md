# CRM 界面模式

本文定义跨业务域稳定复用的界面结构。形状和色值看 [`DESIGN-SYSTEM.md`](./DESIGN-SYSTEM.md)，页面字段看 [`pages/`](./pages/)。有直接对应页时的构图、密度、控件状态与安全路径按 [ADR 0013](../adr/0013-align-all-ui-to-online-design.md) 和[运行参考证据](../design/runtime-reference-audit.md)；瑞航品牌、独有能力与无直接参考页的方案看 `DC重构设计源码/app.dc.html`。

## 1. 列表页

标准顺序：

```text
标题 / 视图在左，搜索与主要动作在右
同一工作面内的次行筛选（需要时）
数据表格或卡片
汇总与分页
```

- 默认展示用户判断所需的最少列组，次要列通过视图或列设置暴露。
- 筛选、搜索、分页和汇总读取同一过滤状态；金额汇总不能绕过当前筛选。
- 实体名用实体穿透，聚合金额用金额穿透；无有效目标时显示普通文本。
- 表格操作具有明确可访问名称；只放图标时仍需 tooltip/aria-label。
- 空态解释为什么为空并给出下一步；不能用“成功 toast”代替真实新建/导入能力。
- 已有连续工作面的页面使用 `ListShell continuous`，不再把标题、筛选和表格拆成独立卡片；窄屏工具有序换行，横向滚动限定在表格内。壳不接管查询、分页、汇总口径或来源恢复。插槽与嵌入式筛选条只看[组件规格第 13 节](../design/kit-ui-component-specs.md)。

[#418](https://github.com/zodea/crm-new/issues/418) 本批接入共用财务/物资列表、施工合同、分供方、项目和材料采购合同列表。该范围表示结构接入；逐页运行参考采证与未接入的领域能力仍由对应模块复核，不能据此认定全站复刻完成。

## 2. 详情页

详情页组织为：

```text
标题与主要动作
简要元信息 / 关键摘要
主区域：资料或业务 Tab → 当前分区 / 事实表
辅助区：真实可用的合作摘要、档案、文件或关联入口
```

- 摘要只放高频判断信息；更多字段进入分区。
- 派生金额和状态必须由真实下游单据计算，并可穿透到来源。
- 关联 Tab 读取同一实体关系，不为展示维护第二份 mock。
- 资料作为一级页签时，完整资料只在该页签显示，业务表格前不重复完整资料。默认页签、URL 深链和金额入口由领域页决定；金额跳转应将目标导航滚入视口并聚焦当前页签，同时保留已有来源参数。
- 宽屏可采用主内容 + 辅助栏；当前 `EntityDetailShell` 在容器不足时将辅助栏堆到主内容下方，不把整页详情自动转成 Sheet。`compact` 与 `navigation`、`ReadOnlySection` 的布局合同见[组件规格第 10、14 节](../design/kit-ui-component-specs.md)。
- 审批、评论、动态或文件能力尚未接入时不为外观造空白占位；证照等专用工作流仍走已定义的独立页面。
- “详情已存在”不等于“闭环”：伪造零值、未接数据却伪装为空的 Tab、只弹 toast 的动作仍记为已搭未闭环；权威查询成功返回的真实零值或空集合是合法状态。

## 3. 整页表单

业务实体新增/编辑遵守 ADR 0014：

```text
返回来源列表 / 面包屑
标题和实体状态
可选分区锚点
分区卡片（字段最多两列，按 ADR 0014 的最小可读宽度降为单列）
明细网格（确有子表时）
sticky 保存动作组
```

- 新建与编辑使用独立路由和应用页签；同一实体编辑页按 id 去重。
- 可编辑字段默认持久化；只读派生值不复制进第二份余额。
- 保存草稿、保存并新建、保存并提交、保存、取消/放弃等动作使用共享合同。
- 必填失败同时提供字段级错误和全局摘要；焦点移到首个错误。
- dirty 状态在路由离开、关闭应用页签和返回列表时统一拦截。
- 行级小对象可用 Dialog；不要把完整业务实体降回大弹窗。
- `EntityFormShell` 已由共用财务/物资整页表单复用，字段网格最多两列，按自身容器降列；分区导航、明细局部滚动与保存动作的组件合同见[组件规格第 11 节](../design/kit-ui-component-specs.md)。本轮结构调整保留原领域字段、校验、保存和 dirty 语义，不宣告所有表单逐页复核完成。

## 4. 工作台

OCR、归档、排版等多区工作台通常包含队列、原件/主视图和校对/操作区：

- 所有分区共享当前实体 id 和草稿状态，不各自复制选择。
- 宽屏允许多栏，窄屏改为分段切换或 Sheet；切换时组件状态不得丢失。
- 上传、识别、核对、归档是独立状态转换。核对完成不代表自动归档。
- process toast 只报告过程；真正成功必须由 store/数据库状态变化证明。

## 5. 树与矩阵

- 项目→分供方、楼栋→楼层→户等层级使用真实 id，显示名变化不改变引用。
- 树选择与右侧列表过滤保持同一状态源。
- 大矩阵只在自身区域横向/纵向滚动；页面和背景工作区不与模态内容竞争滚动。
- 局部网格按容器宽度响应，不能因整个浏览器到达 `xl` 就强制多列。

## 6. 状态与动作

- 状态徽标表达事实，不把按钮的可用性伪装成状态。
- destructive 操作先确认；完成后按领域约束提供撤回。
- loading、空态、错误、无权限和只读都必须有不同呈现。
- 审批、归档、支付等不可逆或高影响动作写明对象和影响范围。
- 占位交互只能用于明确的开发阶段，不得计入闭环完成度。

## 7. 浮层

- Popover / Select / Tooltip 属于触发它的 Dialog 或 Sheet 的交互子树。
- 模态打开后背景 inert、不可点击、不可滚动；关闭后焦点和滚动位置恢复。
- 一个任务只允许一个主要滚动区；长表单使用明确的内容滚动区和稳定操作区。
- 嵌套模态必须有业务必要性，优先用同一模态内步骤、Popover 或 Sheet。

## 8. 验收

每个页面同时验证：

1. 视觉：与当前设计稿同屏比较。
2. 行为：真实 store/数据库状态变化，不只看 toast。
3. 导航：来源、详情、编辑和穿透的页签归属正确。
4. 响应式：390 / 768 / 1024 / 1280–1440px 与 200% 等效宽度。
5. 可达性：Tab 顺序、focus-visible、Esc、焦点返回、可访问名称。
6. 滚动与浮层：页面无横滚、密集区局部滚动、背景锁定、子浮层层次正确。
